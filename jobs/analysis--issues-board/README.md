# Issues в Keryx Desktop. Исследование и передача реализации

Решение связывает очередь тикетов GitHub-аккаунта с обычными сессиями Keryx и управляемыми Flow. Полный рабочий сценарий включает личную доску, список, доску выбранного GitHub Project, чтение описания и обсуждения, подготовку Flow из существующей или новой сессии, восстановление после сбоя и проверку в нативном приложении. База исследования — main на df73018d9.

## Решения для исполнителей

- Личная очередь охватывает доступные репозитории выбранного аккаунта. Папка, открытая в Desktop, нужна для локальной работы и определяется по репозиторию тикета.
- На карточке независимо видны состояние GitHub, Status выбранного Project и фактическое состояние Flow. Перемещение карточки в GitHub Project — явная операция записи с проверкой прав и последующим чтением.
- **Open session** открывает настоящий диалог и сохраняет его идентификатор. **Create flow** запускает подготовку в той же сессии. **Open flow** возвращает пользователя в тот же пакет, включая пакет, ранее созданный через CLI.
- Task Manager и общий навык ведут жизненный цикл; Desktop открывает соответствующую сессию и отображает её события. Повторный запуск сверяет запись операции, источник Flow, привязку сессии и подтверждение первого хода.
- Передача планирования заканчивается перед заморозкой. Пользователь отдельно решает, когда заморозить критерии. Исполнители принимают пакет после этого решения.
