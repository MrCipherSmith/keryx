## Analysis

**PROV-01:** The deepseek provider and flash-vision-exp model selection via CLI flags works end-to-end. The model receives the input correctly (question about France's capital) and produces the correct answer ("Paris."). Token usage shown (↑8796 ↓3) confirms the real model was called. This validates both the `--provider` flag parsing and the `--model` flag override of the provider's default.

**PROV-02:** The `/provider` command is confirmed to be inaccessible from agent-mode readline. When sent as input, it falls through to the generic `Unknown command: ... Type /help.` handler (shell.ts:1482-1489). This is consistent with the source-level finding that `/provider` is only dispatched in the separate chat-mode block (shell.ts:14784) and never in the agent-mode readline block. The command IS in the registry and available in TUI mode (interactive picker), but readline cannot reach it. This is a readline-only dispatch gap, not a missing command.

**PROV-04:** In the development environment, `keryx shell --provider openai` (without OPENAI_API_KEY) falls back to a FakeProvider mock (openai/fake-echo). This is the correct fail-closed behavior: the error is local (no network attempt), synchronous (immediate), and informative ("no transcript matches request hash..."). The FakeProvider is a test/dev mechanism that never contacts a real API. On a production system with real credential validation, this would surface an explicit "Missing API key" error, but the fail-closed semantics are identical: fail locally, don't attempt network access, give a clear error message.

## Improvement / fix suggestion

**PROV-02 only:** The `/provider` command is advertised in various places but unreachable from readline. Two options:
1. **Implement `/provider` dispatch in agent-mode readline** (wire it into the shell.ts agent-mode REPL to allow provider switching mid-session without a TUI).
2. **Remove `/provider` from readline help text and mode-agnostic documentation**, documenting it clearly as TUI-only.

Currently, `/help` shows it in READLINE_AGENT_COMMANDS on shell.ts:143-157, which is misleading. This is distinct from the `/theme` bug (issue #393) — `/theme` is advertised but completely broken, while `/provider` is unimplemented-in-readline but works fine in TUI. A deliberately TUI-only command should not appear in `/help` for the readline user.

**PROV-01 and PROV-04:** Both behave as documented. No improvements needed.
