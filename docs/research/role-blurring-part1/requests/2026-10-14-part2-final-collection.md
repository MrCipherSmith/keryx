## Правила

- В git попадают только числа и коды: никаких текстов вопросов, вариантов и причин, никакого seed, имён хоста и пользователя, путей. Проверку экспорта не обходить.
- Не трогать снимок 04809f4f, `part1-counts.json`, `decisions-export-2026-10-04.jsonl` и файлы flow.
- Не менять код. Доля `forced` и маркеры `[verify]` — отдельные flow; здесь только данные.
- **Рабочие проекты** (папка с журналом keryx, но не репозиторий keryx: другой remote, нет `.metaproject/flows/` keryx, основная ветка не `main` и т. п.) включаются по решению оператора от 2026-10-15, но обезличенно: в git только `raw/decisions-<host>.jsonl` и журнал с числами. Никогда не записывать их ветку, HEAD, remote, имя репозитория, номера задач и PR, имена основных веток, список их flow. Роль в журнале — «рабочий проект».
- Для копий keryx ветку и HEAD источника тоже не записывать: достаточно роли копии.
- Чужую рабочую копию не переключать, не обновлять и не коммитить в неё. Её журнал только читается.
- Не использовать `git stash`, `git add -A`, `git add .`, `git commit -a`: в копиях лежит чужая незакоммиченная работа. Добавлять только файлы из `docs/research/role-blurring-part1/` по именам.
- Без строк `Co-Authored-By` и ссылок на сессию в коммитах и PR.
- В main ничего не сливать. PR открывает только последний запуск (шаг 8), сливает его оператор.

## Вопросы оператору

Задавать инструментом вопросов с вариантами, не списком в тексте: оператор читает с телефона. Все вопросы шага 1 — одним вызовом.

## Шаги

### 1. Определить, что есть на этой машине, и спросить оператора

1. Перечислить seed-файлы: `ls ~/.config/keryx/decisions/*.seed`. Их число — сколько рабочих копий на этой машине писали журнал.
2. Найти все папки с журналом: каталоги, где есть `.metaproject/data/decisions/`, в домашнем каталоге оператора (глубина до 4, без `node_modules`, `.git`, `Library`). Для каждой вычислить `host` командой из шага 3 в режиме проверки (без записи файла) и определить, копия ли это keryx или рабочий проект.
3. Сопоставить с таблицей выше. Спросить оператора одним вызовом:
   - какая это машина (машина 1 / машина 2 / другая);
   - если найден `host`, которого нет в таблице: включать его в сбор или нет (показать `host`, число строк, первую и последнюю `openedAt`, keryx это или рабочий проект; без пути). Рабочий проект по умолчанию включается обезличенно;
   - если копия из таблицы не найдена: где она (оператор ответит путём; путь не записывать никуда, кроме переменной окружения шага 3);
   - будет ли этот запуск последним (тогда шаг 8 открывает PR).

### 2. Подготовить копию с веткой исследования

1. Взять копию, где можно переключиться на `research/part2-data`, не задев чужой работы. Если основная копия чистая или её незакоммиченные файлы не пересекаются с `docs/research/role-blurring-part1/`, работать в ней. Иначе `git worktree add <рядом>/keryx-part2-final origin/research/part2-data`.
2. `git fetch origin`, `git switch research/part2-data`, `git pull --ff-only`. Если ветка отстала от `origin/main`, влить `origin/main`; конфликты в `decisions-export-latest.jsonl`, `part1-counts-latest.json` и `sync-status.md` разрешать версией из ветки, их перегенерирует шаг 4.
3. Запускать код только из исходников ветки через `bun` (глобальный `keryx` может быть старым): `bun install`, если нет `node_modules`.

### 3. Выгрузить каждый источник этой машины

Выполнять из корня копии с веткой исследования отдельно для каждого источника этой машины, передавая путь к его рабочей копии в `SRC`. Путь остаётся в окружении и никуда не пишется.

```sh
SRC=<путь к рабочей копии источника> WRITE=1 bun --eval '
import {writeFile, readFile} from "node:fs/promises";
import {machineExport, renderMachineRows, parseMachineRows, machineFileName} from "./src/decisions/service.ts";
const e = await machineExport(process.env.SRC);
if (!e) { console.log("no seed: this copy never recorded a decision"); process.exit(0); }
const name = machineFileName(e.host);
const file = `docs/research/role-blurring-part1/raw/${name}`;
const text = renderMachineRows(e.rows);
parseMachineRows(text, name);
let before = 0;
try { before = parseMachineRows(await readFile(file, "utf8"), name).length; } catch {}
const last = e.rows.map(r => r.openedAt).sort().at(-1);
console.log(JSON.stringify({host: e.host, rows: e.rows.length, before, added: e.rows.length - before, last}));
if (e.rows.length < before) { console.error("STOP: fewer rows than the previous export"); process.exit(1); }
if (process.env.WRITE === "1") await writeFile(file, text);
'
```

Без `WRITE=1` команда только печатает `host` и числа (режим проверки для шага 1).

Остановиться и спросить оператора, если выгрузка падает (дубль `seq`, нечитаемая запись) или строк стало меньше, чем в прошлой выгрузке. Причину записать в `raw/journal-<host>.md`, не обходить.

### 4. Пересобрать объединение

`bun run keryx research sync` из корня копии с веткой. Он пересобирает `decisions-export-latest.jsonl`, `part1-counts-latest.json` и `sync-status.md` из всех `raw/`. Если у этой копии свой seed, sync заодно перезапишет её `raw/`-файл тем же содержимым, что дал шаг 3; это нормально.

Проверить:

- `bun test --timeout 30000 src/decisions/machine-export.test.ts src/commands/research-sync.test.ts` проходит;
- в `decisions-export-latest.jsonl` строк ровно столько, сколько во всех `raw/decisions-*.jsonl` вместе, без дублей `(host, seq)`;
- ни одно решение (`ref` + `openedAt`) не встречается в двух источниках. Если встречается, значит журнал скопирован вместе с репозиторием: остановиться и спросить оператора, какой источник считать исходным;
- в `raw/` и `decisions-export-latest.jsonl` нет ключей `seed`, `question`, `options`, `reason`, `text`, нет путей, email и имени пользователя;
- в новых и изменённых `raw/journal-*.md` нет имён веток, хешей HEAD источников, remote и имён основных веток рабочих проектов. Проверить поиском по именам веток, которые агент видел на этой машине.

### 5. Записать журнал каждого источника

В конец `raw/journal-<host>.md` каждого источника этой машины добавить раздел `## Финальная выгрузка <дата> <время> UTC`:

- машина (машина 1 / машина 2) и роль копии (основная / параллельная), без путей;
- строк; предыдущая выгрузка; добавлено;
- первая и последняя `openedAt`;
- живых решений после 2026-10-04 15:26 UTC, из них `eligible`, `forced`, плечи A–D у `eligible`;
- версия keryx и HEAD копии с веткой исследования (ветку и HEAD источника не писать);

### 6. Flow вне main

Записать в `raw/journal-<host>.md` и спросить оператора, что делать с flow без ветки.
