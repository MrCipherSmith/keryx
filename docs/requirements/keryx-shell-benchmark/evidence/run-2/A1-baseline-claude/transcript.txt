  Two things that break beyond the type checker

  1. Import-time process.exit(1). config.ts:125-141 runs EnvSchema.safeParse(process.env) at module load and hard-exits on failure. So if your change
  adds a required env var (or narrows a z.enum), it does not fail as a type error in 25 files — it kills the process at startup for all 106 transitive
  dependents, including the 20+ unit tests that pull config in through memory/db.ts. NODE_ENV=test bypasses only the ALLOWED_USERS/ALLOW_ALL_USERS
  access-control check on line 137, not the schema parse.

  2. as const widening. Fields like TTS_PROVIDER and HELYX_PROFILE are literal-union typed. Removing a variant from a z.enum narrows the type and will
  break switch/comparison sites in utils/tts.ts and mcp/dashboard-api.ts even if the field name is untouched.
