  Why it doesn't currently blow up

  Every cyclic binding is either a function declaration (hoisted) or a const Map that's only read inside a function body, never at module top level.
  ESM handles that fine. It's a structural smell, not a live bug.

  Root cause and fix

  bot/handlers.ts:31-88 mixes two responsibilities: router registration (needs to import all handlers) and ownership of pending-input state (which all
  handlers need). Extracting the state into e.g. bot/pending-state.ts — the maps, setPendingInput, clearPendingInput, setPendingTool, pendingScope,
  plus the bot ref — and having both handlers.ts and the leaf modules import that breaks all 7 direct back-edges at once, which collapses cycles 8 and
  9 too. The lazy-import cycles in menu.ts are a separate, intentional-looking pattern; they'd need a command registry to remove, if you care.
