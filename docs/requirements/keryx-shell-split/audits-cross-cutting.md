## Job 2 — coverage

### 1. `src/session/store.callers.test.ts` (lines ~140, 151, 153, 188)

`files`/`callers` are produced by a **real, live filesystem glob scan** — not a manifest, not a hardcoded list, not the gdgraph code graph:

- `sourceFiles(srcRoot)` (`src/lib/config-dir.scan.ts:115-120`): `[...new Glob("**/*.ts").scanSync(srcRoot)]`, POSIX-normalized, filtered to drop any path containing `.test.`, sorted. Runs fresh against the on-disk tree every time the test runs.
- `treeSources(srcRoot)` (`config-dir.scan.ts:123-125`): same glob, plus `readFileSync` of every file's content into a `Map`.
- In `store.callers.test.ts`: `files = sourceFiles(SRC)` (line ~136) and `callers = [...tree.keys()].filter(...)` (line ~146) where `tree = treeSources(SRC)`.

Because these are live scans, **splitting either god-file will break the two "canary" assertions that hardcode the current flat filenames**, but will **not** break the actual guard logic:

- `expect(files).toContain("tui/tui-shell.ts")` (line ~140) — breaks the moment `src/tui/tui-shell.ts` stops existing as that exact path (e.g. replaced by `src/tui/tui-shell/index.ts` + submodules). The glob will simply no longer produce that literal string.
- `expect(callers).toContain("commands/shell.ts")` and `expect(callers).toContain("tui/tui-shell.ts")` (lines ~151, ~153) — break for the same reason, and independently break if the specific throwing-reader call sites (`openSession(`, `loadContext(`, `loadArchive(`, `loadTranscript(`, `exportSessionMarkdown(`) move to a different split-off file that isn't named exactly `commands/shell.ts`/`tui/tui-shell.ts`.
- The core check — `expect(unguardedCalls(treeSources(SRC))).toEqual([])` (line ~131) — is **filename-agnostic**: it iterates whatever the live glob produces and applies the try/catch-region scan to every file. It needs **no change** for a split; it will automatically start scanning whatever new split files exist, and will still fail loudly if any of them calls a throwing reader outside a `try`.
- Fix for the split: update the three hardcoded literals in the two canary tests (lines ~140, 151, 153) to name the new file(s) that actually retain (a) real existence in the tree and (b) the throwing-reader call sites, or relax them to a prefix/`some()` check against the new split directory (e.g. `files.some(f => f.startsWith("tui/tui-shell/"))`) if the call sites end up spread across multiple new files.
- Note: the synthetic probe shapes at lines ~184-191 ("commands/sessions.ts as it was" / "tui/tui-shell.ts /resume as it was") are **hand-written strings mimicking historical code shapes**, not reads of the real files — they are unaffected by the split.
