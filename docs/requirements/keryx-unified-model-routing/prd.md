# PRD: четыре класса и единый роутинг
Version: 0.1.0

Status: spec ready — runtime v2 не реализован.

## Проблема

Таблица категорий, относительные light/standard/deep, классификатор запросов и выбор моделей дочерних задач имеют разные правила приоритета. Переключение основной модели не переносит закреплённые назначения; preview и исполнение получают разные данные. Пользователь не может предсказать фактического исполнителя.

## Цель и пользователи

Оператор управляет общим пулом моделей нескольких провайдеров. Автор проекта задаёт категории и требования в пределах доверенных настроек. Оркестратор рекомендует уровень сложности, не отменяя выбор оператора. Интерактивный и unattended runtime используют одно решение с проверяемой причиной выбора.

## Требования

### R1 — Четыре абсолютных класса

Канонические идентификаторы: frontier, expert, standard, light. Их смысл не зависит от baseline. Каждому классу назначается упорядоченный пул provider/model; одну модель можно явно включить в несколько классов. Имена Astra/Fable и Opus/Sol — примеры пользовательского распределения, не встроенные рейтинги.

Verification: judged

### R2 — Разделение класса и категории

review/subagents/quick/coding/planning/docs/unattended/default обозначают задачи. Их назначения: auto, class, model, baseline. Фиксированный класс не требует классификации.

Verification: judged

### R3 — Один resolver и приоритет

Единая цепочка: пользовательский override запуска → доверенное назначение проекта → назначение пользователя → встроенное назначение. Агент может предложить класс, но не создавать пользовательский override. Gates обязательны на любом уровне. Отказ выбранного жёсткого назначения не открывает более слабую конфигурационную ветку.

Verification: judged

### R4 — Настройки провайдеров

Можно разрешить все подключённые провайдеры, только активный или явный allowlist, задать предпочтение активному и отключить отдельного кандидата. Активный провайдер является отдельным параметром baseline, не меняет класс.

Verification: judged

### R5 — Capability, availability и budget

Исполнитель соответствует обязательным требованиям инструментов, изображений и контекста; учитываются permissions, credentials, внешний доступ, remote candidate scope, доступность модели и budget. Неизвестное обязательное свойство не считается подтверждённым.

Verification: judged

### R6 — Заменяемый классификатор

JEV и другие адаптеры возвращают один строгий контракт класса и причины; им не требуется знать model IDs. Классификация имеет общий deadline, явный выбор вспомогательных моделей и отдельную политику передачи текста. При отказе действует заданный onFailure, а не скрытый выбор дешёвой модели.

Verification: judged

### R7 — Предсказуемый fallback

По умолчанию разрешены другие кандидаты того же класса. Межклассовый переход задаётся явно и не нарушает hard minimum, capabilities или budget. Pin модели по умолчанию строгий. У каждой попытки есть причина; число попыток и время ограничены.

Verification: judged

### R8 — Единые preview и объяснение

На одном snapshot preview и запуск дают одинаковое решение. Перед I/O запуск перепроверяет изменяемые разрешения; изменение условий порождает новое связанное решение. UI показывает baseline, требуемый класс, фактическую модель, источник и fallback.

Verification: judged

### R9 — Смена baseline

В all-connected режиме фиксированный класс сохраняет весь пул. В session-only режиме фильтруется по новому провайдеру. Pin не переписывается; если он запрещён новой политикой, показан конфликт. Уже выполняющаяся попытка не меняет модель.

Verification: judged

### R10 — Все native пути

Интерактивный shell, review, subagent, native remote session и native unattended dispatch используют одну конфигурацию и resolver. Внешний CLI без управляемой model capability обозначается unmanaged; нельзя показывать подтверждённый класс исполнения.

Verification: judged

### R11 — Обратимая миграция

V2 включается явно после dry-run и подтверждения сопоставлений. Конкретные pins сохраняются. Старые относительные тиры не переименовываются автоматически. Сохраняются legacy настройки, активные запуски и старые записи; rollback влияет только на новые запуски.

Verification: judged

### R12 — Проверяемое решение

Записываются configuration/snapshot revisions, источник, классификация, выбранная пара, причина каждого отказа, попытки и fallback. Credentials, сырой prompt и скрытое рассуждение не входят в routing журнал. Отсутствие статистики обозначается явно.

Verification: judged

## Критерии выпуска

- Все AC1–AC12 спецификации проверены поведенческими тестами; judged-поля R1–R12 означают проверку дизайна сейчас, не выполненные runtime тесты.
- Одинаковые fixtures дают одинаковый результат в preview и каждом native call site.
- Ни один генератор model_tier/model_class не обходит операторское назначение.
- Migration dry-run, применение, повторное применение и rollback проверены на копиях конфигурации; оригиналы не повреждены.
- Негативные сценарии budget, credentials, stale catalog, remote scope и побочных эффектов блокируют недопустимый fallback.

## Критерии результата

- Первые 14 дней pilot: сравнить пары preview/dispatch с одинаковым snapshotDigest; ожидается 0 несовпадений. Источник — routing decision events, отдельно учитывать stale snapshots.
- Первые 14 дней pilot: 100% fallback событий имеют reason и ссылку на исходное решение; отсутствие events не считается доказательством.
- Экономия стоимости: not measured — нет согласованного корпуса одинаковых задач и baseline измерений; обещание экономии не является критерием выпуска.
- Пользовательская предсказуемость: judged pilot-сценарий настройки класса, смены провайдера и объяснения исполнителя без чтения логов; результат сохраняется в evidence реализации.

## Риски и рекомендация

Четыре класса — операторская политика, не универсальный benchmark. Разные модели одного класса не гарантируют одинаковое качество; capability gates независимы от класса. Неизвестная стоимость и подписочные тарифы не равны нулевой стоимости. Рекомендуется сначала ввести общий resolver и shadow-сравнение, затем мигрировать настройки и включать исполнение v2 для всего snapshot сессии целиком.
