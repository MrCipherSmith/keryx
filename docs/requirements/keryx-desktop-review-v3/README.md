# Keryx Desktop Review v3 · живая сессия на раунд и `review.json`
Version: 0.1.0

**Статус — этап 1 реализуется в Flow 524 (Draft PR); этапы 2–4 — draft, не реализованы.** Пакет описывает целевое состояние ручного ревью в Desktop и план перехода. Всё, что названо «сегодня», проверено по коду `origin/main` на коммите `ddad229f1` (Keryx 0.4.56, Desktop 0.2.19) и по локальному хранилищу ревью владельца от 2026-11-25; всё остальное — планируемое.

## Назначение

Review v2 (Keryx 0.4.55, Desktop 0.2.18) свёл ревью PR в одну сущность с раундами, но ручное ревью в Desktop по-прежнему выполняется как отсоединённый одноразовый процесс `keryx shell --no-tui --print` в отдельной копии репозитория. На трёх реальных PR это дало десять попыток, ни одна не дошла до ревьюеров: продолжение начинало процесс с нуля и не находило пакет прошлой попытки, разрешение на команду некому было дать, вопрос пользователя уходил в новый процесс без ответа. Тот же скилл `review-orchestrator` в живой сессии (`keryx shell`, Claude) работает: у сессии есть транскрипт, двусторонний разговор, разрешения и контекст между ходами.

v3 делает ручное ревью живой сессией:

- **Одно ревью на PR — одна карточка.** Состояние ревью хранится в `review.json`, как состояние Flow — в `flow.json`.
- **Один раунд — одна сессия.** Продолжение — новый ход в той же сессии, а не новая попытка и не новый процесс.
- **Состояние пишет только CLI** `keryx review state …`, который вызывает скилл на каждом шаге; Desktop его только читает.
- **Живой статус** берётся из сессии раунда (идёт ход, ждёт ответа, простаивает) и вместе с `review.json` даёт один словарь статусов для слота на доске, вкладки Reviews и карточки.

## Область

Входит: ручное ревью PR, запущенное из Desktop (доска Pull requests, вкладка Reviews, диалог `/review` в сессии); хранилище `review.json` и его CLI; процедура записи состояния в `review-orchestrator`; карточка Review; удаление отсоединённого исполнителя для ручных ревью.

Не входит: состав ревьюеров и устройство волн `review-orchestrator`; формат пакета раунда; ревью по расписанию и по правилам вотчера (остаётся фоновый исполнитель, который на этапе 4 пишет тот же `review.json`); вкладки Pull requests и Issues (v2 их не меняет и v3 тоже).
