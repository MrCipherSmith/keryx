# Передача прототипа Team Hub

25 октября 2026, Asia/Muscat. Подготовлен для тестирования на сервере 26 октября. Ветка `codex/team-hub-prototype`; исходный checkout `main` не использовался для реализации. Код прототипа: `b8e3d8931`, контракт и RED-тесты: `c27821eaa`.

Начните с [инструкции запуска](README.md), затем подключите локальную копию по [инструкции коннектора](connector.md). [Спецификация](specification.md) и [API](api.md) описывают реализованный срез; это не вся целевая модель Keryx 2.0.

## Что работает

- Настоящий HTTP Hub, SQLite, браузерные сессии, отдельные серверные operator/reviewer/agent credentials, журнал событий.
- Проекты, импорт wiki/OpenSpec, инкрементальный контекст, предложения изменений и человеческое принятие точного digest без перезаписи старой базы.
- Доска Flow: ссылка на spec, замороженные критерии, точная ревизия, self-reported evidence и отдельная человеческая приёмка.
- Локальный клиент: регистрация checkout, общий project cache, загрузка tracked snapshots/deltas, preview и безопасное применение. Копии и worktree получают разные checkoutId.
- Серверная Git delivery в выделенную ветку, трёхстороннее применение поверх актуальной Git базы, явный конфликт и повтор по receipt. Получение delivery обновляет выделенный Git ref, сохраняя рабочие правки; изменение HEAD остаётся ручным.

Приложения, зависимости Docker и исполнение агентов остаются на машинах разработчиков. Новый Hub — отдельный процесс; существующий Telegram `keryx serve` и прежние локальные Flow не мигрированы автоматически. Нет автоматического GitHub PR, conflict editor, полноценных Intent/Attempt/Run UI, SSO/приглашений/ACL по проектам, независимого CI и прозрачного автоматического reanchor `.git`. Эти функции не следует считать готовыми по наличию прототипа.

## Поставка и границы

Пакет содержит allowlisted source archive, два Linux x64 baseline executable и SHA256SUMS. Исходный архив не требует npm install для Hub, содержит Docker Compose и smoke script; повторная сборка исходного tar даёт одинаковый digest при неизменных файлах. Для ARM сервера используйте исходники/Compose; x64 executable требует Linux glibc. Git нужен отдельно для delivery/connector.

SQLite — один процесс, без multi-instance и production SLA. Bootstrap роли фиксированы, evidence self-reported. Локальные dirty/staged/diverged состояния могут остановить apply вместо автоматического merge. Общий контекст обновляется командой sync, события через polling/Refresh: фоновой интеграции с прежним serve-hub ещё нет.

Flow 473 сохраняется `in-progress`: работа передана для теста, PR/merge и человеческое подтверждение критериев не выполнялись. Тестовые human principals и receipts созданы только в изолированных временных базах и не обозначают приёмку владельцем проекта. Реальные remote репозитории не публиковались; Git-тесты используют временные bare remotes.
