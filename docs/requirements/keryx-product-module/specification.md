# Product Module — Specification

Version: 0.1.0

## Module identity

`product` — a new module beside `gdgraph`, `gdwiki`, `memory`, `tasks`,
`health`, `testing`, `security`. Named for the question it answers, as they are.

Everything in the module is deterministic: it parses, counts, stores and
returns. It calls no model. The one judgement step lives in a skill outside it.

## Storage structure

```text
.metaproject/data/product/
  index.json          # the intent set — derived, disposable, rebuildable
  artifacts/
    latest.md         # the rendered map, regenerated by `product map`
```

Derived like `gdgraph`'s data: safe to delete, rebuilt by `product index`, never
edited by hand, never the source of truth. The sources of truth remain
`.metaproject/flows/**` and `docs/requirements/**`.

## Manifest / config shape

None. The module has no configuration. What it knows comes from the repository.

## CLI surface

```text
keryx product index [--json]            # build the intent set
keryx product admit "<idea>" [--json]   # candidates this idea may collide with
keryx product open [--json]             # closed in code, never checked for effect
keryx product map [--format md|html]    # what the product claims, and how much is proven
```

`index` is the generating command, the peer of `gdgraph build`. The other three
read the index and fail with a clear message naming `product index` when it is
absent or older than the newest flow.

Shape of `product open`:

```text
intents closed in code, never checked for effect: 26 of 31

  flow 285  ACP over the agent client protocol
            outcome: not measured — no instrument stated
            closed 2026-09-22, 6 days ago
  flow 271  session lease
            outcome: "two -c shells no longer overwrite each other"
            never observed
```

Shape of `product map`, in the part that no activity report can produce:

```text
claims 31  ·  proven 12  ·  accepted unverifiable 7  ·  never checked 26
contradictions 2
  flow 166 claims workspace review is operator-gated
  flow 302 claims workspace review is automatic when the corpus is clean
```

## Data contracts

```text
Intent = {
  id: string                  // flow id or docpack name
  source: "flow" | "docpack"
  title: string
  statement: string | null    // the intent in one sentence, where stated
  audience: string | null     // for whom, where stated
  criteria: AcKindRecord[]    // from keryx-acceptance-layer W0
  status: "open" | "closed"
  closedAt: string | null
  outcome: {
    criterion: string | null  // from the package's outcome list, W5
    observedAt: string | null // null ⇒ never checked
    note: string | null
  }
}

IntentIndex = {
  builtAt: string
  intents: Intent[]
  unusable: number            // entries with no extractable statement — the visible limit
  counts: { claims, proven, unverifiable, neverChecked, contradictions }
}

AdmitCandidate = {
  intentId: string
  why: "graph" | "terms" | "criteria"   // which narrowing matched
  score: number
}
```

`unusable` is deliberate. A corpus of titles like "minor fixes" produces a poor
map, and the map must say so rather than quietly shrink.

## Integration points

| Point | Change | Bulk |
|---|---|---|
| `docpack-orchestrator` Phase 0 | Calls `product admit` before anything is written. A non-empty result becomes a section in the PRD. Never blocks. | one call |
| `flow freeze` | Prints the verification-kind distribution (from `keryx-acceptance-layer` W0) and, when the work changes user-visible behaviour with no outcome criterion, one line naming the unclosed product function. Never refuses. | one line |
| `flow complete` | Registers the intent and its outcome criterion in the index queue. | one write |
| `governance report` | Two rows: acceptance coverage, and intents closed without a look back. | two rows |

No other command changes behaviour. No new subagent exists. No step becomes
mandatory.

## The one skill

`product-admit` — invoked by `docpack-orchestrator` Phase 0 **only when
`product admit` returned a non-empty candidate set**.

It reads the candidates and the new idea, decides for each whether it is a real
contradiction, a duplication, a supersession or a coincidence of wording, and
writes a short verdict with the reasoning. The verdict is advisory and is
recorded in the requirements package. It never refuses a flow, and an operator
decision recorded against it closes the matter.

Single pass, no fan-out. If a judgement of this size needs a roster of
subagents, the design is wrong.

## Acceptance criteria

Written in the format of `keryx-acceptance-layer` W0.

- AC1: `product index` parses every flow and requirements package in this repository with zero failures, reports the count of entries with no extractable intent statement, and produces a byte-identical index on a second run over an unchanged tree [verify: exec `bun test src/product/index.test.ts`]
- AC2: `product open` lists only intents that are closed in code and carry no observation, names the flow and the outcome criterion for each, and returns a non-zero count on the current corpus [verify: exec `bun test src/product/open.test.ts`]
- AC3: `product admit` returns candidates without any model call, and a test asserts no provider client is constructed on the path [verify: invariant `bun test src/product/admit-no-model.test.ts`]
- AC4: `product admit` on an idea with no overlap returns an empty set, and the docpack skill is not invoked in that case [verify: exec `bun test src/product/admit-empty.test.ts`]
- AC5: No command in this module refuses a freeze, a completion, a merge or a flow creation; a test drives a flow through the full lifecycle with an empty index and every transition succeeds [verify: invariant `bun test src/product/never-gates.test.ts`]
- AC6: `product map` output contains at least one fact absent from `governance report` and from any activity summary — an unproven claim or a contradiction — demonstrated on this repository's own corpus [verify: judged]
- AC7: The reading commands fail with a message naming `product index` when the index is missing or older than the newest flow, and never answer from a stale index silently [verify: exec `bun test src/product/staleness.test.ts`]
- AC8: The `product-admit` skill is invoked only with a non-empty candidate set, performs one pass, and dispatches no subagent [verify: invariant `bun test src/product/admit-skill-shape.test.ts`]
- AC9: The module's data directory is disposable: deleting `.metaproject/data/product/` and rebuilding produces an equivalent index, and no command reads product data from anywhere else [verify: exec `bun test src/product/disposable.test.ts`]
- AC10: `bun run typecheck` is clean and the full `src/product` suite passes on the branch [verify: exec `bun run typecheck && bun test src/product`]
- AC11: The map is legible to someone who did not write the flows: a reader can name, from the output alone, one thing the product claims and has not proven [verify: none — a judgement about legibility that no check settles; the evidence is whether the first reader asks a question the map should have answered, recorded in the flow journal]
