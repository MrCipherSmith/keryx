# План реализации · Готовность worktree
Version: 0.1.2

Статус: план, ничего не начато. Каждый этап — отдельный flow и PR в `main`.

## Этап 1 — Подготовка и ссылка на metaproject (R1–R6)

- `src/worktree/`: `create`, `prepare`, `link`, `promote`, `status`, `remove`; `.env` (§7.1), зависимости (§7.2), порты (§7.3), реестр связей с проверкой идентичности клона (§5.1).
- Чтение по политике §5.2: одна функция `storeRoots(kind, cwd)` → локальный корень и (при связи) домашний только для чтения; перевести на неё поиск памяти, обучения и активного ревью. Запись остаётся локальной. Журнал решений, номера flow и шина не меняются.
- Строки §5.3 для сессий, подагентов, внешних агентов и `trigger run`; раздел в `keryx doctor`.
- `keryx trigger run` и подагенты используют `src/worktree`.

Демонстрация: `keryx worktree create demo`, `bun test src/lib` в нём без установки, `keryx memory search` находит незакоммиченный урок дома; новый урок попадает в дом после `promote`.

## Этап 2 — Головная ветка и проверка конфликтов (R7–R8)

- Поля `headBranch`, `worktree` в `flow.json`; заполнение в `create --flow` и `flow start`.
- `keryx worktree check` (§7.5).
- Desktop: блок «Перед слиянием» в деталях flow, значок в футере, порты и дом во вкладке Info.

Демонстрация: два flow правят один файл, main ушёл вперёд; проверка называет конфликт и соседний flow.

## Этап 3 — Базовая линия (R9)

- `keryx test baseline capture|show`; захват при `flow start` в фоне; разбор имён падений для шести раннеров.
- Сравнение в `check-ac` для `exec`-критериев тестов.

Демонстрация: ветка с заранее падающим тестом в main — «было 1, стало 1», не блокирует.

## Этап 4 — Нестабильные тесты (R10)

- Повтор один раз, классификация `flaky`, отчёт с именами.

Демонстрация: тест с гонкой падает один раз из двух — помечен нестабильным, назван, не блокирует.

## Проверки

`bun test src/worktree src/testing src/flow`, `bun run typecheck`; для Desktop — `cd apps/desktop && bun test src`, `cargo test`. Пробный прогон на реальном клоне keryx — владелец.

## Порядок с парным пакетом

Этапы этого пакета не зависят от [рабочих панелей](../keryx-desktop-workspace-panels/implementation-plan.md). Desktop-часть этапа 2 удобнее делать после вкладки «Изменения», но может идти раньше.
