# PRD · Рабочие панели и внимание
Version: 0.1.2

## Проблема

1. **Сессия ждёт, а человек не знает.** Одно окно держит несколько проектов и до восьми живых сессий. Сессия с вопросом агента или запросом разрешения стоит, пока человек случайно не откроет её. Метка «ждёт» есть только в списке сессий и на рельсе проектов. Когда окно свёрнуто или закрыто другим приложением, сигнала нет.
2. **Не видно, что агент поменял.** В футере есть только число изменённых файлов. Чтобы прочитать дифф, нужен терминал или редактор. Замечание к конкретной строке приходится пересказывать текстом.
3. **Сослаться на файл неудобно.** Путь набирается вручную, дерева проекта в приложении нет.
4. **Заполнение контекста спрятано.** Индикатор есть только во вкладке Info. Пользователь узнаёт о переполнении, когда качество ответа уже упало.
5. **Скриншот нельзя показать агенту.** Вложения есть только для элементов, выбранных пикером в браузере. Keryx отбрасывает изображения в промпте.

## Цель

Человек замечает ожидающую сессию в течение секунд, проверяет изменения агента и отвечает на них, не выходя из окна, и даёт агенту контекст файлом, строкой или картинкой.

## Кто пользуется

| Пользователь | Сценарий |
|---|---|
| Владелец нескольких сессий | Запустил три задачи в разных проектах, ушёл в браузер. Получает уведомление «keryx ждёт ответа в проекте X», кликает и попадает в нужную сессию |
| Разработчик на ревью своего агента | После хода открывает «Изменения», читает дифф, оставляет два замечания к строкам и отправляет их одним сообщением |
| Пользователь, ставящий задачу | Вставляет скриншот ошибки ⌘V, упоминает `@src/app.ts` и отправляет |

## Требования

**R1. Сигнал ожидания.** Когда сессия переходит в состояние «ждёт человека» (разрешение или `ask_user`) или завершает ход, а окно не в фокусе или сессия не показана, приложение показывает системное уведомление с проектом и сессией. Клик открывает этот проект и эту сессию. Повторное ожидание той же сессии без ответа не порождает нового уведомления.
Verification: judged

**R2. Счётчик на значке.** Значок в Dock показывает число сессий во всех проектах окна, которые ждут человека. Ноль убирает счётчик.
Verification: judged

**R3. Звук и настройки.** Уведомления, звук и счётчик на значке включаются и выключаются независимо в Settings → Sessions. По умолчанию все три включены. В фокусе на показанной сессии сигнал не подаётся.
Verification: exec `cd apps/desktop && bun test src/session/attention.test.ts`

**R4. Группа «Ждут вас».** В списке сессий проекта ожидающие сессии собраны в первую группу над «Pinned». Сессия, на которую ответили, возвращается в свою группу.
Verification: exec `cd apps/desktop && bun test src/session/sessionGroups.test.ts`

**R5. Вкладка «Изменения».** Боковая панель получает вкладку со списком изменённых, добавленных, удалённых и неотслеживаемых файлов рабочей копии проекта и счётчиком на ярлыке. Выбор файла показывает дифф против `HEAD` с подсветкой. Список обновляется после каждого хода агента и по кнопке. Двоичные и слишком большие файлы показаны без диффа, с причиной.
Verification: exec `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml git_changes`

**R6. Комментарий к строке.** В диффе пользователь отмечает строку или диапазон и пишет замечание. Замечания копятся чипами над композером. Отправка передаёт агенту в одном сообщении два блока: замечания с файлами и строками (`keryx-desktop:line-comments`, без пометки недоверенного — это слова пользователя) и цитаты из рабочей копии (`keryx-desktop:line-comment-quotes`, с пометкой недоверенного — файл мог написать агент или третья сторона).
Verification: judged

**R7. Вкладка «Файлы» и `@`-упоминания.** Вкладка показывает дерево проекта (файлы из git и неотслеживаемые, без игнорируемых) с поиском. Выбор файла показывает текст с подсветкой или изображение, только чтение. Ввод `@` в композере открывает список путей с поиском. Выбор вставляет `@путь`. Перетаскивание файла из дерева в композер вставляет то же. Чтение ограничено корнем проекта.
Verification: exec `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml project_files`

**R8. Контекст у композера.** Рядом с выбором модели виден индикатор заполнения контекста последнего вызова с процентом в подсказке. Если размер окна неизвестен, индикатор скрыт. Меню индикатора даёт «Сжать», которое выполняет `/compact` и недоступно во время хода.
Verification: judged

**R9. Картинки во вложениях.** Пользователь вставляет изображение ⌘V или перетаскивает его в композер. Изображение видно миниатюрой в чипе и в ленте. Если keryx объявляет `promptCapabilities.image: true`, изображение уходит блоком `image`. Иначе приложение не даёт отправить картинку и объясняет почему. Keryx передаёт изображения провайдерам, которые их поддерживают, и возвращает понятную ошибку для модели без зрения.
Verification: exec `bun test src/acp/prompt-content.test.ts`

## Критерии выпуска

- Три сессии в двух проектах, окно свёрнуто. Две сессии запрашивают разрешение. Приходят два уведомления, на значке «2». Клик по второму открывает нужный проект и сессию. После ответа счётчик «1».
- На рабочей копии с правками в пяти файлах (один двоичный, один новый неотслеживаемый) вкладка «Изменения» показывает все пять. Два замечания к строкам в разных файлах уходят одним сообщением. В транскрипте keryx виден блок с путями и строками.
- В композере `@spec` находит `docs/.../specification.md`. Попытка прочитать `../outside` через команду вкладки «Файлы» отклоняется.
- С keryx, объявляющим `image: true`, и моделью со зрением скриншот доходит до модели, и модель описывает его содержимое. Со старым keryx кнопка отправки картинки заблокирована с причиной.

## Как оценить пользу после выпуска

- **Время ответа на ожидание.** За две недели до и после выпуска владелец сравнивает время между событием «ждёт» и ответом по журналу сессий keryx. Наблюдение: метки времени запросов разрешения и ответов в transcript сессий.
- **Использование вкладок.** not measured — в приложении нет телеметрии, и добавлять её этот пакет не будет.
- **Комментарии к строкам вместо пересказа.** Владелец через месяц просматривает свои сессии и считает сообщения с блоком комментариев. Наблюдение: поиск блока `keryx-desktop:line-comments` в transcript.

## Риски

| Риск | Что делаем |
|---|---|
| Уведомления раздражают | Только вне фокуса или для непоказанной сессии, одно на ожидание, три независимых выключателя |
| Большой дифф подвешивает окно | Дифф считается в Rust с лимитом размера и тайм-аутом, список виртуализирован |
| Вкладка «Файлы» становится обходом песочницы | Тот же `confine` к корню проекта, что у `fs/read_text_file`, без символических ссылок наружу |
| Картинки ломают провайдеров без зрения | keryx объявляет `image: true` только при поддержке в пути промпта. Отказ модели виден пользователю текстом, а не обрывом хода |
| Рост бандла | Без тяжёлых редакторов. Дифф рисуется существующим `unifiedDiff.ts` и `highlight.ts` |

## Рекомендация

Делать в порядке плана: внимание (R1–R4) и контекст (R8) — малые и ежедневно полезные, затем «Изменения» (R5–R6), затем «Файлы» (R7). Картинки (R9) начинать с keryx: без изменения пути промпта и провайдеров работа в приложении бесполезна.
