# PRD · Рабочие панели и внимание
Version: 0.2.0

## Проблема

1. **Сессия ждёт, а человек не знает.** Приложение держит несколько окон, в каждом — несколько проектов (до 6 в фоне), у каждого проекта свой keryx с живыми сессиями (до 8). Сессия с вопросом агента или запросом разрешения стоит, пока человек случайно не откроет её. Метка «ждёт» есть только в списке сессий и на рельсе проектов, а Rust знает о проекте одно слово `idle`/`busy`/`action`. Когда окно свёрнуто или закрыто другим приложением, сигнала нет. С [#1256](https://github.com/MrCipherSmith/keryx/pull/1256) к этому добавятся вопросы ревью, ожидающие ответа.
2. **Не видно, что агент поменял.** В футере есть только число изменённых файлов. Чтобы прочитать дифф, нужен терминал или редактор. Замечание к конкретной строке приходится пересказывать текстом.
3. **Сослаться на файл неудобно.** Путь набирается вручную, дерева проекта в приложении нет.
4. **Заполнение контекста спрятано.** Индикатор есть только во вкладке Info. Пользователь узнаёт о переполнении, когда качество ответа уже упало.
5. **Скриншот виден агенту только как файл.** [#1254](https://github.com/MrCipherSmith/keryx/pull/1254) добавляет вложения, но изображение уходит путём к временному файлу; keryx на main отбрасывает блоки `image`. Нативный ввод изображений делает flow 493 в keryx, Desktop к нему не подключён.

## Цель

Человек замечает ожидающую сессию в течение секунд, проверяет изменения агента и отвечает на них, не выходя из окна, и даёт агенту контекст файлом, строкой или картинкой.

## Кто пользуется

| Пользователь | Сценарий |
|---|---|
| Владелец нескольких сессий | Запустил три задачи в разных проектах, ушёл в браузер. Получает уведомление «Needs attention — проект X», кликает и попадает в нужную сессию |
| Разработчик на ревью своего агента | После хода открывает «Changes», читает дифф, оставляет два замечания к строкам и отправляет их одним сообщением |
| Пользователь, ставящий задачу | Вставляет скриншот ошибки ⌘V, упоминает `@src/app.ts` и отправляет |

## Требования

**R1. Сигнал ожидания.** Когда сессия любого проекта в любом окне переходит в состояние «ждёт человека» (разрешение, `ask_user`, после #1256 — вопрос ревью) или завершает ход успешно или с ошибкой, а пользователь её не видит (её окно не в фокусе, проект не спереди или сессия не показана), приложение показывает системное уведомление с проектом и сессией. Клик по любому уведомлению, в том числе старому или нажатому через минуты, приводит пользователя в проект и сессию этого уведомления; механизм выбирается по итогам проверки (спецификация §6.1.3), и выпуск без такого механизма не делается. Повторная отрисовка того же ожидания нового уведомления не даёт. Учёт ведёт Rust по отчётам всех представлений проектов.
Verification: judged

**R2. Счётчик на значке.** Значок в Dock показывает число сессий, ждущих человека, по всем проектам во всех окнах приложения. Ноль убирает счётчик.
Verification: exec `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml attention`

**R3. Звук и настройки.** Уведомления, звук, счётчик на значке и учёт вопросов ревью включаются и выключаются независимо в Settings → Sessions. По умолчанию все включены. Если пользователь видит сессию, сигнал не подаётся.
Verification: exec `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml attention_settings`

**R4. Группа «Needs attention».** В списке сессий проекта ожидающие сессии собраны в первую группу «Needs attention» над «Pinned». Сессия, на которую ответили, возвращается в свою группу. Формулировки совпадают с #1256.
Verification: exec `cd apps/desktop && bun test src/session/sessionGroups.test.ts`

**R5. Вкладка «Changes».** Боковая панель получает вкладку со списком изменённых, добавленных, удалённых и неотслеживаемых файлов рабочей копии проекта и счётчиком на ярлыке. Выбор файла показывает дифф против `HEAD` с подсветкой. Список обновляется после каждого хода агента и по кнопке. Двоичные и слишком большие файлы показаны без диффа, с причиной.
Verification: exec `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml git_changes`

**R6. Комментарий к строке.** В диффе пользователь отмечает строку или диапазон и пишет замечание. Замечания копятся чипами над композером (вложения #1254). Отправка передаёт агенту текст: путь, строки и замечание пользователя, без цитат из файла и без пометки недоверенного. Агент читает файл сам, поэтому ход с замечаниями не попадает под порог недоверенного контента.
Verification: judged

**R7. Вкладка «Files» и `@`-упоминания.** Вкладка показывает дерево проекта (файлы из git и неотслеживаемые, без игнорируемых) с поиском. Выбор файла показывает текст с подсветкой или изображение, только чтение. Ввод `@` в композере открывает список путей с поиском. Выбор вставляет `@путь`. Перетаскивание файла из дерева в композер вставляет то же. Чтение ограничено корнем проекта.
Verification: exec `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml project_files`

**R8. Контекст у композера.** Рядом с выбором модели виден индикатор заполнения контекста последнего вызова с процентом в подсказке. Если размер окна неизвестен, индикатор скрыт. Меню индикатора даёт «Compact», которое выполняет `/compact` и недоступно во время хода.
Verification: judged

**R9. Картинки во вложениях.** Изображение, приложенное через #1254, уходит путём к файлу, пока keryx не объявляет `promptCapabilities.image: true`. Когда объявляет (это делает flow 493), Desktop отправляет его нативным блоком `image`, а модель без зрения даёт понятную ошибку с предложением отправить путём. Зависит от #1254 и flow 493.
Verification: judged

## Критерии выпуска

- Два окна, три проекта, приложение не в фокусе. Сессии в двух проектах запрашивают разрешение. Приходят два уведомления, на значке «2». Клик по второму приводит в нужный проект и сессию. После ответа счётчик «1».
- На рабочей копии с правками в пяти файлах (один двоичный, один новый неотслеживаемый) вкладка «Changes» показывает все пять. Удалённый файл показан старой стороной. Два замечания к строкам в разных файлах уходят одним сообщением; в `auto` агент правит по ним без запросов подтверждения.
- В композере `@spec` находит `docs/.../specification.md`. Попытка прочитать `../outside` через команду вкладки «Files» отклоняется.
- Со старым keryx скриншот уходит путём. С keryx, объявляющим `image: true` (flow 493), и моделью со зрением скриншот уходит блоком `image`, модель описывает его, и после повторного открытия сессии он виден в ленте.

## Как оценить пользу после выпуска

- **Время ответа на ожидание.** За две недели до и после выпуска владелец сравнивает время между событием «ждёт» и ответом по журналу сессий keryx. Наблюдение: метки времени запросов разрешения и ответов в transcript сессий.
- **Использование вкладок.** not measured — в приложении нет телеметрии, и добавлять её этот пакет не будет.
- **Комментарии к строкам вместо пересказа.** Владелец через месяц просматривает свои сессии и считает сообщения с блоком комментариев. Наблюдение: поиск строки «Line comments:» в transcript.

## Риски

| Риск | Что делаем |
|---|---|
| Уведомления раздражают | Только если пользователь сессию не видит, одно на эпизод ожидания, четыре независимых выключателя |
| Клик по уведомлению не ведёт в сессию | Spike первым шагом; если данных клика нет — собственный делегат уведомлений macOS; открытие самого свежего ожидания при активации — только временная мера до него, с названной деградацией |
| Большой дифф подвешивает окно | Дифф считается в Rust с лимитом размера и тайм-аутом, список виртуализирован |
| Вкладка «Files» становится обходом песочницы | `PanelRoots::require_project` (из #1254), `confine` к корню проекта, без символических ссылок наружу; дифф — только по путям из `git status` |
| Картинки ломают провайдеров без зрения | Нативный блок — только при `image: true`; отказ модели виден текстом с предложением отправить путём |
| Расхождение с открытыми PR | Пакет строится на #1254 и #1256; ссылки на изменённые ими файлы обновляются после их слияния |
| Рост бандла | Без тяжёлых редакторов. Дифф рисуется существующим `unifiedDiff.ts` и `highlight.ts` |

## Рекомендация

Контекст (R8) от открытых PR не зависит и может идти сразу. Внимание (R1–R4, со spike клика) — после слияния #1256, «Changes» (R5–R6) и «Files» (R7) — после #1254. Картинки (R9) — после flow 493: до него путь из #1254 уже работает.
