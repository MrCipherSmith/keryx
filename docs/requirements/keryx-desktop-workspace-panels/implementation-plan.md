# План реализации · Рабочие панели и внимание
Version: 0.1.2

Статус: план, ничего не начато. Каждый этап — отдельный flow и отдельный PR в `main`. Этапы 1, 2 и 4 независимы и могут идти параллельно в разных worktree. Этапы 3 и 5 зависят от общих правок композера (§ «Общая часть»): им нужны вложения типа `line-comment` и `image`.

## Общая часть (в первом из этапов 3 и 5)

Обобщить вложения композера: тип вложения (`pick`, `line-comment`, `image`), нейтральная подпись списка чипов, хранилище по `cwd` с общим интерфейсом. Пики переезжают на него без изменения поведения.

## Этап 1 — Внимание (R1–R4)

- `tauri-plugin-notification`, право `notification:default`, команды `attention_set` и `attention_notify`.
- `src/session/attention.ts` и его тесты; отслеживание фокуса окна.
- Группа «Ждут вас» в `sessionGroups.ts`; `SessionSidebar` передаёт метки.
- Блок «Внимание» в Settings → Sessions.

Демонстрация: две сессии в двух проектах, свёрнутое окно, два уведомления, значок «2», клик ведёт в нужную сессию.

## Этап 2 — Контекст у композера (R8)

- Мини-индикатор в тулбаре композера из `conv.usage`; меню «Сжать» и «Подробнее».

Демонстрация: длинная сессия, индикатор в зоне предупреждения, «Сжать» уменьшает заполнение после следующего вызова.

## Этап 3 — Вкладка «Изменения» (R5–R6)

- Команды `git_changes`, `git_file_diff` (Rust, с тестами на фикстуре-репозитории).
- Вкладка `changes`: список, дифф, нумерация, выбор строк, замечания-чипы, блоки `keryx-desktop:line-comments` и `keryx-desktop:line-comment-quotes` (untrusted).
- Клик по счётчику изменений в футере открывает вкладку.

Демонстрация: агент правит три файла, пользователь оставляет два замечания, агент исправляет по ним.

## Этап 4 — Вкладка «Файлы» и `@` (R7)

- Команды `project_files`, `project_file_read`; общая функция ограничения пути с `fs.rs`.
- Вкладка `files`: дерево, поиск, просмотр; второй триггер попапа композера.

Демонстрация: `@spec` в композере, выбор пути, агент читает файл.

## Этап 5 — Изображения (R9)

1. keryx: тип части `image` у провайдера, сериализация в Anthropic и OpenAI, ошибка `image_input_unsupported`, передача блока в `prompt-content.ts`, `promptCapabilities.image: true`. Отдельный PR в keryx с тестами `bun test src/acp src/harness/provider`.
2. Приложение: вставка и перетаскивание, миниатюры, проверка флага.

Порядок обязателен: шаг 2 без шага 1 не выпускается. Совместимость: Desktop проверяет флаг, поэтому старый keryx получает заблокированную кнопку, а не потерянную картинку.

Демонстрация: скриншот ошибки ⌘V, модель описывает ошибку по картинке.

## Проверки каждого этапа

`cd apps/desktop && bun test src`, `tsc`, `cargo test` и `clippy` для `src-tauri`; для этапа 5 ещё `bun test src/acp`. Ручная проверка в собранном приложении — владелец.
