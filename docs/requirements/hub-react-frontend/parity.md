# React frontend parity inventory and acceptance test plan

Baseline inventory: commit `9a5f78023`, before the React migration. References to the embedded vanilla UI describe that baseline, not the new React implementation.

Status: planning only. No frontend implementation or Hub state change is recorded by this document.

## Source and scope

Read against the current prototype in `src/hub/web.ts`, `contracts.ts`, `server.ts`, and `domain.ts`. API paths below are relative to `/hub/v1`; `P` means `/projects/:projectId` and `F` means `P/flows/:flowId`.

Target stack chosen by the coordinator: React + TypeScript, Tailwind CSS, TanStack Query, Zustand for client UI state, react-i18next/i18next for English and Russian, Vite. Ant Design is not necessary for the existing surface. This is a frontend migration with UX improvements, preserving server semantics and stored data.

## Cross-cutting parity and state ownership

- TanStack Query owns server data. Query keys include project and entity IDs; auth changes cancel pending work and clear private query caches. Do not duplicate project/document/Flow server records in Zustand.
- Zustand holds UI-only state such as locale, layout, filters and scoped in-memory form drafts. Locale can persist; tokens, cookies, document content, Evidence output and private drafts must not be put in persistent browser storage. Draft keys must include project and entity/form identity.
- Authenticated fetch uses `credentials:'same-origin'` and `X-Requested-With: XMLHttpRequest`; JSON mutations send Content-Type. A 401 or `403 access-denied` clears identity, private data, drafts and operation keys. An ordinary `403 human-required`/`origin-denied` is an operation error, not a reason to impersonate another principal or switch auth mode.
- Invalid enabled auth configuration, expired sessions, missing mappings and network errors remain visible with bounded, explicit recovery. Refresh re-reads `/session` so changed effective roles update in the UI.
- Every non-auth JSON mutation uses an Idempotency-Key. A network error, unreadable response or 5xx is an unknown outcome; retrying the unchanged payload reuses its operation key. Never automatically replay POST actions on focus/reconnect/query refresh. A different payload receives a distinct operation identity.
- Versioned writes pin the version **shown when the draft/action was prepared**, not whatever a background query most recently fetched. On 409, retain the user's draft, show that current state changed, and offer explicit refresh/reconciliation. Do not silently substitute a new baseVersion/expectedVersion or dismiss a conflict by retrying with it.
- Cancel/discard late responses when project, entity or auth identity changes. A slow request for another project must not overwrite the current screen, reset its draft, or reintroduce private data after sign-out.
- When a mutation succeeds but subsequent refresh fails, distinguish “saved; refresh failed” from “write failed.” Clear only the successful form's draft; retain other form drafts. Disabled/pending controls prevent repeated local submissions.
- Translate application labels, navigation, statuses, helper text, validation, error code messages and aria labels into English/Russian. Keep user-authored titles/content/criteria/output, opaque IDs/digests, API enum values and Git data unchanged. Format dates with the selected locale. Language switching must preserve current project, screen, entity and form input.
- Render untrusted content safely: escape raw source, disable raw HTML in Markdown, sanitize or disallow dangerous link/image protocols and remote embeds. Keep CSP and same-origin assets; avoid inline scripts, eval-based production builds or CDN script dependencies.

## Acceptance test matrix

| ID | Scenario and observable result | Appropriate layer |
|---|---|---|
| PAR-01 | SSO mode: missing Hub session causes one config read and one Access exchange, then verified email/role and project list; no token prompt. Disabled mode keeps human token login. Denied/network failure stays visible and retries only on user action. | React integration tests with HTTP boundary mocks; real browser positive smoke. |
| PAR-02 | Session expiry/revoked mapping clears identity, project data, drafts and query caches; a late response cannot restore them. An ordinary authorization 403 retains identity. Refresh reflects operator→reviewer role changes. | React/query integration tests; existing backend auth suite. |
| PAR-03 | Rapid A→B project/entity switches with deferred responses never display A's records or Evidence under B. Back/forward and reload restore a valid selected route. Invalid/missing entity routes show an actionable state. | Component/router/query integration tests; browser navigation smoke. |
| PAR-04 | All parity forms send the exact payload/version and retain sourceRevision-required validation. Import changed existing content creates a proposal; source text and digest remain exact. | HTTP payload assertions and isolated real Hub server smoke. |
| PAR-05 | Conflict on import, proposal review, Flow action or integration selection shows 409 with preserved draft and no automatic retry/new base. A known successful write with failed refresh reports saved state, not failure/duplicate creation. | Deferred-response integration tests with request count and payload assertions. |
| PAR-06 | Unknown mutation outcome retries the identical payload with the same key; changed payload uses a new key. Focus/reconnect does not issue a POST; duplicate button clicks issue one pending operation. | API/mutation tests at the HTTP boundary. |
| PAR-07 | Flow creation shows exact spec path and 8+ criterion lines unchanged. Human-only freeze/accept/review/select/delivery controls are unavailable to an agent principal; server rejects unauthorized writes regardless of UI. Acceptance requires fresh explicit checkbox for the exact revision. | React integration tests plus unchanged backend security/lifecycle tests. |
| PAR-08 | Review bundle remains visible/readable and available for Evidence/Flow review; no Select/Delivery/snapshot-base action is offered. Existing backend/connector review-bundle tests remain green. | Code/Flow UI integration tests and existing guard suite. |
| PAR-09 | Code text form faithfully UTF-8 encodes content, supports deletion and executable mode, rejects malformed JSON. Delivery conflict/failure remains visible with receipt/status; no automatic merge/deploy/PR claim appears. | Component/API tests; isolated Git fixture smoke. |
| PAR-10 | English and Russian render every application screen without raw translation keys; switching locale preserves route and draft. User-authored Markdown/criteria/output/digests are byte-identical. Unsupported locale has documented fallback. | Translation-key parity check and interaction tests in both locales. |
| PAR-11 | Markdown/script/link payloads do not execute or create dangerous navigation; code and Evidence are escaped. Sign out uses only fixed validated same-origin Access logout; credentials never enter storage or URLs. | Security regression tests and browser inspection. |
| PAR-12 | Keyboard navigation, visible focus, associated form labels and live errors work; 375px, tablet and desktop layouts have usable navigation and contained board/diff/code scrolling. | Accessibility-oriented component tests and real browser screenshots. |
| PAR-13 | History over 500 records advances cursor without losing/duplicating records; legacy events lacking role do not invent attribution. Loading, empty, first-load failure and refresh failure are distinct states. | Query/cursor tests and screen tests. |

Geekom serves the new same-origin assets under existing CSP/Access protections; real SSO and both locale smoke checks are recorded against the exact review candidate. | Independent quality gate, artifact/runtime checks and native browser smoke. |

Use isolated fixture projects for mutation/approval tests. Do not freeze, accept, select or publish unrelated live user work during verification. Evidence submitted to the implementation Flow remains self-reported and pinned to the exact candidate; final owner acceptance is separate.

## Explicit non-goals

No new Flow model fields, arbitrary Flow editing/reopening, first-class Attempt, agent execution/queue, user directory, per-project ACL, server development environment, automatic Git merge/PR creation, data migration, backend lifecycle redesign or relaxed human-only gates. These require separate specifications.
