# Managed work and native execution binding
Version: 0.2.0

Status: implemented candidate; independent backend/native UI review and integrated verification passed. Existing machine wire protocol remains v2.

A native session message can include X-Keryx-Work-Attempt (opaque Attempt ID) and X-Keryx-Work-Version (current positive Attempt version). Both headers are required together. They are an additive HTTP sidecar, not extra fields inside frozen MessageSubmit/FlowAssociation JSON. The original authenticated human operator must still own the native session controller and satisfy every existing v2 authority, configuration, ad-hoc-consent and admission check.

The Hub resolves approved requirement/context pins itself and reserves original project/actor/session/operation/Attempt/pins inside the same SQLite transaction as original admission. Queued requests retain that reservation across restart. Actual run allocation binds the run and original command to that reservation; knowing a run ID alone is insufficient. Replays retain the original operation and run identity. Unknown allocation or execution must block replacement allocation, including delayed queue admission. A bound reservation never changes its run ID.

ExecutionLink records the actual machine/checkout/session/turn/run and original reservation pins. It confers no new controller lease, permission or acceptance authority. Existing runtime context consumption remains explicitly unverified: pinning approved work metadata does not prove a model read every referenced document. Required approved specification content is automatically included in a ContextSnapshot; exact archived versions remain the source, never silently latest.

Active/unknown executions and unresolved reservations block submission and work cancellation. Physical cancellation continues through existing native v2 operator actions. Work state changes never release physical leases. Terminal observations refresh from original run/command/machine facts; a successful native turn alone never accepts product work. An Attempt can contain several runs; manual work can contain zero.

Machine result ingestion is not automatic in this candidate. Agents or humans explicitly report progress, exact Git/document/result subjects and Evidence through work API/CLI/MCP. Such reports remain contributor-report; transport through Hub does not promote them into trusted CI Evidence. Git/CI observations are separately configured metadata. Conservative known-refusal queue recovery retains the immutable original allocation and can require an explicit successor operation/Attempt; it never silently replaces an ambiguous run.

The session UI exposes Managed Attempt selection, explicit pinned-context confirmation and existing ad-hoc consent. The frozen original request includes body, raw idempotency key and paired headers across uncertain retry. Live synthetic browser QA proved one original request creates one ExecutionLink; this is a protocol proof without actual provider/model/tool execution.

The initial native browser proof covers the mounted session. The final client recovery delta additionally retains the original request across a tab reload in bounded session storage, scoped to the authenticated principal/project/session and cleared at logout. It restores an unresolved state and requires explicit receipt checking or unchanged original retry, never automatic dispatch. Its focused reload tests and independent review are recorded separately in output/work-ui-independent-review-reload.md and output/work-quality-gate-reload.md; the earlier native review does not certify subsequent edits. A later retry refusal, including changed authority, preserves uncertainty about the original request until an authoritative result is observed. No authorization token or cookie is persisted in this envelope.

## Queued reservation settlement

Reservations have three durable states: `reserved`, `bound`, and `released`. Only `reserved` blocks a fresh allocation. `bound` keeps its immutable run; `released` cannot be resurrected or assigned a run. Release is proof of non-admission, never proof that product work succeeded.

The Hub settles a still-reserved request in the same transaction as an accepted native queue removal/rejection, a confirmed closed-session projection, or a definitive pre-admission refusal. A Hub refusal leaves the native queue projection unchanged; any later retry of that released managed operation is refused rather than silently becoming ad-hoc work. An indexed pending-reservations lookup also reconciles already-stored terminal observations after restart.

Queue edits and reauthorization preserve exact managed pins. A literal edit must match the authorized edit text, original owned queue position/kind, and exact source operation. Its newly observed operation receives the reservation in the same transaction; a forged replacement lineage is rejected. The source remains reserved while its authorized replacement has not yet been observed, including the gap between the source removal event and replacement queue event. Admission follows the validated queue lineage, releases the old operation, and binds a fresh reservation for the replacement's currently authorized human operator. The new run and command must still match the original project, machine, checkout, requirement revisions, context, and wire association.

Missing queue events, unavailable delivery outcomes, and uncertain physical ownership do not establish non-admission. Such uncertainty remains fenced until authoritative native observation or existing physical reconciliation establishes the outcome. Agent reports cannot release it. A confirmed closed session can settle unbound queue reservations; confirmed run cessation continues through the existing native reconciliation path for bound executions.

Delayed admission is atomic across remote run/command allocation and managed binding. A nested SQLite savepoint rolls back the whole attempted admission if binding or quota checks fail; only then can a definitive refusal release its reservation. Session, queue, and operation changes use proposed objects so rollback cannot leak partially mutated JavaScript rows into an outer transaction. Admission receives a lazy read-only legacy-state view, avoiding full revision hydration while preventing uncommitted legacy mutations. Native delivery starts only after successful commit.
