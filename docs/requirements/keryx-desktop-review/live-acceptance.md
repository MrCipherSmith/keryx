## Повтор на базе слитого #1247

Обе ветки обновлены до `568b94e6a`. В проекте, в ресурсах приложения и в приватном checkout агента файл оркестратора совпал с Git-объектом `5c48f29c4` из #1247. В сборку включены схемы пакета и WebAssembly-модуль парсера. Вызов с карточки был проверен и после перехода Desktop на отдельный webview для каждого проекта. [Рефакторинг оркестратора](https://github.com/MrCipherSmith/keryx/pull/1247)

Ручная попытка `1f3d9650` на head `2d6a63452` загрузила 918-строчный навык, выполнила `review plan` и прочитала файл контекста. Второй запрос того же диапазона получил тот же активный ID. План выбрал три задания для ревьюеров. До их завершения исполнитель достиг лимита в 250 000 токенов. Провайдер зарегистрировал 260 897 входных и 863 выходных токена. Из входных 177 024 прочитаны из кэша. После последнего ответа счётчик составил 261 760. Пакет остался черновиком со статусом запуска `budget`. Нулевая сумма замечаний в таком пакете не подтверждает успешное ревью.

Для Desktop команда `review plan` теперь готовит задания по выбранным областям diff и проверяет схему каждого перед передачей ревьюеру. В пакет попадают идентификатор задания, область, роль и ожидаемая модель. Для этого PR проверку прошли три задания. Пакет также использует штатную проверку готовности оркестратора после записи результатов.

## Автозапуск без лимита токенов

В тестовом правиле сняли лимит токенов, сохранили ожидание зелёного CI и интервал опроса в минуту. После исходного снимка и полного выхода из приложения выполнили push `13f13b4b3`. Все 19 выполнявшихся проверок прошли, один этап публикации GitHub пропустил. На следующем опросе launchd запустил одну проверку с источником Scheduled. Профиль Desktop оставался закрытым до завершения попытки.

Попытка `4dfaf7c9` дошла до проверки схемы задания. До передачи первого задания оркестратор обработал 872 922 входных и 3 891 выходной токен. Вход включал 707 200 токенов из кэша. Сумму 876 813 независимо сверили по 37 запросам провайдера, локальному журналу и `summary.json`. После открытия Desktop карточка показала тот же SHA, отсутствие лимита, статус Partial и отчёт. Подписка Codex не вернула цену этой проверки. В этом запуске все измерения относятся к оркестратору.

## Маршрут исполнителей и отмена

При первом повторе с исправленной схемой задания были готовы, но все три дочерних вызова остановились перед обращением к провайдеру. Настроенный маршрут субагентов отличался от OpenAI Codex, указанного в плане. В карточке проверена остановка активного запуска: попытка `1c38f25d` перешла из Stopping в Cancelled, появилась кнопка повтора. К этому моменту координатор использовал 394 923 входных и 3 339 выходных токенов.

Теперь Desktop проверяет явный конфликт маршрутов до первого запроса координатора, а приватный checkout использует одобренную настройку исходного проекта. Для контрольной попытки пользователь выбрал OpenAI Codex для всех трёх ревьюеров этого PR. Маршрут был задан только для временной копии проекта. Глобальный выбор остался прежним.
