# Политики доверия, полноты и доступа
Version: 0.1.5

Статус: **spec ready**. Технические контракты — **proposed**; их runtime-реализация этим пакетом не подтверждается.

## Статус

Spec ready. Нормативы AFC-01..06/15/17/19/25 применяются ко всем публичным операциям. Политика получает trusted invocation от adapter boundary; поля документа, role в тексте, model confidence, handle или handoff не создают полномочий. Уже выданное пользователем разрешение сохраняется в разрешённом scope; новое подтверждение не требуется только из-за смены агента. Действующая owner/SAC policy, включая требования review independence там, где они применяются, не ослабляется.

## Чтение и transport

Reader получает свой узкий owner root, разрешает realpath root и конечного target, проверяет containment перед чтением. Internal symlink допустим; цепочка наружу, абсолютный подменённый locator или path traversal отвергаются. Wiki reader не расширяет root до всего checkout ради удобства. Missing/unreadable path не вызывает поиск обходного source. Конкурентная symlink-подмена требует platform-aware open/identity verification в реализации; realpath сам по себе не заявляется полной защитой от TOCTOU. Acceptance включает безопасный race fixture и явный отказ на платформе без требуемой гарантии.

MCP HTTP допускает только loopback, внешний/wildcard bind отклоняется до listener. Hostname разрешается однозначно и проверяется на loopback; неоднозначность/ошибка разрешения — отказ. IPv4/IPv6 проверяются библиотечным разбором адресов, не substring `localhost`. Host/Origin ограничения и доступность mutating operations фиксируются существующей transport policy; loopback не доказывает доверие всем локальным процессам. Уже запрещённые для HTTP SAC операции остаются запрещены. `serve` — отдельный интерфейс; его guards не считаются автоматически защитой MCP HTTP.

## Redaction и security scan

Единый output validator проверяет tool/resource/SDK payload до сериализации. JSON разбирается, значения классифицируются с контекстом и сериализуются обратно. Safe metrics, decimal values и IDs не маскируются лишь по длине цифр; имя поля также не безусловный bypass настоящего секрета. Text detector использует локальные сигналы, без LLM/egress. URL проверяется на чувствительные query/path значения; наличие публичной Markdown-ссылки не равняется сетевой отправке. Реальные сетевые операции отдельно подчинены egress policy.

Если safe часть сохраняет operation schema, вернуть её и `redaction.state=redacted` с безопасной причиной, без исходного значения/его fingerprint. Если схема не допускает маркер (например обязательное число) и нет предусмотренного safe representation — `format-unsafe`. Секрет не сохраняется в exception, error, receipt, loss manifest или raw continuation. Raw означает полную разрешённую форму, не bypass redaction/retention.

Scan принимает file или recursive directory. До запуска фиксируются scope, excludes, max size/count и required coverage. Directory traversal распознаёт internal symlinks, visited canonical identities и циклы; внешний symlink denied. Итог содержит пофайловые scanned/skipped/failed и причины, но не закрытые имена для неавторизованного caller. Пропуск по согласованному exclusion сужает заявленную область; исчерпанный обязательный limit, unreadable файл или traversal failure дают incomplete. Findings сохраняются независимо от coverage.

### Auto-fetch floor: покрытая и непокрытая область

Отдельный обязательный floor покрывает zero-click auto-fetch — URL, который клиент запрашивает сам при рендеринге tool/resource output, без действия пользователя. Он применяется всегда, независимо от advisory redaction, и работает deny-by-default против `egress.allowlist`: при пустом allowlist внешний auto-fetch destination маскируется, safe часть возвращается с `redaction.state=redacted`.

**Покрыто** (перечень полный, не пример): markdown image во всех четырёх написаниях CommonMark — inline `![alt](URL)`, включая описание с парными скобками (`![a[b]c](URL)`), full reference `![alt][ref]`, collapsed `![alt][]` и shortcut `![alt]` — вместе с их reference definition `[ref]: URL`, **в том числе когда image вложен в ссылку** (`[![alt](URL)](href)` — идиома README-бейджа, в любом из четырёх написаний image): текст ссылки рендерится, поэтому вложенный в неё image запрашивается без клика; `<img|image src|srcset>`, а также SVG-написание того же элемента — `<image href|xlink:href>` и `<feImage href|xlink:href>`; прочие image-запросы — `<input type=image src>` (только при `type=image`; `src` на другом input не запрашивается), `<video poster>` и атрибут `background` у `body`/`table`/`td`/`th`/`tr`/`tbody`/`thead`/`tfoot`; media — `<video src>`, `<audio src>`, `<source src|srcset>`, `<track src>`; embedded documents — `<iframe src>`, `<embed src>`, `<object data>`; navigation — `<meta http-equiv=refresh>` (маскируется вся директива, не только URL, так как это переход клиента, а не запрос подресурса); и `<base href>`, который сам ничего не запрашивает, но переадресует все относительные URL документа.

Markdown **link** — и inline `[text](URL)`, и reference во всех трёх написаниях (`[text][ref]`, `[text][]`, `[text]`) — этим floor не покрыт: переход требует клика, поэтому это не zero-click fetch. Не покрыт сам переход, а не содержимое ссылки: image внутри текста ссылки покрыт (см. выше), тогда как image внутри описания другого image — это alt-текст, который renderer не запрашивает, и он не становится finding. Inline-ссылка остаётся предметом отдельной нормы выше (чувствительное значение в query/path), а не auto-fetch floor.

Значения двух атрибутных gate — `type=image` у `<input>` и `http-equiv=refresh` у `<meta>` — сравниваются после декодирования character references, как их декодирует renderer, поэтому написание `type="&#105;mage"` покрыто наравне с `type=image`. По той же причине список кандидатов `srcset` разбирается по декодированному значению: `&#44;` — граница кандидата для renderer, и когда декодирование открывает границу, которой нет в исходных байтах, маскируется всё значение атрибута целиком (offsets остаются на исходных байтах). Label у reference сопоставляется так, как его сопоставляет CommonMark, — с приведением регистра и со сворачиванием внутренних пробельных пробегов (включая перевод строки) — одинаково у определения и у использования; ограничения на длину label нет: единственный критерий — определён ли такой label в самом документе.

**Не покрыто намеренно** — это принятое решение, а не пробел реализации, и эти surface возвращаются без маскирования с `redaction.state=none`: `<script src>` и SVG `<script href>`; `<link href>` и `<link imagesrcset>` при любом `rel`; CSS-назначения — `url()` в атрибуте `style` и в блоке `<style>`, `@import` (включая форму со строкой без `url()`), `@font-face src`, `image-set()`; `<iframe srcdoc>` как вложенный inline-документ. Причина общая: первые три группы — инфраструктура самого документа, присутствующая в любом процитированном HTML/CSS-файле, поэтому при пустом allowlist по умолчанию покрытие маскировало бы URL внутри исходника, который инструмент попросили показать. Предусловие для покрытия — непустой default allowlist; для CSS дополнительно отдельный extractor значений CSS, для `srcdoc` — рекурсия с переносом offsets на исходные байты.

**Не покрыто, и это известный обход, а не решение о границе.** Reference definition, расположенная внутри блочного контейнера — цитаты (`> [ref]: URL`) или элемента списка (`- [ref]: URL`), — не распознаётся как definition вообще, поэтому использующий её image не становится finding: renderer запрашивает хост, а payload проходит все публичные границы с `redaction.state=none`, и allowlist не помогает, так как находки нет. Двенадцать написаний перечислены и воспроизведены. Причина: распознаватель definition не имеет модели блочных маркеров, и закрытие требует настоящего разбора блочной структуры, а не расширения шаблона. Ограничение принято сознательно 2026-09-07 после того, как замена на внешний парсер разметки была измерена и отклонена. В отличие от предыдущего абзаца, здесь **не** утверждается, что покрытие было бы неверным: оно было бы верным и отсутствует.

**Не покрыто никогда**, так как не является zero-click: `<frame src>` (start tag игнорируется в insertion mode «in body», а markdown-клиент не создаёт frameset-документ), внешний SVG `<use href>` (same-origin ограничение во всех движках) и click/submit-зависимые `<a href>`, `<a ping>`, `<area href>`, `<form action>`, `<button|input formaction>`.

Покрытие определяется по имени элемента и атрибута в исходном тексте. Имена сопоставляются ASCII-регистронезависимо, как их сопоставляет сам HTML, поэтому покрыт и процитированный компонентный markup с теми же именами — `<Video src>`, `<Iframe src>`, `<Embed src>` в `.tsx` или MDX: область шире, чем читается по списку элементов, и средство против ложного срабатывания здесь то же, что и для `<img src>` в README, — allowlist. Вложенность и контекст не учитываются, поэтому конструкция, процитированная в HTML-комментарии, кодовом блоке или `<template>`, тоже становится finding.

Отступлений от этой контекстной слепоты ровно три, и два из них **сужают** область, а не расширяют. Первое: markup, написанный внутри закавыченного значения чужого атрибута, намеренно не является finding — для любого конформного парсера это значение атрибута, а не start tag, и renderer его не запрашивает. Второе: незакрытое закавыченное значение поглощает остаток фрагмента, и всё после него не проверяется — так же поступает с ним и конформный tokenizer. Третье — `<base href>`: он не исключён из проверки и фиксируется везде, где встречается, но именно у него цена ложного срабатывания — разрешение всего документа, а не одного destination; она сообщается вызывающей стороне в remediation самого finding, а не гасится здесь.

## Health и security gate

Required/optional набор задаётся versioned project policy до запуска, а не наличием бинарника. Source-filter сообщает фактически проверенную область. Adapter хранит execution outcome, parse outcome и finding outcome раздельно; Bun/npm formats имеют явные fixtures. Exit 0 с неизвестным форматом не означает отсутствие advisories.

Предлагаемый deterministic fold: если есть установленное нарушение порога — `FAIL`; иначе если required check отсутствует/пропущен/не разобран/не завершён — `INCOMPLETE`; иначе `PASS`. `FAIL` может одновременно иметь `coverage=incomplete`. Strict CI принимает только PASS. Optional skip показывает warning и не подписывается как passed. Security scan применяет тот же принцип, сохраняя per-file coverage. Порог уязвимостей не меняется неявно при исправлении parser.

## Lifecycle и freshness

`current = accepted AND validFrom <= observedAt AND (validTo absent OR observedAt < validTo) AND no effective supersededBy`. Границы дат UTC, malformed/ambiguous даты дают invalid lifecycle. Missing dates означают отсутствие соответствующей временной границы, missing/unknown status не превращается в accepted. Проверка замены учитывает её действительность; циклическая/сломанная цепочка — conflict/unknown с причиной.

История (`draft`, `conflict`, `deprecated`, `superseded`, archived) доступна только по явному режиму и с полным status. Default retrieval не превращает её в instruction. Accepted stale/unknown может быть справочно показан, при этом **author/authority/acceptance metadata сохраняются**. Он не применяется как подтверждённое текущее ограничение до проверки. Freshness, полномочия автора и истинность — разные оси; изменённый source означает needs-review, не автоматическую ложность.

Краткое представление знания сохраняет claimType, exact source fragment/version, author, confirming participant/acceptance basis, scope и оговорки. Source отсутствует → явно unknown. Модельная уверенность не повышает hypothesis до decision и не отменяет ограничение. Handoff переносит сведения о разрешении как evidence; исполняющий adapter сверяет их с текущей доверенной политикой.

## Данные экспериментов и внешняя граница

Публичные fixtures — синтетические либо явно разрешённые к распространению. Исследовательские ветки, имена частных проектов, пути, task IDs, цитаты и результаты не копируются автоматически в runner/docs. Export review охватывает весь diff, history включаемых assets и fixtures, не только README. Внешний runner владеет model/API adapters и оплатой; core не содержит их скрыто под видом benchmark utilities. Тариф, cache и subscription accounting никогда не выводятся из размера prefix как универсальное денежное обещание.
