Исследование read-only, 2026-10-25. Ниже разделены реализованные механизмы и рекомендации. Тесты прочитаны, но не запускались; успешность текущей ветки не утверждается. ## Главный вывод

**Нужно расширять существующую цепочку, а не создавать второй collaboration engine:** `Workspace → private Slate/Seeds → trusted wrap-up → immutable proposal → review → guarded owner writer → owner receipt`. Однако это сейчас локальная файловая система и локальная OS-идентичность. Slate не является коллективной веткой спецификации; `accepted` wiki-страницы не равен защищённой человеческой приёмке и не означает проверку соответствия реализации OpenSpec. Основания: [workspace owner](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:91), [Slate contract](/Users/Goodea/goodea/keryx/src/session/slate.ts:128), [review sequence](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:188), [local identity](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:523), [FWK accepted predicate](/Users/Goodea/goodea/keryx/src/sac/fwk-service.ts:789).

## 1. Workspace: контейнер ссылок и ACL, а не копия знания

- `WorkspaceManifest` содержит `id/title`, `active|archived`, участников `owner|editor|viewer`, ссылки на `component|repository|flow|wiki|memory|skill|evidence|worktree|session`, timestamps. Storage по умолчанию `<cwd>/.metaproject/workspaces/<id>/workspace.json`; при create текущий actor автоматически owner. [Контракт](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:20), [storage/create](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:96), [paths](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:510).
- Ссылки pin-ятся по content digest, а read-report различает `resolved`, `changed`, `unresolvable`, `unverifiable`; отсутствие pin не выдаётся за подтверждённое совпадение. Это готовый контракт для Hub revision diagnostics, но текущий ресурс — локальный URI, не server revision ID. [Состояния](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:44), [inspect/pin](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:445).
- ACL повторно проверяется при использовании, а lifecycle write/review держит общий workspace lock до завершения callback. Actor берётся из server-issued object в WeakSet; claim с ролью от клиента не заменяет actor. Но local composition всегда выдаёт `user:local-<uid>`, а роли читаются из локального manifest. [Lock/at-use](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:205), [trusted actor](/Users/Goodea/goodea/keryx/src/sac/index.ts:550), [authorization](/Users/Goodea/goodea/keryx/src/sac/index.ts:599), [local OS principal](/Users/Goodea/goodea/keryx/src/sac/workspace-service.ts:523).
- CLI уже предоставляет create/list/show/add-resource/archive/remove-resource/rename, FWK overview/read, propose/confirm-review/review, handoff и catch-up. MCP имеет `sac.workspaceList`, `workspaceShow`, `workspaceCreate`, `overview`, `read`, `collaboration`, `propose`, `review`. Переиспользовать service facade; не переносить CLI parsing на сервер. [CLI dispatch](/Users/Goodea/goodea/keryx/src/commands/workspace.ts:30), [MCP registry](/Users/Goodea/goodea/keryx/src/mcp/tools.ts:288), [facade](/Users/Goodea/goodea/keryx/src/sac/service.ts:28).
- Collaboration — reference/handoff metadata, а не shared editor: `reference-added|handoff-recorded`, subject/timestamp формируются сервисом. [Тип](/Users/Goodea/goodea/keryx/src/sac/collaboration-service.ts:9), [record](/Users/Goodea/goodea/keryx/src/sac/collaboration-service.ts:35).

## 2. Slate: частная рабочая память, Seeds — кандидаты

- Native Slate содержит Anchors (`root/tree/runtime/touched/fence`), Course (`flowRef`), Seeds, child dispatches, Trail, Notes, operator Answers. Notes явно не Seed и не часть workspace proposal; Trail harness-owned. Это рабочий контекст одного запуска, а не нормативное хранилище проекта. [Anchors/Course](/Users/Goodea/goodea/keryx/src/session/slate.ts:76), [Seeds attribution](/Users/Goodea/goodea/keryx/src/session/slate.ts:88), [Slate fields](/Users/Goodea/goodea/keryx/src/session/slate.ts:128).
- Native open пересчитывает Anchors из живого checkout, архивирует незакрытую прошлую попытку и записывает новую Slate с пустыми Course/Seeds; всё через atomic open под одним lock. close архивирует и очищает. `writeSlate` делает read-modify-write под lock, archive сохраняет preservation evidence. **Отдельной операции slate.activate или slate.commit в этих lifecycle/API нет**: реальные операции — open/write/appendSeed/archive/close. [Open](/Users/Goodea/goodea/keryx/src/session/slate-lifecycle.ts:128), [close](/Users/Goodea/goodea/keryx/src/session/slate-lifecycle.ts:148), [write](/Users/Goodea/goodea/keryx/src/session/slate.ts:315), [atomic open](/Users/Goodea/goodea/keryx/src/session/slate.ts:403).
- External Slate живёт в `<project>/.keryx/external-slates/<externalSessionId>.json`. У него self-reported Anchors, Seeds, optional workspaceId, `lastWriteAt/closedAt`; это не Keryx session. MCP поверхность — `slate.open`, `slate.writeSeed`, `slate.close`; origin и `trust: external-unverified` задаются сервером, caller origin не доверяется. [External storage/contract](/Users/Goodea/goodea/keryx/src/session/external-slate.ts:42), [path](/Users/Goodea/goodea/keryx/src/session/external-slate.ts:67), [tools](/Users/Goodea/goodea/keryx/src/mcp/tools.ts:443), [Seed construction](/Users/Goodea/goodea/keryx/src/mcp/tools.ts:551).
- External close под per-ID lock запускает `runWrapUp`, затем ставит `closedAt`; данные сохраняются, повторное закрытие no-op. Lazy idle reclaim вызывается при `slate.*`, отдельного daemon нет. Это завершение предложения, а не публикация знания. [Close](/Users/Goodea/goodea/keryx/src/session/external-slate.ts:226), [shim Course unbound](/Users/Goodea/goodea/keryx/src/session/external-slate.ts:243), [reclaim](/Users/Goodea/goodea/keryx/src/session/external-slate.ts:288).
- `slate.open` сначала возвращает существующий record; при отсутствии workspace пытается resolve-or-create, при сбое оставляет unbound. На close внешний unbound Slate никогда не создаёт workspace — сохраняет unbound candidate. Native wrap-up с Seeds может лениво resolve-or-create и привязать workspace. [MCP open](/Users/Goodea/goodea/keryx/src/mcp/tools.ts:224), [external/native close distinction](/Users/Goodea/goodea/keryx/src/sac/machine-wrap-up.ts:842).

## 3. Flow ↔ Slate ↔ SAC уже связаны, но не через OpenSpec

- Course — pointer к Flow, а completed/next/blocked каждый раз выводятся из canonical Flow через `readFlow/resolveFlowDir/deriveFlowWork`; Course сам не вызывает flow complete. FWK Work использует ту же `deriveFlowWork`, загрузив первый зарегистрированный `flow` ресурс workspace. [Course](/Users/Goodea/goodea/keryx/src/session/slate-course.ts:58), [FWK flow selection](/Users/Goodea/goodea/keryx/src/sac/fwk-service.ts:756), [FWK derivation](/Users/Goodea/goodea/keryx/src/sac/fwk-service.ts:812).
- `/goal --auto` уже создаёт Flow через `FlowService.init`, записывает AC1 из goal с `[verify: judged]`, затем freeze/start; полученный flowId пишет в `slate.course.flowRef` и сохраняет binding для reopen. Это реальное повторное использование Flow, но goal text здесь заменяет spec; связанного OpenSpec revision/requirement-ID контракт в этой функции не формируется. [Provision](/Users/Goodea/goodea/keryx/src/commands/goal-command.ts:301), [freeze/start](/Users/Goodea/goodea/keryx/src/commands/goal-command.ts:328), [bind](/Users/Goodea/goodea/keryx/src/commands/goal-command.ts:794), [rebind](/Users/Goodea/goodea/keryx/src/commands/goal-command.ts:956).
- Не доверять старому комментарию `workspace-resolve.ts`, будто flowRef никто не пишет: он противоречит указанному текущему `/goal --auto` коду. [Устаревшее утверждение](/Users/Goodea/goodea/keryx/src/sac/workspace-resolve.ts:11), [текущий writer](/Users/Goodea/goodea/keryx/src/commands/goal-command.ts:798).
- Machine wrap-up группирует Seeds по kind; evidence включает diff, Flow projection и Seeds. Source revision вычисляется из их redacted bytes; proposal ID детерминирован workspace/flow/sourceRevision/kind. При нуле Seeds no-op; результат предлагается, не принимается. [Evidence](/Users/Goodea/goodea/keryx/src/sac/machine-wrap-up.ts:198), [revision](/Users/Goodea/goodea/keryx/src/sac/machine-wrap-up.ts:249), [proposal dedup ID](/Users/Goodea/goodea/keryx/src/sac/machine-wrap-up.ts:728), [group dispatch](/Users/Goodea/goodea/keryx/src/sac/machine-wrap-up.ts:801).

## 4. Proposal lifecycle: полезный готовый transaction protocol

- Proposal — immutable `proposal-created`, `status: proposed`, отдельный `proposalRevision`, kind, author, security, trusted wrap-up reference, pinned evidence. Создание требует выданный trusted wrap-up; это не API «любой текст → знание». Файл предложения отдельно от append-only terminal transitions. [Тип](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:18), [create](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:137), [immutable write](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:169), [storage paths](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:688).
- Review под workspace lock и `activity.jsonl.lock`: same-key replay возвращает исходный event, иной terminal transition конфликтует. Новое принятие проходит interactive/token gates, пишет approval и durable write-intent, затем owner write, затем review decision/terminal event. Неудачный owner write превращает requested accepted в terminal stale. [Review](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:188), [replay/conflict](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:207), [intent/write/terminal](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:291), [ledger path](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:699).
- Непосредственно перед первым owner write проверяются strict policy revision и актуальные bytes всех evidence. Перед границей owner пишется attempt marker; после — immutable write result; receipt связан с workspace/proposal/revision/correlation/idempotency/reviewer/policy hash. [Freshness and attempt](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:420), [receipt binding](/Users/Goodea/goodea/keryx/src/sac/guarded-owner-writer.ts:119).
- Owner target CAS использует **SHA256 bytes**, не человеческий `Version:`: ожидаемая версия берётся из owner target-version record, default null (создать только при отсутствии). Под project-scoped target lock текущие bytes сравниваются с base; mismatch возвращает `version_conflict`, expected/current digest и diffRef на предложенные bytes. Это не универсальный compare-against-client-base API для редактирования существующих wiki/spec. [Version model](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:100), [paths/lock](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:140), [CAS](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:269), [conflict artifact](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:339).
- Перед записью target сохраняется staging plan с prepared receipt и optional predictedVersion, после записи version record и receipt (commit marker). Recovery возвращает receipt или завершает staging; SAC не повторяет произвольный mutate после indeterminate attempt. Для Hub пригодна форма transaction/outbox/idempotency, файловые mkdir-lock и rename заменить серверной транзакцией. [Staging](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:174), [commit](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:199), [recovery](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:467).
- Важно для server refactor: `finishFromStaging` при несовпадении predicted/recorded результата вызывает `apply` без повторного сравнения observed с staged expectedVersion; нельзя переносить это как доказанную полную защиту от правки третьей стороной после crash. Нужен отдельный server recovery-conflict контракт. [Точная ветка](/Users/Goodea/goodea/keryx/src/sac/proposal-evidence.ts:222).

## 7. Рекомендуемое расширение поверх существующего

Это выводы исследования, не описание уже существующей реализации.

1. **Workspace оставить boundary совместной работы**, перенести canonical manifest/revisions/ACL на Hub; локальный workspace — cache/reference binding. Переиспользовать FWK budgeted read, freshness/withheld/report contracts и facade. Не копировать file paths как team identity. Основания: существующие manifest/FWK contracts выше.
2. **Slate оставить private per-agent working context**, Seeds — предложениями намерений/наблюдений. Не превращать Slate close в accept/commit spec. Для server shared draft использовать версионированный change set с Workspace linkage, реализуя переход через тот же ProposalLifecycle/guarded owner seam.
3. **Добавить отдельный owner OpenSpec** и явные routing kinds; нынешний fallback `contract-change → skill` заменить типизированным назначением. Proposed spec revision нельзя выдавать как observed wiki. Замороженный Flow должен ссылаться на конкретную accepted spec revision и requirement/scenario IDs; нынешний `/goal --auto` — пример реального Flow adapter, но без такого traceability.
4. **Human acceptance хранить на Hub**, actor = authenticated human session, immutable decision bound to exact change-set digest/base/targets/evidence, agent token умеет propose/read, но не accept. Native confirm-token/approval floor сохранить для локальных операторских действий; не подменять ими серверное разделение ролей.
5. **После code verification предлагать observed wiki delta**, содержащий проверенную code revision, spec revision, requirement IDs, test/health/review evidence и evidence freshness. Landing через существующий wiki owner/history, но с target/base revision и реальным patch existing page, а не только новой SAC decision stub.
6. **Git adapter оставить финальной публикацией** accepted Hub artifact revisions; owner receipt должен описывать application к canonical Hub store, Git commit/PR receipt — отдельный publication result. Из исследованного SAC writer сейчас видно local target/history landing, а не git publication transaction.
7. **Переиспользовать retry/outbox/staging/idempotency концепции**, но перенести CAS/locks/recovery в server transaction, отдельно разрешая конфликт при изменении target после crash. Роли, acceptance, receipts и canonical history не должны быть agent-writable файлами.

## 8. Что подтверждено тестовыми исходниками

Прочитаны testing skill/context и `keryx test related src/sac/proposal-evidence.ts`; тесты не запускались.
