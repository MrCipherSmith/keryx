## Главный вывод

Разделять **редакторское принятие знания**, **свежесть относительно кода** и **генерацию справки** уже полезно, но нынешние поля страницы не дают надёжного version-bound KnowledgeReview. `Status` хранится как свободная строка; `verify` лишь проставляет provenance; модель может переписать уже accepted страницу и сохранить accepted. Поэтому `Status: accepted`, `VerifiedAt` и новая версия Markdown не эквивалентны проверенному человеком решению по конкретной ревизии текста. Основания: [тип страницы](/Users/Goodea/goodea/keryx/src/wiki/types.ts:76), [verify](/Users/Goodea/goodea/keryx/src/wiki/refresh.ts:383), [выбор accepted страниц](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:300), [сохранение статуса](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:898), [инварианты записи](/Users/Goodea/goodea/keryx/src/wiki/page-invariants.ts:520).

### Provenance и границы актуальности

- Build provenance — `{commit, branch, builtAt}` в `.metaproject/data/<module>/.provenance.json`; это версия исходников производного артефакта, не receipt редакторского approval. [schema/path](/Users/Goodea/goodea/keryx/src/sync/provenance.ts:11).
- Page provenance — валидируемые `VerifiedAt` (40-char commit SHA), `VerifiedScope` (`sha256:`), `Describes`; parse возвращает null для malformed полей. [parseProvenance](/Users/Goodea/goodea/keryx/src/wiki/provenance.ts:31).
- Describe-set: явный `Describes` заменяет производный набор; иначе Related Code; иначе module key files. Поэтому измерение не гарантирует полноту всех файлов модуля. `Describes: none` означает намеренно не code-scoped страницу, а не fresh. [contract](/Users/Goodea/goodea/keryx/src/wiki/describes.ts:1), [none](/Users/Goodea/goodea/keryx/src/wiki/describes.ts:39), [исключение из scoring](/Users/Goodea/goodea/keryx/src/wiki/freshness/report.ts:219).
- Scope hash охватывает разрешённый describe-set, считывает текущие байты файлов, сортирует пути; неизвестный/нечитаемый файл даёт `<missing>`. Это snapshot выбранного набора, а не доказательство смысловой корректности prose. [computeVerifiedScope](/Users/Goodea/goodea/keryx/src/wiki/provenance.ts:121), [computePageNodeHash](/Users/Goodea/goodea/keryx/src/wiki/staleness.ts:60).
- Freshness предпочитает git-log по describePaths при доступном VerifiedAt; если commit отсутствует в здоровом git — допускает scope-hash fallback. Git failure даёт undecidable, не тихий success; hash-only ограничен `review-suggested`. Без scope — undecidable. [evaluatePageFreshness](/Users/Goodea/goodea/keryx/src/wiki/freshness/page-freshness.ts:102), [scope fallback](/Users/Goodea/goodea/keryx/src/wiki/freshness/page-freshness.ts:173).
- Lifecycle `Status/ValidFrom/ValidTo/SupersededBy` уже читается через общий memory computeLifecycle; этот модуль сам не записывает temporal поля. Это фильтрация пригодности знания, отдельно от git freshness. [parsePageLifecycle](/Users/Goodea/goodea/keryx/src/wiki/provenance.ts:61).

## Approval: что действительно защищено

### Wiki metadata и модель

Прямое редактирование Markdown остаётся частью поддержанного lifecycle: history на следующей записи фиксирует отличие как `manual (detected)`. В writer нет проверки reviewer role/approval на произвольный `Status`; данные записи — команда/run/content. Следовательно, принимать Status из Git/файла как авторитетный Hub approval нельзя. [reconcile](/Users/Goodea/goodea/keryx/src/wiki/history.ts:294), [write context](/Users/Goodea/goodea/keryx/src/wiki/history.ts:45), [mutatePage](/Users/Goodea/goodea/keryx/src/wiki/history.ts:395).

Текущий enrich закрывает **только повышение статуса моделью**: даже ответ `Status: accepted` принудительно возвращается к pre-enrichment Status; то же заявлено для RLM light/deep finalize. Но accepted page разрешена через page/force, и сохранение исходного frontmatter означает, что новый model-generated текст может остаться accepted с прежним VerifiedAt/VerifiedScope. Это вывод из состава функций, не результат нового exploit-run. [enrich rationale](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:716), [finalize shared](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:1134), [target selection](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:300), [preserve metadata](/Users/Goodea/goodea/keryx/src/wiki/page-invariants.ts:520).

Есть drift между skill и реализацией: gdwiki skill по-прежнему instructs агенту после enrichment выставить accepted вручную. Эта инструкция не является техническим human gate. [skill step 5](/Users/Goodea/goodea/keryx/.metaproject/skills/gdwiki/SKILL.md:165) против [enrich status invariant](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:716).

### SAC path: реальный guarded review, но локальная trust boundary

SAC review authorizes actor/workspace и под lock проверяет idempotency/terminal transition; новый accepted с `interactive:false` запрещён, с true дополнительно требует confirm token. [review](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:188), [interactive gate](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:235), [consume](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:257).

`confirm-review` — отдельная CLI-команда, не MCP tool; проверяет security gate, требует `--acknowledge-security` для needs-approval, выдаёт token. Однако handler сам не аутентифицирует отдельного человека и не проверяет TTY: гарантия «человек одобрил shell-команду» передана внешнему harness/permission режиму. В окружении, где shell уже разрешён, нельзя автоматически выводить обязательное независимое human action из наличия token. [полный mint handler](/Users/Goodea/goodea/keryx/src/commands/workspace.ts:149), [CLI review passes interactive:true](/Users/Goodea/goodea/keryx/src/commands/workspace.ts:196).

Token имеет TTL 2 минуты, хранится hashed в локальном sidecar, связан workspace/proposal; consume связывает повтор с idempotencyKey и не требует второй token для того же recovery attempt. В StoredToken нет content hash страницы или reviewer identity. Следовательно, механизм полезен как local confirmation primitive, но не заменяет server-side KnowledgeReview authorization. [schema/TTL](/Users/Goodea/goodea/keryx/src/sac/review-confirm-token.ts:16), [mint](/Users/Goodea/goodea/keryx/src/sac/review-confirm-token.ts:58), [consume](/Users/Goodea/goodea/keryx/src/sac/review-confirm-token.ts:100).

MCP `sac.review` запрещает HTTP transport, принимает token и hardcodes interactive:true; один лишь tool access не может mint token через этот MCP handler. Это более узкая гарантия, чем запрет self-approval для всех агентов с shell/filesystem доступом. [MCP adapter](/Users/Goodea/goodea/keryx/src/mcp/tools.ts:356).

Wiki owner writer проверяет owner/editor и механически пишет **новую decision страницу** `decisions/sac-<proposalId>.md` со Status accepted и ссылкой на hash-verified session evidence; это не универсальный patch существующей wiki страницы и не semantic review её утверждений. [render](/Users/Goodea/goodea/keryx/src/sac/wiki-owner-writer.ts:29), [path](/Users/Goodea/goodea/keryx/src/sac/wiki-owner-writer.ts:78), [authorize](/Users/Goodea/goodea/keryx/src/sac/wiki-owner-writer.ts:106).

## Версии: что можно переиспользовать

Две существующие шкалы различны: semantic `Version` в Markdown и history `version:number` плюс SHA/run/by/time. History — локальный undo store: exact prior bytes, lock, baseline/manual detection, idempotent byte-equal no-op, восстановление. Default retention 20, index bounded, runs log trimmed; history сама gitignore-ится. Поэтому это не бессрочный командный revision ledger. [history model](/Users/Goodea/goodea/keryx/src/wiki/history.ts:30), [write](/Users/Goodea/goodea/keryx/src/wiki/history.ts:395), [gitignore](/Users/Goodea/goodea/keryx/src/wiki/history.ts:340), [semantic bump](/Users/Goodea/goodea/keryx/src/wiki/page-invariants.ts:257).

## Предлагаемый разрез Hub KnowledgeReview

Это рекомендации, а не найденный API.

1. `KnowledgeRevision`: неизменяемый content digest + стабильный documentId + parentRevision + sourceRepo/commit/tree + local producer/version/model metadata. Переиспользовать hashing/page-invariants/owner-writer идеи, но хранить revision server-side независимо от bounded local undo. Основание для разрыва: [history retention](/Users/Goodea/goodea/keryx/src/wiki/history.ts:30), [local record identity](/Users/Goodea/goodea/keryx/src/wiki/history.ts:57).
2. `KnowledgeReview`: отдельная запись с revision/content digest, authenticated reviewer principal и role, decision, reason, timestamp, provenance/security evidence. Человеческое разрешение проверяет Hub, agent credential имеет propose/read, но не approve. Token связывать с revision и reviewer; Markdown Status считать импортированным editorial claim, не authoritative approval. Основание: [свободный Status](/Users/Goodea/goodea/keryx/src/wiki/types.ts:84), [локальный token schema](/Users/Goodea/goodea/keryx/src/sac/review-confirm-token.ts:18).
3. Отдельная `CodeApplicabilityAttestation`: codeRepo/commit + describe-set manifest + scope digest + source-graph provenance + measuredAt + outcome fresh/stale/unknown/not-code-scoped. Baseline, refresh и human review не должны порождать друг друга. Переиспользовать describes/provenance/freshness evaluators. Основание: [describes](/Users/Goodea/goodea/keryx/src/wiki/describes.ts:1), [baseline](/Users/Goodea/goodea/keryx/src/wiki/refresh.ts:392), [freshness bases](/Users/Goodea/goodea/keryx/src/wiki/freshness/page-freshness.ts:27).
4. Любая правка accepted текста создаёт новую unreviewed revision; approval остаётся у старого digest. Для graph-owned Reference отдельно определить, требует ли обновление полного rereview или только нового machine attestation. Иначе существующее сохранение accepted после enrich переносит старое решение на новый текст. Основание: [targeting accepted](/Users/Goodea/goodea/keryx/src/wiki/enrich.ts:300), [сохранение metadata при новой версии](/Users/Goodea/goodea/keryx/src/wiki/page-invariants.ts:520).
5. Локальный агент продолжает graph build/collect/enrich и загружает **предложение с evidence**. Hub принимает revision/review, Git integration фиксирует provenance/конфликты; pull/export не должен превращать file Status в human approval. SAC idempotency/owner receipts — кандидат на reuse, но нужен отдельный existing-document patch owner и optimistic concurrency по revision. Основание текущего ограничения: [SAC writer создаёт decision path](/Users/Goodea/goodea/keryx/src/sac/wiki-owner-writer.ts:78), [idempotent terminal review](/Users/Goodea/goodea/keryx/src/sac/proposal-lifecycle.ts:194).
6. Исправить authoring skill: после model enrichment — proposed/unreviewed, явный human review конкретной revision; убрать instruction агенту самостоятельно ставить accepted. Основание: [текущая инструкция](/Users/Goodea/goodea/keryx/.metaproject/skills/gdwiki/SKILL.md:165).
