## Summary

`src/stack` detects which technology stacks a repository uses and persists the result to `.metaproject/data/stack/stack.json`. It groups 5 file(s). Depends on `src/lib`. Exposes 8 public symbol(s).

## Overview

`src/stack` owns deterministic, offline detection of the technology stacks a repository uses, covering JavaScript and TypeScript frameworks, Python, Go, Rust, JVM, .NET, Swift, Dart, PHP, Ruby, C/C++, infra, CI and SQL. It looks only at the repository root: it reads manifests and marker files, plus one bounded source-extension scan. The result is a set of boolean tags with a per-signal breakdown, and `keryx stack detect` is the intended writer of the persisted copy.

## How it works

`detect.ts` holds the pure detection logic. `STACK_DETECT_TAGS` is a plain data table that maps each tag to one `StackFamily`. `detectStack` runs a fixed list of signal functions in order: manifest signals (`package.json`, `pyproject.toml`, `go.mod`, `pom.xml`, `composer.json` and others), marker signals (`Dockerfile`, compose files, `.github/workflows`, `*.tf`, `*.sql`), and `scanExtensions`, a depth-3 walk that skips `SCAN_SKIP_DIRS`. The scan is the only way C/C++ is found, since that family has no manifest. Each signal returns a `SignalOutcome`, or `undefined` when its evidence is absent.

The governing rule is that uncertain always means included. A read failure other than ENOENT or ENOTDIR, a structurally broken manifest, or a workspace root with no leaf dependencies marks only that signal's family as `uncertain`, never every tag. All I/O goes through the injectable `StackDetectFs` interface, so tests do not need the disk.

`service.ts` wraps the pure core. `runStackDetect` computes `inputsSha256` over everything except `detectedAt`, reuses the existing `detectedAt` when the fingerprint matches, and writes through `writeContained` into `stackJsonPath(root)`. The clock is injected through `now`. `index.ts` is the public surface that other lanes import, so they do not reach into `detect.ts` or `service.ts` directly.

## Key concepts

- **Stack family (`StackFamily`)**: a language or platform group such as `js`, `python` or `c-cpp`. Every tag belongs to exactly one family.
- **Tag**: a stack label such as `react` or `django`. `StackDetection.tags` maps every known tag to a boolean.
- **Signal**: one source of evidence, identified by an id such as `manifest:package.json`. `StackPerSignal` records its tags, its `uncertain` flag and a reason.
- **Uncertain**: the module could not decide for that family. The top-level `uncertain` is true when any signal is uncertain, and an uncertain family's tags are reported as present.
- **Fingerprint (`inputsSha256`)**: a hash of the canonical core result. It decides whether the old `detectedAt` is kept, which makes a re-run on an unchanged tree byte-identical.
- **Filesystem seam (`StackDetectFs`, `StackDirEntry`)**: the read interface that every signal uses. Its methods throw when a path is missing, and callers catch the error rather than checking existence first.

## Main flows

1. **Persisting a detection.** `runStackDetect(root)` calls `detectStack`, then `fingerprintOf` on the result. It reads the existing file with `readStackDetection` and compares `inputsSha256`. It builds the `StackDetection`, reusing the old `detectedAt` on a match and taking a new one from `now()` otherwise. Unless `write: false`, it writes the canonical JSON through `writeContained`.
2. **Reading a `package.json`.** `packageJsonSignal` reads and parses the file. It collects dependency names from the four dependency fields. It returns uncertain when `workspaces` is declared or no dependencies are declared. Otherwise it matches names against `JS_TAG_MARKERS` and the `@nestjs/` prefix to produce tags.
3. **A failed read.** `readFailureOutcome` treats ENOENT and ENOTDIR as absent and returns `undefined`. Any other error, such as EACCES or EIO, marks that family uncertain. A permission problem therefore cannot look like a missing stack.
