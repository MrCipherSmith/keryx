# Module src/harness/parallel

## Summary

`src/harness/parallel` is a harness support module that provides a scheduling API for coordinating work through waves. It depends on `src/harness/child` and exposes nine public symbols.

## Overview

The module owns a small coordination layer for child-task work inside the harness. Instead of exposing lower-level child behavior directly, it presents a planner and executor surface: work is organized into waves, then those waves are executed with the help of injected dependencies.

This lets higher-level modules such as `src/harness`, `src/harness/extension`, and `src/commands` depend on a stable scheduling abstraction while child-specific handling remains separate.

## How it works

The module contains two key files:

- `src/harness/parallel/scheduler.ts` contains the implementation and the public scheduling surface.
- `src/harness/parallel/scheduler.test.ts` contains tests for that surface.

The public API can be read as two related phases:

1. **Planning**
   - `planWaves` produces a `PlanWavesResult` from planning configuration and dependency inputs.
   - Planning outputs are represented by `Wave` objects.
   - Task-related work is represented by the exported `ChildTask` interface.

2. **Execution**
   - `executeWaves` consumes planned waves along with `WaveExecutorDeps`.
   - Child-level execution support is provided through the module’s dependency on `src/harness/child`.
   - Execution failures are surfaced through `WaveExecutionError`.

## Key concepts

- `ChildTask`: the task interface exposed by the module for work associated with child handling.
- `Wave`: a scheduling unit produced during planning and consumed during execution.
- `PlanWavesConfig`: configuration values that influence how waves are planned.
- `PlanWavesDeps`: dependencies required while planning waves.
- `PlanWavesResult`: the structured result of wave planning.
- `WaveExecutorDeps`: dependencies required while executing waves.
- `WaveExecutionError`: the error type used when wave execution fails.

These concepts form a narrow pipeline: configuration, dependencies, and task modeling are used to plan waves, and those waves are then executed with executor dependencies.

## Main flows

### Plan work into waves

A caller uses `planWaves` from `scheduler.ts` to turn scheduling inputs into a `PlanWavesResult`. The result is expressed in terms of `Wave` values, which represent the scheduled units of work.

### Execute planned waves

After planning, a caller invokes `executeWaves` with the waves and `WaveExecutorDeps`. Execution relies on the child module for child-task coordination and surfaces `WaveExecutionError` when execution fails.

### Validate the scheduler

`scheduler.test.ts` tests the public scheduler surface. It exercises the planning and execution types defined in `scheduler.ts` against the dependency boundary established by the module.
