## Overview

`fixtures/import-policy/allowed-client-imports-core-facade/gdgraph` is a fixture for the allowed case of the import policy: a client module reaching a core owner only through that owner's declared public facade. The facade is `service.ts`, which the fixture comments describe as the one basename the facade rule exempts. ## How it works

The module is a two-file chain with one direct edge. `service.ts` imports `detail` from `./internal` and exports `serve` as the template string `core-facade:${detail}`. `internal.ts` is a leaf that exports `detail` as a string constant and has no imports. Nothing in the module's consumers imports `internal.ts` directly; the client entry imports only the facade.

The header comment in `service.ts` explains why the facade has a dependency at all. An earlier version was a leaf, which made the allowed case pass only because it had no imports. A reachability set also includes everything behind a facade, so a facade with any import would fail that check. The fixture now uses a realistic facade so the allowed case fails under reachability and passes under direct edges.

## Key concepts

- **Public facade**: `service.ts`, the core owner's declared entry point. It is the only file a client may import.
- **Private internal**: `internal.ts`, which sits behind the facade. The comments say the client entry never imports it.
- **Direct edge versus reachability**: the two ways the import policy can judge a client's imports. Direct edges count only the import statements the client itself writes. Reachability also counts every module transitively behind the facade. This fixture is built to pass under the first.
- **Consumed symbol**: the harness uses `serve` inside `usesServe` rather than re-exporting it. The comment in `harness/entry.ts` says a pure re-export does not survive the bundler's tree-shaking.

## Main flows

1. **Allowed client import.** `harness/entry.ts` imports `serve` from `../gdgraph/service` (line 4) and uses it in `usesServe` (line 7). The client's only edge into this module is to the facade, which is the allowed shape.
2. **Facade resolution.** Loading `service.ts` first loads `./internal`, so `detail` is evaluated before `serve`. The result is `serve` equal to `core-facade:core-internal-behind-the-facade`.
3. **Policy check, as the fixture comments describe it.** The check sees one direct edge from the client to `service.ts` and passes. A reachability check would also count `internal.ts` as reached through the facade, which is why the fixture was reworked for direct edges.
