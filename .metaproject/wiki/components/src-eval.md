# Module src/eval

## Summary

`src/eval` is a small evaluation-support module for running detectors over corpora. It defines shared contracts for evaluation cases, detector functions, and reports, and exposes functions for loading cases and executing a corpus.

The module is consumed by `src/security/detect` and collaborates with `src/testing`, fixture data, and health metric utilities.

## Overview

The module owns the shared vocabulary needed to evaluate detectors against repeatable corpora. Its public surface is intentionally narrow:

- `CorpusCase` describes a case used during evaluation.
- `DetectorFn` describes a detector that can be run against cases.
- `CorpusReport` describes the outcome of an evaluation run.
- `loadCorpusCases` prepares corpus cases for execution.
- `runCorpus` applies a detector function to loaded cases and returns a report.

This keeps evaluation behavior reusable and testable without coupling consumers to detector implementation details.

## How it works

`src/eval` is organized around a few small responsibilities:

- **Public contracts**: `CorpusCase`, `DetectorFn`, and `CorpusReport` form the boundary between this module and its callers.
- **Corpus execution**: `loadCorpusCases` and `runCorpus` provide the main path for preparing cases and evaluating a detector.
- **Testing and fixtures**: test files use `src/testing` and `fixtures/churn-complexity` to exercise corpus loading and evaluation behavior.
- **Health integration**: dependencies on `src/health` and `src/health/metrics` allow evaluation-related reporting to integrate with health metrics when needed.

## Key concepts

- **Corpus case**: A single evaluation item represented by `CorpusCase`.
- **Detector function**: A callable described by `DetectorFn` that can be evaluated against corpus cases.
- **Corpus report**: The result of a corpus run, returned as a `CorpusReport`.
- **Corpus**: A collection of cases prepared by `loadCorpusCases` for a detector run.
- **Shared implementation surface**: `corpus.ts` and `gate.ts` are imported by other modules, forming the reusable evaluation helper surface.

## Main flows

### Evaluate a corpus

1. A consumer imports the public symbols from `src/eval`.
2. It calls `loadCorpusCases` to obtain `CorpusCase` values.
3. It passes those cases and a `DetectorFn` implementation to `runCorpus`.
4. `runCorpus` returns a `CorpusReport` describing the evaluation outcome.

### Exercise the module in tests

1. `src/eval/corpus.test.ts` and `src/eval/block-d-corpora.test.ts` import `src/testing` and fixture-backed data.
2. The tests load or construct corpus cases and call the public evaluation functions.
3. The tests assert expected behavior for the public contract used by consumers such as `src/security/detect`.
