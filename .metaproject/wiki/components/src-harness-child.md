# Module src/harness/child

## Summary

`src/harness/child` groups 22 file(s). It depends on `src/harness/policy`, `src/harness/session`, and `src/contracts`, and exposes 18 public symbols. The module supplies the harness's child/subagent primitives: inheriting budgets and policies, recording provenance, building dispatch extensions, and normalizing child results.

## Overview

This module owns the "child" segment of the harness: the code that lets a parent execution spawn or orchestrate a child subagent while preserving policy constraints and budget bounds. It provides typed contracts between the parent harness and child execution, plus helpers to inherit parent policy and budget, run a child, and parse its output into a canonical result.

The module is a component of `src/harness`. It is used by `src/harness/extension`, `src/harness/parallel`, `src/harness/process`, and `src/harness/tool/builtin`, and is benchmarked by `scripts/benchmark`.

## How it works

The module can be read as three cooperating layers:

- **Contract types** (`contract.ts`, public interfaces such as `ChildContractExtension`, `CanonicalSubagentResult`) define the data shapes that child execution produces and the parent expects.
- **Inheritance helpers** (`inheritBudget`, `inheritPolicy`, `isKnownCapability`) carry policy and budget context from parent to child. `BudgetReservation`, `ParentRemainingBudget`, and `InheritBudgetResult` describe the budget exchange; `InheritPolicyResult` describes the policy exchange.
- **Lifecycle orchestration** (`isolation.ts`, `spawn.ts`, `orchestrate.ts`, `ledger.ts`) runs the child, tracks its ledger, records provenance via `childProvenance`, and serializes/parses results with `parseChildResult` / `serializeChildResult`.

`buildChildDispatchExtension` is the main integration point: it turns the inheritance inputs into a dispatch extension that later consumers (extensions, parallel/process runners) can attach to a child run.

## Key concepts

- **Budget reservation** — `BudgetReservation` and `ParentRemainingBudget` represent how much parent budget a child may reserve and what remains afterward.
- **Budget/policy inheritance** — `inheritBudget` and `inheritPolicy` derive a child's constraints from the parent. `isKnownCapability` guards policy inheritance by checking whether a capability is recognized.
- **Provenance** — `ChildProvenanceDeps` and `childProvenance` record where a child came from, so a result can be traced back through the parent chain.
- **Dispatch extension** — `ChildContractExtension` and `BuildChildDispatchExtensionInput` describe how a child run is added to the harness dispatch flow.
- **Canonical child results** — `CanonicalSubagentStatus`, `CanonicalSubagentResult`, `ParsedChildResult`, and `ParseChildResultMeta` model the normalized outcome of a child. `parseChildResult` and `serializeChildResult` convert between raw child output and these types.

## Main flows

1. **Budget and policy inheritance** — The caller invokes `inheritBudget` with the child's requested reservation and the parent's remaining budget, then `inheritPolicy` with the child's requested capabilities. The resulting `InheritBudgetResult` and `InheritPolicyResult` constrain the child's run.
2. **Child dispatch** — The caller assembles a `BuildChildDispatchExtensionInput`, calls `buildChildDispatchExtension`, and uses the returned `ChildContractExtension` to integrate the child into the harness dispatch pipeline.
3. **Result canonicalization** — When the child finishes, `parseChildResult` normalizes its output into a `ParsedChildResult` / `CanonicalSubagentResult`, `childProvenance` attaches lineage, and `serializeChildResult` produces the serialized form used downstream.
