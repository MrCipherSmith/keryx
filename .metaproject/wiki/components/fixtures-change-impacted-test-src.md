## Key Concepts

### Test Impact Analysis (TIA)
The problem of selecting only tests genuinely affected by changed source files, rather than running the entire test suite.

### Static / naming selection
Selects test files whose names share a prefix with a changed source file. Fast but imprecise — over-selects `alpha.extra.test.ts` because its name starts with `alpha.`, even though it exercises `beta.ts`.

### Coverage-map selection
Selects tests by looking up changed files in a pre-built map of runtime coverage. Because the map records `alpha.extra.test.ts` covered only `beta.ts`, a change to `alpha.ts` does not select it.

### Precision metrics
- **False positive**: selecting an unimpacted test
- **False negative**: missing a truly impacted test
- The fixture validates:
  - Coverage-map: zero false negatives, perfect precision (1.0)
  - Static selection: precision of 0.5 (one false positive)

### Map-absent fallback (AC9)
When a changed file has no coverage entry, the selector falls back to the naming heuristic. For example, `gamma.test.ts` corresponds to `gamma.ts` which is absent from the coverage map.

## Main Flows

### Flow 1 — Unit precision comparison (AC8)

**File**: `coverage-map.test.ts`

1. Load `coverage-map.json` from the fixture directory via `loadCoverageMap`
2. Call `selectByCoverageMap(["src/alpha.ts"], map)` for coverage-driven selection
3. Call `staticChangedSelection(change, testFiles)` for the naming baseline
4. Assert:
   - Coverage-map returns only `["src/alpha.test.ts"]` (precision = 1.0)
   - Static selection also picks `alpha.extra.test.ts` (precision = 0.5)
5. Match values against `expected.json`

### Flow 2 — Map-absent file fallback (AC9)

**File**: `coverage-map.test.ts`

1. Verify `gamma.ts` is absent from coverage map via `coveredFilesInMap`
2. Run `staticChangedSelection(["src/gamma.ts"], testFiles)`
3. Assert returns `["src/gamma.test.ts"]`

This validates the absence-to-naming-fallback path.

### Flow 3 — Corpus gate (AC17)

**File**: `block-d-corpora.test.ts`

1. Plug fixture into Block 0 acceptance harness (`runCorpus` / `gateCorpus`)

4. Assert:
   - `fnRate === 0`
   - `precision === 1`

   - `gateCorpus` returns `"pass"`
