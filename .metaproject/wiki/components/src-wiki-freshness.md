# Module src/wiki/freshness

## Summary

`src/wiki/freshness` groups 12 file(s). Depends on `src/gdgraph`, `src/wiki`, `src/sync`. Exposes 8 public symbol(s).

## Overview

This module owns freshness evaluation for wiki content. It combines graph-derived signals, synchronization state, and Git-backed change evidence to determine whether a wiki page is still current.

The main result is a page-level freshness decision plus a Markdown report that can be presented by commands or used by benchmark workflows.

## How it works

The module is organized around a small pipeline:

- `run.ts` coordinates the overall freshness run using the public input type `RunFreshnessInput`.
- `page-freshness.ts` models the result with `PageFreshness` and evaluates one page against a declared `FreshnessBasis`.
- `classify-change.ts` translates incoming change evidence into a form that can affect a freshness decision.
- `report.ts` aggregates evaluated pages into reportable output, with `renderMarkdown` producing the human-readable form.

Internally, the module depends on:

- `src/gdgraph` for graph-based evidence and code context
- `src/wiki` for page-oriented context
- `src/sync` for synchronization-related state
- `src/gdgraph/treesitter` when graph signals are derived from parsed source structure

`GitRunner` is exposed as a public abstraction, which indicates that Git-based history or diff queries are isolated behind an injectable runner rather than being handled directly by consumers.

## Key concepts

- `RunFreshnessInput`
  - Describes the options and inputs needed to run freshness evaluation.
- `freshnessDir`
  - Resolves the directory used by the freshness workflow.
- `runFreshness`
  - Top-level entry point for evaluating freshness across a set of pages.
- `PageFreshness`
  - Per-page freshness result.
- `FreshnessBasis`
  - The evidence or reference point against which a page is judged.
- `evaluatePageFreshness`
  - Applies a freshness basis to a page and produces a decision.
- `classify-change`
  - Maps change signals into a category or form that can be interpreted by the evaluator.
- `renderMarkdown`
  - Formats the report output as Markdown.

## Main flows

1. **Run a freshness evaluation**
   - A caller supplies `RunFreshnessInput`.
   - `runFreshness` gathers wiki page context and freshness evidence.
   - `evaluatePageFreshness` compares each page against its `FreshnessBasis`.
   - The result is returned as page-level `PageFreshness` data.

2. **Generate a Markdown report**
   - Evaluated page results are passed into report assembly.
   - `renderMarkdown` converts the report model into Markdown output.

3. **Use freshness evidence from Git and graph sources**
   - `GitRunner` provides access to Git-backed change information.
   - `classify-change` turns that evidence into freshness-relevant signals.
   - Those signals contribute to the per-page freshness decision.
