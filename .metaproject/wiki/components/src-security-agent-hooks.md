# Module src/security/agent-hooks

## Overview

`src/security/agent-hooks` provides runtime-specific configuration hooks for Keryx security checks. It defines a `RuntimeHook` interface and a registry of runtime adapters used by the parent `src/security` module.

Adapters describe where a runtime's settings live and how to merge, remove, and validate Keryx-managed hook configuration. The module is intended to keep those operations consistent while accommodating different settings formats.

## Runtime adapters

The module provides adapters for Claude Code, Cursor, Windsurf, and generic MCP targets. Claude Code configuration is event-keyed; the other adapters use a flat hook-array model.

The public API includes:

- `RuntimeHook` and `Settings` for describing runtime hooks and settings.
- `RUNTIME_HOOKS`, `runtimeIds()`, and `getRuntime()` for enumerating and looking up adapters.
- `AGENT_HOOKS_SENTINEL`, `MANAGED_KEY`, and `SECURITY_HOOKS_KEY` for identifying managed configuration.
- `AGENT_CHECK_INPUT_COMMAND`, `AGENT_CHECK_OUTPUT_COMMAND`, `checkInputCommand`, and `checkOutputCommand` for the security-check commands.
- `isManagedGroup()` for recognizing managed hook groups.

## Configuration ownership

Hook installation and removal use ownership markers so managed configuration can be distinguished from other settings. The intended behavior is to avoid duplicating managed entries during repeated merges and to remove managed entries without deleting unrelated user configuration.

The adapters provide the operations needed to:

- Resolve a runtime's settings path beneath a project root.
- Merge managed hook configuration into settings.
- Strip managed configuration while retaining unrelated settings.
- Validate the resulting configuration.

The exact configuration layout and command placement depend on the runtime adapter. Callers should use the adapter contract rather than assume every runtime uses the same schema.
