### Findings

### [S2-SEC-001] Only decide-premise checks that the operator's words are an answer; the other three verbs record any text that does not open with a decline word, including the verb's own decline option "keep"
- Severity: major
- File: src/commands/review-operator.ts:274 (LEAD_DECLINE), :302 (refuseDecline), :385, :411 (the other call sites)
- Attack vector / failing input: the operator is asked "Waive the mutation pass? Waive or Keep?" through the host's question tool and picks Keep (the option the code itself declares as the decline for waive-mutation and override-reviewers: HOST_OPTIONS `decline: "keep"`, lines 257 and 265, and the label the journal stores, "Keep: run the mutation pass"). The agent, acting honestly, records the report: `keryx review waive-mutation --package P --reason "suite takes an hour" --answered-by claude-code:q1 --answer-text "Keep" --question-text "Waive the mutation pass?"`. `refuseDecline` runs `wordsOf("Keep")` = ["keep"]; LEAD_DECLINE does not contain "keep", so nothing refuses, and `recordOperatorDecision` writes a `mutation-waiver` with `confirmedVia: "host-question"` and quote "Keep". The mutation gate (`mutationErrors`, `confirmedDecision`) then reads the waiver as granted and `review complete` closes with "Not run: mutation pass". Same for override-reviewers (`--answer-text "Keep"` or "Keep: run the required reviewers" records a reviewer override and lets a smaller roster close the round). Free text records too: `--answer-text "what does the mutation pass do?"` or "I am not sure" (first word "what" / "i") is recorded as a waiver; `--answer-text "uphold"` is recorded for waive-mutation. Only the `--answer` flag is checked against the decline option (line ~351, tested in review-host-question.test.ts:205); `--answer-text`, the operator's words, is not. The test file covers the decline words n/no/nope/нет only (line 258) and a positive-word check only for decide-premise (line 268, 274).
- Problem: the PRD decision Q2 ("free text is never a decision; the answer must be one of the verb's options") and the docs (TM-04 6b: "an answer that is not one of the verb's options ... for the others a yes"; limitations page; cli-reference) say the verbs refuse an answer that is not a yes. The implementation enforces that positively only for decide-premise (`refuseOtherChoice`). For confirm-plan, waive-mutation and override-reviewers the only text gate is a short deny-list of first words, and the deny-list omits the verbs' own declared decline option. This is not the wave-1 point about "don't waive it" (a negated yes that opens with "don"): here there is no check that the words are an affirmative at all, and a decline word the code itself defines slips through.
- Impact: the operator said no (or asked a question) and a waiver of a review gate is recorded as the operator's decision, with a verbatim quote that reads "Keep". A later reader of `operator-decisions.json`, the `/decisions` modal or the completion card sees a granted waiver. This is the honest-agent path, not a forgery: the operator's decision (keryx does not verify) accepts an agent that lies, it does not accept keryx recording the opposite of what an honest agent reports, and it contradicts the stated Q2 behaviour and the docs.
- Suggested fix: require a positive match for every verb, as decide-premise does. For confirm-plan, waive-mutation and override-reviewers, accept only when the first word set is in an affirmative list (yes, y, yeah, confirm, waive, override, approve, да, ok ...) or the words contain the verb's `confirm` id, and refuse when the words contain the `decline` id (keep, no) or neither. Add the verbs' decline ids to the refusal: derive the deny-list from `HOST_OPTIONS[verb].decline` so the two cannot drift. Add tests for `--answer-text` "Keep", "Keep: run the mutation pass", "what does this mean?", and "uphold" on waive-mutation, override-reviewers and confirm-plan, each asserting the package is byte-identical.
- Evidence: src/commands/review-operator.ts lines 257, 265 (decline "keep"), 274 (LEAD_DECLINE without "keep"), 302-306 (refuseDecline: `words.length === 0 || LEAD_DECLINE.has(words[0])`), 385, 411 (the only text checks on those paths). Test gap: src/commands/review-host-question.test.ts:205 tests `--answer keep`, :258 tests the decline words list, :268 and :274 test the positive check for decide-premise only.
- Confidence: high
- class_scope: sites = src/commands/review-operator.ts:385 (confirm-plan), :411 (waive-mutation and override-reviewers share the branch); decide-premise at :395-396 is correct and is the model. Enumeration: `keryx ctx rg refuseDecline|refuseOtherChoice|decline:` over src/commands/review-operator.ts, three call sites of `refuseDecline` and one of `refuseOtherChoice`.
