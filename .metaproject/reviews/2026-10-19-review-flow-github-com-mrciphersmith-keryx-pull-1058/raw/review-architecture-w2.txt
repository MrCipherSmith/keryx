## Architecture Review (slice-02, wave 2)

### Summary
The host-question path is one function (`recordHostQuestion`) behind the `--answered-by` branch in `runOperatorCommand`. Imports go through `decisions/service` (the stated single door), refusals run before the first write, and the review record is written before the journal so a failed journal only warns. `review complete` is not touched. The weak point is the answer gate for three of the four verbs (A2-001).

### Checked and not reported
- Journal-after-record ordering and warn-only journal failure: a deliberate choice with a stated reason (a retry must not record twice); the reason holds, since a retried decide-premise refuses on a finding no longer held and confirm-plan overwrites.
- `openDecision` twin lookup (src/decisions/journal.ts:65): a host question whose text and option ids match an unanswered open would reuse that record; the immediate answer after open closes the window, so no failing input.
- Zero-unrun-mutant waiver: the card path refuses ("No proposed mutant is unrun"), the CLI path, old and new, does not. Pre-existing terminal-path behaviour, not a regression of this diff.
- Command-layer placement of the English/Russian answer lexicon: works, no second caller, so not reported as a layer violation.
