### Logic Bugs

### [L6-501] `undelivered` is set when the approval post failed in transit, not only when the card never left the shell

- **Severity**: minor
- **File**: src/remote/client.ts:455-461
- **Problem**: The `try` around `this.post("approval", body)` and `await response.json()` ends in `catch { return { decision: "deny", undelivered: true }; }`. `post` aborts at `requestTimeoutMs` (client.ts:675) and `response.text()` / `json()` can throw after serve has already registered and posted the question. The same flag is returned for an already-aborted signal (line 440), where the card is not undelivered but moot.
- **Why it matters**: On a timeout or a truncated body after serve accepted the approval, the shell tells the operator "Telegram mirror not delivered: the topic did not take the card. Answer it here" (tui-shell.ts:6113) while the topic may show live Yes/No buttons. Nothing is unsafe: no waiter is registered for that approval id, the late frame is dropped after the early-decision window, and a press is ignored (fail closed). The operator is only told something untrue, and a stale card stays in the topic until it expires.
- **Reproduction scenario**: serve takes the POST and sends the topic message but answers slower than `requestTimeoutMs`. `askApproval` returns `{ deny, undelivered: true }`, raceApproval fires `onUndelivered`, the shell prints the not-delivered note, and the topic message stays visible with buttons that do nothing.
- **Fix**: Return `undelivered: true` only when the post is known not to have been accepted (no stream, `!response.ok`, a thrown error before a response). After a response was received, or on a timeout where acceptance is unknown, return a plain deny, which raceApproval already reads as `onTopicEnded`; or close the prompt before returning when the id is known. For the aborted-signal branch at line 440, return a plain deny.
- **Confidence**: medium (static reading, no run)
