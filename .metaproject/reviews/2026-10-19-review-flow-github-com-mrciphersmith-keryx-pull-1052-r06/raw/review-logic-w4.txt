### S-401 follow-up: is the fix complete, and is there a regression

Evidence is from static reading of `src/commands/operator-confirm-review.ts:650-702` and `src/review/complete-gated.ts`. Nothing was executed.

1. The cap is enforced before the card is drawn. `completionDispositions` refuses more than `MAX_DISPOSITIONS` (20) entries, a finding longer than `MAX_DISPOSITION_FINDING_CHARS` (200), and an evidence longer than `MAX_DISPOSITION_EVIDENCE_CHARS` (300, measured after `trim()`). The refusal happens in the card's input step, so a refused input produces no card and no token.
2. The card shows the evidence whole. `dispositionLine` no longer calls `clip()`. It prints `cardSafe(record.finding)` and `cardSafe(record.evidence)`. The `clip()` and `WAIVER_QUOTE_CHARS` pair still applies to waiver quotes only, and those were not part of S-401.
3. Shown equals stored. The stored evidence is `evidence.trim()`, and the card shows `cardSafe` of that same string. The only differences are the visible newline marker and the removed control and bidi characters, and both are visible or non-printing, so neither can hide text. The hidden-tail attack, where text past character 300 forged an "Attested by: operator" line, is closed.
4. No uncapped path found from the agent's input to the card or to the stored record. Records are rebuilt as `{finding, state, evidence?}`, which drops any extra keys. `findings.json` and `completion-confirmation.json` receive only these rebuilt records. Finding ids must resolve in the package (the engine refuses the rest).
5. Oversized cards degrade safely. A card whose text goes past `MAX_APPROVAL_PROMPT_CHARS` (3000, `src/remote/protocol.ts:160`) is refused by `operatorCardTooLongForTopic` (`src/remote/shell-bridge.ts:280`). The Telegram buttons are not offered and the card is answered in the shell. With 20 entries at the maximum size the card passes 3000 characters, so that fallback is the expected result.
6. Regression check. `completeReviewGated` runs `resolveReviewPackagePath`, `runProfileRefusal`, `packageRoutingRefusal(..., { refuseUnreadable: true })`, then `completeManagedReview`. That is the order `runComplete` in `src/commands/review.ts` used inline before, and both the CLI and the card now call the same function. I found no change in refusal order or in the arguments.
