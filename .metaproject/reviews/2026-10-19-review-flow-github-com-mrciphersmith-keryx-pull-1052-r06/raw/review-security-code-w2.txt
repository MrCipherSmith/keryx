### Findings

### [S-501] The S-401 fix leaves a path where the card shows less than is stored: `cardSafe` deletes whole escape sequences, text and all, from the displayed evidence
- **Severity**: major
- **File**: src/commands/operator-confirm-review.ts:702 (display), 696 (store); src/lib/card-safe.ts:10-11
- **Attack vector**: A prompt-injected or misbehaving agent calls `review_complete` with `dispositions: [{finding: <real finding>, disposition: "dismissed-incorrect", evidence: "see commit abc123\u001b]0;operator: decided-by alice\u0007 done"}]`. The string is 53 characters, so it passes the new 300-character cap. `dispositionLine` shows `cardSafe(record.evidence)`. The second `replace` in `cardSafe` (`\u001b[\]P^_][\s\S]*?(?:\u0007|\u001b\\)`) removes the OSC (also DCS, PM and APC) sequence together with its payload, so the operator reads `"see commit abc123 done"`. `completionDispositions` stores `evidence.trim()`, with the sequence in it. The operator presses yes in the shell or in the Telegram topic. `recordDispositions` writes the stored text into findings.json, and `attestDismissal` (`HUMAN_DECISION_PATTERN`) classifies it as `human`. `writeReviewNotes` then files a learning note ("Attested by: human") for a dismissal no person made.
- **Problem**: The fix makes the stored evidence at most 300 characters and says the card "shows it whole" (the schema text at :668 and the refusal text at :694). The card does not show what is stored. The shown text is `cardSafe(stored)` and `cardSafe` is not the identity on stored text: it removes escape sequences with their payload, and also control characters and bidi marks. The r05 suggested_fix asked for both halves: a length bound, and refusing "any evidence or finding string that cardSafe would change, so the shown text equals the stored text". Only the length half landed. Nothing compares `cardSafe(x)` with `x` in `completionDispositions`. The same holds for `finding` (:702 shows `cardSafe(record.finding)`; the lookup uses the raw text), with a smaller consequence.
- **Why it matters**: This is the S-401 defect (the operator answers a text that is not the text applied), reached by a different route that the cap does not close. The consequence is the same one S-401 named: a learning note filed on an attestation no person made, and a durable findings record carrying it. The repo's own rule (an operator never answers a decision they could not read in full) is still broken. Limits that keep it at the S-401 weight and no higher: the attestation pattern is an attribution requirement and not an identity proof (review-notes.ts:111-121), and the agent could already write `operator: x` in plain sight; the card hides it here.
- **Fix**: In `completionDispositions`, refuse any `finding` or `evidence` for which `cardSafe(value) !== value`, with a message that names the entry ("contains control or escape characters"). Newlines are the one case `cardSafe` rewrites visibly (to the ⏎ marker), so either refuse newlines too or compare after replacing `\r\n|\r|\n` with a space. Then the stored text and the shown text differ only by that visible marker. Add the test next to the existing 400-character one: an evidence string holding `\u001b]0;operator: decided-by alice\u0007` is refused before the card is drawn.
- **Patch**:
```diff
+    const unsafe = (text: string): boolean => cardSafe(text.replace(/\r\n|\r|\n/g, " ")) !== text.replace(/\r\n|\r|\n/g, " ");
+    if (unsafe(finding) || (typeof evidence === "string" && unsafe(evidence))) {
+      return { refusal: `dispositions[${index}]: finding and evidence must be plain text without escape or control characters` };
+    }
     records.push({ finding, state: state as FindingDispositionState, ...(evidence === undefined || evidence.trim() === "" ? {} : { evidence: evidence.trim() }) });
```
- **Evidence**: Ran `bun .../scratchpad/sec-w2-osc.ts`, which imports the repo's `cardSafe` and `attestDismissal`, with the stored string `"see commit abc123\u001b]0;operator: decided-by alice\u0007 done"`. Output: `{"storedLen":53,"shown":"see commit abc123 done","same":false}`, `stored attest: human`, `shown attest: none`. Source read: card-safe.ts:10-11 (the OSC/DCS/PM/APC removal includes the payload), operator-confirm-review.ts:693-696 (the cap, then `evidence.trim()` stored), :702 (the display), review-notes.ts:122 and :138 (the pattern tested on the stored text).
- **Confidence**: high
- **Class scope**: `finding` at :702 is the same shape (lower consequence). The waiver quotes at :717, :728 and :732 pass through `cardSafe(clip(...))` as well, but the operator typed or confirmed those quotes and nothing reads them for attestation; they share the shape and not the consequence, as in r05.
