### Summary
The SQL rewrite of `attachBadges` matches `localBadge` exactly. Its `supersedes` flag (an active run, a run requested for the card's range, or a finished run whose reviewed range is the card's range) is the same condition under which `localBadge` drops `stale` (`latest || ready`). Each run is parsed once in `scoped`, and the outdated candidate needs both reviewed SHAs. The UI fixes for F-002, F-003 and F-007 are correct. One new defect: the F-008 fix makes the tab indicator use a stale carried set. Changes that receipts or polling make after a load are no longer kept across a scope switch. An already-read reply lights the indicator again in a Merged- or Closed-only view.
