### Logic Bugs

### [F-001] The board card's "View review result" for a superseded, never-started run sends the PR to a Reviews list that does not hold it (sibling of degradation-w2 F-001)
- **Severity**: minor
- **File**: apps/desktop/src/review/ReviewBoard.tsx:458-462 (behaviour pinned by slice-04 ReviewBoard.dom.test.tsx:85-105), with src/review/board-badges.ts:32-49
- **Problem**: `localBadge` filters out only `existing`, archived and deleted runs. It does not filter a queued request that was superseded before it started (state `skipped`, phase `Superseded`). The head Reviews list does drop those rows (desk-run-store.ts:606 `NOT ${neverStarted("r.")}`). Suppose such a request is the only remaining run on the card's current range, for example after the run that superseded it on the same range finished and was deleted. Then `latest` is that request and `runState` is `"skipped"`. The card's action reads "View review result" (ReviewResults.tsx:36), and `openReview` classifies it as `kind: "view"` (ReviewBoard.tsx:458). In this delta, a view intent no longer opens the PR panel; it goes to `onOpenInReviews` (:462). The Reviews tab re-reads once and shows "Pull request #N has no Keryx review in this list." (ReviewsView.tsx:244-249).
- **Why it matters**: degradation-w2 F-001 reported the same dead end on the PR panel's "Open in Reviews". It called the issue mild because "the board card's own review action still starts a review through the start intent". In this state that does not hold. Both PR-tab entry points lead to the dead end, the PR panel no longer offers Start (hasReview is true), and the Reviews tab does not list the Review. A new review for that revision cannot be started from the Desktop until the PR head moves. The trigger is rare: it needs a same-range supersede followed by deleting the superseding run.
- **Fix**: Apply the fix suggested for degradation-w2 F-001 (one shared never-started predicate) to `localBadge` as well. Drop runs that are `skipped` with phase `Superseded` and never started (no `startedAt`, no result) before choosing `latest`, as reviewRows does. Add a board DOM case whose only run is such a request and assert that the card offers "Run review" and starts in the PR panel.
- **Evidence**: code-trace. board-badges.ts:32 (filter), :37 (latest = same-range run), :49 (runState); ReviewResults.tsx:34-36 (label from runState); ReviewBoard.tsx:458-462 (kind "view" routed to Reviews); desk-run-store.ts:26-27 (neverStarted), :606 (reviewRows excludes it), :722-729 (a same-range manual start supersedes a queued request with other options); desk-run-lifecycle.ts:36-44 (delete is allowed on a finished run). I did not check that the superseded request's row actually reaches the badge SQL path (readLocalBadges / attachDeskRunBadges). The JS `localBadge` is stated to share its rules with SQL (board-badges.ts:30), but I did not read the SQL projection.
