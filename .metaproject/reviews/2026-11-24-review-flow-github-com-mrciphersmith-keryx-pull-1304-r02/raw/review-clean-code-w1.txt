### Findings

#### Functions
##### [F-003] `compareHeads` takes four positional parameters, one of them an output argument; `readCards` appends to its caller's snapshot
- **Severity**: minor
- **File**: src/commands/review-reviews.ts (`async function compareHeads(pairs: Pair[], compare: CompareHeads, budgetMs: number, warnings: string[])`; also `readCards`, `if (unreadable) snapshot.warnings.push(...)`)
- **Principle**: Clean Code: function design (Thresholds: positional parameters, and output argument)
- **Problem**: Both helpers are new in this delta, extracted from `readReviews`. `compareHeads` has 4 positional parameters and no options object, and it reports failure by pushing into the caller's `warnings` array. `readCards` takes the whole `snapshot` and mutates `snapshot.warnings`. The return value therefore does not say what the function did. A caller who passes a fresh array, or reuses the helper elsewhere, gets warnings in an unexpected place.
- **Fix**: Return the warning instead of filling an argument, for example `compareHeads(pairs, { compare, budgetMs }) → { comparisons, warnings }` and `readCards(...) → { cards, unreadable }`. Then `readReviews` is the only place that pushes onto `snapshot.warnings`.

#### Comments
##### [F-001] `headComparison` says it is "the one rule" for `freshness`, but `summarizeReview` does not use it and the two disagree for closed Reviews
- **Severity**: minor
- **File**: src/review/review-entity.ts: the `headComparison` doc comment (`The one rule for the command's comparisons and for \`freshness\`.`) and `summarizeReview`'s `freshness: freshness(referenceHead(row), card?.headSha ?? null, compare)`
- **Principle**: Clean Code: comments (a comment that asserts a code path that does not exist); DRY. This is also the leftover part of round-1 F-015.
- **Problem**: `headComparison` returns null for a closed Review (`!reviewClosed(row, card)`), so such a Review is never compared. `summarizeReview` does not call `headComparison`. It calls `freshness(referenceHead(row), card.headSha, compare)`, which has no closed check. So a Review that is closed locally, or whose PR is merged or closed with a head that differs from the reviewed one, is reported as `behind` with `commits: null`, while `headComparison` says there is nothing to compare. The rule still lives in two places, which F-015 asked to remove. The test "summarizeReview reports behind exactly when a comparison is needed" uses only open cards, so it does not catch the difference. Impact: in the closed lane and list (including archived Reviews under Show closed), the card shows "behind" with no count and no warning, and the comment tells a maintainer this cannot happen.
- **Fix**: Make `summarizeReview` derive freshness from the same helper, e.g. `const pair = headComparison(row, card); freshness: !card?.headSha ? {kind:"unknown"} : pair ? behind(compare) : {kind:"current"}`, and add a closed-card case to the "summarizeReview reports behind exactly when…" test. If closed Reviews are meant to keep showing `behind`, narrow the comment to "the rule for the command's comparisons" instead.

##### [F-002] The `reviewState` doc still says the state comes from the latest attempt
- **Severity**: minor
- **File**: src/review/review-entity.ts: `/** The state of a Review, derived from its latest attempt. */` above `export function reviewState(latest: ReviewAttemptSummary, closed: boolean)`
- **Principle**: Clean Code: comments (a doc describing the rule a later change replaced)
- **Problem**: The F-010 fix changed the caller to `state: reviewState(settled, reviewClosed(row, card))`. Here `settled = stateAttempt(attempts)` is an earlier finished attempt of the same round when the latest one stopped, and archived attempts are excluded. The doc and the parameter still describe "the latest attempt", so a reader of `reviewState` alone would expect a failed retry to make the Review `stopped`. That is the behaviour F-010 removed.
- **Fix**: Reword it as "derived from the attempt `stateAttempt` selects: the latest unarchived attempt, or the accepted result of its round when the latest stopped". The parameter name is review-style's call.
