##### [F-001] `board_read_args` takes a new boolean flag (`include_closed`), its ninth positional parameter, so call sites read `…, None, None, true, true)`
- **Severity**: minor
- **File**: apps/desktop/src-tauri/src/review.rs:51 (signature), :156 (the `review_board` call), :679–700 (the test call sites)
- **Principle**: Clean Code: function design. Thresholds rows: Boolean flag parameter (any) and Positional parameters (4 or more, no options object).
- **Problem**: This delta adds `include_closed: bool` after `reviews_only: bool`. Both flags select behaviour. `reviews_only` switches to a different command (`review reviews`). `include_closed` either refuses the request or appends `--include-closed`. The function now has 9 positional parameters, 4 of them `bool`, and `#[allow(clippy::too_many_arguments)]` suppresses the lint. The new test lines show the cost: `board_read_args(None, None, None, false, false, None, None, false, true)` and `board_read_args(None, None, None, true, false, None, None, false, true)`. Only the position tells `repositories_only`, `paged`, `reviews_only` and `include_closed` apart, and a swapped pair still compiles. The 8-parameter signature was already over the Positional row before this delta, so that part is old debt. The new behaviour-selecting flag is this change's.
- **Fix**: Split the Reviews list out of `board_read_args`, as the dev bridge already does with `reviewsArgs`. Add `fn reviews_read_args(repo: Option<&str>, include_closed: bool)`, used by `review_board` when `reviews_only`. Put the refusal of board modes in `review_board`, or pass a small struct. Then `board_read_args` loses both flags. Alternatively, use one `#[derive(Default)] struct BoardRead { … }`, so tests write `BoardRead { reviews_only: true, include_closed: true, ..Default::default() }`.
- **Class scope**: sites are review.rs:51 (definition), :156 (only production caller), and 20 test calls at :679–700 (`keryx ctx rg 'board_read_args\(' apps/desktop/src-tauri/src/review.rs`: 20 matches). The dev counterpart `apps/desktop/dev/reviewBoard.ts` already takes an args object, so it has no such site.

##### [F-002] `FRESHNESS_LABEL` is defined in the view, while its sibling label maps live in the model; the state and source selects keep their empty-option text twice
- **Severity**: info
- **File**: apps/desktop/src/reviews/ReviewsView.tsx: `const FRESHNESS_LABEL: Record<ReviewFilters["freshness"], string> = { "": "Any freshness", … }` and the `title={filters.state ? STATE_LABEL[filters.state] : "All states"}` / `title={filters.source ? SOURCE_LABEL[filters.source] : "Any source"}` lines
- **Principle**: Clean Code: cohesion. A stylistic opinion, so `info`.
- **Problem**: The delta adds a freshness label map in the component, but `STATE_LABEL` and `SOURCE_LABEL` live in `reviews/model.ts`. The three filter selects now follow two patterns. Freshness draws both its options and its `title` from one map, which includes the `""` key. State and source repeat "All states" and "Any source" in the `<option>` and in the new `title`. That is 2 copies each, under the threshold.
- **Fix**: Optional. Move `FRESHNESS_LABEL` to model.ts next to the other maps, and give state and source the same `""`-keyed treatment, or a shared `filterTitle` helper.
