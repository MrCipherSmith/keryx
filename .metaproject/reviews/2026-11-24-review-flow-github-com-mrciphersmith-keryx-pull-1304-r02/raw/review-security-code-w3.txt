### What was checked
- Path and argument injection into `gh api` in review-reviews.ts:133-134. The path is `repos/${repo}/compare/${base}...${head}?per_page=1`, built from three values:
  - `repo` comes from `selectRepository`, which is an exact-match lookup (case-insensitive) in the project's own git remotes (`reviewRepositories` runs `git remote -v`). A `--repo` value that is not one of the project's repositories is refused with a `configuration:` error. In the bridge path, `--repo` is option-guarded in both hosts (wave 2).
  - `base` and `head` reach `compare` only after `OBJECT_ID = /^[0-9a-f]{40}$/` checks both values of the pair (line 58). A `..`, `?`, `/` or `-` cannot enter the path or argv from the stored head or from GitHub's `headRefOid`.
  - The args go to `gh` as an argv vector, never through a shell.
- Parsing GitHub's response: `--jq "{status, ahead_by}"` cuts the comparison down in gh. `parseCompare` then accepts only the four known statuses and a non-negative safe integer, and throws `unavailable:` on anything else. A malformed or hostile body cannot put arbitrary data into the snapshot.
- Authz and cross-account isolation:
  - `readReviews` takes `viewer` and `repositoryId` from the GitHub identity query, never from CLI input. `readReviewRows(repositoryId, viewer, root)` is scoped by that key, so a caller cannot list another account's local Reviews.
  - An unidentified account or repository is refused with `access:` (tested).
  - `access:` and `configuration:` errors from card reads are rethrown instead of being turned into warnings (`cannotRetainData`).
  - `writeBoundJson` checks the GitHub binding again at the output boundary, so a binding change during the read does not publish the previous account's data.
- Data exposure: the output carries summaries only. The test checks that `"private report body"` and `reviewerProgress` are absent from the JSON. The `--include-closed` mode reads only PR numbers already in the viewer's local store.
- DoS bounds: compares are capped at 25 per call (`MAX_REVIEW_COMPARES`), with 4 in parallel and a 60 s overall deadline. Card reads go in batches of 20, 3 in parallel. `parseArgs` is strict, and unknown flags are refused (tested).
- Bridge refusal tests (reviewPages.test.ts) pin that `reviewsOnly` is refused together with every other board mode, and that a `--other` repo is refused ("Invalid repository").
- Desktop tests and fixtures: the `<script>` strings in report and finalOutput fixtures are test inputs that are expected to render as text. There is no dangerouslySetInnerHTML, eval, storage of secrets or credential material in the slice. The "Previous account secret rule" test pins that a pending rules response for the previous account is not shown.
- Docs: no secrets, tokens or personal data. Paths are generic.
- Not applicable to this slice: crypto, CSRF, file-system path traversal (the store root is `deskRunRoot()` or a test temp dir, never CLI input), open redirect, NestJS patterns.
