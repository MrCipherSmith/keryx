### Checked and clean
- SQL injection (desk-run-store.ts): the new `neverStarted(r)` helper interpolates only the compile-time alias literals `""` and `"r."`. `placement(alias)` interpolates column names or `NULL` from the constant `reviewColumns`. Every value (repo, pr, viewer, ids, SHAs) still binds through `?` parameters in `reviewRows`, `assignReviews` and `previousAttempt`. The test-only `editStore` helper also binds its parameters.
- Path traversal (`publication()`): files are still read only under `directory(id)`, and only after `id` matches the UUID regex. The relaxed gate, which now admits partial and budget attempts, did not weaken that check. `transcriptUpdatedAt` keeps its own UUID check and lstat checks.
- Authorization / IDOR: `reviewRows` now returns archived attempts, but the query is still filtered by `v.repo=?` and `v.viewer=?` and receives the GitHub-verified repositoryId and viewer, so archived attempts of another account or repository stay out of reach. Deleted attempts are still excluded. Imported (`existing`) and archived attempts are never offered for publication. Reports and reviewer sessions are still not selected, and the test asserts `private report body` is absent from the payload.
- Publication boundary: `writeBoundJson` re-checks the GitHub binding generation inside `withCurrentGithubBinding` before stdout is written. A throw inside the Promise executor rejects the promise. This was already cleared in wave 6 and is unchanged here.
- Tauri argument building (review.rs): `include_closed` is a bool that adds only the fixed literal `--include-closed`, and only in the Reviews-list branch. Otherwise the call is refused. No user string reaches argv through it. Tests cover the refused combinations.
- Desktop link handling (ReviewDetail.tsx): `followLink` now opens through `openReviewLink`, after `reviewUrl` accepts only `https:` URLs without username or password. A pull request URL goes to `openPullRequest`, any other URL to `openExternal`, and `preventDefault` stops in-app navigation. No `javascript:` or `file:` URL can reach the opener.
- Removed test "a rules dialog pending for a previous account cannot expose that account's rules" (ReviewBoard.dom.test.tsx): the behaviour moved with the rules UI to the Reviews tab. Wave 6 (raw/review-security-code-w6.txt) recorded the equivalent assertion in ReviewsView.dom.test.tsx, so cross-account leak coverage is not lost.
- XSS / eval: no `dangerouslySetInnerHTML`, `eval` or `new Function` added. Removed code (`secondaryNote`, `reviewNote` in laneReason, the PR-panel review tab) has no security role.
- Secrets / PII: fixtures use placeholder logins and repeated-character SHAs. No tokens appear in docs, tests or the changed code.
- Not applicable in these slices: crypto, CSRF, open redirect, NestJS.
