### Findings
No new findings in these slices.

Checked and clean:
- `assignReviews` (desk-run-store.ts:184-204). The old SQL `roundFor` ran up to four queries per pending row: linked, retry, max(round), and newest per round. Now each Review's placed attempts are read once per call (`WHERE review_id=? AND round IS NOT NULL`, covered by the `review_rounds` index) and extended in memory. Each placement is O(k) over that Review's attempts, so O(k^2) per Review at worst. k is the number of attempts on one PR for one account, which is small. The loop runs only when unassigned rows exist: on migration and inside the request/record transaction for the newly inserted row. This is a cost reduction, not a regression. `reviewFor` still makes one indexed lookup per pending row. That predates this delta.
- `neverStarted()` adds five `json_extract` predicates to the `reviewRows` WHERE clause and to the `assignReviews` projections. These run per row of one account's Reviews in one repository, in a CLI call. There is no hot path and no new scan shape: `previousAttempt` already used this predicate inline.
- review-entity.ts: `stateAttempts` (a filter), `stateAttempt` and `newest` (reverse scans) and `headComparison` are each O(attempts) per Review per summary. `referenceHead` re-runs `stateAttempts` inside `summarizeReview`, which is a second O(k) pass on small k. That is not worth filing.
- `writeBoundJson`/`writeBoundJsonText` (board-github.ts:262-272) moved from review-board.ts with the same behaviour. review-performance-w3 already confirmed that. The payload is serialized once.
- slice-06 Desktop changes only remove code: imports, a props pass-through, the rules dialog mount in the toolbar, a tab and its panel. Nothing is added per render or per keystroke. Unmounting `ProjectReviewRules` from the board toolbar removes a component and its rules load from the Pull requests tab.
