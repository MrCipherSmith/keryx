### Logic Bugs
None detected. These were checked and are sound:
- `roundFor`: `linked` is looked up before superseded rows are filtered out, so a continuation keeps its predecessor's round. `previous` is the newest counted attempt of the top round. Ties are broken by `seq`, and a null `created` compares as "".
- In one `assignReviews` call, a row placed earlier in that call carries its `superseded` flag from the pending query. Nothing changes that flag inside the transaction.
- `requestAttempt` calls `end(queued, {state:'skipped', phase:'Superseded', result:null})` before the INSERT. So `neverStarted` is already true for the old row when the new row is placed. This matches the test "a queued request superseded before it started keeps no round".
- `stateAttempt` and `reference` agree. When `settled` is an accepted result, it is the newest accepted result in the latest round, and that is also `newest(attempts, reviewedResult)`. The only exception is imported history placed after newer rounds, a documented known limitation.

### Async & Concurrency
See [F-001] (info).

#### [F-001] `writeBoundJsonText` says concurrent writers stay excluded until the payload reaches the pipe; the binding transaction commits as soon as `write()` returns
- **Severity**: info
- **File**: src/review/board-github.ts:262-272 (moved verbatim from src/commands/review-board.ts, FA-6)
- **Problem**: `withCurrentGithubBinding` runs `watcherTransaction`, which is synchronous (bun:sqlite, src/review/watcher-db.ts:6). The callback only calls `process.stdout.write(json + "\n", cb)` and returns. The transaction commits right then, while the promise resolves later in the write callback. A payload larger than the pipe buffer is still being flushed after the commit. So a binding change in that window is not excluded, contrary to the comment "Concurrent writers stay excluded until the complete payload is handed to the pipe". The binding check itself is correct when the write is queued.
- **Why it matters**: nothing observable on a named input. The payload was read and checked under a binding that was current when it was queued. This is a comment that overstates a guarantee. The text predates this round; FA-6 only moved it, which is why it falls in the delta.
- **Fix**: describe what the code guarantees, for example: "The binding is checked again at this publication boundary, while the payload is queued. The promise settles once the stream has flushed it." Or drop the exclusion sentence.
