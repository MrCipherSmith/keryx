## Findings

### [F-001] Archived attempts now sit in the Rounds timeline unmarked, and the round number shown comes from a different set than the timeline
- Severity: minor
- Class: behaviour-delta
- Evidence kind: base-diff
- File: src/review/review-entity.ts (`rounds: roundsOf(row.attempts),`), apps/desktop/src/reviews/ReviewPanel.tsx (Attempt)
- Problem: On base, reviewRows dropped archived attempts (`NOT IN ('archive','delete')`), so the rounds, `latestRound` and the reviewed-commit fallback all came from the same visible set. On head (FA-4), reviewRows keeps archived attempts flagged and `summarizeReview` builds `rounds` from all attempts (`roundsOf(row.attempts)`) while `latestRound`, state, findings and `reviewed` come from `stateAttempts` (unarchived only). Desktop's `Attempt` row in the Rounds timeline renders state, coverage, time, run id and "after" but never `attempt.archived`. So when the viewer archives the newest attempt (for example a bad round 3), the panel header reads "Round 2" while the timeline's top entry is "Round 3" showing that attempt as "Completed", with nothing saying it was archived. `reviewedCommit`'s fallback (`review.rounds[0]?.headSha`, used when no unarchived attempt finished with a result) can also come from the archived round while freshness is measured from the unarchived attempt's head.
- Why it matters: The timeline shows an attempt the viewer removed as a normal one, and the panel shows two different "current" rounds. No data is lost.
- Fix: Mark archived attempts in `Attempt` (for example an "Archived" label, and leave them out of the "after" link targets or mark them too). Either take `reviewedCommit`'s fallback from the unarchived attempts, or have the summary carry it. Add a ReviewPanel DOM test with an archived newest attempt.
- Evidence: base-diff. Base desk-run-store.ts reviewRows WHERE `... NOT IN ('archive','delete')`. Head `...!='delete' AND NOT ${neverStarted("r.")}`. Head review-entity.ts summarizeReview: `rounds: roundsOf(row.attempts)` next to `latestRound: latest.round` with `latest = stateAttempts(row)[last]`. ReviewPanel.tsx Attempt has no `archived` branch; model.ts reviewedCommit is `review.reviewed?.headSha ?? review.rounds[0]?.headSha`. Refute attempt: the CLI doc now says "Archived attempts stay in the rounds with `archived: true`", so archived attempts in the rounds are intended. That intent does not cover Desktop rendering them with no marker. ReviewRunHistory (the panel's History) is a separate list and does not label the Rounds timeline.

### [F-002] Reviews whose attempts are all archived, hidden by default, now cost PR card reads and take comparison slots
- Severity: minor
- Class: performance
- Evidence kind: base-diff
- File: src/commands/review-reviews.ts (`const cards = await readCards(snapshot, includeClosed ? rows : rows.filter(row => row.closedAt === null), query);`)
- Problem: On base, a Review whose attempts were all archived was not in `rows`: reviewRows dropped archived attempts and "a Review with no other attempt". So it cost no card read and no compare. On head it is listed (`archived: true`). `readCards` skips only `closedAt !== null` rows (the FA-7 skip), and `headComparison` excludes only `reviewClosed` (closedAt, or a merged or closed card), not archived Reviews. An archived Review whose head moved therefore takes one of the 25 compare slots, in activity order, on every call. Yet Desktop lists it only under Show closed (`isClosedOrArchived`) and puts it in the Closed column, where the commit count serves no purpose. With more than 25 Reviews behind, a visible Review can lose its count to a hidden archived one, and the warning "Commit counts are shown for 25 Reviews…" appears.
- Why it matters: Extra GitHub calls on every list read, including the reads the watcher poll, session events and the 60 s timer now trigger. Visible Reviews can lose counts. This is the sibling the FA-7 local-close skip missed.
- Fix: Treat an all-archived Review like a locally closed one: skip its card read and comparison unless `includeClosed`, or exclude `row.attempts.every(a => a.archived)` in `headComparison`. Add a fixture with an archived Review behind.
- Evidence: base-diff and consumer-trace. Base reviewRows WHERE and docstring "so is a Review with no other attempt". Head review-reviews.ts readCards filter `row.closedAt === null`. Head review-entity.ts `headComparison` ends with `&& !reviewClosed(row, card)`, and `reviewClosed` reads only `closedAt` and `card.state`. Desktop model.ts `isClosedOrArchived` and `reviewColumn` send archived Reviews to the Closed column. Refute attempt: the CLI doc and fix-round-1 FA-7 name only local `closedAt` for the skip. No comment or test says archived Reviews must be compared. The test "a Review whose attempts are all archived is listed as archived" checks state only.

### [F-003] Toggling "Show closed" now re-reads the whole Reviews list from GitHub
- Severity: minor
- Class: performance
- Evidence kind: base-diff
- File: apps/desktop/src/reviews/ReviewsView.tsx (`void load(cwd, repo, expectedViewer, showClosed).then(snapshot => {`)
- Problem: On base, `showClosed` only filtered the loaded snapshot (`filterReviewList`). On head it is a dependency of the load effect and is passed as `includeClosed`, and `fetchReviews` keys its read on it. ReviewReadLane only de-duplicates reads in flight; it caches nothing. So every toggle, on or off, runs `keryx review reviews` again: an identity query, ceil(n/20) card batches and up to 25 compares. The same dependency also re-reads in two more cases. `resetView()` sets `showClosed` to false. In `accessLost` that starts a new read right after an access failure while Show closed was on. On an identity change within the same key, it adds a second read straight after the one that just succeeded.
- Why it matters: A filter toggle now costs a full GitHub round trip, and an access failure triggers an automatic retry the access-lost path is meant to avoid ("a later Try again must not act on it").
- Fix: Keep the closed Reviews' cards out of the main read only when they are hidden, but do not re-read on every toggle. For example, read with `includeClosed` once when Show closed is first turned on and keep that snapshot when it is turned off. In any case, do not let `resetView`/`accessLost` change a load dependency: reset `showClosed` without re-running the read, or keep `includeClosed` in a ref read by the effect.
- Evidence: base-diff and consumer-trace. Base ReviewsView load effect deps `[cwd, repo, expectedViewer, attempt, load, resetView, accessLost]`. Head adds `showClosed` and calls `load(cwd, repo, expectedViewer, showClosed)`. platform/review.ts fetchReviews key `[cwd, expectedViewer, repo, includeClosed]`. reviewReadLane.ts has no result cache (the `active` map is cleared in `finally`). ReviewsView `resetView` calls `setShowClosed(false)`, and `accessLost` calls `resetView()`. Refute attempt: the test "closed Reviews' PR cards are read only while Show closed is on" pins the opt-in, not its cost. fix-round-1 FA-7 asks only to skip locally closed Reviews' cards and names no re-read on toggle.
