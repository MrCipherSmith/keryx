## Minor & Info

### [R2-BE-W4-001] The `Pending` row type says it has `round: number`, but the query that fills it selects no `round`
- **Severity**: minor
- **File**: src/review/desk-run-store.ts:184
- **Problem**: `type Pending = PlacedAttempt & { repo; pr; viewer; previousId }` inherits `round: number` from `PlacedAttempt`. The `SELECT rowid AS seq, id, repo, pr, viewer, created, base, head, previousId, superseded ... WHERE review_id IS NULL` that fills it returns no `round`, so every `row.round` is `undefined` at runtime while its type says `number`. The code works today only because `roundFor` never reads `run.round`, and `attempts.push({ ...row, round })` overwrites the field.
- **Why it matters**: The type allows `row.round` to be read on a pending row and promises a number. A later change that passes `row` where a placed attempt is expected, for example to `placed.find` or to a sort by round, would compile and then get `undefined`.
- **Fix**: Type the pending row without `round`, for example `type Pending = Omit<PlacedAttempt, "round"> & {...}`, and build the placed entry explicitly as `{ ...row, round }`. That already matches `PlacedAttempt`.
