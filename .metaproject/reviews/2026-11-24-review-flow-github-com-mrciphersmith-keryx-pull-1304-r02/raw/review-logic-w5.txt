### Logic Bugs
None detected.

Checked and sound:
- `roundFor`, desk-run-store.ts:106-117. A continuation joins its linked round. `counted` drops superseded rows, so a request that supersedes a queued one takes that round (FA-11). The retry check is limited to the top round (D-R1). For a retry, `previous` is the newest counted attempt of the top round by (createdAt, rowid), which matches the old SQL ordering. `assignReviews` pushes each placed row into the per-Review cache, so several pending rows of one Review placed in one call (migration, multi-package import) see each other.
- `stateAttempt` / `reviewState`. Continuations only start from the latest admission (`continuationSource`), and rounds only grow with insertion time, apart from the FA-17 case. So the "accepted result in the latest round" is also the newest reviewed attempt overall. The state (`settled`) and `findings`/`publication` (`reference`) therefore come from the same attempt when both exist.
- `publication()` widened to all finished states. `localBadge` and `SessionReviewActivity` still act only on `"pending"`, which still requires completed+complete. In `ReviewRuns.tsx:103-171`, a partial run with a receipt now shows "View publication" instead of "Publish to GitHub", which is the intended fix.

### Edge Cases

#### [F-001] A queued request cancelled before dispatch still counts as an attempt: it opens a round and turns the Review "stopped"
- Severity: info
- File: src/review/desk-run-store.ts:26-29 (`neverStarted`), :776-780 (`cancel` of a queued run)
- Problem: FA-11 drops only a request superseded before it started (`state='skipped'`, `phase='Superseded'`). Cancelling a queued request also leaves an attempt that never started and spent nothing (`state='cancelled'`, `phase='Cancelled'`, `startedAt` null). But it stays in `counted` and in `reviewRows`. Scenario: round 2 has a completed, reviewed attempt on H2. The viewer queues H3 behind a running run, then cancels the queued H3. The cancelled request opens round 3. `stateAttempt` finds no accepted result in round 3, so the Review reads `stopped`, and `reviewNeedsViewer` lights the "waiting on you" indicator for a request the viewer just withdrew.
- Why it matters: the specification table maps cancellations to `stopped`, so this may be intended. It is filed so the operator can decide whether a cancel before dispatch should be treated like a supersede (no round, not listed). No change is requested if the current table stands.
- Fix (if wanted): widen `neverStarted` to `state IN ('skipped','cancelled') AND phase IN ('Superseded','Cancelled') AND startedAt IS NULL AND result IS NULL AND usage IS NULL`, and add a fixture next to desk-run-store.test.ts:979.
