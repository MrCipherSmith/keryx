### [F-001] Closed Review panel stays open after "Show closed" is turned off and blames GitHub for the missing card
- **Severity**: minor
- **File**: apps/desktop/src/reviews/ReviewsView.tsx:308 (toggle), :162 (selection kept), ReviewPanel.tsx:137-141 (banner)
- **Rule**: canonical rubric (view state consistency / misleading state). No Parts A-C row covers it.
- **Problem**: This delta stops reading PR cards for locally closed Reviews unless `--include-closed` is passed (readCards, `includeClosed ? rows : rows.filter(row => row.closedAt === null)`). The Reviews tab passes `showClosed` as that flag. Turning "Show closed" off re-reads the list. The load effect then keeps the selection because the closed Review is still in `snapshot.reviews` (`setSelected(current => current && snapshot.reviews.some(...) ? current : null)`), and nothing closes a selected closed or archived Review when the toggle turns off. The panel stays open on a Review the list now hides, and its card is now `null`. ReviewPanel renders the fallback "GitHub did not return this pull request, so its current range is unknown. Refresh the Reviews list to try again." with a Refresh button. Refresh cannot help, because the card is skipped on purpose. The same banner also flashes on the focus path: for a closed Review, the code calls `setShowClosed(true)` and `setSelected` together, so the panel opens on the old card-less snapshot until the includeClosed re-read lands.
- **Why it matters**: The panel names the wrong cause and offers a remedy that does nothing. The user is left with a panel for a Review that is no longer in the list.
- **Fix**: When `showClosed` turns false, drop a selection that `isClosedOrArchived`, for example in the toggle handler: `setShowClosed(v => { if (v) setSelected(s => s && !snapshot?.reviews.some(r => r.id === s.id && isClosedOrArchived(r)) ? s : null); return !v; })`. Also let the panel tell the two cases apart: for `review.state === "closed" && !review.card`, show "Turn on Show closed to load this pull request" instead of the GitHub-failure text. Add a DOM test: open a closed Review under Show closed, turn Show closed off, and expect the panel to close.

### [F-002] Watcher-poll reload of the Reviews list is not visibility-gated (sibling of round-1 F-011)
- **Severity**: info
- **File**: apps/desktop/src/reviews/ReviewsView.tsx:199-204
- **Problem**: The fix gated the running-Review interval on `document.visibilityState !== "hidden"` (:194), with the stated intent that "a hidden window reads for nobody". The new `reloadSignal` path calls `refresh()` on every completed PR-watcher poll with no such check. Each refresh runs one `keryx review reviews` read: an identity query, card batches and up to 25 compares. ReviewWatcher reads status every 60 s without a visibility check (ReviewWatcher.tsx:75) and signals whenever `lastSuccessAt` advances.
- **Why it matters**: No concrete bug; this costs GitHub budget in a minimized window. It matches the Pull requests board, which already refreshes on the same signal, so the cost is at most doubled, not new.
- **Fix**: Optional. Skip the refresh while hidden and refresh once on `visibilitychange` to visible, or record a "dirty" flag and refresh when the window becomes visible.

### [F-003] Review rules fallback accepts the board's repository when the Reviews tab is on its default repository
- **Severity**: info
- **File**: apps/desktop/src/reviews/ReviewsView.tsx:274-276
- **Problem**: When the list read fails, `rulesTarget` falls back to the board identity if `(!repo || boardRules.repo === repo)`. With `repo` undefined (the tab is on its default repository), any board repository passes. In a multi-repository project, a board switched to repository B therefore supplies B's rules dialog while the Reviews tab is meant to show the default repository.
- **Why it matters**: The dialog edits rules for the repository it names, so the risk is low. It only applies when the list read has failed. Recorded so the choice is deliberate.
- **Fix**: Optional. Accept the board identity only when it is the board's default repository, or pass the board's `repositories[0]` and compare against it.
