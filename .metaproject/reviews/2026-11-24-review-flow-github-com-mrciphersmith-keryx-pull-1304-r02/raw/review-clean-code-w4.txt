#### Comments

### [F-001] `ReviewAttemptSummary.archived` says an archived attempt is never the state source; for a fully archived Review it is

- **Severity**: minor
- **File**: src/review/review-entity.ts:35
- **Principle**: Clean Code — comments (two places document one field in opposite ways)
- **Problem**: The field doc says an archived attempt is "never the attempt state, findings or publication come from". `stateAttempts` (review-entity.ts:131) returns every attempt when all of them are archived. `ReviewSummary.archived` (review-entity.ts:75) also says that such a Review takes its state from those attempts. The two field docs contradict each other, and the first one contradicts the code.
- **Fix**: Add the exception to line 35, for example "never the source of the Review's state, findings or publication while an unarchived attempt exists".

### [F-002] Two docs still say the Review's state comes from its latest/last attempt; `stateAttempt` now picks the round's accepted result

- **Severity**: minor
- **File**: src/review/review-entity.ts:75
- **Principle**: Clean Code — comments (doc describes the rule a later change replaced)
- **Problem**: `ReviewSummary.archived` says a fully archived Review's "state is its last attempt's". The test title at review-entity.test.ts:195 says the same. The fix routed the state through `stateAttempt` (review-entity.ts:141). When the last attempt stopped in a round that already holds a finished, reviewed result, `stateAttempt` returns that result's attempt instead. `reviewState`'s doc ("derived from its latest attempt", review-entity.ts:98) also predates this. `summarizeReview` now passes it `settled`, which is not necessarily the latest attempt.
- **Fix**: Change both docs to say "the state comes from `stateAttempt`: the latest attempt, or the accepted result of its round when that attempt stopped", and update the test title to match.

#### DRY

### [F-003] The fix adds a fourth copy of the finished-run-state set; `runFinished` already exports it

- **Severity**: minor
- **File**: src/review/desk-run-store.ts:30
- **Principle**: Clean Code — DRY (duplicated domain rule, 3+ copies)
- **Problem**: The delta adds `FINISHED_STATES = new Set(["completed", "partial", "budget"])` to desk-run-store.ts, which `publication()` uses. The same domain rule ("this run finished with a result") already exists three times:
  - `runFinished` in src/review/board-badges.ts:15, exported from a module desk-run-store.ts already imports (line 6);
  - `FINISHED` in src/review/review-entity.ts:96;
  - the SQL `r.state IN ('completed','partial','budget') AS done` at src/review/desk-run-store.ts:513.

  Adding a finished state, or reclassifying `budget`, now means four edits. Missing one would make publication outcomes, Review state and board badges disagree about the same attempt.
- **Fix**: Use the existing `runFinished` in `publication()`, or export one `FINISHED_RUN_STATES` set beside `DeskRun`'s state type and derive the TS checks and the SQL literal from it. Then drop `FINISHED_STATES`.
