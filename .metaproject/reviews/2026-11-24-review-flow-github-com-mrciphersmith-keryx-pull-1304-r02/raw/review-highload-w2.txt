### [F-001] "Show closed" stays on while the tab is hidden, so every background refresh also reads the cards of all closed Reviews
- Severity: minor
- File: apps/desktop/src/reviews/ReviewsView.tsx:152 (`void load(cwd, repo, expectedViewer, showClosed)`), with :124 (`showClosed` state), :238 (a focus request turns it on) and :192-204 (background triggers). Backend: src/commands/review-reviews.ts:55.
- Pattern: Resource B / Retry-Timeout F2. Per-trigger work grows with stored history.
- Failure mode: `includeClosed` follows the toggle. `readReviews` then sends every row, closed ones included, to `readCards`: ceil(N/20) GraphQL batches, three at a time (review-reviews.ts:55, :70-72). The toggle is not cleared when the tab is left (`consumeIntent` clears only the intent). An "Open in Reviews" of a closed or archived Review also turns it on by itself (:238). From then on, until a repository or account change remounts the view, every background trigger reads all closed Reviews' cards:
  - the 60 s timer while any Review runs,
  - each PR watcher poll (`reloadSignal`),
  - each session-review event,
  - each panel mutation.
  None of these needs the cards: the tab indicator (`reviewNeedsViewer`) is about open work.
  - Trigger: Show closed is on, the tab is hidden, and a review is running or the watcher is polling. N is the count of locally closed Reviews for the account and repository. It only grows, because closing is how a Review leaves the default list.
  - Outcome: one extra GitHub batch per 20 closed Reviews on each background read, per project window. Under a GitHub stall, the card phase adds 18 s per 60 closed Reviews, so the 150 s host bound from wave-1 F-002 is reached at a smaller open-Review count. The host then kills the whole list read and the indicator stops updating. This is degradation, not data loss.
- Fix (either of these):
  - Read closed cards only when they are shown: pass `showClosed && active` to `load`, or drop `showClosed` when the tab is left, as is already done for the intent.
  - Have the CLI read closed rows' cards only for the first page or the visible slice.
  The overall deadline in wave-1 F-002 bounds the worst case either way.
- class_scope (optional for minor): one call site that passes the flag. `keryx ctx rg "includeClosed|include-closed"` over apps/desktop/src and src/commands/review-reviews.ts found fetchReviews (platform/review.ts:118), the ReviewsView load effect, and the CLI's readCards filter at :55.
- Confidence: medium. The arithmetic comes from the code, as in wave-1 F-002. The number of closed Reviews in real use is not known.
