### What was checked
- Argument and command injection on the new `reviews_only` bridge mode (review.rs `board_read_args`, dev/reviewBoard.ts `reviewsArgs`):
  - The args are passed as an argv vector, never through a shell.
  - `--repo` is refused when it is empty, starts with `-` (option injection) or contains whitespace.
  - `reviews_only` combined with pr_state, number, repositories_only, paged, cursor or badges is refused. `updated_since` is refused separately: review.rs line 147 now checks `reviews_only` too.
  - The dev mirror applies the same refusals.
- API path injection downstream of `--repo`: src/commands/review-reviews.ts:127 resolves the value through `selectRepository(repositories, values.repo)` against the project's own repository list before `repos/${repo}/compare/${base}...${head}` is built (line 134). Per the comment at line 18, only full object IDs reach the compare path. So a crafted repo such as `../../user` cannot reach `gh api`. This file belongs to the backend slices; I read only the grep hits.
- Open redirect and URL scheme (T17): ReviewPanel now hands `card.url` to `openReviewLink` through `ReviewBrowserLink`. `reviewUrl` admits only `https:` URLs without credentials, and anything else renders no link. GitHub PR URLs go to `openPullRequest`, everything else to `openExternal`. A `javascript:`, `file:` or custom-scheme URL from GitHub data never reaches the system opener.
- XSS: the new views (ReviewsView, ReviewPanel, ReviewWorkspace, ReviewResults title) render GitHub- and CLI-supplied strings as React text only: titles, warnings, SHAs, run ids, `previousRunId`, findings labels. There is no dangerouslySetInnerHTML, eval or `new Function`. `document.getElementById(attemptAnchor(scope, previous))` only focuses an element and injects nothing.
- Cross-account data mixing (authz in the client):
  - `fetchReviews` keeps `assertProtocol` and `verifyProjectViewer`.
  - ReviewsView is keyed by the bound viewer, and on any `access:` or `configuration:` error it drops its snapshot and selection (`accessLost`).
  - The Reviews tab indicator is bound to the viewer and hidden when GitHub is disconnected (App.tsx `reviewsIndicator`).
  - ReviewWorkspace keys its run subject by repositoryId, viewer, number and range.
- Run start still re-checks the range before `start`, and the backend re-validates it: RunLaunchDialog carries the same `sameRange` / `stale` / `state === "open"` guard that the removed ReviewDetail code had.
- Secrets and storage: no new localStorage or sessionStorage use. `rememberSessionReview` and `readSessionReviewLinks` predate this PR and are only called here. No tokens or credentials appear in the code or in error toasts.
- Crypto, CSRF, path traversal on the file system, NestJS patterns: not applicable to this slice.
