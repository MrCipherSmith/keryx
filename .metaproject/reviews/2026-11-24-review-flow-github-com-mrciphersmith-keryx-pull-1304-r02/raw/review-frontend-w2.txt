### Findings

### [FE2-001] The Review panel's "Open pull request" has no in-flight guard; the PR panel's link handler has one
- **Severity**: info
- **File**: apps/desktop/src/reviews/ReviewPanel.tsx (`openPullRequestLink`)
- **Rule**: canonical rubric (no row covers it): an observation with no concrete bug beyond a duplicate open
- **Problem**: T17 (8d95e651a) routes the header link through `onOpen={openPullRequestLink}`, and that function calls `openBrowser(url)` on every click and middle-click. The sibling handler in the PR panel, `ReviewDetail.followLink`, drops a second open while one is pending (`openingLink` ref, lines 128/156-161). This path has no such guard.
- **Why it matters**: a quick double-click opens the PR twice in the system browser. Nothing is corrupted. The two surfaces now share `openReviewLink` but behave differently on a repeated click.
- **Fix**: keep an `opening` ref in `ReviewPanel` (or in `ReviewBrowserLink` when `onOpen` is passed), as `followLink` does. Optional.
