### Logic Bugs

#### [F-001] `resetView()` now starts a list read when "Show closed" was on, including right after access was lost
- Severity: minor
- File: apps/desktop/src/reviews/ReviewsView.tsx:131-146, :148-175
- Problem: The delta adds `showClosed` to the load effect's dependencies (`load(cwd, repo, expectedViewer, showClosed)`, deps `[cwd, repo, expectedViewer, showClosed, attempt, ...]`). `resetView()` sets `showClosed` to false, and two paths call it:
  - (a) `accessLost`. It is meant to stop reading: it bumps `sequence`, settles the pending focus, and leaves `snapshot: null` with the error until the user presses Try again ("a later Try again must not act on it"). If Show closed was on, the `showClosed` change re-runs the effect at once and starts a new read without the user doing anything.
  - (b) The identity-change branch inside `.then`. It applies the new snapshot and then, because `showClosed` flipped, reads the whole list a second time.
- Why it matters: For (a), take a panel or rules command that reports `access:` or `configuration:` through `onAccessLost` (ReviewPanel, ProjectReviewRules) while the list read itself still succeeds. With Show closed on, the access-lost banner is replaced by a fresh list within one read. With Show closed off, it stays until Try again. So the same signal behaves differently depending on an unrelated toggle. If the condition persists, the second read fails the same way and stops, so this does not loop. For (b), the result is one redundant GitHub-backed list read, with card reads and compares, on every account or repository change while Show closed is on.
- Fix: Keep the reset from re-triggering the read. Either leave `showClosed` out of `resetView` on the access-lost path, or bump `sequence` and skip the load while an access error is held. One way is a `held` ref set in `accessLost` and cleared by `refresh`; the effect returns early while it is set. For (b), apply the reset before the read is issued, or accept the snapshot read with `includeClosed` as is.
- Evidence: ReviewsView.tsx:131-137 (`resetView` sets `setShowClosed(false)`), :139-146 (`accessLost` calls `resetView()`), :152 and :175 (`showClosed` is a load argument and a dependency), :157-160 (identity branch calls `resetView()`). In the delta, `git diff 20e4281a2..f6971fd4a -- apps/desktop/src/platform/review.ts` adds `includeClosed`. In round 1, `showClosed` was not a load dependency.
- Confidence: medium. The ordering is read from the code; I did not run it.
