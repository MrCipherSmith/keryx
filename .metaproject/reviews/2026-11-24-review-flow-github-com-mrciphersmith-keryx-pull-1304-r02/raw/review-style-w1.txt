## Minor & Info

### [F-001] One Review-rules target has three names, and `rulesTarget` names two different values
- **Severity**: minor
- **File**: apps/desktop/src/reviews/ReviewsView.tsx:114
- **Problem**: The Pull requests board's verified identity is called `boardIdentity` in App.tsx, where it is passed as `rulesTarget={boardIdentity}`. It arrives as the prop `rulesTarget`, whose doc says "The Pull requests board's verified identity". RepositoryReviews then renames it during destructuring (`rulesTarget: boardRules`). It has to, because line 274 declares a different local `rulesTarget`: the effective target, which is this list's own `target` or the board fallback. So one concept has three names, and inside one component `rulesTarget` means the prop at the call site and something else in the body.
- **Why it matters**: A reader who follows `rulesTarget` from App into ReviewsView reaches a value that is not the prop. This is the Name row ("gives one concept two names").
- **Fix**: Name the prop after what it holds, for example `boardTarget` or `boardIdentity` as in App, and drop the destructuring rename. The local `rulesTarget` then names only the effective target.

### [F-002] The board-rules fallback guard is a six-clause condition with no name
- **Severity**: minor
- **File**: apps/desktop/src/reviews/ReviewsView.tsx:274
- **Problem**: `target ?? (!snapshot && read.error && !accessProblem(read.error) && boardRules && (!expectedViewer || …) && (!repo || …) ? boardRules : null)`. That is four ungrouped `&&` clauses plus two grouped ones, then a ternary inside a `??`. The fix round added it for prior F-017. It crosses the Readability threshold "Boolean condition: more than 3 clauses without grouping".
- **Why it matters**: To read when the board's rules are borrowed, you have to parse operator precedence across three lines. The comment above it gives the purpose but not the conditions.
- **Fix**: Extract a named predicate, for example `const boardRulesApply = !snapshot && !!read.error && !accessProblem(read.error) && sameAccount(boardRules, expectedViewer) && sameRepo(boardRules, repo);` and then `const rulesTarget = target ?? (boardRulesApply ? boardRules : null);`. A small `boardRulesFor(...)` helper beside `inViewOverlay` would also work.

### [F-003] Function `compareHeads` and exported type `CompareHeads` share a name but mean different things
- **Severity**: minor
- **File**: src/commands/review-reviews.ts:86
- **Problem**: `export type CompareHeads = (base, head) => Promise<ReviewCompare>` (line 23) is one GitHub comparison, which callers inject as `compare`. The fix round adds a module function `compareHeads(pairs, compare: CompareHeads, budgetMs, warnings)` (line 86). It runs every comparison within one deadline and pushes warnings. The two identifiers differ only in case, and the function takes the type as a parameter: `compareHeads(..., compare: CompareHeads, ...)`.
- **Why it matters**: A search for `compareHeads` or `CompareHeads` finds both, and the batch-with-deadline step reads like the single-call contract. This is the Name row ("needs a comment / one name, two concepts").
- **Fix**: Rename the function after what it adds, for example `compareWithinBudget` or `countCommitsBehind`, and keep `CompareHeads` for the injected single call.

### [F-004] Generic type name `Pair` for the reviewed-head / PR-head comparison
- **Severity**: minor
- **File**: src/commands/review-reviews.ts:84
- **Problem**: `type Pair = { id: string; reviewed: string; head: string };` and the local `pair` at line 58 do not say what is paired. The same `{ reviewed, head }` concept already has a specific name in this change, `headComparison` (review-entity.ts:157), but its return type is written inline.
- **Why it matters**: `Pair[]` in the `compareHeads` signature gives no information. This is the Name row ("generic").
- **Fix**: Name the concept once. Export `type HeadComparison = { reviewed: string; head: string }` from review-entity.ts as `headComparison`'s return type, then use `HeadComparison & { id: string }`, or name the local type `HeadPair`.
