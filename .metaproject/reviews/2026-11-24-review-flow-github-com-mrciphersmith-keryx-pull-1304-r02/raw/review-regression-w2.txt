  - The only production caller is App.tsx:216 `openInReviews`, which has the same new signature.
  - The panel call in ReviewBoard passes `snapshot.repo/repositoryId`, and the card call passes `boardRepo/boardRepositoryId` (ReviewBoard.tsx:456).

  - App no longer passes it to the board.
  - At base, ReviewDetail already only accepted it and never read it. The Reviews tab still gets `openReviewWorkspace` (App.tsx:644).

- `ReviewWatcher onPollCompleted` changed from `refresh` to `watcherPolled`.
  - ReviewWatcher.tsx:66 lists `onPollCompleted` in an effect's deps. `watcherPolled` depends only on `refresh` (a stable useCallback) and App's `noteWatcherPoll` (a stable useCallback).
  - So the watcher effect re-runs no more often than before. Its only mount is ReviewBoard.tsx:487.

- The ReviewDetail `local.error` banner moved into the header block (ReviewDetail.tsx:264). It was not removed, so start errors in the PR panel are still shown.

  - For a PR whose runs are all archived, the panel offers "Open in Reviews" instead of the launch button.
  - The board card's start intent still starts the review through ReviewDetail.tsx:189-199, because that effect does not read `hasReview`.
  - The Review panel's ReviewWorkspace offers start / "New review round", because `launchAction` excludes archived runs.
  - No start path is lost.
- `launchAction` relabelled "Review again" to "New review round". No code matches on the label string; only ReviewBoard.dom.test asserts that "Review again" is absent.
- `ReviewBrowserLink` gained an optional `onOpen`. Its graph dependents are DiscussionMarkdown, ReviewChecks, ReviewDetail, ReviewResults and ReviewPanel. Only ReviewPanel passes `onOpen`.
