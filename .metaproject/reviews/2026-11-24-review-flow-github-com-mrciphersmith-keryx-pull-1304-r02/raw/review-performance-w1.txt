### Findings

### [I-001] The PR watcher poll now triggers two full list reads, each with its own identity query
- **Severity**: info
- **File**: apps/desktop/src/review/ReviewBoard.tsx:465 / apps/desktop/src/reviews/ReviewsView.tsx:199-204
- **Hot path**: once per completed background watcher poll (watcher interval, default 5 min, minimum 1 min), only while the window is visible.
- **Problem**: `watcherPolled` refreshes the PR board and also bumps `reloadSignal`, which makes ReviewsView spawn `keryx review reviews`. That command repeats the `ReviewIdentity` GraphQL query, then reads PR cards (see F-023) and up to 25 compares.
- **Why it matters**: this is the design FB-4 chose, at a low frequency, so it is not a defect. It is recorded because it compounds with F-023: the cost per poll grows with the number of Reviews.
- **Fix**: none required. If F-023 is taken further, skipping cards of PRs already known to be merged would also cut this cost.

### [I-002] A compare cut off by the deadline is abandoned, not cancelled, and the card phase has no deadline of its own
- **Severity**: info
- **File**: src/commands/review-reviews.ts:85-108, :67-80
- **Hot path**: once per `review reviews` call, and only when GitHub stalls.
- **Problem**: `Promise.race([compare(...), expired])` stops waiting, but the `gh` child keeps running until its own 18 s timeout (`board-github.ts:133`). Whether this keeps the CLI process alive after the JSON is written is NOT verified: I did not trace the CLI exit path. Card batches have no overall deadline. The worst case is 18 s for identity, plus ceil(ceil(N/20)/3) × 18 s for cards, plus 60 s for compares, plus up to 18 s of tail. That exceeds the Desktop host's 150 s bound only with more than about 180 Reviews that are not closed locally and every call stalling to its timeout.
- **Why it matters**: degenerate case only. F-025's compare-phase deadline is in place.
- **Fix**: optional. Pass an AbortSignal or a shorter timeout to `boardGh` for compares, or give the card phase the same deadline.

### Clean Areas
- CLI/TUI hot paths: no per-keystroke work was added. `matchesSearch` (model.ts) runs one small regex replace per Review behind `useDeferredValue`.
- React re-renders: `boardRepo`/`boardRepositoryId` keep `openReview` stable. `watcherTarget` is memoised on primitives, so `onIdentityChange` and App's `setBoardIdentity` fire only when the identity changes. `known` in ReviewPanel is memoised.
- Memory leaks: the new subscription (`subscribeSessionReview`) returns its unsubscribe from the effect. Intervals are cleared. `seenRuns` is a per-number Map bounded by the Review count.
- N+1 / indexes: `assignReviews` makes one query per Review, not per row. The `review_rounds(review_id, round)` index backs that query.
- Redundant API calls: concurrent list reads share one in-flight promise (`ReviewReadLane`), and `includeClosed` is part of the lane key.
- Synchronous blocking: the `publication()` receipt read and `existsSync` per finished attempt run in the short-lived CLI, off any interactive path. Since FA-2 they also run for partial and budget attempts, a small linear addition.
- Bundle imports: none added.
