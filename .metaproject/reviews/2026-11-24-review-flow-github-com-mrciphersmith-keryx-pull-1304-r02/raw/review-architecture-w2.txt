#### [F-001] Link-opening policy now has two mechanisms: parent click delegation and a per-anchor `onOpen`
- **Severity**: info
- **File**: apps/desktop/src/review/ReviewBrowserLink.tsx (`openReviewLink`, `onOpen`), apps/desktop/src/reviews/ReviewPanel.tsx (`openPullRequestLink`)
- **Problem**: T17 moved the "PR URL -> openPullRequest, else openExternal" rule into `openReviewLink` (good: one rule, used by ReviewDetail and ReviewPanel), but how an anchor reaches it is now split: `ReviewDetail` delegates from the sheet body (`followLink`, only on the discussion/checks tabs), `ReviewPanel` passes `onOpen` to one `ReviewBrowserLink`, and `ReviewBrowserLink` without `onOpen` "relies on a parent's click handler" (its own doc comment). A `ReviewBrowserLink` rendered where no parent delegates is a plain in-app navigation the app blocks. I checked the class for the moved review interface: `ReviewReportMarkdown.tsx:9` strips `href` from report links and `ReviewRuns`/`ReviewWorkspace`/`ReviewRunDialog` render no anchors, so the panel header link is the only member today and T17 covers it. Also `openReviewLink` is a platform I/O dispatcher living in a component module.
- **Why it matters**: No defect now; the next anchor added inside the Review panel silently does nothing unless its author knows which mechanism applies.
- **Fix**: Optional: make `ReviewBrowserLink` default `onOpen` to `openReviewLink` (with an error callback) so every anchor opens externally by default and delegation becomes the exception, or move `openReviewLink` next to `openExternal` in `platform/`.
