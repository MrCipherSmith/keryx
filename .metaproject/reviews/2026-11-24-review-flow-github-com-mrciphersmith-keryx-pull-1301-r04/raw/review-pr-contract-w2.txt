## Findings

### [PC-001] The guide says a folder that fails to load shows Retry; a stale-snapshot read instead stays Loading… with no Retry

- **Severity**: minor
- **File**: docs/docs/guides/desktop-metaproject.md:109
- **Problem**: The guide, at :107-110, says a folder "shows **Loading…** until they arrive … If a folder fails to load, its row reads **Could not load.** with the reason and a **Retry** button." The behaviour slice-02 pins is different. When a tree read is refused as stale-snapshot, the row never reads "Could not load." and offers no Retry: `const deadRetry = () => treeRows().some(row => row.textContent?.startsWith("Could not load."));` … `expect(deadRetry()).toBe(false);`. The row stays `["src1", "Loading…"]` (+135-136), and activating a parked Show more asks for nothing (+203-208) until **Refresh catalog**. The guide's tree section never says this. Only the generic troubleshooting row at :327 ("Project knowledge changed while loading … Select Refresh catalog") names the remedy, and it does not say that tree rows wait on it.
- **Why it matters**: A reader of the guide who sees a folder stuck on Loading… expects either data or a Retry row. It is not clear that the Refresh catalog banner is the only way out. This costs a reader, not correctness: the banner is visible and the troubleshooting row names the action.
- **Fix**: Add one sentence after :110: "If the project knowledge changed while the folder was loading, the row stays **Loading…** and the explorer shows the **Refresh catalog** banner; select it to load the folder again."
