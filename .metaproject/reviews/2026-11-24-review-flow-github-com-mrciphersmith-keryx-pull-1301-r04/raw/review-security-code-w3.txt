### Clean Areas (checked)
- Injection / command: the Rust `metaproject_args` passes the request as one JSON argv element after `--request`. There is no shell. Payload size is capped at 16 KiB, and `RequestV2::Tree` uses `deny_unknown_fields`, a typed `TreeScope` enum, and refuses nulls.
- Path traversal: a graph `parent` must pass `relative_path`, which refuses empty, `.`, `..`, empty segments, a leading `/`, a backslash, a drive letter and control characters. Tests pin the `../escape`, `/src` and `src\lib` cases. A wiki `parent` is a group key, not a path; it is bounded by `valid_text`, and the CLI resolves it as a key.
- Snapshot pin: `expectedSnapshotId` must be a 64-hex digest. A v2 answer for another snapshot is refused as `stale-snapshot` in the transport, so no cross-snapshot cursor is reused.
- Response validation: `validTree` / `validTreeEntry` check the scope, the parent, the entry types, a 100-entry page bound, that a module path equals its folder path, and that node kinds match the scope. The response byte cap still applies.
- XSS: tree rows render CLI strings as React text children only. There is no `dangerouslySetInnerHTML`, `eval` or `postMessage` in the slice.
- DoS / resource use: at most 3 tree reads are in flight; a permit refusal is retried at most twice with a bounded jittered wait; a read from a retired generation is never started or repeated.
- Capability handshake: `tree` stays optional (`METAPROJECT_REQUIRED_ACTIONS` matches the Rust `ACTIONS`), so a downgrade is not possible.
- Secrets / crypto / auth / CSRF / open redirect: not applicable to this slice; nothing introduced.
