### [F-001] The new plan.md stale row says every catalog load re-reads parked reads, which the quiet re-read does not do

- **Severity**: info
- **File**: .metaproject/flows/518-2026-11-23-desktop-metaproject-sidebar-tree/plan.md (stale-snapshot matrix row)
- **Principle**: Clean Code — comments (two places documenting one behaviour; claim broader than the code)
- **Problem**: The matrix row added to answer r4-logic-w2-F-001 reads "every catalog load re-reads parked reads, same snapshot id included". When the explorer is shown again, it re-reads the catalog quietly. If that read finds the same snapshot, it returns before `setCatalog` (MetaprojectView.tsx:410-414). So `reload` does not change and the parked reads are not sent again. This is the overclaim r4-degradation-w2-F-002 found in the `reload` doc and the view comment. The fix round copied it into the spec that later fix rounds and the flow-complete verifier check behaviour against.
- **Impact**: Users are not affected. The quiet path does not clear the Refresh catalog banner either, so a user-started load still recovers the row. A verifier reading the plan literally could treat the quiet path as a spec gap and "fix" it so that a background re-read changes `reload`.
- **Fix**: In the plan row and in the `reload` doc (the r4-degradation-w2-F-002 site), say "every user-started catalog load (Refresh catalog, Rebuild) or a new snapshot re-reads parked reads, same snapshot id included".
