### Findings

### [F-001] describeBlockers still tells the agent to use `keryx review complete` when more than 20 blockers are open
- Severity: minor
- File: src/review/completion-gate.ts (line of the `… and N more` string in describeBlockers)
- Attack vector: an attended agent reads the nudge "- … and 3 more (`keryx review complete` lists them all)" and runs `keryx review complete <package>` through shell_exec. Plain complete has no TTY check and no operator-act check. If the blockers have been cleared in the meantime it closes the round without a review_complete card and without `pressedBy`. The practical window is narrow (the string appears only when more than 20 blockers are open, so complete refuses and only lists them), so there is no reproducible bypass in the current code path.
- Problem: D-03 named two strings; only the first (empty list) was reworded. The second still names the CLI as the lister, against the rule in nextStep ("you never run `keryx review complete` yourself").
- Fix: reword to "(`keryx review status <package>` lists them all)", or "the review_complete card's refusal lists them all".
- Confidence: high
- Quote: "…and ${more} more (\`keryx review complete\` lists them all)"

### [F-002] D-12 not addressed: remote-press audit fields on publish, both waivers and the decision recorders are unpinned
- Severity: minor
- File: src/commands/operator-confirm-review-tools.test.ts
- Attack vector: none exploitable today; this is a regression guard for the who-pressed audit trail. A later refactor that drops `cardPressFields(confirmation)` from review_publish, review_waive_coverage, review_waive_readiness or the mutation-waiver and reviewer-override decisions would record a remote waiver or publish with no `pressedBy` or `pressedAt` and nothing would go red.
- Problem: the claimed disposition for D-12 is "fixed in slice-01", but slice-01 and the delta carry no such test; head has remote-press assertions for five of the nine recorders only.
- Fix: the table-driven test D-12 proposed (one remote yes and one tui yes per remaining spec, reading the record each writes).
- Confidence: high
- Quote: null (finding is about an absent test)

### [F-003] The D-01 regression test covers one of the four fixed strings
- Severity: info
- File: src/commands/operator-confirm-review-tools.test.ts
- Attack vector: none; test coverage note. Lines 346-347 assert the review_waive_readiness result ("Call review_complete to close the review." and no "keryx review complete"). The review_waive_coverage result (line 296) and both tool descriptions (262, 312) are not asserted, so the original wording can return there unnoticed.
- Fix: add the same two assertions for the coverage-waiver result, and assert on the descriptions of both waiver tools.
- Confidence: high
