# Style Review Report (wave 5, slice-05: TUI part)

## Verdict: APPROVE_WITH_SUGGESTIONS

## Summary
The TUI slice is readable and consistently commented (every addition carries a "Flow 464" origin note, the new module is small and pure, the pure line builders are unit tested). The style cost sits in three places: `mirrorApprovalToTopic` in tui-shell.ts grew into a function with roughly 25 decision points and two redundant narrowing checks; `operator-confirmations.ts` adds a third copy of `clock` and a second, differently rounded age formatter next to `formatAge`; and one concept is named four ways (`confirmationLines` is both a function and an option property with a different type). No major findings.

## Minor

### [S5-01] mirrorApprovalToTopic now carries two card paths, redundant narrowing and ~25 decision points
- File: src/tui/tui-shell.ts:6095-6148
- The wrapper gained the unmirrored-card early branch (try/finally with a hand-rolled `verdict`), the `isCard` four-clause condition, `cardId` ternary, a conditional spread for `onUndelivered`, and a second try/finally around `raceApproval`. `meta?.card !== undefined` is re-checked at 6102 and 6120 only to narrow the type although `isCard` already implies it, and `meta.card[0] ?? tool` is computed twice (6103, 6120). The same `meta?.alwaysAsk === true && meta.card !== undefined` test now appears a third time (5555, 5563, 6100).
- Fix: derive once `const cardQuestion = isCard ? (meta.card[0] ?? tool) : undefined` (narrow `meta` through a small `operatorCardOf(tool, meta)` returning `{ card, title } | undefined`), and move the two card bodies into named functions (`answerUnmirroredCard`, `raceMirroredCard`) so the wrapper reads: not a card -> old path; card without topic -> A; card with topic -> B.

### [S5-02] Duplicated time helpers: third copy of `clock`, and a second age formatter that rounds differently from `formatAge`
- File: src/tui/operator-confirmations.ts:105 and :113
- `clock` is byte-identical to remote-control-surface.ts:144 and channels-surface.ts:127 (the existing two stay as sibling copies; this adds a third). `age()` (floors minutes, prints `1h05m`) sits beside `formatAge` (remote-control-surface.ts:102, rounds, prints `1h`). Both now render in the same `/remote-control` Status tab: "Last heartbeat: 2m ago" for 90s from `formatAge`, "asked 1m ago" for the same 90s from `age()`.
- Fix: one shared `time-format.ts` (or export `formatAge`/`clock` from a neutral module) used by both; importing from remote-control-surface directly would be circular because that file already imports `waitingCardsText` from operator-confirmations.

### [S5-03] One concept, four names; `confirmationLines` is two different things
- File: src/tui/operator-confirmations.ts:148; src/tui/decisions-surface.ts (OpenDecisionsOptions, DecisionsSidebarOptions); src/tui/tui-shell.ts:126, ~3940
- `confirmationLines(entries, now, heading)` is a function returning `string[]`; `confirmationLines` is also the option property `() => readonly string[]` in decisions-surface. tui-shell has to alias the import (`confirmationLines as operatorConfirmationLines`) to avoid shadowing, then adds `operatorCardLines` and `operatorCards`, while remote-control-surface calls the same thing `getConfirmationLines` and `getWaitingCards`, and the class is `OperatorConfirmationLog`. "Card", "confirmation" and "operator" mix freely, so a reader cannot tell whether `operatorCardLines` and `operatorConfirmationLines` are the same value.
- Fix: choose "card" (matches the user-facing "Telegram cards" heading): `cardSectionLines(entries, now)`, option `cardLines`, local `cardLog`/`cardLines`; drop the import alias.

## Info

### [S5-04] `remoteApproval` placed between SIDE_WORKER_DENIED_TOOL_NAMES and the predicate that documents it
- File: src/tui/tui-shell.ts:571-574
- A pure approval-response builder was inserted at module level between the side-worker deny set and `isToolAvailableToSideWorker`, whose docblock links to that set. It is unrelated to both, and tui-shell.ts is already 10568 lines. Same class as the filed `withMirrorNote` location (tui-shell.ts:1616).
- Fix: move both helpers next to `raceApproval` in approval-mirror.ts (small, already unit tested).

### [S5-05] Docblocks not updated for the new parameters; options type promises what one opener drops
- File: src/tui/remote-control-surface.ts:119, :385; src/tui/decisions-surface.ts:467
- `formatRemoteStatusLines` docblock still lists only `posture`; `projectRemoteRow` docblock still says `Remote: off | <topic name> | offline` and says nothing of the `· N cards waiting` suffix or the new `waitingCards` argument. `openDecisionsArms` accepts `confirmationLines` through the shared `OpenDecisionsOptions` and discards it with `confirmationLines: _cards`, so the type says the arms modal takes cards when it does not.
- Fix: one added sentence per docblock; make the option `Omit`-ted for the arms opener or note that it is ignored.

### [S5-06] "1-hour token" is a literal in four strings while the TTL is a constant
- File: src/tui/operator-confirmations.ts:2, :80, :122, :126; src/standard/help-groups.ts:600
- `REMOTE_CARD_TTL_MS` drives the arithmetic, but the user-visible text hardcodes "1-hour". If the TTL changes the sidebar and status tab would state a wrong limit.
- Fix: build the phrase from the constant (`${REMOTE_CARD_TTL_MS / 3_600_000}-hour`), or keep the literal and have a test assert it equals the constant.

### [S5-07] `at` names an array index in two methods and a timestamp everywhere else in the file
- File: src/tui/operator-confirmations.ts:50, :73
- `const at = this.items.findIndex(...)` in `answer` and `markUndelivered`, while `answered.at` and `clock(at: number)` use `at` for a time. The same lookup is also written twice.
- Fix: `index` plus a private `find(id)` returning `{ index, entry }`.

### [S5-08] Tests for exported functions of other modules live in operator-confirmations.test.ts
- File: src/tui/operator-confirmations.test.ts:1360-1500 (diff lines)
- `projectRemoteRow`, `formatRemoteStatusLines`, `withConfirmationLines`/`presentDecisions` and the help/command lists are tested here, while `remote-control-surface.test.ts` and `decisions-surface.test.ts` exist beside their subjects. The header comment states the feature-level grouping on purpose, so this is a convention note, not a defect.
- Fix: optional; move the three surface tests to their sibling files, or leave as a feature test.

## Positive Notes
- The new module is pure, small and has a header that says what it holds, what it does not (memory only), and who reads it.
- `MirroredCardOutcome` is structurally narrower than `ApprovalRaceOutcome` on purpose, which keeps operator-confirmations free of an approval-mirror import.
- Error paths in `settle` are explicit (a thrown race is "withdrawn"), and each branch is covered by a test.
