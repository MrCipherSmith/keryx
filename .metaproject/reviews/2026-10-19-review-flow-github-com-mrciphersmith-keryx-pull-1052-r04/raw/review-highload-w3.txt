Verified against source at head:
- No new shared mutable state, pool, cache, queue, retry or timer. `cardPressFields` is a pure function; the new fields are plain optional properties.
- remote/client.ts askApproval: the four new `undelivered: true` returns are on paths that return immediately (not connected, aborted, post refused, no approvalId, post threw). No new wait, listener or timer is added; the existing settle / early-decision / abort handling is untouched.
- remote/shell-bridge.ts askApproval: `openPrompts` is incremented before the await and decremented in `finally`, unchanged; the new `undelivered` return on the not-connected path exits before the increment. `mirrorUndeliveredNote` and the `connected` getter are synchronous reads of two fields.
- Write paths keep their existing protection: operator-decisions.json is written under `withOperatorDecisionsLock` (read and write under one lock, so two overlapping writers both land); chunk-estimate.json under `withChunkStateLock`; plan-confirmation.json, published.json, research.json, manifest.json, report.md and the confirm token through `writeFileAtomic`. The diff adds fields to these records without changing when or how they are written.
- recordPremiseDecisionAfter still runs findings.json and operator-decisions.json under one lock with an undo on a failed append; the new `...cardPressFields(input)` only widens the record.
- completeReviewGated (complete-gated.ts) is two synchronous refusal checks then completeManagedReview: no retry, loop or fan-out. It resolves the package path once itself and once inside completeManagedReview (two small path resolutions, not a hot path).
- write-land.ts: only the decision-file body widens (pressedBy / pressedAt). The create-exclusive decision write that arbitrates two concurrent landers, and the cleanup of the branch and the worktree in the catch and finally, are unchanged.
- confirm-token.ts: mint still writes the whole token (replacing the earlier one, latest mint only); consume still marks `usedAt`. pressedBy / pressedAt are copied through; there is no new check-then-act.
