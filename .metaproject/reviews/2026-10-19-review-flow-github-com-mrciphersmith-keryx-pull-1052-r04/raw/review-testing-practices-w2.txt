### F-002 The "model cannot supply a head" test never drives apply with a model-supplied head
- Severity: minor
- File: src/commands/operator-confirm-review-tools.test.ts:694
- The test name promises the gate runs against the recorded head. It only calls `ask(t, { package, head: "deadbeefdead" })`; buildCard ignores input.head, so the card line cannot differ whether or not apply forwards it. The schema assertion is not enforced by the framework (apply receives raw input). apply (operator-confirm-review.ts, completeSpec) takes `_input` and calls completeReviewGated without `head`; a change to forward `input.head` would leave this test green, and the "head that moved" test only varies the tracker's headSha, not the input. The test the name describes is `yes(t, { package, head: "deadbeefdead" })` expecting success against the recorded HEAD (or the moved-head refusal when prLookup disagrees).
- Fix: use `yes()` with the extra `head` input and assert the closed round used HEAD (the completion-confirmation.json head and the gate's refusal when prLookup returns another sha).
