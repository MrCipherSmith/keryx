### Findings

### [F-001] cli-reference says plain `review complete` needs a terminal; the code and TM-04 say it does not
- Severity: info
- File: docs/docs/cli-reference.md:4921
- Attack vector: no new vector in code. A reader (operator or agent) who trusts the sentence believes a plain `keryx review complete <package>` cannot run from shell_exec without a terminal, so the review_complete card is a hard lock. In fact review.ts runComplete checks isTerminal only for --waive and --waive-coverage (lines 4556-4562); an agent that runs `keryx review complete` through shell_exec closes a ready package with no card and no pressedBy. TM-04 section 8 already states this limit; the cli-reference text contradicts it.
- Problem: the sentence lists `complete` among the "operator-only steps here ... need a terminal". For plain `complete` that is false; only the waiver forms need a terminal. The line 4916 listing also tags it "(card review_complete)" without that distinction.
- Why it matters: documentation overstating a control on the operator-confirmation boundary. Info only, because the real limit is stated in TM-04 and in the new autonomous-review text, and the code path is unchanged by this slice.
- Fix: split the list: say `complete --waive` and `complete --waive-coverage` need a terminal, and that a plain `complete` runs the same gates without one, so the card is a rule the skills and gate messages give the agent (as TM-04 section 8 says).
- Confidence: high
- Quote: "The operator-only steps here (`confirm-plan`, `decide-premise`, `chunks estimate --answer`, `complete`, `complete --waive-coverage`, `complete --waive`, `publish`) need a terminal."
