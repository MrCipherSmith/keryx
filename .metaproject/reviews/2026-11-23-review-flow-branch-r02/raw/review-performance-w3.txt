The test 'a render that changes no node list leaves the explorer's node memory alone' pins zero writes across two popover re-renders, so the behaviour is pinned.

### Fix code checked through the performance lens
- seenNodes effect: one pass per `nodes` change. Clean.
- Quiet catalog re-read (visible effect, MetaprojectView.tsx:1527-1536 of the diff, catalog effect with `quiet`): one `catalog` request per hidden-to-visible transition and only when `loaded.current`; no read while hidden; no poll. When the snapshot is unchanged only `freshness` (three scalar fields) is set, so `catalog`, `graphIndex`, `nodes`, `results` and the graph are not recomputed. Frequency is a tab switch, cost is one CLI read plus parse of the catalog (size not measured here; the journal records one request on return). Not a hot path, so not a finding.
- placeFiltersPopover() on resize: the `resize` listener is added in a layout effect of FiltersPopover and removed in its cleanup; the popover is not mounted while the view is hidden (`visible && filtersOpen && filtersAnchor`) or closed, so no window listener outlives the popover. Per event: getBoundingClientRect, one scrollHeight read (forced layout) and a setState with a fresh object, re-rendering only FiltersPopover, whose children are the same element references from the parent. Resize events arrive at most about once per frame, and only while the popover is open. Not throttled, but no named cost, so below the bar for a finding.
- graphState derivation: `catalog && freshness?.snapshotId === catalog.snapshotId ? freshness : catalog`, two comparisons per render, used in place of `catalog.graph*` reads. Clean.
- OpenSpecView.choose(): reorders onLocation and scrollTop write; the same calls, no added work.
- RelationshipList.groupRelationships: adds one `edge.from === edge.to` comparison per edge in a pass that already ran per render; byKind (kinds x rows filter) is unchanged and out of the diff.
- NodeDetailsPanel relationFact: builds a 2 to 4 element array and joins it per render; negligible.
- Tests: the Map.prototype.set patch and window.setTimeout replacement in the new tests are restored in finally blocks; no cost to the product.
