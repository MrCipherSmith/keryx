### Findings

### [F-001] A permit-retry wait is not cancelled when the explorer unmounts, so up to three reads are sent after it is gone
- **Severity**: info
- **File**: apps/desktop/src/metaproject/useMetaprojectTree.ts
- **Hot path**: none. It needs every read permit to be refused at the moment the explorer view unmounts, and it is bounded by MAX_TREE_READS (3) reads and about 750 ms of total wait.
- **Problem**: `attempt` waits `pause(...)` and then re-checks only `current()`, i.e. the snapshot generation. The generation changes only on a snapshot change (useMetaprojectTree.ts:96), not on unmount, and the hook has no unmount cleanup. So a retry whose wait ends after unmount still calls `send(root, input)`, and that takes one of the shared read permits.
- **Why it matters**: This is negligible. It is at most three extra CLI reads, sent at the moment permits are already scarce. A request already in flight at unmount behaved the same way before this round. Recorded only because the retry adds a timer that has no cleanup.
- **Fix**: Optional. Bump `generation.current` in an unmount cleanup (`useEffect(() => () => { generation.current++; }, [])`) so that `current()` is false after unmount and the retry throws instead of sending.

### Clean Areas
- CLI/TUI hot paths: the focus-tracking layout effect and onFocus were checked per keystroke and per render, as described above. `flatten` is unchanged apart from the id function.
- Retry and backoff: the wait is bounded (PERMIT_RETRIES = 2, 150 ms × attempt + up to 150 ms jitter) and applies only to the permit-refusal message. Other `unavailable` answers fail at once (covered by a test). The jitter spreads out retries from several folders. Holding the limiter slot through the wait keeps the tree's fan-out at 3 while permits are short, which is the intended backpressure.
- Memory and cleanup: the limiter's `.catch(console.error)` adds no retained state. The stale-snapshot early return leaves the folder `loading`, which neither re-sends nor polls (the `unread`/`ensure` path skips a parent that already has an entry). There are no new listeners or intervals.
- React re-renders: the new inline `onFocus` closure per row follows the existing per-row `common` object pattern, and the rows are not memoized children, so no re-render cost is added.
- N+1 / indexes / pagination / bundle imports / redundant API calls: none in this delta.
- Tests: the test-only changes (fake `wait`, `refusing` reader, console.error swap) have no runtime cost.
