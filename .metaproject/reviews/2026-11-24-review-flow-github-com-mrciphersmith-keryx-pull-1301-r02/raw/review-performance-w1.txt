### Findings

### [F-001] A permit retry waits while it holds one of the tree's three read slots
- **Severity**: info
- **File**: apps/desktop/src/metaproject/useMetaprojectTree.ts (attempt() inside read())
- **Hot path**: This runs only when Desktop refuses a read permit, which means every one of the 8 shared permits is in use. That happens with several windows open, or during a re-read of many expanded folders after a snapshot change. It is not a per-keystroke or per-render path.
- **Problem**: `attempt` is called inside the `limit()` task, so `await pause(...)` keeps its slot for the whole backoff. The first wait is 150 ms plus up to 150 ms of jitter. The second is 300 ms plus up to 150 ms. Both waits come on top of the refused CLI call. In the worst case one read holds a slot for about 750 ms of waiting. Tree reads queued behind it wait that long too.
- **Why it matters**: The cost is latency only, and only under permit exhaustion. Even then, freeing the slot during the wait would mostly let a queued read run into the same refusal. Holding the slot is arguably the better back-pressure. Retries are bounded (PERMIT_RETRIES = 2) and jittered, so there is no thundering herd and no unbounded loop. After each wait, `current()` is checked, so a retired generation stops retrying. Nobody measured a before/after, but this is a resilience mechanism, not an optimisation, so law 3 does not apply.
- **Fix**: None needed. Optionally, note in the comment that the backoff holds the slot on purpose.

### Clean Areas
- Per-keystroke and per-render DOM work: closed. The layout effect calls `rowElements()` once, and `remember` takes that array. `onFocus` gets its index from `rows.findIndex` with no DOM query. The new anchor lookup (`elements.findIndex` on `before`) runs only when the focused row was lost. `moveTo` makes one query per navigation key, which it needs. `onBlur` re-queries only when the blurred row is still connected and still the focused one.
- Re-renders: `focused` and the slot pool live in refs, the model is memoised and no new state was added.
- Memory: the limiter queue drains in `.finally`, the retry is bounded, and `sleep`'s timer resolves once. Nothing grows without bound.
- Redundant calls: a stale-snapshot answer now returns after `onStale()` and leaves no Retry, so no repeated doomed reads come from that path.
- Bundle, sync I/O, N+1, pagination, indexes: nothing in the delta touches these.
