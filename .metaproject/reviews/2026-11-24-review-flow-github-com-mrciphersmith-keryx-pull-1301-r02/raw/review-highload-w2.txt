### [F-001] The permit-refusal match is a copy of the Rust error string, and no test ties the two together
- Severity: info
- File: apps/desktop/src/metaproject/useMetaprojectTree.ts
- Pattern: Retry F — retry trigger coupled by string literal
- Failure mode: if the message at metaproject.rs:199 is ever reworded, `isPermitRefusal` stops matching. Permit refusals then become terminal folder errors again whenever several windows exhaust the 8 shared permits, which is exactly what F-001 of round 2 fixed. The DOM tests build the refusal from their own copy of the literal (`PERMIT_REFUSAL`), so they would still pass. Today the two strings match, so nothing fails yet. This is a drift risk, not a current defect.
- Fix: export the prefix as one shared constant, or have the Rust side return a stable code (for example `unavailable:busy`), and assert in metaproject.rs's tests that the refusal text starts with it.
