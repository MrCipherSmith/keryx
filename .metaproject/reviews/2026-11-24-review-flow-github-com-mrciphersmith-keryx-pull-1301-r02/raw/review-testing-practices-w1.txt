## Findings

### [F-001] The permit-retry trigger is pinned only against a hand-copied string injected below the transport (minor)

- **File**: apps/desktop/src/metaproject/MetaprojectTree.dom.test.tsx (`PERMIT_REFUSAL`) and apps/desktop/src/metaproject/useMetaprojectTree.ts (`isPermitRefusal`)
- **Problem**: Fixture shape vs producer. The retry fires only when `errMessage(cause)` starts with "unavailable: Too many Metaproject reads".
  - The producer is metaproject.rs:199. In the real app, its error reaches the hook through `requestMetaprojectTree` -> `requestMetaprojectV2`, which passes it on unchanged only because "unavailable" is not in `METAPROJECT_ERROR_CODES` (contract.ts:329-331).
  - The new tests inject `PERMIT_REFUSAL`, a literal copy of the Rust string, straight into the hook's `request`, so they bypass the transport.
  - No test sends the Rust refusal through `requestMetaprojectTree` and checks that the hook's predicate still matches.
- **Why it matters**: Two plausible edits would each silently turn the retry off, with every test green: rewording the Rust message, or adding "unavailable" to the typed codes, which would make the transport strip the prefix into a `MetaprojectRequestError` message. The suite would then pin a shape the producer no longer emits.
- **Fix**: Export `isPermitRefusal` (or move it next to `requestMetaprojectV2`). In platform/metaproject.test.ts, add a test where a reader throws the exact metaproject.rs:199 string, and assert that `isPermitRefusal(await readError(requestMetaprojectTree(…)))` is true. Optionally add a comment at metaproject.rs:199 naming the TS matcher.
