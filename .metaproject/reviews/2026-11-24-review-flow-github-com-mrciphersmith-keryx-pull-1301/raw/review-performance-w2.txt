### [performance-w2r2-F-001] The every-render layout effect queries and scans all tree rows twice; each arrow key queries them about four times
- **Severity**: minor
- **File**: apps/desktop/src/metaproject/MetaprojectTree.tsx (`remember`, and the `useLayoutEffect` with no dependency array)
- **Hot path**: every render of the tree: each keystroke (moveTo → focus → setFocusId), each page that arrives, each expand or collapse. n = the loaded visible rows: 100 per page, growing with Show more and expanded folders.
- **Problem**: the layout effect runs after every render. It calls `rowElements()` (querySelectorAll over every `[data-row]`) and then `remember(document.activeElement)`, which calls `rowElements()` again and runs `indexOf` over the result. On ArrowDown, `moveTo` also calls `rowElements()` and the row's `onFocus` → `remember` calls it once more. That makes about four O(n) DOM queries plus scans per keystroke. Before the fix round, none of these ran unless a scroll or focus request was pending.
- **Why it matters**: the cost is the same order as `flatten` and React's reconcile of n rows, which already run on each render. It is not a bottleneck at the 100-row page size. It is redundant work on a per-keystroke path and grows linearly with how far the user has paged. No timing was measured.
- **Fix**: pass the `elements` array the layout effect already holds into `remember` (`remember(element, elements = rowElements())`). In `onFocus`, derive the index from `rows.findIndex(r => r.id === row.id)`, which is already in memory, rather than from the DOM.

### Clean Areas
- Tree read limiter (`limit`, MAX_TREE_READS = 3): a FIFO with one slot handoff per settle. A queued read whose generation has been retired returns `false` without sending, so no wasted CLI spawns. The queue is bounded by expanded folders plus pages. The slot count stays correct on failure (`.catch(() => undefined).finally`). This closes the round-1 fan-out concern (performance-w1-F-002 / highload-w1-F-001) by inspection. The test also asserts a peak of ≤ 3.
- Stale-snapshot check moved from `matchesRequest` into `requestV2` after validation: O(1), no extra serialisation.
- `onBlur` queueMicrotask: one per blur, O(1) unless focus left a connected row.
- `metaprojectWikiGroupKey`: a constant-time helper, with no per-call allocation.

- Tests and fixtures (core tree test reversed nodes.jsonl, Desktop DOM tests): not production paths.
