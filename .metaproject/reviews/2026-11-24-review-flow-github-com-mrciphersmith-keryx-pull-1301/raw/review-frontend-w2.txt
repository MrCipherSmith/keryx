### Findings

### [F-001] A stale-snapshot tree read also leaves a "Could not load." row whose Retry can only be refused again
- **Severity**: info
- **File**: apps/desktop/src/metaproject/useMetaprojectTree.ts
- **Problem**: After `onStale()` the catch falls through to `setFolder(... status: "failed" ...)`. The folder then shows "Could not load. Project knowledge changed while loading." with a Retry. `retry` calls `read`, which pins `state.current[scope].snapshot`. That snapshot does not change until Refresh catalog loads a new catalog, so Retry sends the same stale `expectedSnapshotId` and is refused again.
- **Why it matters**: There is no data harm: the banner is shown and no rows from the stale answer appear. The cost is a Retry control that cannot succeed and duplicates the banner's message. Operator decision (UX) on whether the row should stay, read as "Refresh catalog", or be suppressed while the banner is up.
- **Fix**: Optional. Return after `onStale()` and leave the folder in loading, or reword the row to point at Refresh catalog.
