### Logic Bugs

### [F-001] A deleted or archived newer round still supersedes the earlier round and points the user at it
- **Severity**: minor
- **File**: src/review/update-round.ts:905-913 (`newerRoundOf`), used at src/review/desk-publication.ts (`newerRound` → `headMoved` and `blockedReason`)
- **Problem**: `newerRoundOf` returns the highest round of the same Review after `current` from every attempt, including ones with a `delete`/`archive` decision. In the same module `earlierRoundAttempts` and `priorAttemptCandidates` drop exactly those attempts as `withdrawn` ("its evidence is discarded"). The decided B6 rule says "any newer round incl. a failed/running one" / "in any state"; a withdrawn attempt is not a run state but an operator decision, and the round rows stay in the store (`roundFor` counts them via `max(round)`).
- **Why it matters**: Trigger: round 1 at head A is done; the user starts round 2 on head B and then deletes (or archives) the round 2 attempt. Outcome: round 1 never gets the as-is variant or the Update action (`headMoved` requires `newerRound === undefined`), and its preview says "Round 2 of this review is newer. Publish from that round." — a round the user withdrew and cannot publish. The draft still saves locally and a new Update can be started from the PR, so nothing is lost, but the message directs to a dead end.
- **Fix**: skip withdrawn attempts in `newerRoundOf` (reuse the module's `withdrawn` predicate), or, if withdrawn newer rounds are meant to keep superseding, word the reason so it does not send the user to a withdrawn round, and record that in the B6 decision. Add one `newerRoundOf` case with a `decision: { action: "delete" }` round.

### Edge Cases

### [F-002] Superseded reason takes precedence over a closed PR or changed base
- **Severity**: info
- **File**: src/review/desk-publication.ts (`blockedReason` chain)
- **Problem**: `!current && newerRound !== undefined` is checked before the closed/moved reason, so a superseded attempt on a closed PR (or after a base change) says "Publish from that round", which cannot publish either.
- **Why it matters**: wrong hint only; `canSubmit` is false either way.
- **Fix**: optional — test `open` first, e.g. `!current && open && newerRound !== undefined`.

### [F-003] Candidate order is "round of the newest attempt first", not "newest round first"
- **Severity**: info
- **File**: src/review/update-round.ts:852-866 (`priorAttemptCandidates`)
- **Problem**: rounds are ordered by Map insertion over `history` (created DESC). `roundFor` places a new attempt on a known range into that older round, so a later retry of round 1 (only possible when the PR head returns to round 1's range, since `verifyDeskSubject` is strict) puts round 1 before round 2. The doc comment says "the newest round first".
- **Why it matters**: no harm shown — in that trigger (head force-pushed back to A) round 1's head is the one still an ancestor, so building on it is the better choice; recorded so the comment and behaviour agree.
- **Fix**: none required; reword the comment, or sort rounds by `round` explicitly if the documented order is intended.
