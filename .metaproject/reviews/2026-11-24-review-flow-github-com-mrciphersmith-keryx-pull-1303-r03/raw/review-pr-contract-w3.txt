## Findings

### [PC-008] The body says the 422 behaviour was "exercised only through fixtures"; no fixture or test drives a 422
- **Severity**: minor
- **File**: src/review/desk-publication.test.ts:92
- **Problem**: The body's Not verified section says: "The GitHub compare call and the 422 behaviour were exercised only through fixtures." The compare half holds, through the `api:repos/*/compare/*` fixture. The 422 half does not. The only POST branch of the gh fixture is `'  api:--method) cat > "$FIXTURE_BODY"; printf \'{"id":23}\\n\' ;;'`, which always succeeds. `keryx ctx rg "422|rejected this review|HTTP 422" src --glob '*.test.ts'` finds no desk-publication test. The only review hit is publish.test.ts:162, the CLI `publishReview` path, which is not `requestDeskPublication`. So desk-publication.ts:452 is never run by a test, and neither is a 422 on an as-is post with `commit_id` set to an older commit. That branch is `if (rejected === 422) throw new Error("configuration: GitHub rejected this review. ...")`. Journal :58 says the round 1 major was fixed "regardless of whether GitHub returns 422". The 422 premise was never exercised.
- **Why it matters**: The owner reads "exercised only through fixtures" and concludes that the 422 path has at least fixture coverage. In fact it has none: neither the refusal on an older `commit_id` nor the message the user sees has been run. That message tells the user to check the verdict and inline comments, but on the as-is path both are forced.
- **Fix**: Correct the claim to "the compare call was exercised only through fixtures; GitHub's 422 response was not exercised", or add a gh fixture case that makes the POST fail with `(HTTP 422)` on a moved head and assert the error and that no receipt remains.
