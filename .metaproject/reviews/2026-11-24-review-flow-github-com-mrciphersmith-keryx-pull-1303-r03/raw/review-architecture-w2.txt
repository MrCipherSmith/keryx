### Other checks (clean)
- Registry lock (T14 B3): `appendRoundRegistry` runs append and compaction under the sync `lib/file-lock.ts` lock and throws on contention. Both writers catch the throw. `recordFinishedRound` returns `{error}`. `recordPartialRound` returns `{error}`, so `.file === undefined`, and the executor moves to the next candidate. `appendRoundRegistry` has exactly these two production callers (round-registry.ts:260 and :303). Using the sync lock here instead of the async `lib/fs` withFileLock fits, because the registry API is synchronous. Both helpers already existed before this PR.
- Compaction keeps the newest entry per packageId regardless of event. A desk-partial entry could evict a finished entry only if one package had both. That is not reachable: a closed package is handed on as closed before `recordPartialRound` is tried, and `recordFinishedRound` refuses a package that is not completed.
- Superseded as-is (T14 B6): `newerRoundOf` sits in update-round.ts beside the other round rules, and desk-publication only consumes it. The publication policy stays server-side.
- `ExecutorPorts.registryDir` and `RoundRegistryPorts.beforeCompactionWrite` are test seams on existing ports objects. The service passes the directory resolver into `previousRunInputs` as a function, so update-round.ts stays free of store I/O.

### Design Pattern Misuse
[F-001] info: `selectPriorAttempt` and `previousRoundAttempt` are exported "first candidate, no fallback" selectors with no production caller, and the PR body still names `selectPriorAttempt` as the rule
- File: src/review/update-round.ts:45 (also :76)
- Problem: after T14 B1 the production path is `previousRunInputs` → `priorAttemptCandidates` plus the executor's ordered fallback. `selectPriorAttempt` (:45) and `previousRoundAttempt` (:76) return `[0]` of the list, which is exactly the no-fallback shape that r02 F-005 removed. `keryx ctx rg` finds them only in update-round.test.ts and desk-run-service.test.ts. pr-context.md:32 still says "One rule chooses the previous attempt: `selectPriorAttempt`".
- Why info: no production code calls them, so there is no failure path today (shared law 1). The cost falls on the next caller, who would pick the advertised function and get a selector that skips the disk check and the fallback.
- What would settle it: drop the two wrappers, or mark them test-only. Point the PR body at `priorAttemptCandidates` / `previousRunInputs` with the executor's hand-on check. The body wording itself belongs to the pr-contract lens.
