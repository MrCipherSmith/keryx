### What was checked against the T15 fixes and the new Desktop surface
- **Update review start (`ReviewWorkspace.updateReview`, `ReviewRuns` onUpdateReview).** The revision it sends is `{ baseSha: run.baseSha, headSha: headMoved.currentHead }`, where `currentHead` comes from the backend's preview state. The backend does not trust it: `runDeskAction` calls `verifyDeskSubject(cwd, key, revision)` for `start`, which refuses unless the PR is open and base/head equal GitHub's `baseRefOid`/`headRefOid`; the CLI also accepts only 40-hex SHAs. A tampered or stale value therefore cannot start a review on an arbitrary range. No finding.
- **Options carried into the update round.** `updateRoundOptions` drops `autoPublish`; the remaining options come from the user's own stored attempt and are re-parsed by the CLI start path (`parseDeskReviewOptions`). Automatic publication additionally refuses a moved head server-side (AC2). No privilege or trust gain. No finding.
- **XSS / rendering.** New strings (`shortSha(...)`, toast title with `revision.headSha.slice(0, 7)`, head-moved banner) are rendered as React text nodes or `<code>` children, never via `dangerouslySetInnerHTML`; markdown rendering still goes through the existing `ReviewReportMarkdown`. No finding.
- **Publication target URL.** `sessionReviewPublication` builds the same `https://github.com/<repo>/pull/<n>` as before (pure extraction), and `RunAttempt` still gates publication on the strict `^https://github.com/<owner>/<repo>/pull/<n>/?$` regex. Sessions offers no Update review (no `onUpdateReview` passed). No finding.
- **Busy/race guard.** `useReviewRuns.request` now returns `done | skipped | failed`; the skip rule (`pending.current` mutation guard) is unchanged, so a stale status read still cannot roll back a mutation. Board refresh runs only on `done`. Not a security surface; no finding.
- **Flow records (`.metaproject/flows/520-.../*`).** No credentials, tokens or keys. The resolved/*.json files hold rule paths and sha256 content hashes only. `flow.json` records the flow owner's name as stated by the `--owner` flag, which is the project's existing flow convention (not a secret). No finding.
