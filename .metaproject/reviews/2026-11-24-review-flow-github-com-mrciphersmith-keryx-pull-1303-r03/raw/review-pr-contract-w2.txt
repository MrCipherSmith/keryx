## Findings

### [PC-006] The body says answers come from "the previous round's draft"; the code takes the newest earlier-round attempt that saved a draft
- **Severity**: minor
- **File**: src/review/desk-publication.ts:116
- **Problem**: PR body, What changes 2: "Keep and dismiss answers from the previous round's draft are pre-selected in the new round's draft, matched by finding id." The code is `savedAnswers = saved?.answers ?? await earlierAnswers(earlier)` (:171) over `earlierRoundAttempts(runs, found.run).slice(0, 8)`. `earlierAnswers` (:116) returns the answers of the first attempt in that list with a `publication-draft.json`. So (a) when no attempt of round N-1 saved a draft, answers come from round N-2 or older; (b) inside round N-1, the newest attempt with a draft wins, while the findings come from `priorAttemptCandidates` (complete before partial). The two can be different attempts. Also option answers carry over, not only keep and dismiss. This is the T14 B2 decision recorded in the journal. Round 2 PC-005 asked to either align the code or narrow the body. The code moved to `earlierRoundAttempts` and the body was not changed.
- **Why it matters**: A reader who trusts the body expects pre-selected answers from the round the update builds on. Answers from an older round, or from a different attempt of that round, can be pre-selected. They remain visible and editable before submit.
- **Fix**: Reword the bullet to state B2, for example: "Answers (keep, dismiss and option choices) from the newest earlier round of the same Review that saved a draft are pre-selected, matched by finding id; deleted or archived attempts are skipped. The new round's own draft always wins."

### [PC-007] The Desktop guide promises Publish as is whenever commits were pushed on top; a superseded round gets neither it nor Update review
- **Severity**: minor
- **File**: docs/docs/desktop-app.md:143
- **Problem**: The guide says: "If new commits were pushed on top of the reviewed commit, the dialog names both commits and offers **Publish as is for** the reviewed commit instead." It lists only "closed, its base changed, or its history was rewritten" as the save-locally cases (:147-148). desk-publication.ts:378 sets `headMoved` only when `newerRoundOf(...) === undefined`. A round superseded by a newer round of the same Review (any state, a failed or running one included, T14 B6) gets `blockedReason` "Round N of this review is newer. Publish from that round." (:297), and no `headMoved`. So the dialog has no "Publish as is" and no "Update review to". The PR body lists this decision; the guide does not.
- **Why it matters**: A user opens an earlier round's result after an update round started, which is the usual case once Update review exists. Following the guide, they expect Publish as is and get a refusal. The dialog does state the reason, so the cost is confusion, not a wrong post.
- **Fix**: Add one sentence after :148: "If a newer round of the same review exists, publish from that round; the earlier round can only be saved locally."
