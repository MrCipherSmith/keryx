### Clean Areas
- **`ReviewWorkspace.updateReview` (T15)**
  - It now filters `local.runs` and calls `latestAttempt`. Each is an O(n) pass over the attempts of one PR.
  - It runs once per click on "Update review". It does not run on render or on a poll.
  - Its `useCallback` deps include `card` and `local.runs`, which change on every status poll. The `publication` literal that carries it is rebuilt on every render anyway, so the memoisation buys nothing.
  - This adds no re-render. `ReviewRuns`, `RunAttempt` and `ReviewPublishDialog` are not `React.memo`, and the `publication` object was already rebuilt on every render before this PR. Not a finding.
- **`ReviewWorkspace`, redundant calls**
  - A click makes one `start` request through the existing `local.request`.
  - The board is re-read once, and only when `outcome === "done" && boardBehind`.
  - The `skipped` outcome only shows a toast. It does not retry or poll.
  - When the target range already has an attempt, nothing is sent.
- **`useReviewRuns.request` (T15)**
  - The only change is the return value (`"done" | "skipped" | "failed"`).
  - Control flow, the generation guard and the follow-up status read in `finally` are unchanged. No polling is added.
- **`latestAttempt` (ReviewRuns.tsx)**
  - This is an extraction of the existing two-`find` expression that `ReviewRuns` already ran on every render. Its cost did not change.
- **`ReviewPublishDialog`**
  - `headMoved`, `updateOffered` and `publishButton` are derived from `draft` during render, with no new state or effect.
  - `shortSha` is a 7-character slice. `useId` is stable.
  - The dialog opens on demand and is not a high-frequency surface.
- **`SessionReviewActivity.sessionReviewPublication`**
  - It replaces an inline object literal with a function that returns the same literal. The cost is the same as before.
- **Memory leaks**
  - No new listeners, timers, intervals or subscriptions in slice-01.
  - The `.then` on `local.request` runs once and holds nothing long-lived. A late toast after unmount was already possible on this path and is not a leak.
- **Bundle and imports**
  - The new imports are `DeskReviewOptions` (type-only), `reviewIsArchived` from `./ReviewLifecycle` (already in this bundle through `ReviewRuns`) and `latestAttempt` and `runActive`, which are siblings that are already loaded.
- **Not applicable to this slice**
  - N+1, indexes, pagination, and sync I/O on an interactive path: no such code is in slice-01.
  - The flow records are data, not runtime code.
