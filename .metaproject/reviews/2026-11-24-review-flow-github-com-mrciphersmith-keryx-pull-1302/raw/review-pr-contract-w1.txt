### [PC-001] "Desktop runs the same command" is stated as current, while Desktop still says the opposite

- **Severity**: minor
- **File**: src/gdskills/bundled/skills/review/review-orchestrator/SKILL.detail.md (same text in .metaproject/skills/gdskills/review/review-orchestrator/SKILL.detail.md)
- **Problem**: Head moved step 4 says "`keryx review advance` opens the next round of the same Review on the current head; Desktop runs the same command." The PR body says that item is not done: "Item 3, the session uses the same update command (T8). `keryx review advance` comes with stage 3. The Desktop prompt line 'New commits belong to a separate request' (`src/review/autonomous-profile.ts:199`) is replaced then." The tree at head still has `src/review/autonomous-profile.ts:199` "New commits belong to a separate request."
- **Why it matters**: an agent or operator reading the skill takes Desktop parity as true today; the PR body and the code say it is not.
- **Fix**: word it as the target, e.g. "Desktop will run the same command (stage 3)", or drop the clause until T8 lands.

### [PC-002] The "Stop and start on the new head" path relies on a partial round that the fallback does not read; the caveat is only in the PR body

- **Severity**: minor
- **File**: src/gdskills/bundled/skills/review/review-orchestrator/SKILL.detail.md (same text in the installed copy)
- **Problem**: step 3 option "Stop and start on the new head: dispatch nothing more, ingest what finished as a partial round, then step 4; the area it did not cover enters the new plan as unchecked", and step 4's fallback "`keryx review plan ... --head <new sha>` ... attaches the prior findings". `src/review/round-record.ts:207`: "a draft or partial package is never a previous round". The PR body's Not verified section concedes this ("may not yet treat a partial package as the prior round (`round-record.ts:207`), which is stage 3's change"), and journal.md says the same, but the shipped skill text states the outcome with no caveat.
- **Why it matters**: an operator who picks the second option today gets a new round that does not carry the partial round's findings, while the skill told them it would.
- **Fix**: add one clause to that option (until `advance` exists, the fallback ignores a partial package, so its findings are not attached), or restrict the fallback text to the "Update after this round finishes" option.
