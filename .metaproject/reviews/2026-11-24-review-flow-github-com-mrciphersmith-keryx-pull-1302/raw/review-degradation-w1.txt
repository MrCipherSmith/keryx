## Findings

### [DEG-1] Head check at every wave boundary is a `gh` call, which the skill says always asks the operator and should be made once

- Severity: minor
- Class: behaviour-delta
- Evidence kind: base-diff
- File: .metaproject/skills/gdskills/review/review-orchestrator/SKILL.detail.md (§ "Head moved", step 1). The same text is in the bundled copy.
- Problem: On base, nothing ran between waves except `keryx review next`. On head, step 1 says to run `gh pr view <n> --json headRefOid --jq .headRefOid` at every wave boundary, before `complete` and before publishing. Round plan step 5 in SKILL.md now does the same before every `keryx review next`. The unchanged SKILL.md "Terminal or card only" bullet (diff context, SKILL.md line 52) still says: "A `gh` call still asks: that is expected, so make it once and reuse what it printed." The two rules contradict each other, and an agent cannot follow both. In a `trust`/`auto` session, reviewer replies are external-agent results that have already entered the turn. From then on, every wave boundary adds a permission prompt to a loop that "Between waves" requires to run without pauses ("No question about pace", "Do not end the turn before `next` returns `done`"). The prompts also pile up: one per wave, plus `complete`, plus publish.
- Why it matters: a round that ran through its waves without a stop on base now stops at a permission prompt after every batch until the operator answers. The result is delayed, not wrong, so this is minor.
- Fix: say how the check stays routine. Either (a) one `gh pr view` per wave boundary is the expected prompt, and the "make it once" sentence gets that exception, or (b) the check runs only before `complete` and before publish, plus at wave boundaries only where a `keryx` command already returns the PR head. Option (b) needs a `keryx review next` field such as `prHead`. Today there is none (unverified: I did not read `next`'s output shape).
- Refute: I read the base SKILL.md text in the slice context (line 381 of slice-01 = SKILL.md:52). The "make it once and reuse" sentence is unchanged. No new sentence in the diff exempts the per-wave head read. Round plan step 1 already used `gh pr view` once, which is consistent with "once", not with "every wave". The PR body does not name the prompt cost.
