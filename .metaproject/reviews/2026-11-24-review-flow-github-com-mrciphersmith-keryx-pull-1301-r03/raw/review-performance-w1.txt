### Summary
- blocker: 0 | major: 0 | minor: 0 | info: 0

No new performance problem in this delta. What was checked, with the execution frequency of each:

- **Stale re-read on catalog load** (useMetaprojectTree.ts, the `reload` effect): runs once per change of the `catalog` object. MetaprojectView sets a new catalog only on a user-driven non-quiet load (Refresh catalog, Rebuild, project change) or a quiet read that finds a new snapshot (MetaprojectView.tsx:390-421; a quiet read with the same snapshot returns before `setCatalog`). There is no polling. Each run walks the folder keys of both scopes once (O(folders loaded)), re-reads only `stale` ones, and those reads go through the existing 3-slot limiter. It does not run on mount (`loadedCatalog` starts at `reload`), and after a new snapshot the folders are already empty. Each catalog load re-reads a stale parent at most once, so it cannot loop.
- **Focus hand-off** (MetaprojectTree.tsx `handOff`, `remember`, the layout effect, `onFocus`): this work runs on every render and every focus move, including keyboard repeat through a long tree. `remember` now does `shown.current.findIndex` (O(rows)) where it used to do `elements.indexOf` (O(rows)), so the cost has the same order. `handOff` is O(1) for entry rows. For a status row it scans back with `rows.slice(0, index).reverse().find(...)`, O(index) plus one array, and only for Loading or Show more rows, which are few. `flatten` already costs O(rows) every render. The layout effect's extra `rows.slice(at + 1)` runs only when the focused row has gone. The `rowElements()` query on every render is unchanged from before the delta.
- **withPermitRetry** (useMetaprojectTree.ts:29-40): this lifts the round-2 retry out of `read()` without changing its behaviour: same count (2), same jittered linear wait, the same liveness check before and after the wait. The slot held during the wait was in the code before this delta (operator decision: a retired in-flight read keeps its limiter slot). Nothing new to report.
- **isMetaprojectPermitRefusal** (platform/metaproject.ts): one `instanceof` and one `startsWith` per failed read. Negligible.
- **MetaprojectView `reload: catalog`**: passes the same object reference between renders, so the effect does not run on every render.
- Bundle, N+1, indexes, pagination, leaks (no new listener, timer or subscription; `sleep`'s setTimeout is one-shot and awaited), synchronous blocking: nothing in the delta applies.

Note on slice-03: it shows two hunks removing lines from apps/desktop/src/platform/metaproject.ts (`if (isMetaprojectV2Response(response, "capabilities")) return 2;` and the `expectedSnapshotId` check in `matchesRequest`). `git diff b2043b98d 3ad918b66 -- apps/desktop/src/platform/metaproject.ts` shows only the 12 added lines (the permit-refusal constant and classifier).
