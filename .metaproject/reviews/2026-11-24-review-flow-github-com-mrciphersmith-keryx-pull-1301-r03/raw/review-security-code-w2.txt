No security finding in the round-3 fix. What changed security-wise and why it is clean:

- **Permit refusal classification** (`isMetaprojectPermitRefusal`, platform/metaproject.ts): a prefix match on Desktop's own refusal text, excluding typed `MetaprojectRequestError`s. A CLI cannot turn its typed errors into retries; a CLI that prints the same prefix as an untyped error only buys at most `PERMIT_RETRIES` (2) extra reads per folder, bounded by `MAX_TREE_READS` (3) in flight. No amplification path.
- **`withPermitRetry` jitter** uses `Math.random()` for a back-off delay only, not for a token, nonce or identifier: not a crypto concern.
- **Stale-snapshot parking and `reload: catalog`**: parked reads are re-sent only after a catalog load; a snapshot change still resets every folder (state rebuilt from `emptyScope`), so a cursor issued under a retired snapshot is never sent to a different snapshot, and the transport still refuses any answer whose `snapshotId` differs from the pinned `expectedSnapshotId`.
- **Request boundary unchanged**: the Tauri `RequestV2::Tree` validation (`relative_path` for a graph parent: no `..`, `.`, empty, backslash, control chars, drive letter or leading `/`; `valid_text` for a wiki key and cursor; `deny_unknown_fields`; null values refused; 16 KiB cap) and the argv-array spawn (`metaproject-explorer --request <json>`, no shell) are untouched by this round.
- **Response boundary unchanged**: `validTree` / `validTreeEntry` check scope, parent, page size (100), relative folder paths, module/path agreement and node kinds; `matchesRequest` ties scope and parent to the request.
- **Rendering**: CLI-supplied error messages, folder names, node titles and kind labels are rendered as React text children; no `dangerouslySetInnerHTML`, `eval`, `postMessage` handler or storage of sensitive data in the changed code. The `console.error` in `limit` logs an internal exception object, no secrets.
