### Round 1 obligation (performance F-001): holds
Round 1 minor F-001 was that automatic publication on a moved head fetched the full PR discussion (three paginated `gh api` reads) and then refused anyway. That is fixed. `src/review/desk-publication.ts:385` now throws `configuration: This review needs a publication decision in Desktop.` for `request.kind === "automatic" && open && !current`. This happens before `reviewedHeadInPull` (the compare call) and before `prepare`, so `publicationDiscussion` is never reached. The `request.kind === "automatic"` term in the discussion guard at line 218 is now unreachable when the head has moved. It is harmless.

### Clean Areas
- **Dialog re-renders (`ReviewPublishDialog.tsx`).** The new values `headMoved` and `updateOffered` are derived from `draft` with no new state or effect. `useId()` for the notice is stable. `shortSha` is a 7-character slice. The new `disabled` and `aria-describedby` props cost nothing measurable. The dialog is opened on demand and is not a high-frequency surface.
- **Preview traffic with a moved head.** Each settings change in the dialog sends a preview. That was already true. The new per-preview work is bounded:
  - `reviewedHeadInPull` (desk-publication.ts:99-112) reuses `cache.aheadHead` and calls the compare API only once per new current head, with `per_page=1`.
  - The subject cache keeps its 15 s TTL.
  - `earlierAnswers` (lines 134-140) reads earlier drafts only when neither the request nor the attempt's own draft has answers (`saved?.answers ?? …`). The dialog sends `settings` on every request after the first, so in practice this runs once, on the first preview.
  - `earlierAttemptDirectories` (lines 119-131) is capped by `answerSourceLimit` (8 hops), uses a seen-set against cycles, and makes one `store.byId` lookup per hop inside the single store open.
- **`ReviewWorkspace.updateReview`.** It is a `useCallback` with deps `[card, action.open, local.request, onRefreshBoard]`. It runs once per click. The `publication` object literal it is placed into is rebuilt on every render, which defeats the callback's memoisation. That object was already rebuilt every render before this PR, and `ReviewRuns`/`RunAttempt` are not `React.memo`, so no re-render is added. This is not a finding.
- **`ReviewRuns.tsx`.** The inline `onUpdateReview` arrow is created only while the dialog is open (`draft && publishOpen`) and is passed to an unmemoised dialog, so it adds no cost.
- **Redundant calls.** "Update review" makes one `start` request. It refreshes the board only when the board is behind the push (`boardBehind`), and it starts nothing when the current head already has an attempt (`action.open`).
- **Not affected by this slice.** N+1, indexes, pagination, memory leaks (no new listeners, timers or subscriptions), bundle imports (only type imports were added) and sync I/O on an interactive path: nothing new in slice-01. The flow records, docs and DOM test fixtures are not runtime code.
