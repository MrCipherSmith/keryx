### Summary
T12 replaces the worker's old previous-attempt filter (completed, complete, same options key) with `previousRoundAttempt` → `selectPriorAttempt`. It also lets a partial Desktop attempt become a delta base through a new `desk-partial` registry event, which only the Desktop executor writes, from the user's run store. T13 adds the head-moved as-is variant on the server side: a same-base `ahead` compare, fail closed, a forced Comment with no inline comments, and the expected head re-verified before the write. It also carries answers from earlier attempts. The direction of dependencies is sound: update-round.ts is pure, the service imports it, the executor gets the registry dir through a port, and prior-round reads the registry as data. The round-1 fix from T11 ("as is only while the reviewed commit is in the PR") holds in `reviewedHeadInPull`. Wave-1 F-001 (the answers rule disagrees with selectPriorAttempt) is anchored in this slice and is not repeated here. I found two new minors.

### Layer Violations

### Module Boundary Violations
- [F-004] minor: the rule "a `desk-partial` entry vouches only for a partial round" is enforced by a caller-side filter in prior-round.ts, not inside the round-registry API. The registry's own `registryVouchesPackage` still counts desk-partial entries. Details are in REVIEW_RESULT.

### Design Pattern Misuse
- [F-005] minor: "the previous attempt has accepted findings" is checked by three different predicates across three modules. selectPriorAttempt can pick an attempt that the executor then refuses to hand on, and that attempt hides an older usable round. Details are in REVIEW_RESULT.

### Dependency Inversion
None detected. `ExecutorPorts.registryDir` is a test seam on the existing ports object. The default is the user's config directory.

### Verified clean (sites)
- T11 fix holds: `reviewedHeadInPull` (desk-publication.ts) accepts only `status === "ahead"`. Any failure, `diverged` or `behind` keeps the refusal. Automatic publication throws before any compare or discussion read. The write verifies `expected` (base plus current head) and posts with `commit_id: run.headSha`. The digest includes `currentHead`. The tests cover diverged, behind, gh failure, a non-sha head, head moved again, and automatic publication.
- One rule for the worker's previous attempt: desk-run-service.ts:385 is `previousRoundAttempt(store.history(key).runs, run)`, and the options-key filter is gone. desk-run-service.test.ts pins this.
- The trust boundary for the partial vouch: `recordPartialRound` has exactly one production caller, desk-run-executor.ts:529 (`keryx ctx rg --all "recordPartialRound|partialRoundVouch|desk-partial" src apps`). `recordFinishedRound` refuses non-completed packages, so a desk-partial vouch cannot be turned into a finished-round entry through decide-premise.
- head-move.ts still has no production caller. That is the recorded follow-up from round 1, and I did not re-raise it.
