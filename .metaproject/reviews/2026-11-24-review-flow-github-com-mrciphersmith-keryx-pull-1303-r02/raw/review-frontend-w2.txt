### Findings

### [F-001] (info) Answer carry-over works only for findings that keep their global_id across rounds, and the dialog cannot tell carried answers from the user's own
- **Severity**: info
- **File**: src/review/desk-publication.ts (`earlierAnswers`, `savedAnswers` in `prepare`; `questionId`)
- **Rule**: canonical rubric (an observation with no concrete bug)
- **Problem**: Answers carry over keyed by `questionId(entry) = global_id || entry.id`. `assignGlobalIds` (managed.ts:2026) mints `<reviewId>#<id>` for every finding that has no key, and the per-round package reviewId differs. So a held finding is matched only when the round N+1 reviewer carries round N's key through `prior_findings[].finding`. In a `fallback-first` (full) round, or when a reviewer re-reports a finding without carrying its key, nothing is pre-selected. The update-round tests use a constant `fixture#F-002` in both rounds, so they exercise only the carried-key path. The bare-`id` fallback (`F-002`) could in principle match a different finding in the next round, but only when both rounds lack global_ids, which the managed ingest prevents. The draft has no field marking answers as carried from the previous round: `savedAt` is absent and the answers look like the user's own. So the dialog cannot say "pre-selected from round N".
- **Why it matters**: There is no wrong output on the designed path. AC10's pre-selection may show up less often in a real update round than the fixtures suggest. AC9/AC10 have not been run live.
- **Fix**: Optional. Add a test where round N+1's findings carry no global_id (re-minted), to state that nothing is pre-selected then. If the UI should label inherited answers, return a marker such as `answersFrom: <previous attempt id>`.
