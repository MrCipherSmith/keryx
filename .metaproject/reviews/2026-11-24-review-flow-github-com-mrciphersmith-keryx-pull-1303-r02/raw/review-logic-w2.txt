### Logic Bugs
[F-001] (major, confidence medium) The previous-round rule selects a partial attempt that the executor then refuses to hand on, and the round loses the older finished round it used to build on.
- File: src/review/desk-run-service.ts:311-318 (`previousRoundAttempt`) with src/review/update-round.ts:22 and src/review/desk-run-executor.ts:525-530.
- Problem: the selection and the hand-on use two different tests for "accepted findings".
  - `selectPriorAttempt` accepts a partial attempt when `result.findingsKnown === true` and returns only that one attempt.
  - `collectResult` (desk-run-executor.ts:389-402) sets `findingsKnown = true` whenever `evaluated.source === "raw reviewer results"`, even when there is no ingested findings.json. Without an owned package, `findingsKnown` comes from summary counts (`summary.findingsKnown ?? counts > 0`, :370).
  - The executor hands a non-closed package on only if `recordPartialRound` succeeds, and that requires `findings.json` to hold a list. Otherwise `handOn` is false and nothing is copied. `previousRoundAttempt` offers no second candidate, so the round starts with no previous package at all.
- Trigger:
  - Round 1 completes: closed package P1, `coverage: "complete"`.
  - Round 2 stops partial (budget or stall) after reviewers wrote raw results but before ingest, so `findingsKnown: true`, the manifest is a draft, and there is no findings.json list.
  - The user clicks "Update review" (round 3). `previousRoundAttempt` returns the round 2 attempt with `partial: true`. `recordPartialRound` returns `skipped: "the partial round has no ingested findings.json"`, so `handOn` is false. `findPreviousRound` in the fresh checkout then finds no local package.
  - Round 3 runs as round 1 (`mode: "first"`) over merge-base..head. It has no prior findings, no carried list and no fix hunks.
  - Before T12, the old rule (completed + complete + same options) picked P1, so round 3 was a delta with round 1's findings attached.
- Why it matters: silent wrong result on a named input. The update round, which the user started to build on earlier rounds, presents itself as a first review. The round number is reset, every prior finding is dropped from context, and the whole range is re-reviewed at full cost. AC7 says a new attempt on a newer head "builds on the previous round". Here it builds on nothing, even though a trusted finished round exists. The executor test (desk-run-executor.test.ts "a draft package is not handed on unless…") asserts the refusal, but no test covers the missing fallback.
- Fix (one of):
  1. Return candidates in order and let the executor hand on the first usable one. `previousRoundAttempt` returns the filtered list run through the same predicate as `selectPriorAttempt` (newest first). The worker passes `previousRuns: [{dir, partial}]`. The executor tries each one, in the closed branch or the `recordPartialRound` branch, and stops at the first copied package.
  2. Narrow the selection to what the executor can hand on. In the worker, skip a `partial` candidate whose `store.directory(id)/package/findings.json` does not parse to an array (for example with `knownFindingList`), then select again. Then `selectPriorAttempt`'s "accepted findings" means the same thing as `recordPartialRound`'s.
- class_scope:
  - sites: ["src/review/desk-run-service.ts:318", "src/review/desk-run-executor.ts:529"]
  - enumeration_method: `keryx ctx rg "selectPriorAttempt|previousRoundAttempt|previousPartial|recordPartialRound" src apps/desktop/src --all`. Outside tests, selectPriorAttempt has one caller (previousRoundAttempt). That has one caller (runDeskWorker :385), which feeds the single hand-on site in executeDeskReview (:525-530). Desktop has no caller. Producers of `findingsKnown: true` without an ingested list: desk-run-executor.ts:370 (summary counts) and :390/:402 (`raw reviewer results`), plus desk-run-service.ts:87 (`coverage complete || counts > 0` fallback).
