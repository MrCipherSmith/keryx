### Findings

### [F-001] "Update review" can close the dialog and start nothing, with no feedback, when another run mutation is in flight
- **Severity**: minor
- **File**: apps/desktop/src/review/ReviewWorkspace.tsx:1950 (slice line), `updateReview`; with `apps/desktop/src/review/useReviewRuns.ts:32`
- **Rule**: canonical rubric (no rule row covers it; `code-style-patterns.mdc` is absent from this worktree)
- **Problem**: `useReviewRuns.request` returns early, without setting an error, when a non-status action is already pending (`if (pending.current && (action.kind === "status" || pending.current !== "status")) return;`). The Update button in the publish dialog is disabled only by the dialog's own `writing`, not by the workspace's `working`, and `RunAttempt` closes the dialog before calling `updateReview`. If the user clicks Update while a cancel/start/answer is still running in the workspace, the dialog closes, the start is silently dropped, and in the board-behind case `.then(() => onRefreshBoard?.())` still refreshes the board as if the round had started.
- **Why it matters**: The user's explicit action is lost with no message; they see the dialog close and no new attempt. Narrow window (needs a concurrent mutation), so it is not a correctness bug of the main path.
- **Fix**: Pass the workspace's `working` to the dialog (or to `PublicationTarget`) and disable "Update review" while it is true; or have `request` report whether it ran and only refresh the board / close the dialog when the start was accepted.

### [F-002] (info) The current-head-already-has-an-attempt guard uses `launchAction(...).open`, which is false for a partial or failed attempt on the current head
- **Severity**: info
- **File**: apps/desktop/src/review/ReviewWorkspace.tsx:1949 (slice line)
- **Problem**: `if (!boardBehind && action.open) return;` skips the start only when the current range has an active attempt or a completed full-coverage one. With a partial/failed attempt already on the current head, Update starts another attempt (the same as the panel's "Retry review"). This matches the launch semantics and the PR decision text ("If the current head already has an attempt, nothing new starts") only approximately; no defect, recorded so the decision wording can be read precisely. In the board-behind case the guard is skipped entirely and the backend decides.
