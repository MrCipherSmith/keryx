### [F-001] Round registry compaction is an unlocked read-modify-write, now also reached from concurrent Desktop workers
- Severity: major (location_class pre-existing: the compaction code is not in the diff; the new writer recordPartialRound is)
- File: src/review/round-registry.ts:139 (appendRoundRegistry); new caller src/review/desk-run-executor.ts (recordPartialRound in the hand-on of a partial previous package)
- Pattern: Part 0 / concurrency-patterns.mdc Rule 2. A read-modify-write of a shared state file holds no lock.
- Failure mode: The registry is one file per repository identity, shared by every clone and worktree on the machine. appendRoundRegistry appends a line, which is safe. But once the file is past REGISTRY_COMPACT_BYTES (512 KB), it reads the file, compacts it and renames a rewrite over it, with no lock. Process X can read and compact while process Y appends. X's rename then drops Y's line. Two processes that can reach this are named: two Desktop workers for two PRs of the same repository, each running recordPartialRound in executeDeskReview; or one Desktop worker and a `keryx review ingest|complete|publish` or decide-premise in another session. The lost entry is a trust record. The `review start` in the update round's checkout then finds no `desk-partial` vouch for the package it was just handed. It falls back to a full review with the prior findings as context, so AC7's delta round is silently lost for that round. A lost `complete`/`publish`/`decide-premise` entry costs the same. No trust is granted wrongly, since a missing entry only removes trust. A second effect, in the same code: when the repository has more distinct packages than fit in 512 KB (about 1,500 entries), compaction cannot shrink the file below the threshold. Every append then rewrites the whole file and opens this window, and once the file passes the 1 MB read cap it is restarted with one entry, which drops every vouch.
- Why major, not blocker: the table rates a lost write `blocker`. But what is lost here is a record whose absence the registry's own contract treats as one more full round ("costs at most one full round per package, never trust it should not give"). The race needs the file past 512 KB. And the code predates this PR, so as pre-existing it does not block the merge.
- Fix: Take an exclusive-create lock file (O_EXCL, with PID or age stale recovery, released in finally) beside the registry for the compaction branch. Re-read the file under the lock before rewriting, so an append that landed after the first read is kept. Optionally compact on a count of distinct packages, with eviction of the oldest packages, so the file shrinks below the threshold instead of being rewritten on every append.
