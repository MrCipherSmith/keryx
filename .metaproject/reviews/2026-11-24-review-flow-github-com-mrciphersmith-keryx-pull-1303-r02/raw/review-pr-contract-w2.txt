## Findings

### [PC-004] The body says automatic publication refuses a moved head "before it makes any GitHub read"; the code reads the PR first
- **Severity**: minor
- **File**: src/review/desk-publication.ts:384
- **Problem**: PR body, What changes 1: "Automatic publication refuses a moved head before it makes any GitHub read." In `publication()`, `const cache = await previewSubject(cwd, directory, key, connection, request, run);` (line 380) reads the pull request (`verifyDeskSubject`; an automatic request never uses the cache) before `if (request.kind === "automatic" && open && !current) throw ...` (line 385). The code comment says "before any further GitHub read", and the test is named "refuses before any compare or discussion read".
- **Why it matters**: A reader of the body may think the refusal needs no network. In fact it needs one PR read to see that the head moved; only the compare and discussion reads are skipped.
- **Fix**: Change the body to "before it makes any compare or discussion read (after the one read that shows the head moved)".

### [PC-005] Answers carry over along the `previousRunId` chain, not from the previous round `selectPriorAttempt` picks
- **Severity**: minor
- **File**: src/review/desk-publication.ts:119
- **Problem**: The PR body says "One rule chooses the previous attempt: `selectPriorAttempt`, over the earlier rounds of the same Review", and "Keep and dismiss answers from the previous round's draft are pre-selected". The Review section says T12 merged the "two different rules for choosing the previous attempt" into one. But `earlierAttemptDirectories` (desk-publication.ts:119) is a second selection. It follows `previousRunId` up to `answerSourceLimit = 8` attempts, checking only `sameReview`, and `earlierAnswers` takes the newest of them that has `publication-draft.json`. Stage 2 sets `previousRunId` to the newest attempt of the previous round, or to the newest attempt of the same round for a retry (desk-run-store.ts:192-198). So that newest attempt may be one `selectPriorAttempt` rejects. It may be withdrawn (decision `delete` or `archive`), and `byId` still returns it while `history` drops deleted attempts. It may be from an older round than the one the new round was cut from, or a retry of the same round. Example: the previous round's newest attempt had no draft but has findingsKnown false. Then the round builds on round N-2 (by `selectPriorAttempt`) while its answers come from whichever earlier attempt in the chain saved a draft.
- **Why it matters**: A reader who trusts the body expects one previous attempt for both the findings and the answers, which was the round 1 point. Answers from a withdrawn attempt, or from a round other than the one the findings came from, can be pre-selected. They are still visible and editable before submit, so the cost is a wrong default, not a wrong post.
- **Fix**: Either take the answer source from the same `selectPriorAttempt` choice (or apply its delete/archive exclusion in `earlierAttemptDirectories`), or narrow the body to "answers from the newest earlier attempt of the same Review that saved a draft".
