## Findings

### [PC-001] The Desktop guide's head-moved paragraph omits the new primary action "Update review"
- **Severity**: minor
- **File**: docs/docs/desktop-app.md:143-144
- **Problem**: The guide, updated in this range, says the head-moved dialog "names both commits and offers **Publish as is for** the reviewed commit instead." The diff (T13) makes "Update review to <sha>" the first, primary footer button of that same dialog (ReviewPublishDialog.tsx `className="btn btn-primary" ... Update review to <code>{shortSha(headMoved.currentHead)}</code>`) and demotes Publish as is to a secondary button. The PR body calls it "the primary action". No document names the button or says it starts the next round on the current head with the same settings.
- **Why it matters**: A Desktop user who reads the guide before a pushed-to PR sees an unexplained primary button and is told only about publishing as is or saving locally; they do not learn that the recommended path is a new round that builds on the previous one and carries their keep/dismiss answers.
- **Fix**: Add one sentence to that paragraph: the primary action **Update review to <sha>** starts the next round of the same review on the new commit with the same settings, builds on the earlier findings and pre-selects your earlier keep/dismiss answers; **Publish as is** remains available.

### [PC-002] AC3's verify command points at a test file the rebase removed, while the body says the AC suites pass
- **Severity**: minor
- **File**: .metaproject/flows/520-2026-11-24-desktop-review-v2-stage3/acceptance-criteria.md:20
- **Problem**: PR body Verification: "`bun test` passes for the review suites listed in the flow's acceptance criteria." AC3 reads `[verify: exec \`sh -c 'cd apps/desktop && bun test src/review/ReviewRuns.dom.test.tsx'\`]` (also flow.json acKinds.AC3.check). `git ls-files | grep -i ReviewRuns.dom` returns nothing at head: stage 2 renamed it to apps/desktop/src/reviews/ReviewPanel.dom.test.tsx (journal: "stage 2 renamed ReviewRuns.dom.test.tsx to reviews/ReviewPanel.dom.test.tsx"), where the AC3 tests now live. AC7, AC8 and AC10 were updated after the rebase; AC3 was not.
- **Why it matters**: The command of the suite AC3 names finds no test file, so `keryx flow ac confirm 520 AC3` (exec) cannot pass as written, and a reader of the body believes every AC suite was run green. The tests themselves exist and pass (Desktop src/reviews in the brief's 142 pass); only the criterion's pointer is stale.
- **Fix**: `keryx flow ac update 520 AC3` to `cd apps/desktop && bun test src/reviews/ReviewPanel.dom.test.tsx`, or narrow the body's claim.
