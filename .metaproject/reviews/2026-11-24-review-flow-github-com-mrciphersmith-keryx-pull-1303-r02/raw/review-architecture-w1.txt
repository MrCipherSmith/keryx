### Summary
On the Desktop side, slice-01 threads one optional callback, `onUpdateReview`, from `ReviewWorkspace` through `PublicationTarget`/`RunAttempt` into `ReviewPublishDialog`. The update round goes through the existing start path (`local.request({ kind: "start" })`), so there is still one way to start an attempt. The dialog takes the head-moved lock from server state (`draft.headMoved`), and the server forces those settings, so the component holds no publication rules. Round-1 architecture F-001 (two previous-attempt rules for the run start) holds: `desk-run-service.ts` now calls `previousRoundAttempt` → `selectPriorAttempt`, and the options-key predicate is gone.

I found two minor issues:
- T13 introduced a second "which earlier attempt does this round build on" rule for finding answers. It walks the `previousRunId` chain and does not use `selectPriorAttempt`, while the PR body says one rule chooses the previous attempt.
- The new prop reaches only two of the three render sites that open the publish dialog.
