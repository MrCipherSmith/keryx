### [F-001] The committed round-1 review package contains absolute home-directory paths (local OS user name)
- **Severity**: info
- **File**: .metaproject/reviews/2026-11-24-review-flow-github-com-mrciphersmith-keryx-pull-1302/ (payloads/*.json, drivers/*.json, plan.json, research-evidence/*.txt, tool-calls/wave-events.jsonl, and others)
- **Attack vector**: none. This is a privacy and hygiene observation, not an exploit.
- **Problem**: Package files record `review_plan.path`, `skill_path`, slice paths and test-run cwd as absolute `/Users/<os-user>/…` paths. No tokens, keys or e-mail addresses were found in that package, in pr-comments/MrCipherSmith__keryx__1302.json, or in the flow 521 folder (zero matches for each pattern). The flow folder has no absolute paths.
- **Why it matters**: It leaks the local account name into a public repository. This is pre-existing: `keryx ctx rg --hidden -l "/Users/" .metaproject/reviews` lists 619 files across earlier packages, so it is the package writer's convention and not something this PR introduced.
- **Fix**: Optional, outside this PR: have the package writer store paths relative to the project root, or redact the home prefix, when a package is committed. Track it separately.
