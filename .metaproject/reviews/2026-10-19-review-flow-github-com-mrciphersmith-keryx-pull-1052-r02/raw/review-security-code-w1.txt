### Authorization and token handling: results

1. Allowed user id is fail-closed. src/commands/operator-confirm-tools.ts remote branch refuses when pressedBy or pressedAt is missing, and when `allowed === undefined || !allowed.includes(pressedBy)`. An empty or absent list refuses. The provider (src/commands/shell.ts:4224) reads `loadRemoteConfig()` fresh, and src/remote/config.ts requires a non-empty allowedUserIds. The hub sender allowlist (src/remote/hub.ts:1086) is a second layer, and `mapApprovalAnswer` (src/remote/shell-bridge.ts) sanitises `fromId` as a safe integer.
2. The token is one-time and burned on rejection. `pending.delete(token)` runs before any remote check, so wrong-user, wrong-question (the key(input) mismatch drops the token), expired and missing-provenance answers all spend it. A replay finds nothing. The dock/topic race is settled in `raceApproval` (src/tui/approval-mirror.ts): the first answer wins and the other leg is aborted. `isTopicPress` accepts only an allow or a deny that names who pressed, so a timeout or abort never counts as a press.
3. The TTL is 1h (`REMOTE_CARD_TTL_MS`) and is measured on the shell clock, not on a value in the payload.
4. Provenance is taken from the driver, not the model. src/commands/agent.ts:6120-6124 sets confirmationVia, confirmationPressedBy and confirmationPressedAt from the response only when a card exists and `response.via === "remote"`, and 6187-6192 pass them in the `tool.invoke` ctx. The model input has no field for them. `consumeConfirmationToken` (src/flow/confirm-token.ts) carries stored.pressedBy and pressedAt into the SignatureConfirmation, and types.ts and schema.ts add them with type checks.
5. The review_complete card can no longer complete a different head. The model-supplied `head` input is gone from the schema, buildCard and apply. The head is the recorded manifest.target.head. apply re-reads the facts, checks the factsDigest, then calls `completeReviewGated`, which runs completeHeadGate with prLookup. A failure after the manifest closed is treated as closed. completion-confirmation.json carries cardPressFields, and an unwritable record returns isError. Waivers and reviewer overrides appear on the card via `readOperatorDecisions`, which accepts only gate-relaxing kinds that pass `validGateDecision`.
6. The display layer (OperatorConfirmationLog, `waiting()`, `markUndelivered`, the try/finally settle in tui-shell.ts) carries no authorization decision.
