### Findings

[review-logic-w1-1] minor - src/review/publish.ts:264. The "unknown result" refusal tells the operator to remove `<receiptDir>/publication-receipt.json` and publish again. Since the T2 fix, a pending receipt is written to both the Attempt directory and the package (publish.ts:247-248, 282). Following the instruction removes only the Attempt's copy; the next publish reads the package's copy (publish.ts:255-256), refuses again and names the file that is already gone. The same applies when register() carried the pending receipt into the Attempt (session-attempt.ts:157-160). Fix: name every receipt path in receiptDirs (or both explicitly) in the message, or offer a keryx-level way to clear the receipt in both places.

[review-logic-w1-2] minor - src/review/session-attempt.ts:102-106 (with publish.ts:206-221). T4's base check is still missing on the session path, and the T1 fix makes the gap wider. For a package whose base was recorded as a branch (the common case), every registration pins the base to the PR's baseRefOid at that moment. Registration happens on each complete and on each session publish, and recordSession overwrites the undecided row's details, so run.baseSha always follows the PR's current base. If the PR is retargeted after the round (for example main -> release), the next `keryx review publish` re-pins the Attempt to the new base and posts. It also leaves Desktop's `pr.baseRefOid === run.baseSha` test (desk-publication.ts:377) passing, although the session reviewed against another base. A full recorded base that differs from the PR's base is never compared on the session path either. Fix: return the PR base in PrSnapshot and refuse on the session path when a full recorded base differs from it, as Desktop does. Pin a symbolic base once, at the first registration, and keep it on later registrations: reuse the stored run.baseSha when the row exists, rather than re-reading baseRefOid.

[review-logic-w1-3] minor - src/commands/operator-confirm-review.ts:191-192. The publish card's attemptOf passes `() => undefined` as warn. Since T1, registerSessionPackageForProject throws every skip reason so that callers can show it, but in keryx shell (where the skill requires the card) a failed or skipped registration on publish is still dropped silently. The review is then posted with the package-local marker and receipt, and the operator is not told that Desktop will not list it. Fix: collect the warnings in buildCard and show them as card lines, the way the complete card does with done.warnings.

[review-logic-w1-4] minor - src/review/session-publish-github.ts:94 with src/review/publish.ts:219-221. githubReviewedHeadInPull returns false both when the history was rewritten and when it cannot tell: a ref pullRequestPath does not parse (a PR number, branch, owner/repo#N, a GitHub Enterprise URL), a non-zero gh exit, or a thrown spawn. publishReview reports every false as "is no longer in the pull request's history (force-push or rebase)". runPublish and both card paths always supply this seam (review.ts:5082; operator-confirm-review.ts:197). So for the non-URL refs T15 restored, a moved-head `--event COMMENT` publish is always refused with a false reason, though trackerPrLookup (gh pr view <ref>) can detect the move. A transient GitHub failure also produces the same misleading refusal, which is the T12 class of bug on a new read. Fix: return a tri-state (in / not-in / unknown) from the port. On unknown, refuse with "could not check whether the reviewed commit is still in the pull request". For refs the compare API cannot address, skip the check and rely on GitHub's commit_id refusal, as the option's doc comment (publish.ts:46-50) already describes for a missing seam.

No blocker or major findings in this slice.
