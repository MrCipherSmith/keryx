Findings

1 (minor, T7 partial) session-attempt.ts:110 reads `store.byId(id)?.run.decision` before the Attempt lock is taken at :145, and Desktop's decision actions do not take that lock. If the operator completes/archives the Attempt in Desktop between :110 and the copy at :147-150, registration still rm -r's and re-copies the package under a now-decided row; the SQL guard keeps the row but the evidence copy changes, which is exactly what T7 set out to prevent. Window is small (readiness computation + a few file reads). Fix: re-check the decision inside the lock right before the rm/cp (a fresh store.byId), and skip the copy if it is set.

2 (minor, T7 partial) desk-publication.ts:389-392 renders Desktop's preview without the Attempt lock, while registration (session-attempt.ts:144 comment: "so a preview or submit never reads a half-copied package") deletes and re-copies `<attempt>/package` under it. A preview concurrent with a session-side registration can read a missing or half-copied report/findings and show an error or a wrong draft; submit re-renders under the lock, so what is posted can differ from what the operator last previewed if the package was refreshed between them. Fix: render the preview under the same lock (it is short), or copy into a temp directory and rename it over `package` atomically so readers see either the old or the new copy; correct the comment either way.

3 (minor) publish.ts:251-266: the session path takes the package lock and the Attempt lock and then awaits `options.confirm` (the interactive terminal prompt / operator card) while holding both. withFileLock waits 5 s by default (fs.ts:104) and heartbeats the held lock, so while the operator reads the body: Desktop submit/skip for that Attempt fails with "Timed out waiting for lock", and any registration of that Attempt (another `review publish`/`review complete` or the complete card) times out and degrades to a warning. Fail-closed, no duplicate post, but the Attempt lock is now held for human-scale time across two processes. Fix: confirm outside the locks and, after the yes, re-take the locks and re-check receipts and PR head before posting (the post-yes PR re-read already exists at :268-279).

4 (info) A publisher whose registration failed (sessionPublication returned undefined, no desk-attempt.json yet) holds only the package lock and uses the marker sessionPublicationId(reviewId, round) (publish.ts:85, :241). A concurrent successful registration in another process reads the package receipt without the package lock (session-attempt.ts:157): it can copy a pending `{}` receipt into the Attempt and then miss the later confirm, leaving Desktop with a pending receipt whose marker (the Attempt id) it can never find on the PR, so Desktop asks for manual cleanup. Requires concurrent publish + registration with divergent registration outcomes. Fix: take the package lock around the receipt carry in register (package -> Attempt order is already the session's), or have Desktop also look for the sessionPublicationId marker.
