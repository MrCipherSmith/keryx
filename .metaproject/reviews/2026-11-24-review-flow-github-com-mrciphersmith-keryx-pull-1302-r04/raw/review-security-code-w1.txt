Findings

1 (info) session-attempt.ts:52-54 binds desk-attempt.json to the package's PR number only. A record naming the UUID of another existing Attempt for the same PR number in a different repository (or for another viewer) is accepted; session publish then locks and writes its receipt in that Attempt's directory and uses its id as the marker. The file is written by keryx inside the package, so this needs write access to the package; impact is limited to mis-attributing a receipt. Fix: require that the store row for attemptId exists with the same repositoryId/number/viewer (laterRoundOf already opens the store read-only), or store the repo slug in the record and compare it with pullRequestPath(ref).repo.

2 (info) session-attempt.ts:157-160 copies the package receipt into the Desktop store whenever the Attempt has none, keeping any non-empty `url` string (publication-guard.ts:45). DeskRunStore.publication (desk-run-store.ts:426) treats any string url as "published", and Desktop shows it as the review link. A package receipt with a non-GitHub url (writable only by someone who can already write the package) marks the Attempt published and puts an arbitrary link in Desktop. Fix: carry only `{}`, `{posted:true}` or a url matching ^https://github\.com/<o>/<r>/pull/<n> into the store.

3 (info) session-publish-github.ts:32 -> flow/tracker/github.ts:144 passes the manifest ref to `gh pr review` positionally without a `--` separator. A ref beginning with `-` (e.g. `--approve`) is parsed by gh as a flag and could change the event. The ref is operator-supplied at `review start --target`, and this is base behaviour restored by T15, hence info. Fix: reject refs starting with `-`, or pass `--` before the ref.
