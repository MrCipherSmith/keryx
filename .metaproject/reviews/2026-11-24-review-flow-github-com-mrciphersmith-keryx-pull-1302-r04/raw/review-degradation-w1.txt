The refusal tells the operator to remove only `<receiptDir>/publication-receipt.json` (publish.ts:264, receiptDir = Attempt dir). On base there was one receipt and the instruction cleared it.

3. (minor) A session Attempt registered from a package whose base is a branch name gets the PR's *current* base commit, not the one reviewed. session-attempt.ts:100-103 takes `subject.pr.baseRefOid` (the base branch tip now) and pins it into the copied manifest (:166-170). If main moved after the review, Desktop sees `pr.baseRefOid === run.baseSha` and treats the attempt as current for the present base (desk-publication.ts:377-378), showing it as publishable as a normal review although it never covered that range; each later registration (every publish/complete) re-pins to the newer base under the same attempt id. Before the fix such packages were skipped (T1); now they are registered with a range that can be wrong.

Same root cause as review-architecture finding 1; filed here for the user-visible change.
