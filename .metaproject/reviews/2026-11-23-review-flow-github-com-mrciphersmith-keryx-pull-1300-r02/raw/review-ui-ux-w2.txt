## Strings checked, no finding

- `SUBJECT_NOT_SAVED` (apps/desktop/src/session/subjectBinding.ts, wired as a warn notice in useAcpSession.ts). It names the cause ('This keryx did not save the pull request binding'), the consequence ('the card will not find it again') and the remedy ('Update keryx'). It says 'pull request' correctly: the only caller of `bindSubject` is App.tsx `openPrSession`, and issue sessions get their subject on the server side through `withIssueBinding`.
- `Promise.reject(new Error("keryx is not running"))` in the PendingSubjects `write` (useAcpSession.ts). `PendingSubjects.apply` catches it and retries after the session's turn, so the user never sees it.
- Server refusals in src/acp/server.ts (`subject must be an object, null or omitted`) and src/session/organize.ts (`not a GitHub subject: ...`) are JSON-RPC errors for client developers. Desktop builds valid subjects, so they never reach a board or a notice.
- The issue-session error texts in issue-session.ts ('The linked session is archived or missing. Restore it in Sessions and retry.') were not changed by this diff.
- AppShell `titleLinks` render beside the title only in the session view. The links are review-frontend's concern. `.session-subject-links` uses `white-space: nowrap`, and any overflow belongs to review-layout.
