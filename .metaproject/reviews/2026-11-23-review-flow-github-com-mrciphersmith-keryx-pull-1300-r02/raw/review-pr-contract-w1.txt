## Findings

### [PC-001] User docs for Desktop Issues and `keryx issues list` still describe the behaviour this PR replaced
- Severity: minor
- File: docs/docs/guides/desktop-issues.md (outside the diff; unchanged between base and head per `git log b147408a8..88e3faba9 -- docs/docs/guides/desktop-issues.md docs/docs/cli-reference.md`, empty)
- Problem: The PR body says the default Issues source is now the project repository, the Flow stage filter is removed, the card button is "Open in session", and the default grouping is by GitHub state. The user guide still says: "The personal board initially shows open issues assigned to the selected account across its repositories." (line 3), "**Filters** can narrow the queue by repository, state, update date, author, label, assignee and Flow stage." (line 7), "Select **Open session** on the issue." (line 13), "The personal board groups those same issues by Keryx stage." (line 31). The CLI reference says "Use `assigned`, `created`, `mentioned` or `subscribed` for the source." and "The current directory does not restrict the personal queue." (docs/docs/cli-reference.md ~5175-5180), while the diff adds `repository`, which is resolved from the cwd. Code at head: apps/desktop/src/issues/model.ts `export const DEFAULT_SOURCE: IssueSource = "repository";`, IssueWorkRow.tsx `: stage === "needs_answer" ? "Open question" : "Open in session";`, src/integrations/issues-contract.ts `export type IssueListSource = IssueScope | "repository";`.
- Why it matters: a user following the guide looks for a Flow stage filter and an "Open session" button that no longer exist and expects their assigned queue by default; a CLI/agent reader of the reference does not learn the new `repository` source.
- Fix: update desktop-issues.md (default source, grouping Open/Closed, stage as a work-row link, "Open in session", no stage filter) and the `issues` section of cli-reference.md (add `repository`, say it reads the repository of the current directory).
- class_scope (not required at minor): sites docs/docs/guides/desktop-issues.md lines 3, 7, 13, 31; docs/docs/cli-reference.md issues section. Enumerated with `keryx ctx rg -i "issues list|source.*(assigned|mentioned|created)|Needs attention|In review lane|Flow stage filter|Open in Sessions" docs README.md` and a second pass over docs/docs and apps/desktop/README.md for the PR board (docs/docs/desktop-app.md "Find a pull request in Review" names no lanes and was not contradicted).
