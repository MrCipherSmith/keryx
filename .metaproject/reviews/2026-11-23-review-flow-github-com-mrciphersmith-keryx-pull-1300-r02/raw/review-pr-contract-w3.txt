## Findings

### [PC-004] The older-keryx notice comes only after the session's first turn; the body and the scenario fixture present it on open
- **Severity**: minor
- **File**: apps/desktop/src/session/subjectBinding.ts (claim in the PR body, "Sessions bound to a Subject")
- **Problem**: Body: "On an older keryx that ignores `subject`, the session still opens, with a notice that the binding was not saved." "Open in session" on a PR with no bound session (always the case on an older keryx) creates a new session, which keryx has not stored yet, so `_keryx/session_flags` is refused (`locate` → "no session ... in this project"). `PendingSubjects.apply` then does `catch { return; // not stored yet: tried again after its turn }`, and the only retry is in useAcpSession.ts's turn `finally`: `void applyPendingFlow(sessionId).then(() => subjects.apply(sessionId))`. The notice (`if (!flags.subject) this.deps.onNotice(sessionId, SUBJECT_NOT_SAVED)`) therefore appears only after the person sends a first prompt; until then the card counts the session as bound through `withPendingSubjects`. The Verification's scenario evidence shows the opposite timing: app-navigation.fixture.tsx's mock answers `_keryx/session_flags` for any session id (`const flags = storesSubject && subject ? { subject } : {}; ... result = flags;`) and asserts `assert.match(host.textContent ?? "", /did not save the pull request binding/);` right after the open, with no turn. prWork.test.ts models it correctly ("After the first turn keryx has stored the session and answers, but without the subject.").
- **Why it matters**: the owner and the stage-2 hand-off (implementation-plan.md repeats the claim) read that an older keryx warns on open; in fact a person who opens a PR session and does not send gets no warning, and the card shows the session as bound for the app's lifetime. The App-level test that is cited as proof passes only because its mock accepts flags for an unsaved session, which no keryx does.
- **Fix**: say in the body and in implementation-plan.md that the notice appears after the session's first turn, and make the fixture's older-keryx mock refuse `_keryx/session_flags` for a session it has not stored (assert the notice after a turn); or surface the notice at open when keryx lacks subject support.
