## Findings

### [RG-001] Issues board's new default source "repository" fails on any keryx CLI that predates this PR (the "Automatic" CLI choice included)

- Severity: major
- File: apps/desktop/src/issues/IssuesBoard.tsx (VerifiedBoard source initializer)
- Problem: The change sets the board's default source to `DEFAULT_SOURCE = "repository"` (apps/desktop/src/issues/model.ts) for every account with no stored source. A source is stored only when the user picks one in the select (`change()`), so on update almost every account starts on "repository". useIssueCollection.ts sends that `source` through requestIssues and `issues_request` to whichever keryx CLI Desktop runs. Before this PR, keryx's `listUrl` accepted only `["assigned","created","mentioned","subscribed"]` and threw `invalidInput` ("configuration: Invalid Issues request.") for anything else (src/integrations/issues-board.ts:97 at base b147408). "repository" is accepted only by the keryx built from this PR (src/integrations/issues-board.ts, src/commands/issues.ts, same PR).
- Trigger: Desktop at this head, with the CLI setting on "Automatic" (the recommended default: "keryx on your PATH … else the keryx inside this app", apps/desktop/src/shell/SettingsView.tsx), "keryx on PATH" or "Custom", and that keryx older than this PR. The user opens Issues for an account that never chose a source explicitly.
- Outcome: On base, that board loaded "Assigned to me". At head, the first load fails with "configuration: Invalid Issues request." and shows no issues. `isAccessError` does not match `configuration:`, so the user gets a Retry button that fails the same way. Nothing says the CLI is too old: requestIssues maps only "unknown command" and "invalid response" errors to "Choose the bundled CLI". The user gets issues back only by guessing to change Source. The PR handles the same version skew for `subject` (a notice on an older keryx). It does not handle it for the default source, and the PR, the journal and the D5 decision say nothing about it.
- Fix: Do not let the default depend on a CLI feature the Desktop cannot assume. Two options:
  - When a list with the default (not stored) `repository` source fails with `configuration:`/invalid input, fall back to "assigned" for that load and show a one-line hint ("This keryx cannot list the project repository; update keryx or choose the bundled CLI").
  - Or map that error in requestIssues to the existing "Choose the bundled CLI in Desktop Settings" message.
  Add a board test where the request rejects `source: "repository"` with `configuration: Invalid Issues request.` and the board still shows issues or the update hint.
