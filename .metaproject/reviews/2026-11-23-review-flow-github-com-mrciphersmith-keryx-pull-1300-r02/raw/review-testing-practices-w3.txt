## Findings

### [TP-R2-006] The `.`/`..` and charset gates on repository names have no fixture that reaches them
- Severity: minor. Gates the diff added survive deletion, and the fixture that names the case is refused by a neighbouring clause.
- Files: src/session/organize.ts (REPO_REF) and src/integrations/issues-board.ts (projectRepository).
- Problem:
  - S42, the `.`/`..` refusal in projectRepository, survives. No test builds a remote whose name is `..`. The probe shows `https://github.com/org/...git` yields `org/..`, and that the request path then collapses to `/repos/issues`.
  - In organize.test.ts, the "invalid subject" fixture `{ ...good, repo: "../x/y", url: "https://github.com/../x/y/pull/1" }` is refused by SUBJECT_URL's two-segment shape, not by REPO_REF.
  - `{ repo: "org/re po" }` keeps the url `…/org/repo/pull/1`, so the repo/url agreement check refuses it.
  - As a result, S02 (no REPO_REF) and S03 (no `.`/`..` lookahead) are both green.
- Fix:
  - In issues-board.test.ts, add `withProject("https://github.com/org/...git", …)` and assert that `listIssuePage(auth, { source: "repository" }, cwd)` rejects and that `requested === 0`.
  - In organize.test.ts, add to `bad` the consistent pairs `{ repo: "org/..", url: "https://github.com/org/../pull/1" }` and `{ repo: "org/re po", url: "https://github.com/org/re po/pull/1" }`.

### [TP-R2-008] The CLI never passes `cwd` in any test; the repository source is tested only below `keryx issues list`
- Severity: minor.
