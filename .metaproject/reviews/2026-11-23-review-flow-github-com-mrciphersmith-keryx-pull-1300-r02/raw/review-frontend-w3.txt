### Checked, no finding
- **act and cleanup.**
  - Every DOM file creates one root in `beforeAll` and unmounts it inside `act` in `afterAll`, then calls `unregisterDom()`.
  - IssuesBoard.dom, ReviewLaunchDialog.dom and usePendingFlowLinks.dom render `null` in `beforeEach`, so each test starts from a fresh tree and a fresh hook.
  - PrWorkRow.dom and ReviewBoard.dom remount through a new `key` on every render. The CSS-only tests render nothing.
  - All state changes run inside `act`: clicks, select `change` events, `publishSessionReview` and the hook's `expect`.
  - The App fixture unmounts inside `act`, then calls `clearMocks` and `unregisterDom` in `finally`.
- **Timers and listeners.**
  - The new AC2 ReviewBoard test replaces only the 6000 ms `setTimeout` and restores it in `finally`, the same pattern as the existing badge-tick test.
  - usePendingFlowLinks.dom injects its clock as `() => clock.now` and needs no real timers.
  - `publishSessionReview` is a listener bus that stores nothing; testing-practices w2 verified this. The board that subscribed is unmounted by the next keyed render.
  - No new sleep was added beyond the `settle` already reported.
- **Queries that could pass on a wrong render.**
  - Negative assertions in these tests are paired with a positive anchor:
    - AC4: `bodies` has length 4 and `reasons` has length 4.
    - Visible text: `containers.length` is 2 or 3, `controls.length > 1` or `> 5`, and exact labels are checked.
    - The reason-line test maps `.flow-id` to its reason and compares exact values.
    - "a card with an active review…" also asserts "No matching pull requests".
  - The AC4 list check reads `row.children[3]`. At head, the header order is Pull request, Author, State, Reason, Checks, Keryx work, Actions (ReviewResults.tsx), so index 3 is the Reason cell. The tile's `.review-card` button is a sibling of `PrWorkRow`, not its parent, so the body check cannot see work-row text.
  - The Issue visible-text selector is scoped to `.issue-work-row` and `.card-actions`. The only other controls on the card and row are `.flow-card-main` and `.review-list-link`, and both render text. Nothing unlabelled escapes the check.
  - The session menu sequence closes the menu after the item click and reopens it. If it did not close, the second `more` click would close it and `.at(-1)!` would throw, so the sequence fails loudly.
- **Keys and accessibility queries.**
  - Controls are found by accessible name (`aria-label`, or visible text through the `button()` helper), by `role="menu"`/`menuitem`, `aria-haspopup`, `aria-pressed`, `role="dialog"`, and `data-slot`. CSS classes are used only where a test asserts styling.
  - Work-row labels contain their visible text ("Review · ready" inside "Review · ready for #101"), which satisfies label-in-name.
  - Repeated cards in one render have distinct numbers and URLs, so key collisions would surface as missing rows.
- **TypeScript in tests.**
  - The `!` non-null assertions follow a length or presence check, or fail loudly through a TypeError.
  - Casts are limited to fixture builders (`as SessionInfo`, and `as unknown as` for `act` and the rules stub). This pattern already exists in the files.
