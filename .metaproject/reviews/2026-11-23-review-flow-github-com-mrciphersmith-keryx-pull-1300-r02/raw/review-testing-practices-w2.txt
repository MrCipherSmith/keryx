## Findings

### [TP-R2-005] The AC2 DOM test passes when no local review ever reaches a card
- Severity: minor. It is a test that asserts only unchanged state, with no positive artifact that the path ran.
- File: apps/desktop/src/review/ReviewBoard.dom.test.tsx, the test "a local review starting, progressing and finishing keeps every card's lane, position and visibility; cards are newest first".
- Problem: after each badge tick, the test asserts only that the layout equals `before`, plus `polls === 3`. Nothing checks that the polled badge reached the card, for example that #202's review slot reads "Review · running", then "Review · needs your answer", then "Review · publication pending". W2-01, which drops the badge application, leaves this test green. The file stays red only because of an older, unrelated test. Also, the only card whose review changes (#202) sits in Waiting for review, and the test runs in Status grouping only. W2-05 (active → waiting) is green on this test, and W2-06 (active → others under My role) is green on the full Desktop suite. In My role grouping, lane independence is pinned only at model level (`reviewLane` in model.test.ts). The DOM path in ReviewResults is not covered there.
- Why it matters: AC2 names this DOM test as its verification. As written, the test reads as coverage of "a local review starting, finishing or being published changes neither lane nor position". It would also pass if the board stopped showing local review at all.
- Fix: after each tick, assert the review-slot text of #202 (a positive artifact), then the unchanged layout. Put the changing card in a lane other than Waiting for review, for example `decision: "APPROVED"` or `"CHANGES_REQUESTED"`. Repeat the loop under `chooseGrouping("My role")`.
