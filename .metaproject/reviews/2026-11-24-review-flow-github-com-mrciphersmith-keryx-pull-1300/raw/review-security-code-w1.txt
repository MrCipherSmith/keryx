### What was checked in slice-01
- **Error text that echoes repository names (Desktop side).** `IssuesBoard.tsx` renders `{error}` and `ReviewBoard.tsx` renders `{focusNotice}` (`${focus.repo}#${focus.number} is not in a repository this board shows (${snapshot.repositories.join(", ") ...})`) as React text children. React escapes them, and no `dangerouslySetInnerHTML` is involved, so XSS is not possible. The repository names come from the user's own session flags and their own board snapshot and are shown only in the user's local app. Nothing is logged or sent elsewhere. The regexes `/(?:^|\b)configuration:/i` and `/Invalid Issues request/i` are linear, with no ReDoS risk.
- **Focus to another repository.** `selectRepo(listed)` takes the name from `snapshot.repositories`, the board's own list, not the raw `focus.repo`. So a session's subject cannot steer the board to an arbitrary repository string. An unlisted repository is refused with a notice and the nonce is consumed (no replay).
- **Flow link confirmation (HL-001 fix).** `usePendingFlowLinks` no longer writes `flow` on arrival. `accept` reads and clears `offersRef` before calling `link`, so a double press cannot write twice. `dismiss` writes nothing. The `dir` written comes from keryx's own flow list (`flows.cards`) and is matched back in `App.tsx` (`flows.cards.find(card => card.dir === offer.dir)`), so no user-typed path reaches `linkFlow`. This change removes the earlier integrity weakness (any package created within the window was silently linked).
- **Prefill into the shown session only.** `openSubjectSession` / `fillShown` check `isShown(id)` (read live from `live.current.reg.shown`) before `fill`. A session switch while opening cannot drop the PR/flow prompt into another session's composer. `subjectOpener` returns `filled: false` for coalesced presses, so a coalesced press registers no pending link. The prompt is never sent automatically.
- **Subject identity.** `sameSubject` now goes through `subjectKey` (kind/lower-cased repo/number), the same key `boundSessionIndex` uses. A session cannot match a different PR or issue across code paths. Archived sessions are still excluded.
- **Issues source fallback.** `fallback` exists only for the default, not-yet-chosen source. `change("assigned")` persists only the source id (validated on read with `Object.hasOwn(SOURCES, value)`). `clear` still deletes per-account filter keys that may hold private repository names. Nothing new is persisted.
- **useAcpSession.isShown** is a pure read and exposes no new RPC surface.
- Flow metadata, journal, resolved context JSON, CSS and the ReviewProgress refactor: no security-relevant content. No secrets, tokens or personal data in the added journal or AC text.
