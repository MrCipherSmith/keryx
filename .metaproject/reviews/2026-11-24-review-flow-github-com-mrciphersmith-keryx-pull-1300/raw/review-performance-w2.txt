### Cost checks on slice-02 production code (no finding)
- **issues-board.ts listIssuePage loop**: at most `REPOSITORY_PAGES = 3` serial REST reads per request, only for `source: "repository"` and only while every page so far held only pull requests. Each read needs the previous page's Link header, so the pages cannot run in parallel. The GraphQL `nodes(ids)` hydration runs once, after the loop, on the final page only. The worst case is 3 REST calls + 1 GraphQL per load or "Load more", triggered by the user. The new test ("a repository page made only of pull requests ... stops after three pages") pins the bound at 3 per request (`endless` = [1,2,3] then [4,5,6]).
- **turnPage**: `pageKeys.includes` runs per query parameter of a short continuation string. Negligible.
- **issuePage / failure()**: the 410 mapping is one status check per response. No added cost.
- **commands/issues.ts**: the injectable `connect` parameter has no runtime cost. `issue-workspace` stays a lazy import.
