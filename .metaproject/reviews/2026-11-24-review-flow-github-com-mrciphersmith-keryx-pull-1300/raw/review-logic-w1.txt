### Logic Bugs

### [F-001] PR body describes the cross-repository header focus as "stays armed"; the code switches or clears it
- **Severity**: minor
- **File**: PR #1300 body (owner choices)
- **Problem**: The body says: "A header link to a PR of another repository shows a banner and stays armed until that repository is shown." In ReviewBoard's focus effect, a repository among `snapshot.repositories` is selected at once (`selectRepo(listed)`). A repository the board cannot show gets the notice and is handled at once (`focused.current = focus.nonce; ... onFocusHandled?.(focus.nonce)`), so it is not armed. The sentence is the round-1 behaviour that LG-009 asked to change.
- **Why it matters**: The owner decides from the "Choices for the owner" list. That list records a behaviour the head no longer has, and it omits the one the head does have: the board switches its repository for the person.
- **Fix**: Replace the line with: "A header link to a PR of another repository of this board switches the board to it and opens the panel; one the board cannot show gets a notice and is dropped."

### [F-002] A focus request for a PR that the shown snapshot does not hold stays armed (residual of LG-009)
- **Severity**: minor
- **File**: apps/desktop/src/review/ReviewBoard.tsx
- **Problem**: The fix handles a focus whose repository differs from the snapshot. When the repository matches but the PR is not among `snapshot.cards`, the effect still returns early, so the request is never handled and App never clears it. Example: a merged or closed PR while the State filter is the default "open", whose scope loads only open PRs (AC3).
- **Why it matters**: Trigger: a session bound to a PR that has since been merged (bound sessions outlive the PR), whose header PR link is pressed. The board opens with no panel and no notice. Outcome: when the person later sets the State filter to include merged PRs, the snapshot holds the PR and its panel opens unrequested. This is LG-009's reported symptom (no feedback at click time, a panel at an unrelated later moment) at its remaining site. It is low cost, like LG-009, hence minor.
- **Fix**: When the snapshot of the matching repository holds every PR of its scope and the PR is not there, refuse the request. Call `onFocusHandled(focus.nonce)` and set a notice such as "#N is not in the current filter (merged or closed?)". Alternatively, open the panel by number through `loadDetail` without requiring the card. Add a test: a focus for a number absent from an open-scope snapshot, followed by a filter change to "all", asserts the panel stays closed.

### [F-003] An offer ends the request: after a foreign package is dismissed, the session's own package is never offered
- **Severity**: info
- **File**: apps/desktop/src/review/prWork.ts
- **Problem**: `resolveFlowLinks` returns `pending: []` whenever it makes an offer. If another producer's package appears first (the trigger HL-001 named), the person correctly presses Dismiss. The package their own prompt creates a minute later is then not offered, and the card keeps "Create Flow". AC9 as re-frozen allows this ("Dismiss ... link nothing"), and the body says Dismiss stops offering *that* package. It does not say Dismiss also ends the wait for the real one.
- **Why it matters**: This is a spec'd behaviour, so it is not a defect. Recorded so the owner sees it.
- **Fix**: Optional. On Dismiss, re-arm the request with the dismissed dir added to `knownDirs` until its original `expiresAt`. Alternatively, add the limit to Known gaps.
