## Findings

### [LY-005] The "Link Flow #N?" offer needs about 94px, but the Flow slot is 60px: the question collapses and Dismiss is covered by the Session button (info, unverified)

- **Severity**: info (unmeasured; the `layout-rendering.mdc` row "Content clipped" would make it `major` once it is measured at a supported width)
- **File**: apps/desktop/src/review/PrWorkRow.tsx (`FlowOffer`), with apps/desktop/src/styles/review.css
- **Problem**: In offer state the Flow slot holds three items:
  - `span.pr-work-link.pr-work-offer` (`flex: 1 1 auto; min-width: 0`)
  - two `.pr-work-more` buttons, "Link" and "Dismiss" (`flex: none; padding: 0 4px; margin-inline-start: 2px`, 1px border)

  The buttons cannot shrink, and `.pr-work-slot` is `display: flex` with no overflow clip. The row's tracks are `minmax(0, 1fr)`, so the slot does not grow either. The result:
  - The question text shrinks to its 14px of padding and border, so "Link Flow #N?" shows no text at all.
  - The buttons overflow past the slot's end into the session slot. Grid items paint in DOM order, so the session slot's button paints over them.
  - An offer only exists for a PR with a bound session, so that button is "Session" or "N sessions", which is not `is-empty`. It has an opaque `var(--bg-sunken)` background and it receives the clicks in the overlap.
- **Measurement (hand arithmetic, not an engine)**:

  Tokens: `--fs-xs` 11px, `--sp-1` 4px, `--sp-2` 8px, `--sp-3` 12px. Text widths are estimated for SF Pro at 11px.

  Element widths:
  - "Link" button ≈ 19 + 8 + 2 = 29px, plus a 2px margin
  - "Dismiss" button ≈ 37 + 8 + 2 = 47px, plus a 2px margin
  - The question span at its minimum is 14px. With the text "Link Flow #517?" it is about 80 + 14 ≈ 94px.

  ```
  host                                   slot width   offer min   overflow into session slot   question text
  board lane at basis 230px              60.0px       ~94px       ~30px (Dismiss ~17 of 47px visible)   0px (hidden)
  list column th:nth-child(6) = 16rem    ~74.7px      ~94px       ~16px                        0px (hidden)
  width at which the text also fits      ~174px       —           —                            needs a lane ≥ ~572px
  ```

  How the widths were derived:
  - **Board lane.** `.review-lanes .lane { flex: 1 0 230px }`. Subtract the `.lane-body` padding of 8px on each side, then the `.flow-card` padding (12px each side) and border (1px each side), which leaves 188px. The row has 3 tracks and two 4px gaps, so each slot is 60px.
  - **List column.** 256px minus the `.flow-list td` padding of 12px on each side leaves 232px. Three tracks and two gaps give about 74.7px per slot.
- **Supported width**: the Tauri window has `minWidth: 720` (apps/desktop/src-tauri/tauri.conf.json). Four status lanes need 4 × 230 + 36 + 48 = 1004px of board, so 230px lanes occur at any window up to roughly 1000px plus the shell chrome. 720px is a supported width.
- **Why it matters**: after Create Flow, the only place the confirmation question appears is the work row (owner decision on HL-001). In a lane at the supported widths:
  - The person sees two bare buttons, "Link" and a mostly hidden "Dis…", without the question or the Flow number. The text survives only in the span's `title`, which keyboard users cannot reach.
  - A click on the visible right part of "Dismiss" lands on the Session button.
  - The row's fixed 24px height still holds: the span is `box-sizing: border-box; line-height: 22px` and the buttons are 24px. So the defect is horizontal only.
- **Fix**: make the offer fit 60px rather than overflow. For example:
  - Let the offer's buttons shrink: `.pr-work-offer ~ .pr-work-more { flex: 0 1 auto; min-width: 0; overflow: hidden; text-overflow: ellipsis; }`.
  - Or render the offer as one truncating `Link #N?` button plus a "Dismiss" text button, dropping the static span.

  Whichever you choose, give the slot `overflow: hidden`, so a future flex-none child cannot paint over the session slot. Then measure in a real engine at a 230px lane and at the 16rem list column (see "What would settle it").
- **class_scope**:
  - Sites: `apps/desktop/src/review/PrWorkRow.tsx` `FlowOffer`, rendered at both PrWorkRow call sites in `apps/desktop/src/review/ReviewResults.tsx` (the board tile and the list `<td>`). IssueWorkRow has no offer.
  - Enumeration: `keryx ctx rg "pr-work"` over `apps/desktop/src`. `.pr-work-offer` occurs only in PrWorkRow.tsx and review.css. PrWorkRow is rendered only from ReviewResults.tsx.
  - Related but different shape: LY-002 (round 2) is truncation in these slots. This finding is overflow and overlap from the new offer content.
