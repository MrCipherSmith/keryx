### Summary
The fix serialises every read-modify-write of flags.json behind a per-session `flags.json.lock`, using the existing synchronous `lib/file-lock` primitive. It keeps the unlink marker (`subjectUnlinked`) private to the store: `StoredFlags` is internal, and the public `readSessionFlags`/`SessionFlags` contract is unchanged. The policy "backfill only if absent and not unlinked" lives in the store (`backfillSessionSubject`), the one module that can see the marker. The issue binder calls it instead of building that rule itself. The dependency direction is correct: session store → lib, and issues binder → session store. flags.json still has a single owner module. The documented lock order (binding lock, then flags lock, never the reverse) holds for every caller. Architecture is sound in this slice.
