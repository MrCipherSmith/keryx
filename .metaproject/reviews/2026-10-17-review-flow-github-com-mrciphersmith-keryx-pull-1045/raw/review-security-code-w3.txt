## Security Review: slice-04 (PR #1045, flow 460)

### Scope
- Branch: `fix/review-gate-consistency`, head `dff7a38a1`
- Slice: `slice-04`. Files: completion-gate.ts, coverage.ts, dispatch-usage.ts, dispatch.test-helpers.ts, git-fixture.test-helpers.ts, ledger.ts, locate.ts, managed.ts, mutate.ts, readiness.ts, research.ts, types.ts
- Scope mode: supplied slice diff, with context read at head

### Summary
- Blockers: 0
- Major: 1
- Minor: 1
- Info: 3

### Findings
- **SEC-001 (major).** The new `REVIEW_PACKAGE_PATH` regex in completion-gate.ts has an unbounded lazy prefix. It runs over the whole session history on every stop, so it is quadratic on long delimiter-free tokens. A PR can put such a token into tool results and stall the shell. Fix: an indexOf-based scan, or a bounded prefix.
- **SEC-002 (minor).** Gate roots are harvested from untrusted tool-result text, and absolute paths are accepted. Also, `closedAt` is taken as the maximum over all roots. So a closed package under any named root can release the gate, and a sibling worktree's open package can be chosen in place of this one. `review complete` still refuses, so the record stays honest.
- **SEC-003 (info).** A reviewer can forge the `KERYX_USAGE` line when the host does not append its own line. This affects telemetry only.
- **SEC-004 (info).** The `quotes-located` item inherits the existing trust model for agent-recorded dispositions. This is not a new weakness.
- **SEC-005 (info).** Reviewer names written into coverage.md are not sanitised. No attacker reaches them today.

### Clean Areas
- **Git argument injection:** `gitDiffAt` asserts both revisions and uses `--end-of-options`. `resolveBase` skips refs that start with `-`, and `mergeBaseOf` uses `--end-of-options`. Values in error strings are not executed.
- **Path traversal:** `resolveActiveReview` keeps the pointer inside the project root. The locator reads go through `lexicalRelativePath` and `git show` (unchanged). `dirSignature` skips symlinks.
- **Operator-decision binding:** `overrideRecorded` requires a decision bound to the head that covers a superset of the left-out reviewers. This fails safe, and it is no weaker than the agent-written dispatch override that ungated packages already accepted.
- **Ledger:** `DONE` without `slices` no longer claims coverage, and a reply stating an unreadable mandatory input stays incomplete. Both fail safe. The new regexes are bounded or line-anchored.
- **Test helpers:** test-only, with no production reach.
- **Injection, secrets, crypto (sha256 only), CSRF, open redirect:** nothing in this slice.
