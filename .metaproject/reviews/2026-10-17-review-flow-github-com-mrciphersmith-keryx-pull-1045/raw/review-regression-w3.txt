### Findings
- **REG-W3-001 (major)** `src/review/retry-eval.ts:81`: collectLateResults still credits a DONE reply that has no `slices` with its whole assignment. `review next --apply` and `retry-plan` save that to retry-state, and the ledger trusts retry-state's `covered`. This undoes flow 460 D (`ledger.ts` buildLedger), and `review next` and `ledger build` now disagree.
- **REG-W3-002 (major)** `src/commands/agent.ts:3487`: `completion-gate.ts` findReviewGateState now drops open packages and active pointers older than the session start. A review continued in a fresh shell session is reported as "no package exists", and the model is pushed to `review start` a duplicate.
- **REG-W3-003 (major)** `src/review/publish.ts:156`: the new `readiness.ts` coverage-md omission check fails every package ingested before flow 460 (coverage.md lists only `review-orchestrator`). That blocks `review publish` and the shell's `gh pr review` guard on rounds already closed, where the repair it names (re-ingest) is not available.
- **REG-W3-004 (info)**: wholeFileResult does not strip the new `KERYX_USAGE` line. It is harmless for schema-conformant results.
- **REG-W3-005 (info)**: the review panel now runs the coverage gate, including git diff for light rounds, for every package. Not measured.

Checked and not regressions: the extra `usage` fields on runs and the ledger (dispatchErrors and researchErrors ignore unknown keys); the `line: null` that newly unrefused findings carry (bot/post.ts, pr-comments.ts, publish.ts and dedupe.ts handle null); the research.ts refactor into packageCoverageErrors (same behaviour); and `ledger.ts` notRun with mutationRecorded.
