### Findings
- **[SEC-001] major** `src/commands/agent.ts:3487` — the review-gate's extra roots come from all session history text, tool output included. A crafted `.metaproject/reviews/*/manifest.json` (closed) in an untrusted PR can make the gate accept a stop early, and a crafted open manifest + pointer can put attacker text (`reviewId`) into a harness-provenance nudge. Fix: take roots only from keryx's own `review start`/`plan` output, contain them in the repo, ignore extra-root `closedAt`, sanitize `reviewId`.
- **[SEC-002] minor** `src/commands/review-ledger.ts:113` — `KERYX_USAGE` is trusted as host-measured, but on Claude Code/Codex the reviewer writes the raw file and can emit the line itself; counts are unbounded. It only affects the reported spend.
- **[SEC-003] info** — unbounded recursive content hashing of `<root>/.metaproject/data/review` for roots named in history.
- **[SEC-004] info** — the quote check moved from ingest (refuse) to readiness item 12 (operator disposition/waiver). That is a relocated control, not a removed one.

### Clean Areas
Checked with nothing found: injection (no shell/SQL/template construction in the changed code), secrets (none in the flow JSON, docs or CHANGELOG), crypto (sha256 only for signatures), path traversal in ledger raw reads (fixed `raw/` dir, `.txt` filter), auth/CSRF/redirect (not applicable). `--skip/--reason` parsing still refuses a skip without a reason.
