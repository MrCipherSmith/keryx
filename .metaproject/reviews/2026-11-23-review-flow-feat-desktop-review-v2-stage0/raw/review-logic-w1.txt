### Findings
- F-001 (minor) ReviewResults.tsx: `|| lanes.done.length > 0` in the Done lane condition is unreachable. When showDone is false the state filter holds only open/draft, so every visible card has state "open"; reviewLane returns "done" only for state !== "open" without awaitingAnswer/active. The comment "never hidden, whatever the state filter says" claims a guarantee no input exercises.
- F-002 (minor) review.css: `.review-board { container-type: inline-size; }` applies layout containment, so `position: fixed` descendants resolve against the board section. ProjectReviewRules and ReviewWatcher render `Dialog` (non-portaled, `.overlay` fixed, inset 0) inside `.flows-toolbar`, inside `.review-board`. Before, the containing block was `.review-workspace` (already a container, ReviewDetail.css:1), spanning board and detail panel; now the scrim and aria-modal dialog cover only the board section, so with the detail panel open the panel stays clickable behind a modal dialog and the dialog centers in the narrower area. Fix: put the container on an element that holds no dialogs, or render those two dialogs outside the section. Not run in a browser (exec budget 0).
- F-003 (minor) ReviewBoard.tsx (load callback `setAttentionPrs`): on a card-only refresh the fresh snapshot has no `addressedReplyIds`, so a PR whose only attention reason is unread replies is deleted from the set; the carry-over of replies happens in the following `setRead`, and the new `[snapshot, receiptVersion]` effect re-adds it one render later. The indicator derived from `attentionPrs.size` can emit null and then "attention" on a refresh. Fix: leave adds/deletes to the sync effect, or compute from the carried cards. Whether the parent visibly reacts to the intermediate value was not verified.
- F-004 (info) review.css: the toolbar is `flex-wrap: nowrap` with `flex: none` children and no overflow handling; AC7 holds at the 820 px board width the journal measured, but the detail panel width is user-resizable (`onResize`) and the live check lacked the Review rules button and the real watcher label. A narrower board overflows instead of wrapping.

### Other observations (not defects)
- laneReason ranks the outdated label above GitHub reasons (documented T7 decision), so a card in the attention lane for failed checks or changes requested shows "Outdated review" as its reason. Matches plan.md.
- needsViewerAttention requires state open; a merged PR with awaitingAnswer lands in the attention lane but leaves the tab indicator off. Consistent with AC4.
