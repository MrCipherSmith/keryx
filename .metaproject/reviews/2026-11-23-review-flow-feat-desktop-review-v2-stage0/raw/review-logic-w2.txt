### Logic Bugs

#### [F-001] "Outdated" covers any other reviewed range, so a base-only move shows the current head SHA as the outdated commit
- **Severity**: minor
- **File**: src/review/board-badges.ts (stale/outdated lines); same predicate in src/review/desk-run-store.ts (`NOT (... IS w.wb AND ... IS w.wh)`)
- **Problem**: The candidate is any finished run whose reviewed range differs from the card's range. It is not limited to a run whose reviewed head differs. The card's `baseSha` is `pr.baseRefOid` (`src/review/board.ts:90`), which changes when the base branch advances while the PR head stays put. In that case `outdated.headSha === card.headSha`, and `laneReason` (`apps/desktop/src/review/model.ts:92`) renders "Outdated review · <current head short SHA>". The same happens when the reviewed head is newer than the card's (a delayed GitHub snapshot).
- **Why it matters**: AC5 and the plan matrix define the badge for "an earlier head" and "author pushes a commit". The label tells the user the review was of an older commit, but it names the commit the PR is on now, and nothing in the PR changed. Before this change the result just vanished from the card. Now it is shown with a misleading label.
- **Fix**: Either carry `baseSha` in `outdated` and have the client say "base moved" when `headSha === card.headSha`, or narrow the candidate to `reviewed.headSha !== revision.headSha` (and `json_extract(...,'$.result.reviewed.headSha') IS NOT w.wh` in SQL). Make the same change in both places so the SQL and history paths stay equal, and add a test case with the same head and a different base.
