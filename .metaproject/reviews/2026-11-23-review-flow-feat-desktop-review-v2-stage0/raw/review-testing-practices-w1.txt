## Findings

### F-001 (info) SQL outdated lookup: four gates have no input that separates them
- File: src/review/desk-run-store.ts, the `wanted` CTE: `WHERE o.repo=?2 AND o.viewer=?3 AND o.pr=w.n AND o.state IN (...) AND ${visible("o")} AND json_extract(o.details,'$.result.reviewed.headSha') IS NOT NULL`
- Problem: the new store test builds one PR (`key.number`), one account with runs, and only terminal runs that carry a reviewed range. No fixture gives (a) a second PR or second account whose newer finished run would win the `LIMIT 1` slot if `o.pr=w.n` or `o.viewer=?3` were dropped, (b) a newer `completed`/`partial` run with `result: null` that would shadow the real older result if `IS NOT NULL` were dropped, (c) a `delete` decision or an `existing`-source run inside the outdated subquery (only `archive` is built). The "another account" assertion uses a key with no runs at all, so it passes with or without the viewer predicate in the subquery. The main query's own `r.pr`/`r.viewer` predicates would still hide a foreign row, so a wrong run is selected, then discarded, and the card loses its outdated badge.
- Why it matters: this is the new SQL; the `LIMIT 1` makes a wrong pick lose the badge, and the next edit to these predicates is unprotected. Evidence class: structural reading, not an executed mutation, hence info.
- Fix: in the store test add a second PR and a second viewer with a newer finished run on another head, one newer `completed` run whose result is null, and one `delete`d and one `existing`-source finished run; expect the original card's outdated to stay unchanged.
- Confidence: medium.

### F-002 (info) `lanes.done.length > 0` in the Done-lane gate cannot be tested
- File: apps/desktop/src/review/ReviewResults.tsx: `lane !== "done" || showDone || lanes.done.length > 0`
- Problem: a card lands in Done only when `state !== "open"` and it has no active or awaiting run. Under any state filter that leaves `showDone` false (non-empty, only open/draft), `filterReviews` already removes every non-open card, so `lanes.done` is empty there. The third operand is unreachable; its comment ("never hidden, whatever the state filter says") describes a guarantee the code gets from the filter; deleting it is an equivalent mutant. Not a defect, but a reader will take it as protection no test provides.
- Fix: delete the clause and the comment, or keep it and say it is defensive.
- Confidence: high.

### F-003 (info) `badgesEqual(outdated)` is pinned only by a direct call (known gap, restated)
- File: apps/desktop/src/review/ReviewBoard.dom.test.tsx "a badge whose only change is the outdated review counts as changed"
- Problem: the test proves the function, not that a changed `outdated` reaches the card. The poll covers active cards only, where `outdated` cannot be present, so deleting the `outdated` terms from `badgesEqual` fails only this unit test; no board-level test would notice. Accepted by the implementers; recorded so the gap is explicit.
- Confidence: high.
