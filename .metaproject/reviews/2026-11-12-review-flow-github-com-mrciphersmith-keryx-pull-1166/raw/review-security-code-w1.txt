### Findings

**[F-001] The outcome criterion says "without an operator card or a TTY", but the accepted channels include `--answered-by`, which the agent itself can supply** (info)
- File: `.metaproject/flows/488-2026-11-12-review-audit-p0-gates/description.md`
- Attack vector: none in this slice. On a host without operator cards and without a TTY (Claude Code, Codex), the waiver channel AC1-AC3 accept is `--answered-by <source>:<ref>` plus a quote; both are strings the reviewing agent passes. An agent could therefore still waive `verifier` or `head`, or relabel `--head`, with text it wrote, recorded as `confirmedVia: "host-question"`. This is a known, deliberate limit: `completion-host.ts` is described as "reported provenance, not a cryptographic attestation", the description's Out of Scope excludes verifying host-question answers, and AC6 makes the published body say such decisions were not verified. So it is not a defect of this change (law 4); the criterion's wording simply overclaims.
- Fix: reword the Effect line to "without an operator card, a TTY, or a recorded host-question answer (which keryx does not verify, and the published body says so)", so the flow's claim matches AC1-AC3 and AC6.
