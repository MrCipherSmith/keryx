### Findings

### [F-001] The PR focus request from the session header is never cleared and carries no repository, so it can open the wrong PR panel or reopen one later
- **Severity**: minor
- **File**: apps/desktop/src/App.tsx (the producer), apps/desktop/src/review/ReviewBoard.tsx (the consumer)
- **Rule**: canonical rubric (trigger and outcome): a UI-only wrong panel, no data loss
- **Problem**: `onOpenSubject` sets `reviewFocus` to `{number, nonce}`. Nothing resets it to null: `setReviewFocus` is called only at App.tsx:626. The consumer stores the nonce it last handled in a per-mount ref (`focused = useRef<number | null>(null)`). `RepositoryBoard` is keyed by `[cwd, repo]`, so choosing another base repository remounts it. The ref is then null again, and the old focus opens `#N` once more whenever that snapshot holds a card with the number. The request also has no `repo`. A subject from repository A therefore opens PR `#N` of repository B when the board shows B, on a project with more than one base repository. A focus that waits for a PR the current state filter hides (for example a merged PR with the default open filter) stays armed. It opens the panel later, unasked, when the user widens the filter.
- **Why it matters**: The detail panel can show a different pull request than the one the header link names, or appear unprompted after a repository switch or a filter change.
- **Fix**: Add `repo` to the focus request and compare it with `snapshot.repo` (case-insensitive) before opening. Have the board report that it handled the request, for example with an `onFocusHandled` callback that sets `reviewFocus` to null, so a remount cannot replay it. Or keep the handled nonce in App rather than in the board's per-mount ref.
