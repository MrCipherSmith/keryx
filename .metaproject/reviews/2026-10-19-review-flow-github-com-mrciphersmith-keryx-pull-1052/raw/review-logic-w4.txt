Checked and found correct (no finding):
- approval-mirror.ts raceApproval: `settled` is checked before onUndelivered and before topicAnswer is set, so a late topic answer after the dock answered is ignored; `topicAnswer` is set only for an explicit press (allow, or a deny that names fromId); a timeout or abort is not a press; on a topic win the dock is aborted with "topic" and the dock's own result is discarded; on a dock answer the topic is aborted with "shell". First answer wins; second ignored.
- pressedBy / pressedAt: remoteApproval() is called only on the two topic paths, with fromId from the bridge answer (mapApprovalAnswer accepts only a safe-integer number). The dock path returns a plain boolean, so tui-card never carries them. A topic allow without fromId yields no pressedBy and the tool refuses ("did not say who pressed it"): fails closed. pressedAt is the shell's receipt time, not a Telegram timestamp (note only).
- AC5 pre-check path: mirrorUndeliveredNote(bridge) covers undefined, inactive and not-connected; the note is placed above the subject line, which is the dialog subtitle for cardTitle cards, and only meta.card (display) is changed; the recorded card (entry.shown) comes from the tool, so the note is never recorded. The user_prompt card is excluded from the note and the log.
- operator-confirmations.ts empty states: confirmationLines([]) -> [], withConfirmationLines unchanged when empty, formatRemoteStatusLines unchanged without confirmations (test asserts equality). Rendering of via/pressedBy: telegram -> "pressed by Telegram user N" (or "a Telegram user"), shell/withdrawn never name a user. answer() on an unknown or already-answered id is a no-op.
