### Clean Areas (reviewed, no finding)
- Token single use and binding (src/commands/operator-confirm-tools.ts invoke): the entry is deleted before any check that can refuse, so a refused answer still spends the token. A token presented with a different input also deletes the entry. The `pending` Map is process-local, so there is no cross-process or crash replay. JavaScript is single-threaded and the delete sits ahead of every `await`, so no check-then-set race exists.
- Allowed-user check: `allowed.includes(pressedBy)` compares number to number from `loadRemoteConfig().allowedUserIds`. Missing `pressedBy`, `pressedAt` or `allowed` are all refused. An unreadable config returns undefined and so refuses (fail closed).
- TTL: `issuedAt` is taken from the injected `now()` at card build and stored in the process-local entry. It is compared at answer time, never taken from the model or the press.
- Press fields: `pressedBy` and `pressedAt` are forwarded in agent.ts only when `via === "remote"` and `confirmationVia === "remote"`. `cardPressFields` emits nothing for `tui-card`. Both fields are written by the shell, not by model input.
- Flow confirm token (src/flow/confirm-token.ts, src/flow/service.ts): additive optional fields, written with `writeFileAtomic` under the existing flow lock. Old tokens without the fields still parse.
- Two answerers on one card: `raceApproval` (first answer wins) plus hub `pressApproval` (single-use `dropApproval`, session-bound, expiry-checked) leave one decision per card.
- Concurrent `review_complete` on one package: the second call re-reads the facts and the gates, which refuse an already-complete review, so there is no double close.
