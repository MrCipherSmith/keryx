## Security Review (slice-02)

Scope: PR 1052 (flow 464), head d2cb377f59f7f9c8553d9f377f99360bff3f6328, base 062aa9c36484e7b7f6b8a1dd6140671330646e66, slice-02 diff plus traced sources in src/remote/, src/review/, src/tui/tui-shell.ts.

Summary: blockers 0, major 0, minor 1, info 3.

### Answers to the lens questions

1. Authorization of the remote answer. Telegram callback ids are filtered in src/remote/hub.ts (allowedUserIds.includes(fromId); updates with an undefined fromId are dropped). http-surface pressApproval is session-bound and expiry-checked, drops the approval before writing to SSE, and ignores a second press. client.readApprovalEvent keeps fromId only if it is a safe integer. operatorConfirmTool.invoke repeats the check against binding.allowedUserIds() (loaded from the remote config, positive safe integers, non-empty) and refuses when the list is undefined or does not contain pressedBy. Both missing pressedBy and missing pressedAt on a remote answer fail closed.
2. Token binding, single use, expiry. confirmation() mints an in-memory token stored with the exact input (JSON.stringify), card and issuedAt; invoke deletes the entry before validating, so a failed attempt also burns it; a different tool or different input is refused; the 1h TTL (REMOTE_CARD_TTL_MS) is measured on the local clock from issuedAt. Nested agents (KERYX_TOOL_CALL=1) are refused by nestedAgentCardRefusal.
3. No tool-result path. via:"remote" has exactly one producer, tui-shell.remoteApproval, fed by answer.fromId from the hub-filtered event. agent.ts executeCallUnbounded passes confirmationVia/PressedBy/PressedAt into invoke's ctx only together with a confirmationToken minted by the same driver and only when response.via === "remote"; model-supplied tool input cannot set them, and the TUI path ("tui-card") never records pressedBy/pressedAt.
4. Provenance. Every review tool, record() and recordScheduleDecision spread the press fields into the stored record; flow confirm passes them through service.confirmMint into the token store (F-003 notes the signature does not copy them). pressedAt is delivery time (F-002).
5. Can an agent record an operator act itself? Not through the card path: the token and the presser id come from the driver and the hub. The only routes are the documented same-OS-user ones (writing package files or running the CLI through shell_exec; F-004, TM-04, AC7), all pre-existing.
6. review_complete. facts (head, evidence level, waivers) are re-derived at apply and compared with the shown digest; the same completeReviewGated gates as the CLI run at answer time; the head input is validated as 7 to 40 hex characters; the absolute prepared.dir is accepted by resolveReviewPackagePath only when it holds a manifest.json.
