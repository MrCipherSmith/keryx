## Architecture Review (review-architecture, wave 4, slice-04)

### Review Scope
- PR 1052, base 062aa9c36484e7b7f6b8a1dd6140671330646e66, head d2cb377f59f7f9c8553d9f377f99360bff3f6328
- Stack: TUI shell (OpenTUI), remote bridge, review gates; no NestJS or MobX

### Checked and found sound
- Dependency direction: operator-confirmations.ts imports a runtime constant (REMOTE_CARD_TTL_MS) from commands/operator-confirm-tools, which pulls in the review and flow gate graph. Heavy for one constant, but 47 tui files already import commands/review/flow, there is no cycle (the gate modules import nothing from src/tui) and the view does not feed back into the gate. Not filed. Cleaner: move the constant to a leaf module such as flow/confirm-token.ts.
- The agent cannot reach the log or the answer path from tool-result text: the log is written only from bridge answers (fromId, decision) and from the dock verdict, and the operator question text comes from meta.card.
- pressedBy / pressedAt are set only inside remoteApproval (topic answers); the dock branches return outcome.result untouched, so a tui-card answer carries no press fields. (Field duplication across sites is excluded by the brief.)
- decisions-surface.ts: confirmationLines is an optional thunk threaded through OpenDecisionsOptions and DecisionsSidebarOptions. openDecisionsArms drops it deliberately. Unchanged output with no cards. Acceptable coupling for AC6.
- approval-mirror.ts: onUndelivered is optional and fires before the press check; behaviour for existing callers unchanged.
- remote-control-surface.ts: the confirmations argument is optional and the output is unchanged when it is empty.
