Scope: slice-01 (docs, CHANGELOG, package.json, TM-04, SKILL files, flow 464 files). Read the slice diff in full, then the code the doc claims depend on: src/commands/operator-confirm-tools.ts, src/tui/tui-shell.ts (remoteApproval), src/remote/hub.ts (allowed-id check), src/remote/config.ts, src/remote/shell-bridge.ts and client.ts diffs, src/commands/review.ts (TTY seams), src/lib/command-risk.ts, src/trigger/unattended.ts.

Summary: 1 major, 2 minor. The TM-04 section states the three limits it was asked to state (same-OS-user store forgery, bot token reachable by the agent, Telegram ordering) and the claims it makes about the allowed id, single use, 1-hour TTL, `pressedBy`/`pressedAt` only on the remote path, and `pressedAt` from the shell clock all match the code. The problem is the `review_complete` act: the docs and one SKILL sentence treat it as card-only or terminal-only, and the code does not enforce that.

Checked and clean:
- Allowed-id check: hub.ts:1086 drops any press whose `fromId` is undefined or not in `allowedUserIds`; operator-confirm-tools.ts:213-217 checks again at the record and fails closed when the list is absent. Config loader (config.ts:104) rejects an empty list, so "a binding with none refuses every remote answer" holds.
- `pressedAt` is `new Date().toISOString()` in the shell (tui-shell.ts:584), not Telegram's clock, as TM-04 says. `pressedBy`/`pressedAt` are spread into the record only when `remote` is true (operator-confirm-tools.ts:227), never from model input.
- Token is a `randomUUID` held in process memory and deleted before the remote checks (lines 191-206), so a refusal spends it; replay finds nothing.
- package.json: the only change is `version` 0.3.123 -> 0.3.124. No script, dependency, `files`, bin or lifecycle-hook change, so no supply-chain surface.
- Flow 464 files (flow.json, context.md, description.md, journal.md, plan.md, tasks.md, acceptance-criteria.md) and the diff as a whole: a pattern scan for GitHub/API tokens, Telegram bot-token shape, private-key headers and `password=`/`secret=` found nothing. The quoted operator request and helyx message id are not secrets.
- SKILL.md / review-premise: the new text keeps "You never run --mode automatic or --yes, and never write an operator quote yourself" and tells the agent to call the card, not to send the operator to a terminal. Nothing there lets the agent answer a card.
