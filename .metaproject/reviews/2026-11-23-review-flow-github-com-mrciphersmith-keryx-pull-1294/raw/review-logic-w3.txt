### Summary
`localBadge` now drops imported (`source: "existing"`) runs once, up front. Before, it excluded them at each of its three reads (active, latest, ready), so behaviour is the same. It also adds an `outdated` fallback: the newest finished run with a recorded reviewed range, offered only when no run is active and no run's requested or reviewed range is the card's. The SQL in `attachBadges` adds a per-card materialized lookup (`wanted.outdated`) that brings exactly that one extra row across the SQLite boundary. I traced the SQL against `history()` + `localBadge` and they agree:
- the same ordering (`createdAt DESC, rowid DESC` in both);
- the same visibility rules (archive and delete excluded, `existing` excluded, `recoverable` mapped to `failed`);
- the same gate: any active row or any covering row suppresses `outdated` on both paths;
- the extra `NOT (reviewed == card)` predicate is redundant but harmless, because such a run makes `ready` true, which suppresses `outdated` anyway.

The tests pin each predicate of the lookup (another PR, another viewer, deleted, imported, no result, ordering). No blocker, major or minor defect found.
