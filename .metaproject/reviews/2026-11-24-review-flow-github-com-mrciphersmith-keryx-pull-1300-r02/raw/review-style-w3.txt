## Minor & Info

### [ST-R4-006] info — `whileStored(dir, apply)()` builds a closure only to call it at once (src/session/organize.ts)
Both lock wrappers pass `() => ({ value: whileStored(dir, apply)() })`. `whileStored` returns a function `() => T`, and the only two callers (organize.ts:168, :181; `keryx ctx rg -n --all whileStored src`: 1 definition, 2 calls) invoke it on the spot. So the reader sees an arrow that calls a factory that returns an arrow that is then called. A plain call reads straight through. For example, `function applyWhileStored<T>(dir, apply): T { if (!existsSync(…summary.json)) throw goneError(dir); return apply(); }` called as `() => ({ value: applyWhileStored(dir, apply) })`. Another option is to inline the check in the section. No comment gives a reason for the curried shape, and nothing else uses the returned closure.
Fix (optional): turn `whileStored` into a function that runs `apply` and returns its value, and drop the trailing `()` at both sites.
