### Summary
The Desktop half of fix round 3 is logically sound.

**Link flow (usePendingFlowLinks).** `accept` marks the offer `linking` in the ref and in state together, so a second press, or a press during the write, sends nothing. It settles by matching (sessionId, dir), so an offer dismissed or replaced while the write runs cannot come back.

**linkFlow.** It now rejects instead of queueing a retry after the turn. `accept` catches the rejection, so there is no unhandled rejection. The flags dispatch matches applyPendingFlow's.

**Issues fallback.** `repositoryUnavailable` matches the three backend texts exactly: board-github.ts:45, issues-board.ts:114 and :188. It treats "Invalid Issues request" as an older keryx only on a first page (`!snapshot`). A snapshot is null only before page one, after a filter change (the load effect resets it) or after an access invalidation, so a later-page malformed cursor keeps Retry.

**Source focus and storage.** The select ref attaches in the child commit, before VerifiedBoard's `[source]` effect runs, so focus lands on the new select. Reading the per-account key as a fallback is a migration of the key main writes.

**Flow slot refocus.** PrWorkRow moves focus only when focus fell to `<body>` and the offer is gone.
