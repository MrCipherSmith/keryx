### Prior dispositions (slice-01)
- HL3-001 (merged with PF-R3-001), flags-lock sync wait blocks the ACP server: **fixed**. `handleSessionFlags` is now `async` and awaits `setSessionFlagsAsync` → `updateSessionFlagsAtAsync` → `withFlagsLockAsync` → `withFileLockAsync`, which yields with `await new Promise(r => setTimeout(r, RETRY_MS))` between attempts; the dispatch entry `[KERYX_ACP_EXTENSION_METHODS.sessionFlags]: (params) => handleSessionFlags(params)` returns the promise. Class check (`keryx ctx rg 'setSessionFlags\b|updateSessionFlagsAt\b|setSessionFlagsAsync|withIssueBinding\(' src --glob '!*.test.ts'`, 11 matches, complete): the only remaining synchronous flags writers are `issues-launch.ts:116` (`setSessionFlags`, predates this range, blame 670f35385) and `withIssueBinding → bindIssueSubject → backfillSessionSubject`; both are reached only from `src/commands/issues.ts` and `src/commands/issue-workspace.ts`, the short-lived CLI child the original finding said may keep the sync form. Each async attempt still does a few sync syscalls (openSync/statSync) per 15 ms tick: sub-millisecond, not a stall.
- HL3-002, lock mkdir recreates a trashed session: **fixed** (read, not executed). `lockOptions` passes `createDir: false`, `LockAttempt.prepare` skips mkdir, an ENOENT on the O_EXCL open throws at once (no wait-out), and `whileStored` refuses when `summary.json` is gone. Adds one `existsSync` per flags write: negligible.
- DG3-001, issue reopen fails on flags backfill: **fixed**; also a perf improvement on the per-open path: a later open first calls `sessionSubjectSettled` (lock-free read of the atomically replaced flags.json) and skips the lock entirely when the subject is stored or unlinked, so the common reopen no longer takes the flags lock.
- HL3-004, age-only 2 s stale threshold: **deferred, unchanged** (`FLAGS_LOCK_TIMING = { timeoutMs: 3_000, staleMs: 2_000 }`; no PID check added). Acknowledged as deferred; nothing in this range makes it worse.
