# review-ui-ux — round 4, wave 1 (slice-01, range d7b0f7058..4cb6c43ef)

## Verdict

The round-3 UX findings this slice touches are addressed in code: the offer names the Flow title in its accessible name, Link keeps the offer in "Linking…" and shows the failure reason, the Issues source is stored per project and account, the offer lost its button box and hover, the machine prefix is stripped, and the Settings label is correct. Focus now lands on a real control after every self-removing control (Flow slot button, PR search field, Issue source select). No blocker or major. One minor: at the board's own widths the offer's text span has no room, so a sighted user does not see which Flow is offered, that Link is running, or why it failed. The busy buttons have no visual style either.

- Product: Keryx Desktop. Audience: a developer working on GitHub PRs and issues through Keryx sessions.
- Primary task (inferred from AC9/AC13): confirm or dismiss a Flow link on a PR card. Switch the Issues source when the repository source is unavailable.
- Surface: app screen (work row, focus notice, Issues notice). The marketing rows of `ui-anti-slop.mdc` do not apply.
- Mode: code only (no URL or screenshots supplied).

## Findings

### [UX-R4-001] At board widths the offer's text has no room, so the question, "Linking…" and "Not linked: …" do not show (minor)

- Criterion: Nielsen #1 (status visibility) and #6. State: loading and error on a secondary view.
- File: apps/desktop/src/styles/review.css and apps/desktop/src/review/PrWorkRow.tsx
- Evidence (computed from CSS, not rendered):
  - `.review-lanes .lane { flex: 1 0 230px }` and `.pr-work-row` (3 × `minmax(0,1fr)`, gap 4px) give a Flow slot of about 60px in a 230px lane. LY-005 computed 74.7px in the 16rem list column.
  - Link and Dismiss are `.pr-work-more { flex: none; padding: 0 4px; margin-inline-start: 2px }` plus a 1px border at 11px text, about 80px together.
  - The `.pr-work-offer` span (`flex: 1 1 auto; min-width: 0`) therefore shrinks to its 8px padding. The question text is visible only when the slot is wider than about 120px, i.e. in lanes wider than about 400px.
  - The same span carries all three states. Its `title` (the only other visible place) sits on an 8px-wide non-focusable span.
  - While `linking`, the buttons get only `aria-disabled`. No CSS rule matches `[aria-disabled]` (searched `apps/desktop/src/**/*.css`: no match). `.pr-work-more:hover:not(:disabled)` and `cursor: pointer` still apply, so the buttons look and react as active.
- Impact: a sighted user sees "Link" and a clipped "Dismiss" in the Flow slot without the Flow number or title, which are the whole decision HL-001 asked the user to make. After pressing Link, nothing visible changes while the write runs. When the write fails ("Not linked: … locked by another keryx process; retry", the path `app-work-row.fixture.tsx` exercises), the slot looks the same as before the press. Screen-reader users get the name and the alert; sighted keyboard and mouse users get neither.
- Fix:
  - Carry the state on the controls, which always have room. Label the Link button "Linking…" (and the `.pr-work-more[aria-disabled="true"]` dim/cursor style the `:disabled` rule has) while the write runs. Show a short "Retry" label plus the warn tone on it after a failure.
  - Give the Link button a `title` with the full question or error. Or, at narrow widths, drop the static span for one truncating "Link #N?" button as LY-005 proposed.
  - Then measure at a 230px lane and the 16rem list column.
- class_scope: sites `apps/desktop/src/review/PrWorkRow.tsx` (FlowOffer, the only renderer of `.pr-work-offer`) and `apps/desktop/src/styles/review.css` (`.pr-work-offer`, `.pr-work-more`). Enumeration method: `keryx ctx rg "pr-work-offer|aria-disabled" apps/desktop/src`. FlowOffer is the only component using either in the work row. ContextMeter's aria-disabled is outside this range.

### [UX-R4-002] The new "filtered out" focus notice offers only Dismiss (info, same class as UX-014)

- Criterion: Nielsen #9.
- File: apps/desktop/src/review/ReviewBoard.tsx
- Evidence: the notice says ``#${focus.number} is not in the current list of ${snapshot.repo}: its state may be filtered out.``. The banner has only "Dismiss notice". The request is cleared (`onFocusHandled`), so widening the state filter afterwards does not open the PR.
- Impact: the user came from the session header link to see a (typically merged or closed) PR. To get there they must open Filters, add the state and then find the card by hand.
- Fix: add one action, either "Show all states" (apply the state filter and keep the request armed for that one load) or "Open on GitHub" (the UX-014 fix, which serves both notices). The owner decision "is cleared" stands; this asks only for a way forward.

### [UX-R4-003] Offer failure copy runs the CLI reason into the next sentence (info)

- Criterion: Nielsen #2 / copy.
- File: apps/desktop/src/review/PrWorkRow.tsx
- Evidence: the title is ``${name} was not linked: ${offer.error} Press Link to try again.``. The lock error from `src/session/organize.ts` is "the flags of session <id> are locked by another keryx process; retry" with no closing period. The tooltip then reads "…; retry Press Link to try again.", and the visible text also exposes the session directory id.
- Fix: end the reason with a period when it has none (or put the remedy on its own line). Prefer a short user-facing reason ("another keryx process is busy with this session") over the raw message.

### [UX-R4-004] `role="alert"` is added to an already-mounted span (info, unverified)

- Criterion: WCAG 4.1.3 (status messages).
- File: apps/desktop/src/review/PrWorkRow.tsx
- Evidence: the span ``{...(offer.error && { role: "alert" })}`` keeps its position between the "Linking…" and the error render, so React updates the role attribute and the text in place instead of inserting an alert node. Assistive technologies announce an attribute-switched alert inconsistently.
- Settle by: a VoiceOver/NVDA run on the failure path. A sure fix is a persistent `aria-live="assertive"` (or `role="status"`) region in the slot whose text changes.
