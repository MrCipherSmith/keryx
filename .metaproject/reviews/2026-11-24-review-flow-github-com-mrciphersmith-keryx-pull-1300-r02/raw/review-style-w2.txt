## Minor & Info

### [ST-R4-004] minor — a ternary nested in the true branch of another ternary in `settle` (apps/desktop/src/review/usePendingFlowLinks.ts)
`settle` in `accept` reads `old.flatMap(item => item.sessionId === sessionId && item.dir === dir ? next ? [next] : [] : [item])`. The inner ternary has no parentheses. The reader has to work out that `: []` closes `next ?` and `: [item]` closes the outer test. No other line in this file nests a ternary (`keryx ctx rg -n ' \? [^:;]{1,40} \? '` over usePendingFlowLinks.ts, prWork.ts and useAcpSession.ts: 1 match, this one). The same nested-in-true-branch shape does occur in 20 non-test files under apps/desktop/src (`keryx ctx rg -c ' \? [^:;]{1,40} \? [^:;]+ : [^:;]+ : ' apps/desktop/src -g '!*.test.*' -g '!*fixture*'`). It is a common habit, not a recorded decision, and this one is new code in a file that did not have it.
Fix: split the match from the replacement, e.g. `old.flatMap(item => item.sessionId !== sessionId || item.dir !== dir ? [item] : next ? [next] : [])`. That is a flat chain. Another option is a small helper `const replace = (item) => …` with `if` / early return.

### [ST-R4-005] info — `unavailable` holds a reason whose values include "older" (apps/desktop/src/issues/IssuesBoard.tsx)
`const unavailable = fallback && error ? repositoryUnavailable(error, !snapshot) : null;`. It then reads `unavailable === "older"`. The variable is named after one of its own values ("unavailable" | "older" | null), so the check reads as "unavailable equals older". `repositoryUnavailable` likewise reads as a predicate but returns a reason. The JSDoc on `repositoryUnavailable` explains it, and both sites are 120 lines apart in one component (consumers: `keryx ctx rg -n repositoryUnavailable apps/desktop/src`, 1 call site). That is why this is info.
Fix (optional): `const repositoryProblem = …` / `repositoryProblem === "older"`, or rename the function `repositoryUnavailableReason`.
