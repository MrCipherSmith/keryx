### What was checked, with frequencies
- **PrWorkRow per-row work.** The new `useEffect(..., [offer])` is one per row; `offer` is `undefined` for every row without an offer, so the effect does not re-run on those rows. For the offered row it re-runs when the offer object changes (linking → settled/error), and its body returns at once unless `refocusFlow` was set by a click. `document.activeElement` and `querySelector("button")` run only after a Link/Dismiss click, on one row. FlowOffer builds three template strings per render. No per-row allocation that scales with sessions or flows was added; the row still reads `index.sessions`/`index.flows` from the shared `prWorkIndex`.
- **Re-render churn from the offer state (UX-010 fix).** `accept` now changes `offered` twice per Link (linking, then removed or error) instead of once. Each change gives App's `flowOffers` memo a new array, so ReviewBoard's `flowOffer` and `work` memos change and every PR row re-renders. This happens per user click on Link, twice, over the rows of one loaded board. It is not a keystroke, frame or loop, so it is not a finding. `offers` in the hook is `offered.filter(...)` with a `sessions.find` per offer: offers are 0-1 in practice.
- **Focus effect (FE-R3-001 fix).** The deps gained `loading` and `stale`, so the effect also runs when a load starts or ends. Without a pending focus, or with a nonce already handled, it returns on the first line. With a focus it does one `cards.some` over the snapshot. Each load toggles it twice at most. Negligible.
- **IssuesBoard.** `fallback` is now a fresh closure on every render whenever the source is `repository` (it was only for an unchosen source). Its consumer `Collection` is not `React.memo`, so the new identity costs nothing extra. `sourceKey` does a `JSON.stringify(cwd)` per render. `repositoryUnavailable` runs two regex tests per render, and only while an error is shown. The `useEffect([source])` focus hook does nothing unless its ref flag is set. Storage reads (`stored(sourceKey) ?? stored(legacy)`) run in the `useState` initialiser only, once per mount.
- **useAcpSession.linkFlow.** One `_keryx/session_flags` request per Link, with stable `useCallback([cwd, dispatch])` deps. The earlier `pendingFlow` and after-turn retry path is gone for this caller, so no request repeats.
- **App.** The `flowOffers` mapping adds two conditional spreads per offer. `linkFlowOffer` keeps its identity, because `flowLinkActions` is stable.
- **Memory leaks.** No listeners, timers or subscriptions were added. If the component unmounts during an `accept`, the awaited `setOffered` is a no-op after unmount, not a leak. `claimed` (Set of offered dirs) grows only by offered packages, and that predates this range.
- **CSS.** `.pr-work-slot { overflow: hidden }` and the offer's ellipsis rules are static. No layout-thrash pattern.
- **N+1 / indexes / pagination / bundle imports / redundant API calls:** none in this slice. `errMessage` is a local named import. Tests and fixtures are not on a production path.
