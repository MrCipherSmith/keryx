### Module Boundary Violations
[AR-R4-002] minor: The CLI-reason prefix is stripped for display by two hand-written regexes with different vocabularies.
- File: apps/desktop/src/issues/IssuesBoard.tsx (unavailable notice)
- Problem: The UX-013 fix strips only `configuration:` inline (`error.replace(/^configuration:\s*/i, "")`). ReviewBoard.tsx strips `^(access|configuration|unavailable):`. UX-013's suggested fix named a shared helper. The result is a second copy of the same display rule for the same CLI error contract, and the two copies disagree on the prefix set. A third reading of that contract, `isAccessError`, lives in useIssueCollection.ts.
- Why it matters: Trigger: an error the Issues board shows whose prefix is not `configuration:`. Today `repositoryUnavailable` only lets `configuration:` reasons into this branch, so nothing shows wrongly yet. The cost is that the next edit to the CLI's category vocabulary has to find two regexes in two components.
- Fix: Add one `displayReason(error)` next to `isAccessError` in useIssueCollection.ts (or in lib/format), covering the full category set, and use it in both boards.

### Design Pattern Misuse
[AR-R4-003] minor: The flags-write-then-dispatch sequence now has a fourth hand-written copy (`linkFlow`), with its own guard set.
- File: apps/desktop/src/session/useAcpSession.ts (linkFlow)
- Problem: The rewritten `linkFlow` repeats `client.request<SessionFlags>(SESSION_FLAGS, { sessionId, cwd, flow })` then `if (l.client === client) dispatch({ t: "flags", ... })`. The same pair already exists in `applyPendingFlow` (:236-238, quiet), `archiveIdle` (:301-303) and `setFlags` (:944-945, banner). `setFlags` already accepts `flow` in its change type. The copies differ only in their guards and error policy. `setFlags` and `archiveIdle` require `l.usable`; `linkFlow` and `applyPendingFlow` do not. Each copy swallows, banners or rethrows in its own way.
- Why it matters: The guard sets have already drifted. A later rule for flag writes, such as a capability check (`l.extensions.includes(SESSION_FLAGS)`, which archiveIdle applies) or a client-generation check, has to be added at four sites. The fix round itself chose to write a new copy instead of reusing one.
- Fix: Extract one `writeFlags(sessionId, change): Promise<SessionFlags>` that holds the client and usable checks, the request and the stale-client-guarded dispatch, and throws on failure. `setFlags` adds the banner, `applyPendingFlow` and `archiveIdle` catch quietly, and `linkFlow` becomes `writeFlags(sessionId, { flow })`.
