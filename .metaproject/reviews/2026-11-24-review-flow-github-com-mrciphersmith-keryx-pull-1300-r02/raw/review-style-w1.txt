## Minor & Info

### [ST-R4-001] info — `handle` holds the "timeout" sentinel (src/lib/file-lock.ts)
`LockAttempt.step()` returns `number | null | "timeout"`, and both `withFileLock` and `withFileLockAsync` keep the result in `let handle = attempt.step();`, then test `if (handle === "timeout") return null;`. A variable called a file handle that can be the string "timeout" asks the reader to track three meanings. Fix (optional): name it for the attempt result (`taken`), or have `step()` return `{ handle } | "retry" | "timeout"`.

### [ST-R4-002] info — boolean refs named as imperatives (IssuesBoard.tsx, PrWorkRow.tsx)
`const focusSource = useRef(false);` and `const refocusFlow = useRef(false);` are flags that a focus is owed, named like actions. `focusSource.current = false` sits next to `sourceSelect.current?.focus()`, where it reads as a call target. Most boolean refs in apps/desktop/src name a state (`refreshPending`, `catalogPending`, `inFlight`, `openingLink`), though a few do not (`archiveSelection`, `again`), so the convention is mixed and this stays info. Fix (optional): `sourceFocusPending`, `flowRefocusPending`.

### [ST-R4-003] info — pre-existing: `age` holds an mtime, not an age (src/lib/file-lock.ts)
`const age = statSync(this.lockPath, { throwIfNoEntry: false })?.mtimeMs;` then `Date.now() - age > this.staleMs`. The value is a timestamp; the age is the difference. Pre-existing since 05a9a8e36 (2026-08-01); this range only re-indents it into `LockAttempt.step` and adds `this.`, so it is not made worse (diff mode: out of scope). Disposition (round obligation 4): recommend renaming to `mtime` the next time the line is touched; small and in the same contract, not a reason to hold this change.
