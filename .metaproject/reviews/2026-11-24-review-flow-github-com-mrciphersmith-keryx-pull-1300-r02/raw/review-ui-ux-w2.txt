# review-ui-ux — round 4, wave 2 (slice-02, range d7b0f7058..4cb6c43ef)

## Verdict

Slice-02 holds the same Desktop UI sites as slice-01 (PrWorkRow FlowOffer, review.css, ReviewBoard focus notice, IssuesBoard fallback) plus their tests and the App fixtures. Every UX defect in these sites is already filed in wave 1 (UX-R4-001..004) and is not filed again. The slice adds nothing new for this lens. The tests pin the behaviour the round-3 UX findings asked for: the offer is named, it stays visible while linking and after a failure, focus is restored after self-removing controls, the Issues fallback is limited to the named reasons, and the source is stored per project. No blocker, major, minor or new info finding.

## Context

- Product: Keryx Desktop. Audience: a developer working on GitHub PRs and issues through Keryx sessions.
- Primary task (inferred from AC9/AC13): confirm or dismiss a Flow link on a PR card. Switch the Issues source when the repository source cannot be read.
- Surface: app screen. The marketing rows of `ui-anti-slop.mdc` do not apply.
- Mode: code only (no URL or screenshots supplied).

## Scores

- Slop score: 0. The range adds no T1/T2/T3 tell. The only CSS change is `overflow: hidden` on `.pr-work-slot`.
- WCAG 2.2 AA floor (code reading): accessible names on Link/Dismiss carry the Flow number and title. `aria-disabled` keeps focus during the write. Focus lands on a real control after Link/Dismiss ("Create Flow for #101" in the test), after "Dismiss notice" (the search field) and after "Show issues assigned to me" (the source select). Contrast and target size were not measured.
- Viewports: not run.

## Findings

None new. Candidates I checked and did not file:

- A failed Link leaves `refocusFlow.current` set while the offer stays. The effect refocuses only when focus is on `body`, so a later removal of the offer cannot pull focus away from a control the user is on. No path to harm.
- The older-keryx notice leads with the CLI text "Invalid Issues request.". The next paragraph gives the cause and remedy ("update keryx or choose Bundled keryx in Settings → Desktop"). The class is UX-013, which wave 1 recorded as fixed for this branch, and the remedy is present.
- With an older keryx, "Open in session" now shows no "binding was not saved" notice until the first turn (app-navigation fixture). The PR body lists this ("Older keryx") and AC8 was re-frozen on it. Owner choice.
- The Retry branch of the Issues notice still shows raw prefixes such as "rate-limit:". This predates the range and is outside UX-013 as filed (wave 1 already noted it).
