## Judgement on the round-3 fix (`overflow: hidden` on `.pr-work-slot`, Link/Dismiss `flex: none`)

- Containment: fixed. The Flow slot now clips its own overflow, so Link/Dismiss no longer paint over, or take clicks from, the Session slot (grid tracks `minmax(0,1fr)` with a 4px gap; the clip also clips hit-testing). That half of LY-005 is closed.
- Presentation: not fixed. `.pr-work-more` was already `flex: none` before this range (review.css line 32 is unchanged), so the only shrinkable item in the offer is the `.pr-work-offer` span. Static arithmetic (same token values as LY-005): the span's floor is its 8px padding; Link ~29px + 2px margin; Dismiss ~47px + 2px margin; total ~88px. Slot width: (lane − 50px) / 3, which gives ~60px at the 230px lane floor and ~74.7px in the 16rem list column. So:

```
host                        slot     offer text box   Link visible   Dismiss visible
board lane 230px (floor)    ~60px    0px (8px pad)    29/29px        ~19/47px  ("Dism", no ellipsis)
list column 16rem           ~74.7px  0px (8px pad)    29/29px        ~33/47px
board lane >= ~314px        >= 88px  > 0px            full           full
```

  The text becomes visible only once the slot is wider than ~88px, i.e. a lane of at least ~314px. The default Status grouping draws 4 lanes, so that needs about 1290px of board content. At the 720px Tauri minimum and a typical 1180px window, every lane sits at or near the 230px floor. The question, the Flow number and title, "Linking …" and the new error text "Not linked: …" (role=alert) are all drawn in a 0px box; sighted users see them only through the `title` tooltip.
- Is a clipped Dismiss acceptable? As a containment measure, yes: better than the round-3 overlap. As the offer's resting state, no. The owner chose a confirm for HL-001 so that the user identifies the package before linking. At default widths the user gets a bare "Link", a cut-off "Dism" with no question beside it, and a visible Dismiss target about 19px wide, under the 24px WCAG 2.5.8 minimum. Also unverified: the slot is now a scroll container (`overflow: hidden`), so Tab focus on the clipped Dismiss should make the engine scroll the slot by ~28px. That would shift Link partly out of view, and the shift stays until the offer goes away.
