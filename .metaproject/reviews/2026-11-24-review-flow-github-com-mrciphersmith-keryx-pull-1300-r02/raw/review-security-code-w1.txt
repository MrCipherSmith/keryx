### Prior dispositions (findings this slice touches)
- SC3-001 (info, src/lib/file-lock.ts) — open (deferred by the owner, recorded in the PR body Known gaps). The refactor into `LockAttempt.step()` keeps the stat-then-rm takeover verbatim (file-lock.ts:118-126): (a) two waiters that stat the same stale lock can still each remove a lock, the second removing the first one's fresh lock; (b) a holder that outlives `staleMs` is still broken while it runs. Note for the separate change: `withFileLockAsync` now accepts an async `fn` (file-lock.ts:192, `return await fn()`), so a future caller that awaits inside the section would hit (b) on every slow await; its only production caller today (`withFlagsLockAsync`, organize.ts:181) passes a synchronous section, so nothing reaches it now.
- HL3-001 (minor) — closed. `handleSessionFlags` is async and calls `setSessionFlagsAsync` (server.ts:2940, 2965), which waits through `withFileLockAsync` (setTimeout between attempts), so the ACP server's event loop is not blocked by another process's flags lock.
- HL3-002 (minor) — closed. Flags locks pass `createDir: false` (organize.ts `lockOptions`); `LockAttempt.prepare()` then skips `mkdirSync` and `step()` rethrows ENOENT at once (file-lock.ts:86, 116); `withFlagsLock[Async]` turns it into `no session <id> in this project`. `whileStored` re-checks `summary.json` under the lock, and `writeOwnerOnlyFileAtomic` creates no directory (config-dir.ts:461-477), so a session trashed between the check and the write fails with ENOENT instead of coming back as a stub.
- HL3-004 (info) — open (deferred; `FLAGS_LOCK_TIMING.staleMs` is still 2 000 ms). Same mechanism as SC3-001 (b).
- DG3-001 (info) — closed. `bindIssueSubject` is loud only on first bind; later opens skip when `sessionSubjectSettled` and swallow a failed backfill (issue-session.ts bindIssueSubject).
- UX-011 (minor) — closed. The source preference key is now `account + ".source." + JSON.stringify(props.cwd)` (IssuesBoard.tsx VerifiedBoard). Security check of the new key: the value read back is still gated by `Object.hasOwn(SOURCES, value)`, the key holds a local project path and an account key (host + node id), no token or secret; no finding.
- UX-013 (info) — closed. The unavailable notice strips the leading `configuration:` (IssuesBoard.tsx `error.replace(/^configuration:\s*/i, "")`); rendered as a JSX text child, so escaped.
- PC-008 (minor) — closed. docs/docs/cli-reference.md now names `subject`, the answer fields and the "retry" refusal.

### Verified clean (with sites)
- Lock exclusivity and ownership: file-lock.ts:104-115 (`openSync(..., "wx", 0o600)` refuses an existing path, symlink included; nonce from `randomUUID()`, file-lock.ts:73); release removes only a lock holding its own nonce (file-lock.ts:145-151). Sync and async waits share `LockAttempt`, so the rules cannot diverge (enumerated with `keryx ctx rg "withFileLockAsync|createDir: false" src apps`: production callers only in src/session/organize.ts).
- ENOENT path: only thrown with `createDir === false` (file-lock.ts:116); callers map it to a fixed message without paths when the directory is gone (organize.ts `withFlagsLock`/`withFlagsLockAsync`).
- Error texts shown to the user: `lockedError`/`goneError` carry only `path.basename(dir)` (the session id the client sent); `refuseStore` (server.ts:2935-2937) echoes `error.message` to the local ACP client — a raw fs error there can name a local path, but the client is the same user's Desktop, so nothing crosses a trust boundary. Desktop renders `offer.error` (`errMessage(cause)`, usePendingFlowLinks.ts), `offer.flow.title` (PrWorkRow.tsx FlowOffer) and the Issues `error` as JSX text/attributes, never HTML. `dangerouslySetInnerHTML` in apps/desktop/src/review and src/issues (`keryx ctx rg "dangerouslySetInnerHTML|innerHTML" ... --all`: ReviewReportMarkdown.tsx, IssueMarkdown.tsx, DiscussionMarkdown.tsx) is untouched by this range.
- Subject input: `handleSessionFlags` still type-checks `subject` and the store refuses a non-GitHub subject (server.ts:2955-2962; organize.ts `parseSessionSubject`), unchanged in this range.
- `repositoryUnavailable` (useIssueCollection.ts) classifies by regex over the CLI reason; it only chooses which notice and button to show, no privileged action.
- Categories with nothing in this range: SQL/command/template injection, eval, auth/authz, IDOR, crypto, CSRF, open redirect, path traversal (session id → directory resolution in `locate` is unchanged).
