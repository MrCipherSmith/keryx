### Logic Bugs
[F-001] (major, confidence low) As-is publication is offered when the reviewed commit is no longer in the PR.
- File: src/review/desk-publication.ts (headMoved classification in `publication()`)
- Problem: `headMoved` is set for any open PR with the same base and a different valid head. It does not check that `run.headSha` is still an ancestor of the current head. After a force-push or rebase that keeps the base, the dialog offers "Publish as is for <sha>" and the POST sends `commit_id: run.headSha`, a commit the PR no longer contains.
- Why it matters: GitHub's create-review endpoint is expected to answer 422 for a `commit_id` that is not part of the PR (not verified against the live API here: read-only round). The 422 branch then throws "GitHub rejected this review. Check the verdict and inline comments. Authors cannot approve their own pull requests.", which names neither cause nor remedy. The user is offered an action that cannot succeed, and the error points at the wrong thing. Nothing is posted and the receipt is removed, so no data is harmed.
- Fix: classify head-moved only when the reviewed head is an ancestor of the current head (for example `gh api repos/{repo}/compare/{reviewed}...{current}` with status `ahead`). Otherwise keep the existing "closed or its revision moved" refusal. Alternatively, when `headMoved` is set, map a 422 to a specific message: "The reviewed commit is no longer part of this pull request. Save locally or start a new review."
