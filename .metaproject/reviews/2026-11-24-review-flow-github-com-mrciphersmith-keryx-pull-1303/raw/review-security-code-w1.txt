The head-moved write path holds. I traced the focus questions against the code:

1. **Digest binding.** On submit, `prepare` runs again. `previewSubject` skips the cache for every kind except a non-refresh preview, so the subject is read fresh. The digest covers `settings`, `body` (whose first line names both SHAs), `comments`, `questions`, `discussion` and `headMoved.currentHead`. When the as-is variant appears or disappears between preview and submit, `body` and `settings` change, so the digest changes and the submit fails with `stale:` before any write. This holds in both directions: a current-head preview submitted after a push, and an as-is preview submitted after the PR is force-pushed back to the reviewed head.
2. **Forced verdict and inline.** In the head-moved case, `settings.verdict` and `settings.inline` are server-derived. The client-requested verdict and inline values are discarded, `comments` stays empty because the inline branch requires `current`, and `outbound.event` is taken from those forced settings. A crafted request therefore cannot turn the as-is review into APPROVE or REQUEST_CHANGES. The digest is computed over the forced settings, so what the user previewed is what gets posted.
3. **Subject check before POST.** `verifyDeskSubject(cwd, key, expected, …)` runs with `expected = {run.baseSha, headMoved.currentHead}`. It checks the viewer, the repository id, `state === "OPEN"` and the exact base and head. It runs for both the default connection and the pinned connection, after `confirmSubmit` and before the receipt is written and the POST is sent. `commit_id` stays `run.headSha`. Every other caller of `verifyDeskSubject` is unchanged.
4. **Automatic publication.** In the head-moved case, every branch of the `blockedReason` chain for `kind: "automatic"` ends in a block. The explicit `headMoved ||` term covers the case where nothing earlier blocks it. The test at `desk-publication.test.ts` confirms that nothing is posted.
5. **Injection into the body.** `headMovedLine` interpolates only `run.headSha` and `pr.headRefOid`. Both pass `/^[a-f\d]{40}$/i` before use (`headMoved` is set only when `sha.test(pr.headRefOid)`), so the GitHub-sourced value cannot inject markdown or HTML. In the dialog, the values are rendered as React text or `title` attributes, which React escapes.
6. **Redaction and English screens.** `screenCommentBody` iterates `outbound.body`, which is the full `publicationBody` including the prepended line, the round block and the marker. `englishReviewText` runs on `visibleBody`, which also includes the line. The SHAs are in backticks and stripped, and the remaining prose is ASCII English. Both screens therefore still cover the as-is body.
7. **Discussion re-read.** The discussion re-read now also runs in the head-moved case (`current || headMoved`). This adds a staleness check and removes none.

### Findings

### [F-001] The terminal confirmation for a submit does not say that this is the as-is variant for an older commit
- **Severity**: info
- **File**: src/commands/review-desk-publish.ts (unchanged file; its input changed with this PR)
- **Attack vector**: none. This is an operator-clarity observation, not an attacker path.
- **Problem**: `confirmSubmit` prints only the verdict, the inline count, the repo and number, the viewer, and a 12-character digest prefix. In the head-moved case it shows "Publish a comment review with 0 inline notes …". It does not mention that the review is anchored to the reviewed commit rather than the current head. Desktop answers this prompt itself (`review.rs:443`), and its dialog does show both commits and the "Publish as is for …" label, so Desktop is not affected. Only a direct CLI user sees the terse prompt. That user received the `headMoved` field in the preview JSON, and the digest binds that preview.
- **Why it matters**: nothing is posted that differs from the bound preview. The prompt is simply less informative than the dialog for a decision that the PR treats as distinct. What would settle this as a defect: a documented CLI flow in which the operator confirms without having read the preview JSON.
- **Fix**: when `state.headMoved` is present, append "as is for reviewed commit <short> (PR head is now <short>)" to the prompt.
