### Findings

### [F-001] With the head moved and General comment turned off, the refusal points the user at the disabled Inline checkbox
- **Severity**: minor
- **File**: src/review/desk-publication.ts (blockedReason chain), shown by apps/desktop/src/review/ReviewPublishDialog.tsx
- **Rule**: canonical rubric (no rule row covers it)
- **Problem**: When the head has moved, the server forces `inline: false` and the dialog disables the Inline comments checkbox (`disabled={!!headMoved}`). If the user turns off General comment and there is no slots overlay, the status line shows "Enable General comment or select inline comments that are on the diff." The second half of that message asks for an action the dialog has just disabled.
- **Why it matters**: Refusing the submit is the right behaviour, and the PR accepts it on purpose (decision 4, "no silent override"). That reason covers the refusal but not the wording. The message sits in the server's `blockedReason` chain, and the dialog renders it next to a locked control. That is a cost for anyone editing this chain, and the user gets a misleading hint.
- **Fix**: In the `!settings.general && !comments.length` branch, choose the wording by `headMoved`, e.g. "Enable General comment. A review published as is has no inline comments." Optionally, add an assertion to the head-moved DOM test.
