## Findings

### [PC-001] Desktop guide still says a moved PR can only be saved locally
- Severity: minor
- File: docs/docs/desktop-app.md (lines 139-142, not in the diff)
- Problem: The guide says: "Choose **Submit review** ... If the PR has moved or closed, you can still save the draft locally." The diff makes a same-base head move publishable: ReviewPublishDialog.tsx labels the primary button `Publish as is for <code>{shortSha(headMoved.reviewedHead)}</code>` and desk-publication.ts only blocks `!current && !headMoved`. The PR body ("What changes" 1) describes this user-visible change; no document was updated.
- Why it matters: A Desktop user reading the guide after a push believes publishing is impossible and the only option is a local save, and does not learn the button name, the forced Comment verdict, or the first-line notice.
- Fix: Extend the paragraph: when the PR is open on the same base with a newer head, the dialog offers "Publish as is for <sha>", which posts a Comment for the reviewed commit with a first line naming both commits; a changed base or a closed PR still allows only a local save.

### [PC-002] "headMoveResponse encodes the spec table" — the table has no finished-phase rows
- Severity: info
- File: src/review/head-move.ts
- Problem: PR body: "`headMoveResponse` encodes the spec table." specification.md:98-102 ("Во время выполнения раунда") lists only the running-phase rows. The code also answers phase `finished` (`ask` → offer `["update"]`, `follow` → `queue-update now`), which journal T6 attributes to the spec section "Перед публикацией".
- Why it matters: A reviewer checking the function against the cited table cannot find the source of the finished-phase answers. No runtime effect; nothing calls the function yet.
- Fix: Optional: say "encodes the spec table (running) and 'Перед публикацией' (finished)".

### [PC-003] Per-file pass counts in Verification are not backed by package evidence
