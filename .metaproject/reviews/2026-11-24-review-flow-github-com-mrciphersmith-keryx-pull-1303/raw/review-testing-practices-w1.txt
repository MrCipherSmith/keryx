## AC1–AC6: do the tests pin them?

- **AC1** is pinned by `desk-publication.test.ts` "a moved head publishes as is…". It checks `headMoved`, the verdict and inline settings, the first body line of the preview and the posted body, `event: COMMENT` and `commit_id = reviewed head`. D4, D7, D9 and D11 each turn it red.
- **AC2** is pinned. The forced verdict and inline are covered (D10 red). A head that moves again is covered on both the digest path and the verify-before-write path, and the receipt file is checked as absent. Automatic publication with a moved head is covered (D8 red). A changed base, closed+moved and closed are covered (D1 and D2 red). One gap: the slot-overlay discussion stale check now runs for a moved head and is not exercised at all (F-001).
- **AC3** is pinned by the two new DOM tests: both short shas, disabled verdict and inline controls, the "Publish as is for bbbbbbb" label, and a current-head control with nothing disabled and "Submit review" shown. U2, U3 and U4 are red. The "Update review to" offer is not pinned to the head-moved and not-posted states (F-003).
- **AC4** is pinned. H1 and H2 are red. The test also covers bad stored values for both sources.
- **AC5** is pinned for accept and reject (R2, R3 and R4 red). The `state === "partial"` disjunct is not separated by any fixture (F-005, info, producer-equivalent).
- **AC6**: the new `prior-round.test.ts` case passes, and the journal says it was also green before the change. It is a regression guard with no gate behind it, so there is nothing to mutate. It changes `mode`, `options` and `settings.effectiveOptionsKey` in the manifest, which covers the plausible regression of filtering on settings.

Fixture against producer: the as-is DOM mock returns server-forced settings (`verdictOverride: "comment"`, `inline: false`) together with `headMoved`. This matches what `prepare` emits for the head-moved branch (desk-publication.ts settings ternary). The `update-round.test.ts` builders start from the `DeskRun` and `DeskResult` shapes, and the "partial" fixture sets state and coverage consistently with `finishExecution` and the executor. I found no fixture that claims one scenario while carrying another's shape.

Not run: AC8's full suites and AC3's command outside the single files above. The verify-tests-to-run-1.txt timeout in `src/commands/review-desk-run.test.ts` is outside this PR and I did not re-check it.
