No rendered geometry was measured: this was a static pass against the stylesheets and the tests that assert on them, with no dev server, Storybook or Playwright run. Nothing below is a pixel claim except where marked unverified.

**Select chevron blocked by the Hub CSP (LY-001, major, confidence medium).** The chevron is a `data:` URI used as a `background-image`, and the Hub serves the app with `default-src 'self'` and no `img-src` (`src/hub/server.ts:175`). `'self'` does not cover `data:`, so on a Hub-served page every non-multiple Select loses its native arrow (`appearance:none`) and gets no replacement. The PR's Chrome check at 390 and 1366 px would not show this if it ran against a dev server. The e2e script runs against the Hub origin but asserts nothing about the arrow. A gradient-drawn chevron avoids the image request and the per-theme colour copies. Settle it by loading a Select page from a running Hub and reading the console for the CSP violation.

**Collapsed rail and layer placement read correctly.** The new rules sit in `@layer components`, apply only at 1024px and above where the unlayered 1023/767 media rules do not, and out-rank the base `.sidebar`, `.nav-item` and `.identity .hub-button` rules by specificity. The toggle is `display:none` below 1024px, and the focus query in `App.tsx` skips it. I found no cascade defect there.

**Minor and info items.** LY-002 is a hole in the layering guard test (the toggle's base rule is not checked). LY-003 is a physical chevron position beside logical padding, unreachable because there is no RTL locale. LY-004 is the actions' alignment differing between the 481-600px and 480px-and-below bands, unverified. LY-005 is a parser hole for statement at-rules in the test helper, not reachable at this head.

Not reviewed here: i18n files, the e2e script body, `client.ts`/`client.test.ts` and the non-CSS test files in the slice.
