## Security review: round 1, slice-01

Reviewed `slice-01` (16 files, hub-web source and i18n) at head `0be1e717`. No blocker or major. One minor and one info observation.

**Findings**
- **SEC-1 (minor)** The session launch `onSuccess` now awaits a digest and then writes the draft and navigates without the `getClientScope()` generation check its siblings use. The only trigger is an auth loss landing inside that one-call window. The outcome is a draft kept in memory until reload under a dead scope key. The next principal cannot read it.
- **SEC-2 (info)** The first-message textarea in the New session form lacks the `secretWarning` hint that the composer and the command arguments field carry.

**Checked and clean**
- **Command catalogue and invoke.** The catalogue now lists unavailable commands as selectable. `invoke()` and the button are both gated by `allowed`, `stale`, `control.active`, `control.binding`, the association requirement for workspace commands, and the `local-only` / `sensitive-setup` exclusions. The new early-return in `invoke()` is strictly tighter than before. Confirmation cards keep their lease, version and expiry checks. No path invokes a command from the `/` shortcut or from Escape, which only toggles UI and restores the typed slash.
- **Observer access.** Moving `Commands` into the composer exposes the catalogue read to the same audience as before, since it sat in the settings tab. Invocation still requires `control.active`.
- **Injection and XSS.** The diff adds no `dangerouslySetInnerHTML`, `eval` or `Function`. Command `result`, `errorCode`, `inputSchema`, machine `displayName`, flow titles and event ids are rendered as React text or inside `<pre>` and `<code>`. The `Markdown` rendering of assistant messages was moved into `MessageItem` unchanged, and the acceptance review keeps `safeLinksOnly`.
- **Path and URL construction.** The operation follow-up uses `encodeURIComponent(operationId)`. The new History links navigate only to ids found in the loaded flow and document maps. The remaining navigation and external-link code is untouched (`safeExternalUrl` with `noopener noreferrer`).
- **Access to the machines list.** `SessionsView` now fetches `/machines?projectId=` for every viewer. The server handler (`src/hub/remote-v2/read-model.ts`) scopes it by `scoped(auth, projectId)` and filters inventory by the actor's project ids, the same authorization as the sessions list it sits beside.
- **Flow pin integrity.** The prepared first-message draft only seeds text and pins. `submit()` returns early while `draft.prepared`, and `association()` re-checks the draft's flow version, spec digest and criteria digest against the currently loaded Flow before it returns an association, so a Flow changed after launch fails closed.
- **Draft storage.** Drafts live in an in-memory zustand store, not localStorage or sessionStorage, and `clearAll()` runs on sign-out. The launch form calls `clearDraft()` after success, so the first message does not survive into the next New session.
- **Secrets and cryptography.** No tokens or credentials are logged or put in URLs. The only crypto use is the existing `digestCriteria`.
- **CSRF and redirects.** The diff adds no new state-changing request shapes beyond the existing `remoteMutate` calls, and no redirects.
- **Not in scope.** `src/lib/hub-machine/client.ts` and its clock-lead change sit in slice-02.

**Routing audit.** `graph_used`: payload layers block only (no extra queries). `wiki_used`: not-relevant. `ctx_used`: yes (`keryx ctx rg`). `raw_rg_used`: no. History of the unguarded launch handler was not needed: the previous handler was synchronous, as the diff shows.
