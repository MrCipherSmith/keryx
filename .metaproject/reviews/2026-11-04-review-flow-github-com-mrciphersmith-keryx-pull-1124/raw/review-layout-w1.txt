## Summary

No rendered geometry was measured in this pass. There was no hub-web dev server, no Storybook and no Playwright run, and the PR's "verified in Chrome at 1366 and 390 px" is unreproduced here. Reasoning about CSS does not become a measurement, so all four findings are `info`, marked unverified. Each one says what would settle it.

**Checked and found sound (static):**
- The `.session-header-actions > button[aria-expanded]` change is correct. The header's first button is now Settings, so the old `button:first-child` rule would have hidden it at 1280 px and wider. Only the navigation toggle carries `aria-expanded`.
- The new rail and Select rules sit inside `@layer components`, next to the rules they extend. The unlayered max-width media queries that set `.sidebar` width (1023 px and 767 px) cannot overlap the new `min-width: 1024px` rail rules, so the unlayered-beats-layered trap does not apply there.
- The collapsed rail is internally consistent. The 60px sidebar with 7px side padding leaves about 45px for 17px icons and a 20px project initial. Every text node that is hidden has an `aria-label` and `title`. `.desktop-rail-toggle` is `display: none` below 1024 px and is excluded from the mobile menu's focus query.
- The `.hub-select` rule uses only background longhands, and its specificity (0,3,0) beats `.hub-input:disabled` (0,2,0), so the disabled fill and the chevron both survive. `multiple` and `size` selects are excluded.

**Most worth measuring first:** LY-001. A `display: contents` wrapper around CreateSession swallows the parent's `space-y-5` margin. If the 20px gap is confirmed missing, it is a `minor`.
