## High-Load Review: slice-01 (hub-web source and i18n)

**Verdict:** no blocker or major at any load I can name. Slice-01 adds no server-side shared state, queue, pool, retry loop or lock. The load surface is the number of queries a websocket invalidation burst fans out to.

**Minor observations (3)**
- **HL-001 History loads all document bodies for name lookup.** `context.tsx`. Each History mount, and each project `context` frame while it is open, re-downloads every document including content. History does not wait on it. No size at which it hurts could be named.
- **HL-002 The settle guard is defeated for the latest command.** `settings.tsx`. `Commands` follows the same operation without `settled`, so the most recent command's receipt is still refetched on every session invalidation. Bounded to one request per batch; the new comment overstates the effect.
- **HL-003 The Flow pin is computed after the irreversible session create.** `sessions.tsx`. It fails only without `crypto.subtle` (insecure context), and the failure leaves the form open for a duplicate create. Low confidence, not reproduced.

**Checked and clean**
- **Per-outcome receipt follow:** it stops at `applied`/`rejected`. The other statuses, `queued`, `confirmation-required` and `recovery-required`, keep following, and each such outcome costs one GET per batch. The count is user-driven and each batch is coalesced over 100 ms (`remote-hooks.ts`), so this is not an unbounded path.
- **`outcomes` state:** it grows only by user-invoked commands. `recordOutcome` is dedup'd by `operationId` and has a stable identity, so the `Commands` effect does not loop.
- **Message submit:** the `current===submitted` identity check on the shared draft store prevents a stale submit from clearing a newer edit. The `prepared` draft effect is guarded and self-terminating.
- **`useRemoteQuery` function-valued `enabled`:** it reads the query's own cached data and makes no extra request.
- **Not claimed:** the two failing `hub-machine` tests in `research-evidence/tests.txt` are outside this slice and I did not reproduce them.

Routing audit: graph_used: payload layers only (not rebuilt); wiki_used: not-relevant; ctx_used: yes (`keryx ctx rg`); raw_rg_used: no. Git history of the deliberate choices was not needed: the new comments in the diff state their reasons, and I checked the reasoning against the code (HL-002).
