### Findings

### [F-001] Waiver tools still tell the agent to run `keryx review complete`
- **Severity**: major
- **File**: src/commands/operator-confirm-review.ts:296 (also 262, 312, 358; comment at 24)
- **Attack vector**: the agent completes a waiver card, reads the tool result 'Run `keryx review complete` to close the review.', and runs the CLI through shell_exec. Plain `complete` has no TTY check and no command-risk floor, so the round reaches `closed` with no review_complete card, no press, no `confirmedVia` and no `pressedBy`. The gates still apply; the operator's final yes and its audit record are skipped.
- **Problem**: four agent-facing strings contradict the PR's own rule (an agent never runs `keryx review complete`; it calls the review_complete card), which SKILL.md, SKILL.detail.md and completion-gate.ts nextStep now state.
- **Why it matters**: the operator decision on C-05 was uphold. The strings the agent reads last, right after the waiver, point it at the unguarded path, so the card is bypassed by following the tool's own output. This is the unfixed part of C-21.
- **Fix**: say 'call the `review_complete` card in keryx shell to close the review' in the four strings and the line-24 comment; add a test that the waiver result and description do not contain 'Run `keryx review complete`'.
- **Patch** (line 296 and 358 shape):
```diff
- ... not reviewed. Run \`keryx review complete\` to close the review.
+ ... not reviewed. Call the \`review_complete\` card in keryx shell to close the review.
```
