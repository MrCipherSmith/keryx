### Prior findings

- C-04: closed. `review_complete` no longer declares `head` in its input schema (`additionalProperties: false`), `completionFacts(dir)` takes no head input, and `apply` calls `completeReviewGated` without a `head` option, so `completeManagedReview` never replaces `manifest.target.head` on the card path. The card shows the recorded head, run through `cardSafe`, and `factsDigest` covers it. An extra `head` in the model input is ignored (test "the model cannot supply a head"). `--head` stays on the CLI, where the operator types it in a terminal.
- C-40: closed. `consumeConfirmationToken` (confirm-token.ts) copies `pressedBy` and `pressedAt` from the stored token into the returned `SignatureConfirmation`. `SignatureConfirmation` (types.ts), the TS `flowStateSchema` (schema.ts) and the docs schema (flow-state.schema.json, under `definitions/flowSignature/properties/confirmation`) all declare both fields. The new test 464 reads the signature back from disk and validates it against the schema.

### Findings

None. Slice-02 changes were checked for the following and no exploitable path was found:
- Card text built from package data: head, review id, evidence line, waiver item, waiver quote, mutation/override items and quotes all pass `cardSafe`. `decision.confirmedVia` is interpolated raw, but `readOperatorDecisions` accepts only `tui-card|remote-card|terminal`.
- Remote acceptance in `operatorConfirmTool.invoke`: the allowed-id list must contain `pressedBy`, a missing id or time is refused, the token is deleted before the checks (spent on every refusal), and the 1-hour age is enforced. `remoteApproval` in tui-shell sets `pressedAt` from the shell clock. If `fromId` is undefined, `pressedBy` is absent and the remote answer is refused.
- Between card and yes: `factsDigest` now covers the mutation-waiver and reviewer-override decisions as well as readiness and coverage waivers, so one added after the card is refused.
- The close is gated by `completeReviewGated` (run profile, narrowed routing, head, evidence, research, readiness), identical to the CLI. A throw after the manifest closed is reported as closed with the problem, not as "nothing was recorded".
- TUI mirror wrapper: `markUndelivered` and `settle` only change the in-memory log and affect no approval decision. An expired mirrored card stops counting as waiting in the topic, and the shell dock still answers it.
