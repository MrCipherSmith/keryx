### Findings
- **[SEC-001] minor**: a premise-question decision is accepted without `confirmedVia`, unlike the gate decisions in the same file, and the new tests lock this in. An agent that writes to the package can append a dismiss entry with no provenance, and readiness and the verdict accept it. It is hardening only, because `confirmedVia` is self-asserted and the trust model of flow 457 already rests on the file. Fix: require `confirmedVia` in `validPremise`, add it to the test fixtures, and add a test that an entry without it is refused.
- **[SEC-002] info**: the decision readers match on the display id as well as the `global_id`. The writers refuse ambiguous ids and record the `global_id`, so there is no current path; only a hand-written record could over-match.

### Clean Areas
- Unattended exclusion: `review_decide_premise` is added to `OPERATOR_CONFIRM_TOOL_NAMES`, and `operator-confirm-rosters.test.ts` checks the list against the registry. The terminal command refuses when stdin or stdout is not a TTY.
- Card: `apply` re-reads the finding and refuses when its severity or verdict changed after the card was shown (a TOCTOU guard). Card text goes through `cardSafe`.
- Premise claims: the tests cover the rejection of unknown properties (no editing of finding text or disposition), raised severity, self-judgement (including names normalised by case and whitespace and reviewers folded in by dedupe), duplicate claims, and claims that are not objects. A malformed premises file is refused before any package is written. A downgrade stops at minor.
- Parsing: `parseEmbeddedPremises` refuses two blocks, a block that is not JSON, and a `keryx:findings` block, and there is no eval or dynamic code. `PREMISES_FILE` is a fixed relative path, so nothing user-controlled reaches it (no path traversal).
- The tests themselves use only temp dirs from `mkdtemp`, no secrets, and no shell execution.
- Not applicable: injection (SQL, command, SSTI), crypto, CSRF, open redirect, React and NestJS patterns.
