### Findings

**[SEC-001] major: the finding record's own `premise.operator` dismisses a finding at the gate, and ingest input can set it.** The gate (`toGateFinding` -> `premiseGateState` -> `findingVerdict`) and `premiseHoldState` accept `premise.operator.answer` from the record. A premise carried in `--findings` passes `mergePremises` unchecked (already-judged path) into findings.json. Result: an agent-written report can dismiss any blocker with no operator decision, no TTY/card and no verifier `refuted`, which undoes the decide-premise TTY rule. Fix: trust only operator-decisions.json, strip `operator` from ingested premises, require `confirmedVia`.

**[SEC-002] minor: intent signals the PR adds itself count as premise evidence.** A PR author can plant a "deliberate" comment to get a security blocker downgraded to minor or challenged. With the default `minor` floor it still blocks. With `severity_floor: major` it does not.

**[SEC-003] minor: the terminal decide-premise prompt prints reviewer/judge text unsanitised.** The card uses `cardSafe` and the terminal path does not, so ANSI sequences can rewrite what the operator confirms.

**[SEC-004] minor: the premise-question decision is weaker than the gate decisions in the same file.** `confirmedVia` is optional, no operator quote is stored, and nothing binds the decision to what was shown, so an id reused on re-ingest inherits an old dismissal.

**[SEC-005] info: unescaped newlines in the judge name or claim id can inject lines into scope.md's Premise check block.** No decision reads those counts today.

### Clean Areas
- Injection (SQL/command/eval): none in the slice. The `keryx:premises` fence regex is anchored per line, with no catastrophic backtracking.
- Path traversal: PREMISES_FILE and OPERATOR_DECISIONS_FILE are constants joined to the package dir. `findHeldFinding` reads only package files.
- Delete-only claim merge: unknown properties, raise-severity, below-minor downgrade, self-judgement (actorKey over-matching), external downgrade, duplicate claims and unknown/ambiguous finding ids are all rejected, and every rejection keeps the finding.
- Dedupe: held findings are excluded from merges, so a hold cannot be laundered into or out of a duplicate.
- recordOperatorDecision/recordPremiseDecision keep each other's entries (no lost gate decisions).
- Secrets/crypto/CSRF/open redirect: not applicable to this slice.
