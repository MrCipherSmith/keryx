## review-regression (wave 8, slice-08): summary

**Question:** does the premise-judge wiring in slice-08 break existing behaviour in its dependents?

### [RG8-001] An operator's premise dismissal does not reach the next round or the PR round block (major, plausible)
- **File**: src/review/prior-round.ts:241 (also :723, :936, and src/review/publish.ts:137)
- **Problem**: `round-record.ts findingStatus` reads status only from findings.json. The operator's `dismiss` (recordPremiseDecision in operator-decisions.ts) is written only to operator-decisions.json, so a dismissed finding is carried as `open`, attached to a fix slice when its hunk changes, and published as `open`.
- **Why it matters**: Before this change, a dismissed finding was never carried as open. Now reviewers are asked again about a finding the operator closed, round.json says it is open, and so does the PR round block.
- **Fix**: Make decide-premise / the card write the applied decision into findings.json, or have priorFindingsOf and buildRoundBlock apply `readPremiseDecisions` as review-gate's `withPremiseAnswers` does.

### [RG8-002] Readiness item 11 can be waived (minor, scope A)
- **File**: src/review/readiness.ts:440. The generic `--waive` accepts `premise-decisions`, against the check's stated contract. Flow-less PR reviews can then publish with unanswered held questions.

### [RG8-003] The docs still describe ten readiness items (minor, scope A, docs)
- **File**: docs/docs/cli-reference.md:4857 and both review-orchestrator SKILL.detail.md copies (:654, :665).
