### Findings

### [F-001] The keyboard test never presses ArrowUp, which AC5 names
- **Severity**: minor
- **File**: apps/desktop/src/metaproject/MetaprojectTree.dom.test.tsx
- **Rule**: canonical rubric (test gap on an AC-listed behaviour; no defect shown)
- **Problem**: "keys move, expand, collapse and select as a WAI-ARIA tree" exercises ArrowDown, ArrowRight, ArrowLeft, Home, End, Enter and Space. No test in the slice (nor in MetaprojectView.dom.test.tsx) dispatches `ArrowUp`. AC5 lists Up/Down/Left/Right/Home/End/Enter/Space.
- **Why it matters**: the `ArrowUp` branch (`moveTo(rows[index - 1])` in MetaprojectTree.tsx) could break or be dropped with the AC5 verify command still green.
- **Fix**: add one `await key(document.activeElement!, "ArrowUp"); expect(focused()).toBe(...)` step to the existing keyboard test (for example after the ArrowDown to `server.ts`, expect `client.ts`).

### [F-002] The guide documents an "Other" wiki group that the reader never produces
- **Severity**: info
- **File**: docs/docs/guides/desktop-metaproject.md
- **Problem**: the guide says pages without a page type are under **Other**, and `wikiTree` groups `node.pageType ?? "other"`. But every wiki node the explorer builds sets `pageType: type` from the fixed `WIKI_PAGE_TYPES` folder list (src/integrations/metaproject-explorer.ts:78), so no page reaches that group today. Not a bug; the sentence describes a fallback that is currently unreachable.
- **Fix**: none required; drop the sentence or keep it as forward-compatible wording.

### [F-003] "Name order" in the guide is code-unit order
- **Severity**: info
- **File**: docs/docs/guides/desktop-metaproject.md
- **Problem**: folders and files are sorted with `compareText` (`a < b`), so `Zeta/` sorts before `alpha/` and accented names after ASCII. The guide says "in name order".
- **Fix**: optional; say "in name order, capitals first", or sort with a locale compare if the UI should match a file manager.
