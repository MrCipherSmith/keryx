### Checked and found clean
- Input validation at the boundary: `tree` in parseV2 uses an exact key allowlist (action, version, expectedSnapshotId, scope, parent, cursor), a closed scope enum, `expectedSnapshotId` as SHA-256 hex, a graph `parent` through isMetaprojectRelativePath (rejects absolute, drive-letter, backslash, control chars, empty, `.` and `..` segments, >4096 chars), a wiki `parent` and `cursor` length-bounded. Tests cover `/src`, `../outside`, `src/../outside`, `src/`, `C:/src`, wrong types and extra keys.
- Path traversal: the `tree` action never touches the filesystem with `parent`. graphTree and wikiTree work only over the in-memory graph model, and that model's nodes are already filtered by safeGraphNode at metaprojectExplorerV2 (metaproject-explorer-v2.ts:460), so a hostile nodes.jsonl path such as `../x` cannot reach a tree answer. The Desktop validator also refuses a folder path that escapes and a module whose path differs from its folder (platform/metaproject.test.ts "rejects malformed tree pages").
- Wiki `parent` is used only as a Map key (no prototype-pollution exposure: Map, not object), and is echoed back only in the `parent` field.
- Cursor integrity: tree cursors reuse cursorValue (strict base64url round-trip, 3-tuple, SHA-256 snapshot, key bound to hash(["tree", scope, parent]), positive safe-integer offset); offsetPage refuses out-of-range offsets. Cross-parent and cross-scope cursors answer invalid-input; another snapshot answers stale-snapshot (tests present).
- Resource bounds / DoS: pages capped at METAPROJECT_PAGE_SIZE_V2 (100) and TREE_ITEMS_BYTES (900 KiB), whole response capped at METAPROJECT_RESPONSE_BYTES_V2 (1 MiB). Per-request work is linear in the graph's node count for the graph scope; wikiTree's per-group array spread is quadratic in pages per group, which is a performance concern for the performance lens, not an attacker vector (the input is the local checkout's own wiki).
- Error disclosure: not-found and invalid-input messages are fixed strings; no path, parent or internal detail is echoed; non-typed errors collapse to source-unavailable.
- Injection (SQL, command, template, eval), secrets, crypto, auth/IDOR, CSRF, open redirect: not applicable to this slice (local read-only CLI action and its tests; no execution, no secrets, no network surface).
- React patterns in the slice's test files: no dangerouslySetInnerHTML, eval or storage of sensitive data. MetaprojectTree.tsx itself is not in slice-02 and was not reviewed here.
- Docs: no secrets or personal data.
