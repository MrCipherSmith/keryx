### Findings

### [F-001] Desktop tree response guard does not tie entries to the requested parent
- **Severity**: info
- **File**: apps/desktop/src/platform/metaproject.ts (validTreeEntry)
- **Attack vector**: none reachable. It would need a CLI that answers `tree` with a folder `path` or group `key` outside the requested parent; the CLI is the user-selected/bundled local executable that Tauri already authenticates in its probe, and every value echoed back as a later `parent` is re-validated by Rust `relative_path` / `valid_text` before reaching argv (no shell).
- **Problem**: `validTreeEntry` checks that a folder path is checkout-relative and a group key non-empty, but not that a folder is a direct child of `parent` or that a group key is bounded (Rust caps it at 4096 UTF-16 units, so an oversized key only produces an `invalid-input` on expand).
- **Why it matters**: defence-in-depth only; a misbehaving CLI could render rows under the wrong folder. No filesystem, shell or HTML sink is reached.
- **Fix**: optional: in `validTreeEntry` require `value.path` to equal `${parent}/${value.name}` (or `value.name` at the root) for folders, and cap group key length at 4096.

### Clean Areas
- Injection / command injection: `metaproject_args` still builds an argv vector (`metaproject-explorer --request <json>`), no shell; the new `Tree` variant goes through the same `deny_unknown_fields` serde enum, null rejection and 16 KiB cap.
- Path traversal: graph `parent` is validated with `relative_path` (rejects `..`, `.`, empty segments, leading `/`, backslash, control chars, drive letters); Rust tests cover `../escape`, `/src`, `src\\lib`. The core tree service (context read only, other slice) answers from the in-memory graph model; `keryx ctx rg "readFile|readdir|statSync|existsSync|join\("` over src/integrations/metaproject-explorer-v2.ts found no filesystem call.
- Snapshot pinning: `expectedSnapshotId` must be a 64-hex digest (Rust `digest`), the TS `matchesRequest` checks snapshot, scope and parent of the answer, and the hook drops answers from an older generation and never resends an old-snapshot cursor.
- XSS / React: all CLI-supplied strings (titles, names, error messages) render as JSX text; no `dangerouslySetInnerHTML`, `innerHTML` or `eval` in the new files (ctx rg, 0 matches). Row lookup uses `dataset.row ===` comparison rather than interpolating ids into a CSS selector. Inline style uses only the numeric level.
- Response bounds: tree pages are capped at `METAPROJECT_PAGE_SIZE_V2` entries and `METAPROJECT_RESPONSE_BYTES_V2` bytes; node kinds are restricted per scope.
- Capability handshake: relaxing the required set to six fixed actions does not widen what Desktop sends; `tree` is sent only when the CLI lists it.
- Secrets, crypto, auth/authz, IDOR, CSRF, open redirect, logging: no relevant code in the slice; nothing found.
