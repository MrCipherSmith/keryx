### Findings

#### [F-001] Wiki group key rule re-derived on the client
- **Severity**: minor
- **File**: apps/desktop/src/metaproject/MetaprojectTree.tsx (`revealSteps`)
- **Problem**: The client hard-codes the core's grouping rule: `const group = node.pageType || "other";`. The rule's owner is the core service (`src/integrations/metaproject-explorer-v2.ts:33` `const WIKI_UNTYPED_GROUP = "other";`, applied at line 145 as `node.pageType ?? WIKI_UNTYPED_GROUP`), which the contract does not export. Two copies of one domain rule on two sides of the contract, and they already differ (`||` vs `??`: an empty-string `pageType` maps to `"other"` on the client but to `""` in core).
- **Why it matters**: Reveal (AC6) depends on the client predicting the server's key. If core changes the untyped-group key or its normalisation, reveal of wiki pages silently stops at the root (`setHandled` after "not found"), and no test on either side ties the two together.
- **Fix**: Export the key (or a `metaprojectWikiGroupKey(node)` helper) from `src/integrations/metaproject-explorer-contract.ts`, use it in `metaproject-explorer-v2.ts` and in `revealSteps`.

#### [F-002] Test seams shape the production prop type and initial state
- **Severity**: info
- **File**: apps/desktop/src/metaproject/MetaprojectView.tsx
- **Problem**: `type Negotiate = (cwd: string) => Promise<1 | 2 | MetaprojectNegotiation>;` keeps the bare-number form only so older test doubles still type-check, and `useState(!negotiates && Boolean(requestTree))` turns the tree on because a test injected a reader. This follows the file's pre-existing pattern (`negotiates` is already derived from which seams were injected), so it is not a new violation.
- **Why it matters**: Production behaviour branches on which test seams are present; the union widens every future caller's contract.
- **Fix** (optional): migrate the test doubles to return `MetaprojectNegotiation` and narrow `Negotiate` to it.

#### [F-003] Reveal algorithm sits in the component, not in the tree model
- **Severity**: info
- **File**: apps/desktop/src/metaproject/MetaprojectTree.tsx (the reveal `useEffect` with no dependency list)
- **Problem**: The hook owns data and paging, but the multi-step reveal (walk ancestors, `ensure`, `more`, `setExpanded`, `setHandled`) is orchestrated from an effect that runs after every render in the component. The rule the skill cites for this (`.metaproject/rules/stacks/react/code-style-patterns.mdc` Rule 2) does not exist in this checkout, so no named rule is violated.
- **Why it matters**: The reveal state machine is only testable through the DOM and re-evaluates on every render.
- **Fix** (optional): move `revealSteps` and the step loop into `useMetaprojectTree` as `reveal(scope, node)`, leaving the component to request a scroll.

#### [F-004] Required action set duplicated in Rust and TS
- **Severity**: info
- **File**: apps/desktop/src/platform/metaproject.ts (`METAPROJECT_REQUIRED_ACTIONS`); apps/desktop/src-tauri/src/metaproject.rs (`ACTIONS`)
- **Problem**: Previously the TS check used the contract's `METAPROJECT_CAPABILITIES`; now the required set is a Desktop-local literal, mirrored in Rust. Each side pins its literal by test (`metaproject.test.ts:117`, Rust `tree_stays_optional_for_a_cli`), so per-side drift is caught; cross-language drift is not. This is the intended design (plan.md: the CLI must offer only what Desktop always sends).
- **Fix**: none required.

```diff
+++ b/src/integrations/metaproject-explorer-contract.ts
+/** The tree group key of a wiki page: its page type, or `other` without one. */
+export const metaprojectWikiGroupKey = (node: { pageType?: string }) => node.pageType || "other";
--- a/apps/desktop/src/metaproject/MetaprojectTree.tsx
+++ b/apps/desktop/src/metaproject/MetaprojectTree.tsx
-    const group = node.pageType || "other";
+    const group = metaprojectWikiGroupKey(node);
```
(and use the same helper at `metaproject-explorer-v2.ts:145`; choose `||` or `??` once, deliberately.)
