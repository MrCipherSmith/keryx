### Logic Bugs

### [F-001] Home on the first row / End on the last row leaves a focus request that a later data render executes, stealing focus
- **Severity**: major
- **File**: apps/desktop/src/metaproject/MetaprojectTree.tsx (moveTo, and the layout effect that consumes `focusRequest`)
- **Problem**: `moveTo` calls `setFocusId(row.id)` and sets `focusRequest.current = true`. The request is consumed only in a dependency-free `useLayoutEffect`, so it needs a commit. Press Home while focus is already on the first row, or End on the last row. `focusId` already equals that row's id, because `onFocus` keeps it in sync, so React bails out of the state update. Nothing commits and `focusRequest` stays `true`. The next commit of the tree then runs `root.querySelector('[role="treeitem"][tabindex="0"]').focus()`, whatever caused that commit: a folder page arriving, a reveal's `setHandled`, a snapshot reset.
- **Why it matters**: Repro: focus the first tree row and press Home. Click a node in the graph canvas, or the details panel. The selection change runs the reveal effect, `setHandled` re-renders the tree, and keyboard focus jumps from the canvas into the tree. The plan says "Focus is never moved by data arriving", and AC6 says a selection made elsewhere scrolls its row into view "without moving focus". This is a silent wrong result on a named input.
- **Fix**: In `moveTo`, focus at once when the target is already the focus target. Do not rely on a commit: `if (row.id === focusId) { list.current?.querySelector<HTMLElement>(`[data-row="${CSS.escape(row.id)}"]`)?.focus(); return; }`. Otherwise, clear `focusRequest` when no state change follows. Add a DOM test: Home on the first row, then a model update, then assert `document.activeElement` did not change.

### Edge Cases
- [F-002] info: revealing a symbol expands its file's folder but scrolls to no row, because the tree has no symbol rows. A wiki node selected in Graph mode also has no row. Both leave `scrollRequest` set to an id that never renders until the next reveal replaces it. This is harmless and already noted as untested in the journal. If a symbol should reveal its file row, push a `node` step for the file. The tree would then need the file's id, which the symbol node does not carry, so the simplest fix is to set no scroll request when `revealSteps` yields no row.
- [F-003] info: the `requestTree` prop doc in `MetaprojectView` says "injected without a negotiation, it alone turns the tree on". Without `requestV2`, though, `protocol` starts at 1, and `treeScope` requires protocol 2. The tree turns on only with `requestTree` **and** `requestV2` injected. This affects the test seam's documentation only.

### Suggested Patches
```diff
   const moveTo = (row: Row | undefined) => {
     if (!row) return;
+    if (row.id === focusId) {
+      list.current?.querySelector<HTMLElement>(`[data-row="${CSS.escape(row.id)}"]`)?.focus();
+      return;
+    }
     setFocusId(row.id);
     focusRequest.current = true;
   };
```
