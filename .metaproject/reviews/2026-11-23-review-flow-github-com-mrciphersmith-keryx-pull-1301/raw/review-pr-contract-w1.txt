## Findings

### [PC-001] The CLI reference's capability paragraph does not mention optional actions such as `tree`

- **Severity**: info
- **File**: docs/docs/cli-reference.md:8301
- **Problem**: The reference says "Require the actions you send and ignore the others. A later CLI can list more actions, and Desktop accepts any CLI whose list includes the ones it uses." With this diff, Desktop sends `tree` but does not require it. platform/metaproject.ts adds `METAPROJECT_REQUIRED_ACTIONS` with the comment "Optional actions (`tree`) are used only when the answering CLI lists them", and `requestMetaprojectTree` is "call only when the negotiation reported `supportsTree`". The statement is still true as a sufficient condition, so a reader following it gets no wrong result. It just no longer describes the whole handshake, and the `tree` action appears nowhere in the reference.
- **Why it matters**: a third-party CLI or client author reading the reference cannot learn that `tree` exists or that it is optional. Following "require the actions you send" literally would make a client refuse an older CLI, which is the defect T5/T6 fixed in Desktop.
- **Fix**: optional. Add one sentence after line 8301, for example: "Some actions, such as `tree`, are optional: Desktop sends them only when the CLI lists them, and works without them."
