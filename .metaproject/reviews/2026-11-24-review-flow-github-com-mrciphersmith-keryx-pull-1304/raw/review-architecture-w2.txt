### Summary
Slice-04 adds the `keryx review reviews` CLI command (`src/commands/review-reviews.ts`), wires it into the review command group, help and subcommand list, exports `writeJson` from `review-board.ts`, adds store migration and Review-entity tests, and updates the stage-2 docs. The layering mostly follows the existing board command: the Review state and freshness rules live in `src/review/review-entity.ts`, persistence in `desk-run-store.ts`, GitHub I/O is injected (`query`, `compare`, `root`), and the command parses arguments and writes output. There are no blocker or major findings. There are two minor findings: the command recomposes the "behind" rule that the domain's `freshness` already owns, and the new command imports its output primitive from a sibling command module. There is one info note.

### Layer Violations
[F-001] (minor) `readReviews` in `src/commands/review-reviews.ts` (the `behind` flatMap) decides which Reviews are behind their PR: `reviewed !== card.headSha && !reviewClosed(row, card)`. The domain function `freshness(reviewed, head, compare)` in `src/review/review-entity.ts`, called by `summarizeReview`, makes the same decision. So two layers now hold the rule, and the command's copy selects which comparisons are made. If the domain rule changes (for example, how a closed Review or an unknown head is treated), the command will compare a different set from the one the summary reports. Rated by clean-architecture.mdc, "Controller ... holds business rules": minor. No defect is named today. Fix: add a domain helper in review-entity.ts, such as `needsComparison(row, card): { reviewed, head } | null`, used by both the command and `summarizeReview`. The command would keep only the GitHub-safety check (`OBJECT_ID`), the cap and the pool.

### Module Boundary Violations
[F-002] (minor) `src/commands/review-reviews.ts` imports `writeJson` from `./review-board`, and `review-board.ts` changed `writeJson` from private to `export` for this. This is the only place under `src/commands` where one command module imports a helper from a sibling command. The other sibling imports are the group router `review.ts` taking `*_USAGE` and `run*`, and tests. `writeJson` is not plain JSON output. It wraps `withCurrentGithubBinding` (from `src/review/board-github.ts`) to re-check the GitHub binding when the payload is published. So a GitHub-binding guarantee now reaches a second command through another command's file. Fix: move `writeJson`/`writeSerialized`, for example as `writeBoundJson`, next to `withCurrentGithubBinding` in `src/review/board-github.ts`, import it from there in both commands, and keep `writeJson` private in review-board.ts.

### Info
[F-003] (info) `readReviews` passes `ReviewsSnapshot` to `listActiveReviewCards`, whose parameter is `Pick<ReviewBoardSnapshot, "repo"|"repositoryId"|"viewer">`. This works through structural typing. The board card reader and the new Reviews snapshot are now coupled by field names, not by a named subject type. A small `{ repo, repositoryId, viewer }` subject type in board-types.ts would state the contract. No change is required.
