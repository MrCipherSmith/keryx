### What was checked, and why it holds

1. SQL injection in the new store code. Every value reaching SQL is bound with `?`: reviewFor (repo, pr, viewer), roundFor (reviewId, round, previousId, base, head), the assignReviews UPDATE, reviewRows (repositoryId, viewer), attachBadges (`?1..?3`). The interpolated fragments are constants: `ALTER TABLE runs ADD COLUMN ${name} ${type}` iterates the module-level `reviewColumns` tuple; `placement(alias)` yields either a fixed column name with a literal alias ("", "r.") or `NULL`; `questionRows`, `pending` (table names from a fixed IN list in sqlite_schema) and `visible(r)` are internal. No request, GitHub or run-details data is interpolated.

2. Account scoping / IDOR. reviewRows selects by `v.repo=? AND v.viewer=?`; the only caller (src/commands/review-reviews.ts:33-40) takes both from the GitHub identity query for the bound account and refuses with `access:` when either is missing. Review assignment keys on the runs table's own repo/pr/viewer columns, not on `details`, so a run's JSON cannot place it in another account's Review. Both `reviews.viewer` and `runs.viewer` are COLLATE NOCASE, matching GitHub's case-insensitive logins, so case variants neither split nor cross accounts.

3. Forged placement on import/save. `storedDetails` overwrites `reviewId`, `round` and `previousRunId` with undefined before serializing, in save and recordExisting, so an imported run (source `existing`) cannot carry its own placement into `details`; `place()` projects only from the columns. roundFor links a continuation only when `previousId` belongs to the same reviewId (`WHERE id=? AND review_id=?`), so a crafted `continuation.previousId` cannot join another Review's round.

4. Path traversal. reviewRows and attachBadges call `publication(id, ...)` and `transcriptUpdatedAt(id)`, both of which require the id to match the UUID regex before building a path under `attempts/`; no new path is built from input.

5. Data exposure. reviewRows reads no report body and no reviewer sessions; history continues to strip `result.report`, `workerIdentity` and `continuation.guidance` from the metadata. The badge `outdated.round` adds only an integer.

6. Untrusted parsing. `JSON.parse(item.findings)` parses a value SQLite extracted from the store's own JSON; it is not a new trust boundary.
