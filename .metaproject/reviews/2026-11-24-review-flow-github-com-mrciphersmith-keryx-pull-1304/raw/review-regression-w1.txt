Short summary: I found 2 regressions, both `major`. Both come from moving the "view" and "answer" Review actions, and the attention signal for local reviews, from the Pull requests tab to the new Reviews tab.
1. "Open in Reviews" hands over only the PR number, not the repository. The Reviews tab keeps its own repository choice, separate from the Pull requests tab. When the two tabs show different repositories, "View review", "Answer question" or the panel's "Open in Reviews" opens the Review of a different PR that has the same number, or shows "has no Keryx review in this list".
2. The Reviews tab's attention indicator only reloads when the tab is opened, or every 60 s while the tab is open and a review is running. Before this change, the PR watcher's 60 s poll refreshed the board on every tab, and session-review snapshots also updated it, so the Pull requests indicator lit while the user was on another tab. The change removed awaiting-answer and publication-pending from that indicator, so a scheduled or session-started review that now waits on the user lights no tab until the user opens Reviews.

Checked and not a regression:
- `needsViewerAttention` now ignores awaitingAnswer and publicationPending. Its callers are ReviewBoard (attention set and hidden-attention hint) and model.test.ts. AC8 intends this change. `reviewLane` and `attentionReason` still put those cards in the attention lane.
- `ReviewDetail` dropped the `publishCommand` prop and the "Keryx review" tab. Its only production caller is ReviewBoard (App.tsx), and it no longer passes `publishCommand`.
- `useReviewRuns(..., visible=false)` still reads status once on mount, so `hasReview` and `loaded` resolve.
- Readers of an unmigrated DB: `readReviewRows` opens the store for writing and migrates it, so older runs still appear as Reviews.
- `ReviewIntent` is re-exported from ReviewDetail, so importers still compile.
