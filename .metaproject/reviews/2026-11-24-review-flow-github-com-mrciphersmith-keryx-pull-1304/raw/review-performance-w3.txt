### Findings

### [F-001] roundFor's retry lookup parses the full `details` (report included) of every attempt of the Review, once per unassigned row
- **Severity**: minor
- **File**: src/review/desk-run-store.ts:192 (roundFor), called from assignReviews:161 via the constructor migration (:138-142), recordExisting (:397) and requestAttempt (:741)
- **Hot path**: once per writable open of a pre-Reviews store (migration of every row), and once per new attempt row (dispatch, history import). Not a per-keystroke or per-render path.
- **Problem**: the retry query filters `WHERE review_id=? AND round IS NOT NULL AND json_extract(details,'$.baseSha') IS ? AND json_extract(details,'$.headSha') IS ?`. The `review_rounds(review_id, round)` index narrows to the Review's rows, but every one of them is then JSON-parsed in full, and `details` embeds `result.report` (history() caps inline previews at 512 KiB, so reports of that size exist). In the migration loop this runs once per pending row, so the cost per Review is O(k^2) full-document parses for k attempts, all inside the immediate write transaction the constructor opens.
- **Why it matters**: for a long-lived PR with many scheduled attempts (e.g. 50 attempts with ~100 KB reports: ~1,250 parses, ~125 MB of JSON) the first open after upgrade holds the write lock noticeably longer while other windows wait on busy_timeout (8 s). After migration each dispatch pays one O(k) scan of full documents. Estimated, not measured; real attempt counts and report sizes per PR are not in the payload, and whether Bun's bundled SQLite JSON parse cache softens this was not verified.
- **Fix**: in assignReviews keep an in-memory map `(reviewId, base, head) -> round` and `(reviewId) -> max round` across the loop (seeded by one query per Review), so a migration parses each row once; or select `json_extract` of base/head only via a narrow query `SELECT round, json_extract(details,'$.baseSha'), json_extract(details,'$.headSha') FROM runs WHERE review_id=?` once per Review and match in JS. Persisting base/head as columns alongside `round` would remove the JSON parse entirely.
