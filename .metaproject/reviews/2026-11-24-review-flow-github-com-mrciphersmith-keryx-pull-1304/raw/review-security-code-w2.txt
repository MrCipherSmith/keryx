### What was checked, and why it holds

1. Command / URL-path injection in the new compare call (src/commands/review-reviews.ts:424-425).
   `gh` runs through `boardGh` -> `execFile` with an argv array (board-github.ts:16,123), no shell. The API path `repos/${repo}/compare/${base}...${head}?per_page=1` takes `repo` only from `selectRepository`, which returns an entry of the project's configured GitHub.com fetch remotes (a `--repo` value not in that list is refused). Both SHAs pass `OBJECT_ID = /^[0-9a-f]{40}$/` before any compare is queued (review-reviews.ts:377), including the reviewed head read from the local store, so a tampered store row cannot add path segments or query parameters. `--jq "{status, ahead_by}"` limits what leaves gh, and `parseCompare` accepts only a known status and a non-negative safe integer.

2. GraphQL. `identityQuery` is a constant; owner/name go as `-f` variables, not interpolated into the query text (boardGraphql).

3. SQL. `reviewRows` binds repositoryId and viewer as `?` parameters (desk-run-store.ts:586-587). All 36 `${...}` interpolations in desk-run-store.ts are module constants or internally built fragments (state lists, `placement`, `questionRows`, the fixed `reviewColumns` list for ALTER TABLE, `?` placeholder lists); none carries request or GitHub data.

4. Account/IDOR. Rows are selected by the repositoryId and viewer login GitHub returns for the selected account (the identity query runs as the project-bound gh account; `boardGh` calls `verifyGithubBindingUnchanged` after every call, and the response is written under `withCurrentGithubBinding`). Another account's Reviews and archived/deleted attempts stay out (test "one summary per Review ..." pins the colleague and archived cases). An unidentified account or repository is refused with `access:`.

5. Data exposure. Report bodies and reviewer progress are not in the output (test asserts `private report body` and `reviewerProgress` absent). Compare failures are swallowed into a fixed warning; `boardGh` already maps subprocess errors to fixed diagnostics, so stderr with URLs/tokens does not reach the JSON. `access:`/`configuration:` errors are rethrown rather than turned into a partial list.

6. Forged projection on import. `recordExisting` ignores `reviewId`/`round`/`previousRunId` carried in an imported run, and the projection is never written into `details` (desk-run-store.test.ts "a new attempt is assigned its Review and round ..." pins both), so an imported package cannot attach itself to another account's Review.

7. Resource bounds. Compares are capped at 25 per call with parallelism 4; the board writer's 30 MiB guard is unchanged (the only change to review-board.ts is exporting `writeJson`).

8. CLI surface. `parseArgs` is strict with no positionals; `reviews` is added to the help table (a printer, cannot execute) and to group-subcommands; no new mutating flag.
