### Findings

### [PC-005] The stage 1 overlap list omits `model.test.ts`, which conflicts
- **Severity**: minor
- **File**: apps/desktop/src/review/model.test.ts
- **Problem**: The body's "Expected overlap with stage 1" section opens with "Expect conflicts in:". It names `apps/desktop/src/review/model.ts` ("stage 1 rewrites the lanes and quick filters; stage 2 removes the local-review clauses ... Keep both") and other test files, but not `model.test.ts`. Slice-03 changes that file in the same places stage 1 rewrites:
  - the import line (`+import { EMPTY_FILTERS, filterReviews, laneReason, needsViewerAttention, ...`);
  - the outdated-review tests (`laneReason(...)` → `reviewNote(...)`, and "No review requested").

  Stage 1 also rewrites the import (adding `ROLE_LANES, STATUS_LANES, drawnLanes, newestFirst`) and the same outdated/base-moved tests. `git merge-tree --write-tree feat/desktop-review-v2-stage1 20e4281a2` reports `CONFLICT (content): Merge conflict in apps/desktop/src/review/model.test.ts`.
- **Why it matters**: Whoever merges the second stage reads the list as the full set of conflicts and the guidance for each. For `model.test.ts` there is no guidance. The two sides disagree on what `laneReason` returns for an outdated card: stage 2 pins "No review requested", and stage 1 pins its own lane reasons. Resolving it by taking one side silently drops either the new `needsViewerAttention` test, which guards the "Pull requests tab no longer lights" claim, or stage 1's lane tests.
- **Fix**: Add `apps/desktop/src/review/model.test.ts` to the overlap list, with the same "keep both" guidance as `model.ts`: keep stage 1's lane tests and stage 2's `needsViewerAttention` test and the `reviewNote` assertions.
