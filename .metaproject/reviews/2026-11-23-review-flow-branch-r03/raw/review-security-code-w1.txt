## Security Review (round 3, slice-02)

Read in full: slice-02.diff (App.tsx, MetaprojectView.tsx, RelationshipList.tsx and their three test files); surrounding code at head only for the MetaprojectWork callers (keryx ctx rg). Not run: anything (read-only, exec budget 0).

### Followed to the input an attacker could control

1. Quiet read no longer shows errors (catch at MetaprojectView.tsx ~859, `!quiet`). A refused or tampered read on return is silent. Source of the read is the local CLI for the user's cwd; no remote or cross-user input. A standing error is kept (the effect does not clear it for a quiet read), a non-quiet read still shows its failure, and a return during a pending read starts none, so a user-started action always surfaces a persistent failure. Stops at: the attacker would need write access to the project's index or the CLI, which is already local code execution. Reported as info F-001.
2. Wiki-link lookup surviving a catalog replacement (openPath ~950-960). `snapshotId` is captured before the read and compared with `result.snapshotId`; a mismatch sets the existing "Project knowledge changed" banner. A lookup that started against the old snapshot and is answered from the old snapshot opens a node from that snapshot (stale, not foreign data). The query is the href-derived repository path sent as a `search` string, never a file path read by the app, so a crafted `../` href yields a search query, not a file read (resolveRepositoryPath is unchanged by this slice). `project.current` is not bumped for a quiet read, but it still moves for a project change, protocol change, Retry, Refresh, Rebuild and unmount (cleanup bumps unless the next run is quiet); a cwd change remounts the explorer, so the one case where cleanup and a quiet flag coincide (cwd change at the instant of a return) is not reachable through the UI.
3. Exported MetaprojectWork with an `explorer` prop. It is the single place a component is injected; callers are ProjectWindow (App.tsx:618, passes none, so the lazy MetaprojectView is used) and App.dom.test.tsx. The prop is a React component reference set in source, not read from props that originate in URL, IPC, storage or CLI data. Whoever can pass one already runs code in the renderer. The injected component receives cwd, visible, onRebuild and onDraft (onDraft opens a draft session); that is within the same trust boundary. Stops at the module boundary.
4. Counts from grouped relationships. `wikiRelationshipRows` is a sum of three numbers from summarizeRelationships and is rendered as a React text child (escaped). Titles and paths in the list are rendered as text and `title` attributes by React, unchanged by this slice. Edge counts are bounded by the projection the CLI returns; no new unbounded loop (one extra grouping pass in a useMemo).
