## Findings

### F1 (minor, diff-vs-description / behaviour-delta, consumer-trace) Desktop calls a session Attempt "Existing review" while treating it as a worker run with a coordinator

The PR body says a registered session package "appears in ... the Reviews tab ("Session")", and the flow journal (slice-01:277) records "Desktop's source label "Session"". Only `reviews/model.ts` SOURCE_LABEL learned the new value. The two other source labels are ternaries whose else-branch is "Existing review", the label of an imported review: `ReviewRuns.tsx:131` (attempt detail) and `ReviewRunDialog.tsx:32` (History menu). In the same components, every `source !== "existing"` branch now treats a session attempt as a Desktop worker run: `ReviewRuns.tsx:117` shows the "Open review session" chat button, `ReviewRunDialog.tsx:55` sets `hasCoordinator` and subscribes to coordinator activity, and `ReviewRuns.tsx:168` renders ReviewSessions. A session attempt has no coordinator transcript (session-attempt.ts writes only `package/`), so the operator sees it labelled as imported and offered a coordinator session that is empty.
Refute: read model.ts:1568-1573 (only SOURCE_LABEL has "Session"); no other label map in apps/desktop/src handles `session` (search for `"Existing review"`). Base had no `session` source, so these branches were unreachable for it; the change makes them reachable.
