## Findings

### F1 (minor, diff-vs-description, consumer-trace) The `review_complete` card does not register the package as an Attempt, yet the skill says `keryx review complete` does and `advance` depends on it

`SKILL.detail.md` § "Head moved" step 4 (both copies, line 387 of the installed file) says `keryx review advance` "updates from the Review's latest round, which must be an Attempt of the Review: `keryx review complete` and `keryx review publish` register a pull request package as one (`keryx review complete` prints `desktop attempt: <id>`)". Registration was added only to the terminal `runComplete` (review.ts:5171-5178) and to the publish card (operator-confirm-review.ts:191-192, 928). `completeSpec` (operator-confirm-review.ts:789-872) still calls `completeReviewGated` and nothing else. In keryx shell the skill makes the `review_complete` card the only way to close a round ("Call the card and never send the operator to a terminal"), so a round closed there is not an Attempt. "Update after this round finishes" then runs `keryx review advance`, which either refuses with "This pull request has no review to update" (no Desktop round) or, when a Desktop round exists, opens the update from that older Desktop round instead of the session round just completed (`reviewedAttempt` picks the newest registered round, review-advance.ts:665-675).
Refute: searched operator-confirm-review.ts for `registerSession|sessionPublication`: only publishSpec uses them; complete-gated.ts:11 has no registration. The skill's fallback (`keryx review plan --head` when advance refuses) limits the outcome to a detour in the no-Desktop-round case; the stale-base case is silent.
