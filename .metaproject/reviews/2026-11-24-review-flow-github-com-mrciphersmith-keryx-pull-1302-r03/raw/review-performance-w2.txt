### [PERF-W2-1] Registering before publishing runs the readiness checklist twice, so `keryx review publish` reads the same PR 4 times and its files twice
- **Severity**: minor
- **File**: src/commands/review.ts:5073
- **Hot path**: once per `keryx review publish` (interactive: the operator waits at the prompt), once per `review_publish` card build and once per `keryx review complete`. Not a loop; each read is a `gh` subprocess with a network round trip.
- **Problem**: `runPublish` now calls `sessionPublication(packageDir, register)` where `register = registerSessionPackageForProject(..., readiness)`. `registerSessionPackage` calls `computeReadiness(packageDir, readiness)` (session-attempt.ts:88) only to choose `completed`/`partial`, which costs one `prLookup` (readiness.ts:367 head gate) and one `prFiles` (readiness.ts:419), plus `resolveDeskSubject` gh calls for the key. `publishReview` then calls `readPullRequest` (publish.ts:195), `computeReadiness` again (publish.ts:202: `prLookup` + `prFiles`), and `readPullRequest` after the yes (publish.ts:243). Before stage 4 the same command made 1 `prLookup`, 1 `prFiles` and the post. Now: 4 `prLookup`, 2 `prFiles`, the subject resolution and the post. The card path does the same twice over (buildCard registers and dry-runs publishReview at operator-confirm-review.ts:215-225; apply runs publishReview again). `runComplete` (review.ts:5175) adds a second readiness pass after `completeReviewGated` already computed one.
- **Why it matters**: each `gh pr view` / `gh api` call is roughly 0.3–1.5 s; the change adds about 3–5 sequential network calls to an interactive command, i.e. several seconds before the body is shown. Only the post-confirm re-read (publish.ts:243) is needed for correctness (stale check); the rest repeat data read moments earlier.
- **Fix**: compute readiness once and pass it through: let `registerSessionPackage` accept a precomputed `ReadinessReport` (or a `complete: boolean`) and have `publishReview` take the PR snapshot it already read for the head gate (pass `pr` into `computeReadiness`, or memoize `prLookup` per ref for the duration of one command, e.g. wrap `readiness.prLookup`/`prFiles` in a once-per-ref cache in runPublish / publishSpec / runComplete). Keep the post-confirm read uncached.
- **class_scope**: sites review.ts:5073 (runPublish), review.ts:5175 (runComplete), operator-confirm-review.ts:928 with :215 and :245 (card build and apply); enumerated with `keryx ctx rg -n "registerSessionPackageForProject|const publication = await|attemptOf\(dir" src/commands/review.ts src/commands/operator-confirm-review.ts` (3 registration callers, all pass live `prLookup`/`prFiles`).
