## Findings

### TP-W3-1 (major, defect) A session package whose manifest records the base as a ref name is never registered, and the skip is silent

- File: src/review/session-attempt.ts:67 (gate), :139 (reason dropped), src/commands/review.ts:5174-5179.
- Problem: `registerSessionPackage` refuses a package unless `manifest.target.base` is a 40-hex SHA. The session
  producer writes a ref name there in the common case: `review start/ingest --target pr` without `--base` stores
  `base: "origin/main"` (review.test.ts:175-176, prBaseRef at review.ts:698), and `keryx review plan --target <pr-url>
  --head <sha>` is the skill's documented start. Of the 15 GitHub PR packages under .metaproject/reviews/, 11 carry
  `base: "origin/main"` (every first-round package, and 1302-r02). I ran `registerSessionPackage` on
  2026-11-24-…-pull-1302-r02 (read-only up to the guard): `{"skipped":"the package does not record the full base and
  head commits it reviewed"}`. `registerSessionPackageForProject` turns the skip into `undefined` with no message, so
  `keryx review complete` prints no `desktop attempt:` line and no warning, and `publish` falls back to the package's
  own receipt.
- Outcome: for those packages none of flow 521's session/Desktop sharing happens: the Review in Desktop does not list
  the round, Desktop cannot publish it, and `keryx review advance` (SKILL.detail.md Head moved step 4: "keryx review
  complete and keryx review publish register a pull request package as one") has no session Attempt to update from.
- Fix: resolve the base for registration (rev-parse the recorded ref against the package's head, or read the PR's
  baseRefOid through the same resolveKey call), or have `review start/plan` record the base SHA beside `prBase`; and
  surface the skip reason as a warning in `complete`/`publish`. Add a test whose package has `base: "origin/main"`.
- class_scope: sites session-attempt.ts:67 (the only full-SHA gate), :139 (the only place the skip reason is dropped);
  callers review.ts:5073 (publish), :5174 (complete), operator-confirm-review.ts:215 (card). Enumeration:
  `keryx ctx rg registerSessionPackage|registerSessionPackageForProject src` (3 callers, all through ForProject).

### TP-W3-2 (minor) The AC5 fixture carries a Desktop package's shape, not a session package's

- File: src/review/desk-publication.test.ts:775-779
- Problem: `sessionAttempt()` copies the Desktop attempt's own `package/` and changes only `reviewId`; it inherits a
  full-SHA `target.base` that the session producer usually does not write (see TP-W3-1), and TP3-M12 (deleting the
  full-SHA guard) survives. The AC5 tests read as coverage of "a package an agent made in a session" while covering
  only Desktop-shaped packages.
- Fix: build the fixture from what `keryx review start --target pr` writes (or add a second case with
  `base: "origin/main"`) and assert the outcome the fix for TP-W3-1 chooses.

### TP-W3-3 (minor) Four guards `publishReview` added are unpinned

- File: src/review/publish.ts:229, 244, 247, 251
- Problem: survivors TP3-M1 (the package's own pre-registration receipt is no longer read, so a package published
  before registration could be published again through the Attempt), TP3-M2 (an unreadable head after the operator's
  yes no longer refuses), TP3-M3 (a PR merged while the operator read no longer refuses), TP3-M5 (a short head is sent
  as `commit_id`). The "push while the operator reads" test covers only a changed SHA; no fixture has a receipt
  beside the package plus a registered Attempt, a lookup returning null/MERGED on the third call, or a 7-char head
  with an asserted `commitId`.
- Fix: four small cases in the "publication guard shared with Desktop" describe: receipt in packageDir + `publication`
  pointing elsewhere -> refused; `at(REVIEWED, REVIEWED, {exists:false})`-style null after the yes -> refused;
  `at(REVIEWED, REVIEWED, {state:"MERGED"})` -> refused; head `abcdef1234567` -> `commitId` undefined.

### TP-W3-4 (minor) Receipt, session-state, advance and port guards survive deletion

- Files: src/review/publication-guard.ts:38, :55; src/review/session-attempt.ts:99; src/review/review-advance.ts:43;
  src/review/session-publish-github.ts:52
- Problem: survivors TP3-M7 (an unreadable receipt counted as absent -> a second post), TP3-M8 (a `{posted:true}`
  receipt, written when GitHub answers without `html_url`, no longer reads as published), TP3-M10 (a session package
  failing readiness registered as `completed`), TP3-M16 (a base-only change reads as "already current"), TP3-M18 (a
  non-github.com `html_url` lands in the receipt). Every receipt test posts with a URL; no fixture has an unreadable
  receipt, a failing-readiness session package, or a base-only move.
- Fix: one case per guard: chmod 000 / directory-as-receipt -> refused as unknown; post returning `{ok:true}` without
  url, then republish -> "already been published"; register a package whose readiness fails -> state `partial`,
  coverage `partial`; advance with `{baseRefOid: other, headRefOid: B}` on a round at B -> starts; `html_url:
  "https://evil.example/x"` -> no `url`.
