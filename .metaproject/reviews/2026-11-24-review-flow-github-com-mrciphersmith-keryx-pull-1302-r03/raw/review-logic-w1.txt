### Summary
Desktop's "Update review" now runs `keryx review advance` (Rust `RunAction::Advance` -> `review advance --json ... --id --base --head`); argument order and flag validation match the CLI parser. Two consequences of the change are not handled: advance refuses an archived attempt with an `access:` error that Desktop treats as lost account access, and the new `session` source is rendered as "Existing review" / offered a coordinator session in the attempt card.

### Logic Bugs
[LOG-W1-1] Update review from an archived attempt now fails as "access lost"
- Severity: minor
- File: apps/desktop/src/review/ReviewWorkspace.tsx:152 (the `local.request({ kind: "advance", id: reviewed.id, ...revision })` call)
- Problem: `reviewedAttempt` (src/review/review-advance.ts:24-26) drops withdrawn attempts (archive/delete) and throws "access: This attempt is unavailable…" when the named id is one of them. Desktop still offers the publish dialog, and its "Update review" button, on an archived attempt: ReviewRuns.tsx:105 `draft` does not check the decision, and desk-publication.ts `publication()` does not refuse archived attempts, so `headMoved` is computed for them. useReviewRuns.ts then sees an `access:` message, clears the snapshot and calls `onAccessLost`.
- Why it matters: before this change the same click started a new round (`kind: "start"`); now it reports lost GitHub access and empties the panel for a condition that has nothing to do with access.
- Fix: in `reviewedAttempt`, use a `stale:`/`configuration:` prefix for a withdrawn or imported attempt ("This attempt was archived; restore it or update from the Review's latest round"), or have Desktop not offer Update review for `reviewIsArchived(run)`.

[LOG-W1-2] The new `session` source is shown as "Existing review" and offered a coordinator session
- Severity: minor
- File: apps/desktop/src/review/ReviewRuns.tsx:131
- Problem: the change adds `session` to `DeskRun.source` and to `SOURCE_LABEL` (model.ts), but the attempt card and the run dialog keep three-way switches that send every non-manual, non-scheduled source to "Existing review" (ReviewRuns.tsx:131, ReviewRunDialog.tsx:32). Sites that test `source !== "existing"` to decide that an attempt has a Desktop coordinator transcript now include session attempts too: ReviewRuns.tsx:117 (the "Open review session" button), ReviewWorkspace.tsx:100 and :213 (`onOpenReviewSession`), ReviewRunDialog.tsx:55 (`hasCoordinator`), desk-run-service.ts:294 (`coordinatorActivity`). A session attempt directory holds only `package/` (session-attempt.ts:116-122), with no coordinator transcript.
- Why it matters: a session review is labelled as an imported review, and the card offers to open a review session that does not exist for it.
- Fix: add a `session` branch to the two labels (or use `SOURCE_LABEL`), and gate coordinator UI on `source === "manual" || source === "scheduled"`.
