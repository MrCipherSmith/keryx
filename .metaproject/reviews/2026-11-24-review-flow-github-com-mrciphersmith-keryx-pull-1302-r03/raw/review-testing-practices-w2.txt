## Findings

### TP-W2-1 (minor) The command wiring that makes `keryx review publish` / `complete` / the review_publish card share Desktop's receipt is untested

- Files: src/commands/review.ts:5073-5081 (runPublish), :5174-5179 (runComplete), src/commands/operator-confirm-review.ts:215,259,261 (card).
- Problem: AC5 says `keryx review publish` uses the shared receipt and marker. The AC5 tests
  (desk-publication.test.ts:812, :831) call `publishReview` with a hand-built `publication: { directory, id }`; no
  test reaches it through a command. Deleting the `publication` argument in runPublish (TP2-M6), the registration in
  runComplete that prints `desktop attempt: <id>` (TP2-M5, the line the skill's step 4 tells agents to read), the
  card's apply-time `publication` (TP2-M4), or either `findPublished` default (TP2-M3, TP2-M7) leaves every suite
  green. The `ReviewCommandSeams.registerSession` / `ReviewConfirmSeams.registerSession` seams exist and no test sets them.
- Why it matters: the AC5 claim rides the function-level seam; the path an operator actually runs can lose the shared
  receipt (and post a duplicate after a Desktop publish) with the suite green.
- Fix: in publish.test.ts drive `reviewCommand(["publish", …], { registerSession, postReview, findPublished, … })`
  after a Desktop publish of the same Attempt and assert the refusal; in operator-confirm-review-tools.test.ts build
  the card with `registerSession` set and assert the posted body ends with the Attempt's marker; in review.test.ts
  assert `complete` prints `desktop attempt:` when `registerSession` returns a record.

### TP-W2-2 (minor) `keryx review advance`'s argument validation has no test

- File: src/commands/review-advance.ts:26-29
- Problem: the CLI Desktop's Tauri `review_run` Advance arm calls (`--id --base --head --repository-id --viewer`) has
  no test of its own; removing the paired `--base/--head` rule (TP2-M1) or the UUID check on `--id` (TP2-M2) stays
  green. review-advance.test.ts tests `advanceReview`, never `runReviewAdvance`. Nothing checks that the args
  review.rs:356 builds parse here either.
- Fix: a small test of `runReviewAdvance` (or `reviewCommand(["advance", …])`) for: `--base` without `--head`
  refused, non-UUID `--id` refused, missing `--json` refused, and the exact argument vector review.rs emits accepted
  (with `advanceReview`'s deps stubbed, or by asserting the thrown usage text).
