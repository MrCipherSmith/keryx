### Summary
The session path now writes the Desktop receipt and marker, takes the same lock in the Attempt directory, refuses non-COMMENT events on a moved head, pins `commit_id` and re-reads the head after the operator's yes. The cross-path guard holds in the tested order (registered first, then either path publishes). It can still be bypassed in two orders the tests do not cover: a receipt written before registration is invisible to Desktop, and deleting a session Attempt deletes its receipt while the next session publish recreates the Attempt. Smaller issues: the moved-head first-line test differs from the head gate's, a definite "not found" from the marker search never unlocks a retry, re-registration overwrites a decided Attempt's package copy, and a `{posted:true}` receipt is not read as published by Desktop.

### Logic Bugs

[LOG-W3-1] A session receipt written before registration is invisible to Desktop: the Attempt registered later can be published again
- Severity: minor
- File: src/review/session-attempt.ts:120
- Scenario: `keryx review publish` runs while registration fails (warning, publish.ts falls back to `receiptDir = packageDir`), posts, and leaves `{url}` in `<package>/publication-receipt.json` with marker `<reviewId>#r<n>`. A later `review publish` or `complete` registers the package: the copy filter excludes `publication-receipt.json`, and the Attempt directory gets no receipt. `DeskRunStore.publication` (desk-run-store.ts:421-429) and `desk-publication.ts prepare` (:145, :283) read only `<attempt>/publication-receipt.json`, and the Desktop marker is the Attempt id, so `findPreviousPublication` cannot find the session's marker either. Desktop shows "Publish to GitHub" and posts a second review. The same holds for a package published before flow 521 (it has only published.json).
- Fix: at registration, if the package holds a receipt (or published.json) and the Attempt directory has none, write it to the Attempt directory (published receipt as is; `{}` as unknown).

[LOG-W3-2] Deleting a session Attempt deletes its receipt; the next session publish recreates the Attempt and posts again
- Severity: minor
- File: src/review/session-attempt.ts:116
- Scenario: a session package is published through its Attempt (receipt in `<attempt>/`). The operator deletes the Attempt in Desktop: desk-run-lifecycle.ts:115 `rm(directory)` for any source other than `existing`, and the row stays as a tombstone with `decision.action = "delete"`. `keryx review publish` on the package re-registers: `recordSession`'s WHERE leaves the row alone, but `register` still `mkdir`s the directory, copies the package and returns the record. publish.ts reads both receipt locations, finds none, and posts again; `findPublished` is only consulted when a receipt exists.
- Fix: have `register` return `skipped` (and `sessionPublication` keep the package's own receipt directory) when the stored row for that id is withdrawn; or keep the receipt outside the deletable directory.

[LOG-W3-3] Publish's "report already names the reviewed commit" test differs from the head gate's
- Severity: minor
- File: src/review/publish.ts:211
- Problem: publish takes the first non-empty line, HTML comments included, and only checks that it contains the 7-char reviewed SHA. complete-head-gate.ts:56-58 skips `<!-- … -->` lines and also requires a moved word (SAYS_SO). Two inputs: (a) the template skeleton starts with `<!-- slot:pre-verdict -->` (templates/review-report.md:36), which `publicProjectReport` does not strip, so a report that carries the proper "Reviewed `<sha>` — the PR has since moved on…" line second gets Desktop's line prepended as well (two notices); (b) a report whose first line names the SHA without saying the PR moved (e.g. a title with the SHA, completed before the head moved) gets no moved notice at all, so a COMMENT on an outdated commit goes out without the D1 statement.
- Fix: reuse the gate's predicate (skip comment lines, require SHA and SAYS_SO) — export it from complete-head-gate.ts and call it here.

### Error Handling

[LOG-W3-4] A definite "not found" from the marker search never unlocks a retry, and local gh failures count as uncertain
- Severity: minor
- File: src/review/publish.ts:233
- Problem: `PublishOptions.findPublished` documents three answers (URL / undefined = none / null = cannot tell), but publish.ts:233-238 treats undefined exactly like null: the package stays refused. `githubPostPullReview` (session-publish-github.ts:40-44) marks every non-zero gh exit without an `(HTTP 4xx)` as `uncertain`, including failures before any request (not logged in, bad token, DNS), so such a failure leaves `{}` and every later publish is refused until the operator deletes the receipt by hand, even though the marker search can say nothing was posted. Desktop drops the receipt when the POST never started (desk-publication.ts:453).
- Fix: when `findPublished` returns undefined, drop the receipt and continue (or say so in the doc and remove the three-way contract); classify gh exits whose stderr shows no HTTP status and no response as not started.

### State consistency

[LOG-W3-5] Re-registration overwrites the package copy of an Attempt the operator already decided on
- Severity: minor
- File: src/review/session-attempt.ts:119
- Problem: `recordSession`'s WHERE (desk-run-store.ts:404-409) refreshes only an undecided session row, but `register` runs `rm(target)` + `cp` on `<attempt>/package` unconditionally. Desktop's "complete" decision closes and writes coverage into that copy (desk-run-lifecycle.ts:83-88) and records the result in the row; the next `review publish`/`complete` from the session replaces the closed copy with the session's package while the row keeps the decided result. The rm+cp also runs outside the publication lock that Desktop's publish holds while it reads `package/`.
- Fix: skip the copy when the row was not updated (check `changes()` of the upsert, or read the row first), and do the copy under `<attempt>/publication.lock`.

### Type Contract

[LOG-W3-6] `{posted:true}` receipt is "published" to publish.ts but "pending"/"unknown" to Desktop
- Severity: info
- File: src/review/publication-guard.ts:189
- Problem: `confirmPublicationReceipt(dir, undefined)` writes `{posted:true}`; `receiptPublished` accepts it, but DeskRunStore.publication (desk-run-store.ts:426) requires `url` and desk-publication.ts:283 falls back to a marker search, blocking with "unknown result" if it finds nothing. Reached only when GitHub's answer lacks `html_url`.
- Fix: have the two Desktop readers use `readPublicationReceipt`/`receiptPublished`.
