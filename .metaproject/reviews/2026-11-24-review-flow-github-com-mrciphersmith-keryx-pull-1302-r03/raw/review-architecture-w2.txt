### Design Pattern Misuse

#### [ARCH-W2-1] The publish preview registers the package as a Desktop Attempt (query with a durable side effect)
- **Severity**: minor
- **File**: src/commands/operator-confirm-review.ts:215 (also src/commands/review.ts:5074)
- **Problem**: `buildCard` is documented as "A dry run of the real function: it checks readiness, builds the body and asks
  `confirm`, which declines", but before the dry run it calls `attemptOf(dir, ctx.projectRoot)` (line 191/215), which, with the
  production seam from `reviewConfirmSpecs()` (line 928), runs `registerSessionPackageForProject`: it inserts/updates a `runs` row
  in the shared Desktop store (`DeskRunStore.recordSession`), copies the package into `<desktop-review>/attempts/<id>/package`
  and writes `desk-attempt.json` into the package (src/review/session-attempt.ts:116-125). `runPublish` does the same before the
  operator is asked (review.ts:5074). The marker does not need the registration: the Attempt id is a pure function of key,
  review id and round (`sessionAttemptId`, session-attempt.ts:30), so only the key lookup is needed to render the body the card shows.
- **Why it matters**: showing a card, or a terminal publish the operator declines, leaves a new "Session" Attempt in Desktop's
  Reviews tab and refreshes an existing undecided one's copy, for a publication that never happened; the card is no longer a
  side-effect-free preview, and the apply path then depends on that side effect having happened (line 259 re-reads
  `desk-attempt.json` with no registrar).
- **Fix**: compute `{directory, id}` for the card from the resolved key and `sessionAttemptId` without writing, and register
  (recordSession + copy) inside the publish lock only after the operator's yes, or keep registration as an explicit step
  (`keryx review complete` already registers).
