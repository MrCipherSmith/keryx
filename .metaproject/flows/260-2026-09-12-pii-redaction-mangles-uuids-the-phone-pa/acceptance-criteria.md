# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `keryx security check-output` on `{"correlationId":"730344f3-3668-4760-9056-bf7292686b67"}` reports zero PII findings and returns the input unchanged, byte for byte.
- AC2: 10 000 v4 UUIDs generated by `crypto.randomUUID()` pass through the detector with zero redactions — asserted in a test that seeds the generator or enumerates the digit shapes, so the run is deterministic rather than probabilistic.
- AC3: A regression test contains the failing UUID as a literal and fails against the pre-fix detector. Recorded evidence: the test run on the unfixed code, showing the failure.
- AC4: The existing phone-detection corpus still passes unchanged — every phone number the detector caught before is still caught, including the formats separated by hyphens, spaces, dots and parentheses. No expectation in the existing PII tests is relaxed or deleted to make AC1–AC3 pass.
- AC5: `src/sac/proposal-lifecycle-parity.test.ts` passes with a correlationId forced to the phone-shaped UUID above, so the parity gate can no longer fail on a dice roll.
- AC6: The same boundary weakness is searched for across the other PII patterns; each one is either shown not to match inside a longer token, or fixed alongside. The check and its result are recorded, so "not affected" is a finding rather than an omission.
- AC7: Full gate green on the branch head: `bun test`, `bunx tsc --noEmit -p .`, `bun run lint`.
