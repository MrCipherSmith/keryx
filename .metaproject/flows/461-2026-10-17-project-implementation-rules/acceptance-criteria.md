# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- Every criterion ends with [verify: exec `<command>`],
  [verify: invariant `<command>`], [verify: judged] or
  [verify: none — <reason>].
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

Revised to the operator's decisions of 2026-10-17 (both modes; warn then block; supplement only; configurable cap raised above 40 KB; TUI required; live run by the operator). Test file names marked (new) do not exist yet.
Stages: 0 (AC1-AC3) order and slot; 1 (AC4-AC8, AC23) kinds, rule import and link mode; 2 (AC9-AC14, AC25) resolver, contracts and project contract files; 3 (AC15-AC16, AC24) orchestrators, shell and TUI; 4 (AC17-AC18) blocking mode; AC19-AC22 cross-cutting.

Tests per case. [verify: exec `bun test src/gdskills/context-resolver.test.ts`]
- AC10: selection: a rule is included when one of its `globs` matches a target file or its `alwaysApply` is true (an `alwaysApply` rule of at most 30,720 bytes competes for the cap like any other; a larger one is an index, listed with `index: true` as `on_demand`, never read whole); the bundled task-type table (`ui_component`, `store_logic`, `service_api`, `fix`, `mixed`) still adds the bundled rules it adds today; `--for test` returns `testing` kind entries plus the project rules whose globs match the test files; with no project content the output equals today's bundled list. Tests per case. [verify: exec `bun test src/gdskills/context-resolver.test.ts`]
- AC11: budget: the per-task cap on project-sourced content is `gdskills.projectContext.maxBytes` in `.metaproject/tasks.config.json` (default 131,072 bytes = 128 KiB, the Vantage frontend-relevant set measures about 85 KB; a non-integer value or one outside 4,096..1,048,576 reads as the default and warns) and `--max-bytes` overrides it for one call; project entries are ordered by glob specificity then size; entries that fit within the cap are `must_read`, the rest are `on_demand` with their `description`; when anything is `on_demand` the output sets `budget.exceeded: true` and the CLI prints one warning line that names the setting to raise and still exits 0; nothing is dropped silently. Tests at cap and cap+1 bytes, for the default and for a configured cap, and for each invalid value. · sensitive: boundary [verify: exec `bun test src/gdskills/context-resolver.test.ts src/gdskills/project-context-config.test.ts`]
