# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- Every criterion ends with [verify: exec `<command>`],
  [verify: invariant `<command>`], [verify: judged] or
  [verify: none — <reason>].
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

Source: requirements package `review-engine-speedup`, step 1 (R1 = E1.1–E1.7, R2 = E2.1–E2.10; specification A1–A5, B1–B8). Not in this flow: R3–R6, E3.x, E5–E7.

## Criteria

- AC1: `next` reports whether the plan is authorized. `NextResult` gains `planAuthorized: boolean | null` and `continue: boolean`; `planAuthorized` is `true` exactly when `packagePlanGate(...).refusal === undefined` (a `plan-confirmation.json` with the current `planKey`, or a plan not above the threshold, or a package the gate does not apply to), `false` when the gate refuses, and `null` when the gate throws (a malformed `plan-confirmation.json` is, for the gate, no confirmation: `false` above the threshold, `true` under it); `continue` is `true` only when `planAuthorized` is `true` and there is at least one dispatch. Existing `--json` fields are unchanged. [verify: exec `bun test src/review/review-next.test.ts -t "planAuthorized"`]
- AC2: With an authorized plan and open slices, text-mode `next` prints a continuation line right after the first line: "plan authorized; continue the loop without asking the operator; stop only for the card list, for plan growth, or on done / Not run". With a refused plan, or when nothing is left to launch, the line is absent. [verify: exec `bun test src/review/review-next.test.ts -t "continuation line"`]
- AC3: A gate that throws (for example an unreadable manifest for the estimate) does not make `next` fail: the dispatch decision is identical to the run without the check and `planAuthorized` is `null`; a malformed `plan-confirmation.json` does not fail it either. [verify: exec `bun test src/review/review-next.test.ts -t "gate failure"`]
- AC4: Every `next` call run through the command appends exactly one JSON line to `<package>/tool-calls/wave-events.jsonl` with exactly the fields `time, event:"next", package, planAuthorized, dispatches, wave, wavesLeft, reasons{missing,retry,stalled,escalated}, notRun, blocked, done, sincePrevMs, sinceConfirmMs` (`wave` = max dispatch wave, `wavesLeft` = max wavesLeft, `sinceConfirmMs` = `null` when there is no confirmation, `sincePrevMs` = `null` on the first event); a second call adds a second line; every row validates against `schemas/wave-event.schema.json` of the requirements package. [verify: exec `bun test src/review/wave-events.test.ts -t "next event"`]
- AC5: Idle gaps. Gap A = now − mtime of the newest `raw/` file; gap B = mtime of the earliest `raw/` file that appeared after the previous event − the previous event's time. With open slices and an authorized plan, A above its threshold (default 10 min) or B above its threshold (default 15 min) makes `next` print "gap N min without a launch after the plan was authorized (A|B)" and append `{time, event:"idle", kind, gapMs, since}`; both thresholds are read from `routing.config.json`; below the threshold, with no open slices, or with a refused plan nothing is printed or written. Tested with an injected clock and set mtimes. [verify: exec `bun test src/review/wave-events.test.ts -t "idle gap"`]
- AC6: A write failure (unwritable directory) prints one warning to stderr and changes neither the exit code nor the stdout of `next`; the engine function `reviewNext` itself writes nothing without `--apply`. [verify: exec `bun test src/review/wave-events.test.ts -t "write failure"`]
- AC7: Events carry only numbers, booleans, reviewer names, package path and times: no diff text, findings or PR comments; the row size is capped in code and an oversize row is shortened by cutting the only free-length field, `package`, to its last path segment, never truncated mid-JSON. [verify: exec `bun test src/review/wave-events.test.ts -t "event size"`]
- AC8: `orchestrator.jsonl` and `memoryCalls` are untouched by `next`: the file bytes (or absence) and the `memoryCalls` result are identical before and after a call. [verify: exec `bun test src/review/wave-events.test.ts -t "orchestrator log untouched"`]
- AC9: The "read-only" contract is restated. Without `--apply` the only file `next` changes is `tool-calls/wave-events.jsonl`; `--help` says "and appends an event to tool-calls/wave-events.jsonl"; the "(read-only: nothing was written)" line no longer claims that nothing was written; `--apply` still owns re-cut slices, manifest and retry state. [verify: exec `bun test src/commands/review-next.test.ts -t "only wave-events changes"`]
- AC10: Deleting `wave-events.jsonl` breaks nothing: `next`, `review status`, `report-parity` and `complete` run the same and the file is recreated by the next call. [verify: exec `bun test src/review/wave-events.test.ts -t "file optional"`]
- AC11: The round summary shows "Gaps without a launch after the plan was authorized: N, longest M min (waits for operator cards are possible)" from the `idle` events: in `keryx review status` and `report-parity` through the parity view, and in the TUI review panel and sidebar through the same view; there is no line when the file is absent or holds no `idle` event, and the gaps never become a parity warning or block `complete`. [verify: exec `bun test src/review/parity.test.ts -t "gaps"`]
- AC12: `review-orchestrator/SKILL.md` and `SKILL.detail.md` carry the rule for Claude Code in item "One batch" and in the exception to "Open question": the plan is authorized when `keryx review estimate` does not ask for confirmation or the confirmation is recorded (E1.1); while it is authorized the orchestrator asks no "continue?" / "launch the next wave?" / "close with waivers or continue?" question and does not end the turn before `next` returns `done` or `Not run` (E1.2); the stop list is closed and names the nine cards `review_waive_coverage`, `review_waive_readiness`, `review_waive_mutation`, `review_override_reviewers`, `review_chunks_answer`, `review_publish`, `review_comments_reply`, `review_decide_premise`, `review_complete`, the round ceiling, plan growth beyond the confirmed plan (a changed `planKey` needs a new `review_confirm_plan` card), irreversible actions, credentials and untrusted content (E1.3); `INCOMPLETE/BLOCKED/NEEDS_CONTEXT/RATE_LIMITED` follow the existing rules and a role that cannot answer is `Not run` (E1.4); the status to the operator is one line per event without a question (E1.5); every stop from the list is recorded in the report with its reason (E1.6); an operator's status question is answered in one line without interrupting the work (E1.7); the host table says the shell gate `decideReviewGate` covers only the keryx shell host. [verify: judged]
- AC13: The four copies of the skill (installed and bundled, `SKILL.md` and `SKILL.detail.md`) are byte-identical pairwise, and `docs/docs/cli-reference.md`, the review pages of the docs site, `README.md` where it describes `next`, and `CHANGELOG.md` `[Unreleased]` describe `planAuthorized`, `continue`, the continuation line and `wave-events.jsonl`. [verify: exec `sh -c 'cmp src/gdskills/bundled/skills/review/review-orchestrator/SKILL.md .metaproject/skills/gdskills/review/review-orchestrator/SKILL.md && cmp src/gdskills/bundled/skills/review/review-orchestrator/SKILL.detail.md .metaproject/skills/gdskills/review/review-orchestrator/SKILL.detail.md && grep -q wave-events.jsonl docs/docs/cli-reference.md && grep -q wave-events.jsonl CHANGELOG.md && grep -q planAuthorized docs/docs/cli-reference.md'`]
- AC14: Acceptance by `Verification:` on copies of the closed packages (vantage-frontend #8174, #8111, #8158, #8086; originals are not changed): on the #8086 copy the retrospective gap A is about 58 minutes and exceeds the threshold; `next` on each copy writes only inside the copy; the cost of `packagePlanGate` inside `next` is measured and recorded in `verification.md` of the flow folder together with every requirement that could not be checked on a copy. [verify: judged]
- AC15: Representation in the TUI: no new surface is needed because the gaps line travels through the parity view that the review panel, the reviews inspector and the sidebar already render; `parity.test.ts` and the existing TUI tests that render the parity view pass with the new field. [verify: exec `bun test src/review/parity.test.ts src/tui/review-panel.test.ts`]
- AC16: The type check passes and the related test files pass. [verify: exec `sh -c 'bun run typecheck && bun test src/review/review-next.test.ts src/review/wave-events.test.ts src/review/parity.test.ts src/commands/review-next.test.ts src/commands/review-revision-operand.test.ts'`]
- AC17: The work stays local: no commit or push without the operator's word, and nothing in the files, branch or flow text carries an AI authorship line. [verify: judged]
