# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `keryx decisions export --since <date>` keeps every record whose opening time falls on or after the date, whatever form the timestamp takes (`Z`, `+00:00`, `+03:00`, `-05:00`), compared as instants. A fixture with one record per form around the boundary shows all in-window records kept and all earlier ones dropped, and a record whose time cannot be read is still dropped. Run on the real journal, `--since 2026-10-02` returns the same count as the unfiltered export minus only records opened before that date (the 47 vs 37 gap of flow 402 closes). [verify: exec `bun test src/decisions/export.test.ts`]
- AC2: `keryx research sync`, run from the repository root, creates or updates `docs/research/role-blurring-part1/part1-counts-latest.json`, `decisions-export-latest.jsonl` and `sync-status.md`, and leaves `part1-counts.json` and `decisions-export-2026-10-04.jsonl` byte-identical (SHA-256 before and after). It makes no git commit, no branch and no PR, and `git status` after the run lists only those three files. [verify: exec `bun test src/commands/research-sync.test.ts`]
- AC3: `part1-counts-latest.json` is the output of the unchanged `part1-counts.py` at the current HEAD (the script file is byte-identical to the one in the catalog), and `decisions-export-latest.jsonl` has the same record format as the snapshot export, from 2 October 2026 on, produced by the fixed `--since`. [verify: exec `bun test src/commands/research-sync.test.ts`]
- AC4: No record in `decisions-export-latest.jsonl` carries question text, option text, reason text or an own answer: the test checks the field names against the same allow-list as AC6 of flow 402 (identifiers, mode or arm, order, preselection, match, time to answer, whether a reason exists, source). [verify: exec `bun test src/commands/research-sync.test.ts`]
- AC5: `sync-status.md` holds the UTC date and time of the run, the HEAD hash, a table "снимок 04809f4f / сейчас" over every key of `part1-counts.json`, the journal summary (decisions, with a recommendation, matches by mode normal/blind until arms exist, deviations with and without a reason, `excluded-irreversible` records, progress to the P7 threshold of 150 reversible questions per arm and to AC11 of flow 392), and the number of rows in `contribution-log.md`. The file is rewritten whole on each run. [verify: judged]
- AC6: A second run with no new data changes no file except the run date and time in `sync-status.md`. [verify: exec `bun test src/commands/research-sync.test.ts`]
- AC7: No file the sync writes, and no file in the catalog after the sync, mentions the operator's team repositories: a case-insensitive search for `frontend`, `backend`, `board`, `process-metrics` finds nothing in the new and rewritten files, and the result is written to the flow journal. [verify: exec `bun test src/commands/research-sync.test.ts`]
- AC8: The keryx local scheduler runs `keryx research sync` once a day; the daily entry is created by a documented command, a run that fails leaves the previous `-latest` files untouched and writes the reason into `sync-status.md`, and there is no event hook and no hourly commit logic anywhere in the sync code. [verify: exec for the entry and the failed-run behaviour, `keryx ctx rg` for the absence of hooks]
- AC9: The README of the catalog gains one paragraph that says what the `-latest` files are, how they differ from the snapshot (04809f4f stays the only base of the article's numbers; `-latest` serve part 2 and the document), how to run `keryx research sync`, and where to see the date of the last run. The docs site and the command help list `keryx research sync`, and the TUI shows the last sync date in an existing surface (a `/research` line or the sidebar), as the standing TUI rule requires. [verify: judged]
- AC10: After a sync, and after each release, I replace the section "Текущее состояние / Live status" of the claude.ai document "Материалы к части 1 / Part 1 materials" (right after "Статус / Status"; created if missing) with the content of `sync-status.md` in both languages, and change nothing else in the document. If the document is unavailable, the sync still succeeds and the unavailability is written to the flow journal and to `sync-status.md`. [verify: judged]
