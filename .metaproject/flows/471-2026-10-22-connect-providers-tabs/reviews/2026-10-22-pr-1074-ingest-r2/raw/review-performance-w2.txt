### Findings

### [F-001] Connected-providers cache expires an in-flight probe
- **Severity**: minor
- **File**: src/tui/remote-provider-hooks.ts (`createConnectedProvidersCache`)
- **Hot path**: each Telegram `/connect` press (listProviders then listAddableProviders)
- **Problem**: TTL runs from load start, so a load slower than 15s is treated as expired while still pending; the second call starts a parallel full probe.
- **Why it matters**: only with several slow providers; doubles /models requests and the wait.
- **Fix**: stamp `at` on resolution; always return the pending promise while it is in flight.

### [F-002] [Test] has no in-flight guard (info)
- **File**: src/tui/tui-shell.ts (Add-tab `runTest`), src/tui/remote-provider-hooks.ts (`testProviderForRemote`)
- **Hot path**: per button press; user-bound
- **Problem**: repeated presses start concurrent /models probes, each refreshing the model-profile store.
- **Fix**: a pending-key set in the dialog and, if the router does not do it, in the remote hook. Settled by reading `command-router.ts` (not in this slice).

### [F-003] /connect opens only after a sequential probe of every keyed provider (info, pre-existing)
- **File**: src/tui/tui-shell.ts (`runProvidersModal`)
- **Hot path**: per `/connect` open; N = keyed providers
- **Problem**: the Add tab does not need the probe, but the dialog waits for it. Same wait as the old `/connect`.
- **Fix**: bounded-concurrency probe or open first and fill Connected later; track separately.

### [F-004] Add rows list reallocated per call (info)
- **File**: src/tui/tui-shell.ts (`addRows`/`rowsOf`)
- **Problem**: copy of tens of entries about ten times per arrow key. Not measurable.
