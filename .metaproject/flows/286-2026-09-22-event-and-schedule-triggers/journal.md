- note (implementer): T16, review round 2 (systemd over-quoting, `src/trigger/schedule.ts`) — the T15 fix applied `systemdQuote` (syntax(7)'s unified quote/unquote rules) to every interpolated systemd value uniformly, but systemd only runs that quote-removal on WORD-SPLIT/LIST-TYPED directives, not on every directive that happens to accept text. Classified by checking `man systemd.exec`/`man systemd.unit` on this machine plus confirming behavior directly with the real `systemd-analyze verify` (not by inference alone): `ExecStart=`/`ExecStartPre=` are documented "command line" values (word-split into argv exactly like a shell command line) and `Environment=` is documented as "unquoted using the rules described in the 'Quoting' section in systemd.syntax(7)" (`man systemd.exec`, ENVIRONMENT section) — these three keep `systemdQuote`. `WorkingDirectory=`, `StandardOutput=`, `StandardError=` are single-value directives with no such documented word-splitting/quoting behavior — they take the rest of the line verbatim — so quoting them is wrong: confirmed live by feeding `WorkingDirectory="/srv/my project"` to `systemd-analyze verify`, which rejected it outright with `WorkingDirectory= path is not absolute: "/srv/my project"` (the leading `"` becomes part of the path, not stripped), and `StandardOutput=`/`StandardError=` would fail to parse their `append:` prefix the same way, silently falling back to the journal instead of erroring — a worse failure mode because nothing at unit-load time flags it. Fix: those three now get ONLY `systemdEscapePercent` (`%` -> `%%`, still needed since specifier expansion runs regardless of a directive's quoting rules), never `systemdQuote`. `Description=` was already correctly unquoted-but-percent-escaped from T15 and needed no change. Added a new regression class of test rather than only fixing string assertions (the T15 tests had pinned the buggy quoted form as the expected value, which is how this slipped through): `src/trigger/schedule.test.ts` now also feeds a generated `.service` unit — project root containing a space — to the REAL `systemd-analyze verify` via `Bun.spawn`, writing it to a temp `.service` file (the tool requires that suffix) and asserting exit 0; `test.skipIf(!Bun.which("systemd-analyze"))` with the reason embedded in the test name skips cleanly (visible as "skip" in bun test's summary, not silent) on a machine without systemd, following the same probe-at-module-scope pattern as `src/gdgraph/treesitter/real-grammar-fixture.test.ts`. Verified the test actually catches the regression: manually re-quoting `WorkingDirectory=`/`StandardOutput=`/`StandardError=` and running `systemd-analyze verify` on that unit by hand reproduced the exact "not absolute" rejection before reverting.
