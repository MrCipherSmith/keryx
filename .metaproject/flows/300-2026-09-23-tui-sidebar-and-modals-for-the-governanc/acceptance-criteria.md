# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: The TUI sidebar has a Governance section, mounted in `sidebarTop` after the Jobs section by an exported `mountGovernancePanel(otui, renderer, parent, opts) → {refresh, dispose}`. It shows exactly one of four states, read from `readLatestGovernanceReport`: `no report — click to run` when the report is absent. A malformed report shows this too, with the reason given in the modal. `running…` while a run is in flight. `last report <YYYY-MM-DD HH:MM>`, taken from `generatedAt`. `failed — click to retry` after a failed run. Row text stays within `SIDEBAR_TEXT_WIDTH`. Colours come from theme roles only, so a `/theme` switch recolours them. Proven by a panel test over fixture project directories, one per state.
- AC2: Clicking the section, or running `/governance`, while there is no report starts the report in the background. It calls the same `buildGovernanceReport` + `writeGovernanceArtifacts` that bare `keryx governance report` calls, for the current project with no filters. The composer stays usable while it runs. A second click during a run starts nothing. When the run finishes, the section changes to `last report <date>` without a restart, and one toast appears. A thrown error leaves the `failed` state and never a stuck `running…`. The run never starts an agent turn: nothing goes through the JobRegistry or a task-notification. Proven by a test with a deferred report builder and a fixture project. It asserts the state sequence and that `latest.json`/`latest.md` were written with `schemaVersion` and the CLI's markdown rendering.
- AC3: Clicking the section in the `last report` state, or running `/governance` when a report exists, opens a report modal through `modal-host`. The header shows `generated_at`, the filters and `all_projects` of the stored report. The body is `latest.md`, wrapped to the panel width and windowed. ↑/↓/j/k scroll by a line and PgUp/PgDn by a page, clamped so the last line of a report longer than the body can be reached. `r` re-runs the report in the background. The open modal refreshes when the run finishes. Esc closes the modal. Proven by a keypress-driven modal test over a report of at least three body-heights.
- AC4: The TUI sidebar has a Triggers section, mounted after Governance by an exported `mountTriggersPanel`. It is hidden when `.metaproject/triggers.json` is absent. A config that cannot be read shows one error row. The header shows project trigger spend as recorded USD, plus the count of runs whose cost was not recorded, never folded into $0 (`readProjectTriggerSpend`). The number of open spend reservations is shown in the `attention` role. Each event-fired trigger gets one row: name, enabled or disabled, and either the last outcome with its age or `never fired`. A `flow-next` entry whose dispatch has `network: true` carries a `NET` marker in the `attention` role. Schedule-fired entries get no rows, only one `N scheduled` line. This is the seam that leaves them to flow 295's Schedules section. Clicking a row opens that trigger in the modal. Proven by a panel test over a fixture `triggers.json` and `runs.jsonl`.
- AC5: `/triggers`, or a click on a Triggers row, opens a list+detail modal through `modal-host`. The detail tab shows: the fire, the action and whether the hook is installed; for a dispatching `flow-next`: provider/model, permission mode, ceiling, max seconds, max attempts, the unattended roster, and network, with the full `NETWORK_ON_WARNING` text when it is on; the last N ledger records, with outcome, cost (`not recorded (<reason>)` when unrecorded), refusal code and denials; every open reservation, with the exact `keryx trigger resolve <runId> --spent <usd>` command. The wording comes from formatters extracted from `src/commands/trigger.ts` and shared with `keryx trigger status/list`, not copied. A test asserts that the CLI and the modal print the same descriptor for the same entry.
- AC6: Run-now has one path and cannot do anything the CLI would not. In the Triggers modal, `r` arms run-now on the selected trigger, `y` confirms, and any other key cancels. A disabled or rejected entry cannot be armed, and the modal says why. A confirmed run executes `keryx trigger run <name>` as a child process of the same keryx build the TUI is running (`resolveKeryxInvocation()`, not `keryx` on PATH), in the project root. It is never an in-process call and never a JobRegistry task. The modal shows `running…`, then the new ledger record and the tail of the child's output. Proven by tests on a fixture project: With the maintenance lock held, run-now records `lock-refused`. An `open-flow` over the spend ceiling records `budget-refused`. A `flow-next` dispatch that cannot run records the same `dispatch-refused` code the CLI records. In each case, the ledger record written from the TUI equals the one written by `keryx trigger run` on the same fixture, apart from `at`.
- AC7: Work that finishes updates the TUI without a restart, including work done by other processes. One shared, change-detecting watcher, working name `src/tui/trigger-ledger.ts`, is exported for flow 295 to reuse. It polls `runs.jsonl`, `triggers.json` and governance `latest.json` on an injectable interval, and also runs after every settled agent turn. It repaints the Governance section, the Triggers section and an open modal only when one of those files changed. A run the TUI started ends in exactly one toast. Runs started elsewhere repaint silently. Proven by a test that writes a record and a new `latest.json` from outside, fires the injected timer, and asserts that both sections changed and nothing repainted on an unchanged tick.
- AC8: Everything is reachable without a mouse, and the commands are registered everywhere they must be. `/governance` and `/triggers` are registered in `AGENT_SLASH_COMMANDS` as agent-mode only. They are listed in `ACP_TUI_ONLY_COMMANDS`. `classifyBusyDispatch` classifies both as read-only while a turn is busy. The registry, busy-dispatch and ACP command tests are updated. Each modal's footer lists its keys. A keypress-driven test with no mouse event goes from the composer through `/triggers` → ↓ → Enter → `r` → `y` to a recorded run, and through `/governance` → `r` to a new report.
- AC9: External agent runs are recognisable in the existing sessions UI. The TUI Session Switcher (`/sessions`, `/resume`) already lists sessions written by `keryx agents external run`. A row whose session provider starts with `acp:` shows `acp:<agent>` in its description, and that text is searchable by the filter. Proven by a `sessionPickerOptions` test over an `acp:claude` summary.; and `keryx shell -c` continues the latest session of the shell's own kind, not a session written by `keryx agents external run` (today `latestSession` has no provider filter, so `-c` right after an external run resumes the ACP session) — a test covers it.
- AC10: The new sections leave the shell's layout and themes intact. With a fixture project holding a governance report and three triggers, `shell-pty-launch.smoke.test.ts` still finds `Model`, `Context`, `Tools`, `Status` and `Ready` on an 80x24 pty. No new renderable sets `alignSelf`. A `/theme` switch recolours both sections and both modals. The new tests are headless OpenTUI tests (`otui.testing.createTestRenderer`) or fake-renderable panel tests, and they run under `bun run test:client:terminal`.
- AC11: Documentation is updated. `docs/docs/cli-reference.md` (the TUI section), `README.md` and the docs site document the Governance and Triggers sidebar sections and their states. They also document both modals and their keys, and `/governance` and `/triggers`. They state that run-now is `keryx trigger run` in a child process, bound by the same locks, budgets and refusals. They state that external agent runs appear in `/sessions`.
- AC12: CI is green on the branch, and `keryx health run` passes.
