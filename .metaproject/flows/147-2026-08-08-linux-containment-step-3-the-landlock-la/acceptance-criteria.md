# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `buildLandlockRuleset` returns `ok: true` for the profiles the product actually builds — the output of `defaultSandboxProfile` and of `sandboxProfileFromPolicy` for workspace-write and read-only, each carrying the non-empty `readDenyList` those functions populate — and the resulting ruleset handles read rights as well as write rights, grants the writable roots and the session temp directory read-write, grants the system roots read-only, grants `/dev` through the narrow device set with `/dev/shm` as a nested read-write rule, and grants `$HOME` through no rule at all. Asserted offline with an injected ABI, per profile shape, including that every entry of that profile's `readDenyList` lies beneath no granted path.
- AC2: A profile whose boundary Landlock cannot carry yields an explicit failure carrying every reason, never a partial ruleset — including the case the grant model does not cover: a `readDenyList` entry that lies beneath a granted root fails the translation rather than being left readable. Asserted for that case and for each pre-existing inexpressible code, with a mutation check that no failure path can return a ruleset.
- AC3: Layer selection happens per profile in `wrap.ts`, with the ABI and both launcher paths injected: an expressible profile produces the specification §4.2 Landlock command shape; a `network: "off"` profile produces the bubblewrap command on a host where Landlock is present; a profile that neither layer can serve returns `ok: false` carrying the translator's own detail. `wrap.ts` remains free of spawn, `bun:ffi` and filesystem access, held by the extended purity guard rather than by review.
- AC4: On this host (kernel 6.8, Landlock ABI 4), a command run through `landlock-exec` writes inside the workspace successfully, is refused with `EACCES` on a write outside every writable root and on a read of a path under `$HOME`, and the restriction is inherited by a grandchild process. Every one of these assertions has a negative control that passes uncontained and fails contained, so an assertion cannot be green because the command never ran. Skipped with a recorded reason, never silently, when the kernel ABI is below 3.
- AC5: PATH resolution refuses rather than falls back: with an executable file planted in the working directory, `landlock-exec` given that slash-free program name which is not on `PATH` exits at the apply/resolve stage without executing it, while the control — the same file named as an explicit relative path — does execute. The resolver also refuses a directory that satisfies `access(X_OK)`.
- AC6: Application failure is fail-closed and observable: an unopenable required rule path, a kernel refusal and an ABI below the ruleset's `minimumAbi` each exit 125 with the command never started, asserted by the absence of the command's side effect **and** by the exit status, against a positive control in which the same command does run when application succeeds.
- AC7: Exit status fidelity: a contained command's own exit code arrives unmodified, and a contained command killed by a signal is reported as `128+N` with `N` taken from `node:os` `constants.signals` rather than a hand-written table. Asserted for a normal non-zero exit and for at least one signal.
- AC8: Fail-closed behaviour is unchanged: no absent ABI value, unresolved layer, failed probe or missing launcher produces an unsandboxed spawn. The existing adapter fail-closed tests are unmodified and still green, and `mode: "danger-full-access"` remains the only pass-through.
- AC9: macOS is untouched: `seatbelt.ts` and its tests do not appear in this flow's diff, and the darwin branch of `wrap.ts` is unchanged.
- AC10: The layer that ran is reported from the parent's decision, not from the child's exit status: the run receipt's `sandbox.launcher` records `"landlock"` where that layer ran, and `keryx sandbox status` names the selected layer and the kernel's Landlock ABI. A contained command that exits 125 itself cannot make the receipt claim a boundary failure, and one that exits 0 cannot erase one.
- AC11: Quality gate green on this branch: `tsc --noEmit` clean; the full `src/harness/process/sandbox` suite green with no regression against the 243-pass baseline; `bun run test:guards` green including the extended purity guard; `bun scripts/check-doc-links.ts` with no broken links; `keryx health run` not regressed against score 93; and every document this flow's own changes falsify is corrected in the same flow.
