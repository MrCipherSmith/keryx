# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- Every criterion ends with [verify: exec `<command>`],
  [verify: invariant `<command>`], [verify: judged] or
  [verify: none — <reason>].
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

DRAFT — PROPOSED, NOT FROZEN. The operator reads these and the open questions in description.md before `flow freeze`. Command and file names below (`review layers`, `layers.json`, `tail-pass.json`) are proposals.

## Criteria

- AC1: `keryx review layers refresh --package <pkg> --head <sha>` rebuilds the code graph, runs `wiki refresh` and `memory index` in the review worktree, makes no model call (a provider that throws on any call is injected and never fires), and writes `layers.json` in the package: for each layer the commit it describes, the build time, counts (graph nodes/edges, wiki pages refreshed and pages with stale prose, memory entries). The tracked `.provenance.json`, `module-map.json` and `summary.md` of the checkout are byte-identical before and after (the review build is written outside tracked files). [verify: exec `bun test src/review/layers.test.ts`]
- AC2: `keryx review blast-radius` and `keryx review dispatch` refuse when the graph's recorded commit is not the review head, naming both commits and the fix command; an operator quote (`--accept-stale-graph "<quote>"`) lets the round run and records the mismatch in `layers.json`. An empty graph and a graph without provenance are refused the same way. A graph at the head passes. [verify: exec `bun test src/review/layers.test.ts src/commands/review.test.ts`]
- AC3: In a worktree created for a PR head (no `storage/`, tracked artifacts from another commit), `review layers refresh` produces a graph whose commit equals that head, and `review layers status` reports the wiki and memory index as described by the worktree's commit with their ages. A test builds such a worktree from a fixture repository with two commits and a gitignored `storage/`. [verify: exec `bun test src/review/layers-worktree.test.ts`]
- AC4: Each driver payload carries a bounded `layers` block for that reviewer's files: graph-affected files (depth 1, then 2 while under the byte cap), symbol neighbours, related tests, wiki pages that describe those files, and memory entries matched by module. The block states what was truncated and the command that fetches the rest. It is deterministic: the same inputs give byte-identical output. [verify: exec `bun test src/review/layers-payload.test.ts`]
- AC5: Every reviewer skill that reads code (`review-logic`, `review-regression`, `review-architecture`, `review-frontend`, `review-backend`, `review-performance`, `review-security-code`, `review-testing-practices` and the project overlays) carries one shared instruction block that names the exact commands (`keryx gdgraph affected <file>`, `keryx test related <file>`, `keryx wiki ask "<q>"`, `keryx memory search "<q>"`) and when to use them; the block is identical across skills and the bundled and project copies are byte-identical. [verify: exec `bun test src/gdskills/reviewer-layer-block.test.ts`]
- AC6: For each reviewer run, the package records `layersUsed` {graph, wiki, memory, ctx} counted from the run's tool-call log (not from the reviewer's own statement): the number of calls to the graph, wiki, memory and ctx commands or tools. `ledger build` carries it, and a reviewer whose log is missing is recorded as `unknown`, not zero. [verify: exec `bun test src/review/layers-usage.test.ts src/review/ledger.test.ts`]
- AC7: The files the blast-radius cap cut (`dropped`) get a tail pass: they are grouped into slices (reusing the slice machinery of flow 430), run through `review-regression` at one tier down from the session model, bounded by a configured file/byte cap, and recorded in `tail-pass.json` with files reviewed and files still not reviewed. `keryx review complete` refuses a package with dropped files when neither a tail pass covers them nor the operator's quote waives them, and prints the count. [verify: exec `bun test src/review/tail-pass.test.ts src/commands/review-ledger.test.ts`]
- AC8: TUI. The `/reviews` sidebar panel shows one line per review: `graph@<sha7> fresh|STALE`, wiki and memory ages, and `layers used n/m`; the Review depth tab of the `/reviews` modal shows the full `layers.json` lines (commit per layer, mismatch, per-reviewer counts, tail pass reviewed/not reviewed); the `/reviews` menu has a "Refresh layers" action that runs AC1 for the selected review; the slash command `/review layers` and the readline text print the same lines as the panel. All four read one projection. [verify: exec `bun test src/tui/review-panel.test.ts src/tui/reviews-inspector.test.ts`]
- AC9: `keryx help`, `README.md`, `docs/docs/cli-reference.md`, `docs/docs/guides/review-with-a-record.md` and the gdgraph/wiki guide describe `review layers refresh|status`, the stale-graph refusal and its quote override, the layers block in payloads, the per-reviewer usage record, the tail pass, and state plainly that the refresh uses no model and that `wiki enrich` is the only model step; the docs build passes. [verify: exec `bun test src/docs && mkdocs build --strict -f docs/mkdocs.yml`]
- AC10: Live: a managed review of PR 7659 on a fresh worktree of its head, started with one command, ends with `layers.json` showing the graph, wiki and memory described at the PR head commit; at least 12 of the 18 reviewers show non-zero graph or wiki use in `layersUsed`; `tail-pass.json` accounts for every one of the dropped files; and `keryx review compare-reference` against the Claude report reproduces no fewer items than the 12.10 run of flow 428 (4 of 19). The counts, duration and token usage are recorded next to the 12.10 run. [verify: judged]
- AC11: Control: the same flow on PR 7840 records a graph commit equal to its head and raises no major finding that the operator rejects; the operator signs. [verify: judged]
