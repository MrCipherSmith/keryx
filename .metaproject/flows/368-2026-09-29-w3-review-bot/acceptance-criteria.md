# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `keryx review bot run --pr <n> --repo <owner/repo>` reviews the local checkout's diff against the PR base headlessly: one reviewer model turn (through `runModelTurn`, fail-closed, credentials from the existing provider resolution) produces findings in the existing `keryx:findings` format, then one verifier turn per finding may refute it; refuted findings are dropped and the result is ingested as a managed review. The diff is capped at a configurable byte limit and the cap is stated in the output; a model turn is injected in tests, so no test calls a provider. Modules live in `src/review/bot/`. [verify: exec `bun test src/review/bot/run.test.ts`]
- AC2: `keryx review bot post` builds ONE pull-request review (`POST pulls/{n}/reviews`, event COMMENT, `commit_id` equal to the PR head SHA, inline comments with path, line and side) from a managed review; a finding whose line is not in the diff goes into the review body, never as a misplaced inline comment; the default is a dry run that prints the payload and `--post` is required to send; posting is refused when the given SHA is not the PR head or the PR is not open. The GitHub allow-list in `src/review/pr-comments.ts` gains exactly this one write endpoint, and the test that pins the allow-list is updated to pin it. [verify: exec `bun test src/review/pr-comments.test.ts src/review/bot/post.test.ts`]
- AC3: The bot refuses to run or post when the PR's head repository differs from its base repository (fork), before any model call, with a stated reason; comment bodies pass the existing security output check (secrets, PII, prompt-injection markers) before they are sent, and a finding that fails it is withheld and counted. [verify: exec `bun test src/review/bot/fork-guard.test.ts src/review/bot/redaction.test.ts`]
- AC4: `keryx review metrics [--json]` reports, from the managed review packages and the stored PR state: findings raised, acted-on, each dismissed kind, answered-disagree, still unknown, precision (acted-on over acted-on plus dismissed-incorrect), and the resolved-before-merge ratio (findings with a recorded disposition before the PR's merge time over findings raised); unknown counts as open; a ratio with no data is null and printed as `n/a`, never 0. `review metrics` is in `GROUP_SUBCOMMANDS`. [verify: exec `bun test src/review/bot/metrics.test.ts`]
- AC5: A composite `action.yml` at the repository root installs keryx, runs `review bot run` then `review bot post --post`, declares `permissions: contents: read, pull-requests: write` in its documented example workflow, uses `pull_request` (never `pull_request_target`), skips fork pull requests, and reads the model key only from a secret input; an example workflow ships under `docs/`, and a test parses both files and fails on `pull_request_target` or on a missing fork guard. [verify: exec `bun test src/review/bot/action-workflow.test.ts`]
- AC6: The TUI shows the reviews: `/reviews` is in the slash registry and help and opens a modal listing managed reviews (round, head, findings by disposition, precision, resolved-before-merge), the sidebar shows a reviews section with the open-findings count, and readline has a text equivalent; the existing `/review` (SLATE catch-up) is untouched. UI text is English. [verify: exec `bun test src/tui/reviews-inspector.test.ts src/commands/shell-slash-registry.test.ts`]
- AC7: Documentation covers the bot (setup, secrets, same-repo-only rule, dry run, metrics, cost and diff cap) on the docs site and in the README; CHANGELOG has an entry; package.json is bumped to the next patch. [verify: exec `bun run docs:links`]
- AC8: The change ships as the next patch release: CI green on the PR head, a review round against the PR head with the verifier on, and the installed build passes `keryx --version`, `keryx review tier`, `keryx mcp list`, `keryx review metrics`, a fork refusal from `keryx review bot run` against a fixture and a `keryx review bot post` against a fixture through the real CLI route (it stops at the documented no-review refusal; a live model turn needs a provider key and is not run in the smoke). [verify: judged]
- AC9: The flow stops after the release smoke; enabling the Action on a repository waits for the operator's word. [verify: none — a stop is an absence of work; the journal entry and the operator report are the evidence]
