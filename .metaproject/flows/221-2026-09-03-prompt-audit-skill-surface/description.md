# Починить маршрутизацию скиллов и убрать устаревшие паттерны, найденные prompt-audit

## Проблема

Прогон `/claude-api prompt-audit` по поверхности скиллов (67 файлов `SKILL.md`,
20 289 строк в `src/gdskills/bundled/skills/`) дал пять находок. Две из них — не
стилистика промптов, а поломанная маршрутизация.

**Корневой дефект.** `parseSkillFrontmatter` в
`src/harness/tool/metaproject-adapter.ts:206` читает поле `description:`
однострочным регекспом `/^description:\s*(.*)$/`. Пятнадцать скиллов объявляют
это поле YAML-блоком (`description: |`), где текст лежит на следующих строках с
отступом. Парсер забирает первую строку и получает сам индикатор блока —
description становится литералом `|`.

Подтверждено вызовом MCP-инструмента `mcp__keryx__skills_catalog`, то есть
поведением, а не чтением кода:

```
- review-core-boundaries (review) — |
- review-flow-graph (review) — |
- review-frontend-conventions (review) — |
- review-testing-practices (review) — |
- review-clean-code (review) — | [triggers: review clean code, ...]
```

`.metaproject/index.md` предписывает агенту выбирать скилл именно через этот
инструмент, вместо чтения `catalog.md`. У одиннадцати из пятнадцати уцелел
список `triggers:`, и по нему скилл ещё выбираем. У четырёх —
`review-core-boundaries`, `review-flow-graph`, `review-frontend-conventions`,
`review-testing-practices` — ключа `triggers:` нет тоже: в каталог они выходят
с нулевым сигналом маршрутизации и невыбираемы в принципе.

Остальные три находки — устаревшие паттенры в самих скиллах: дублирование
триггеров прозой поверх машиночитаемого ключа (11 файлов), тридцатипунктовый
пересказ собственного документа в `job-orchestrator`, и поведенческое правило,
протащенное в маршрутизирующее описание `feature-analyzer`.

## Ожидаемый результат

1. `skills_catalog` не возвращает ни одной записи с описанием `|` или пустым.
2. Каждый скилл в каталоге имеет и описание, и хотя бы один триггер.
3. Одна и та же информация о триггерах не хранится в файле дважды.
4. `job-orchestrator` не содержит блока, дублирующего собственный текст без
   причин; сохранённые правила несут свою причину.
5. Регрессия закрыта тестом, а не только правкой.

## Вне области

- Сокращение описаний `Use when:` / `NOT for:` у ревьюеров. Это контракт
  инструмента и граница против соседних ревьюеров; prompt-audit относит их к
  keep-листу («детали контракта остаются и часто прирастают»).
- Дедупликация 102 harness-копий `SKILL.md`. Расхождений по существу нет:
  88 копий идентичны, 14 отличаются только строкой `compatible_harnesses`.
  Работающая избыточность — не cruft.
- Смягчение 26 употреблений `never` в `job-orchestrator`. Почти все идут с
  причиной и описывают хрупкие операции с единственной безопасной
  последовательностью.
- Любые правки в `.metaproject/skills/gdskills/` вручную: это установленная
  копия, она приходит из `src/gdskills/bundled/skills/`.
