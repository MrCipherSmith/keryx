# Критерии приёмки

Критерии для работающей функции. Команды приёмки исполняются в GitHub CI. T12 поставляет тесты с идентификаторами критериев по правилам verification.md. Проверки с участием пользователя фиксируются по [сценариям](verification.md).

- AC1: Переключение Assigned / Created / Mentioned / Subscribed возвращает тикеты выбранного viewer из нескольких репозиториев. Одинаковые номера в разных репозиториях различимы, PR отсутствуют. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC1`]
- AC2: Board и List сохраняют поиск, репозиторий, метки, состояние, диапазон обновлений и сортировку. На выборке из 3 страниц каждая запись отображается один раз, переход не загружает остальные страницы или каждое обсуждение. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC2`]
- AC3: До первого ответа видна загрузка. Пустая выдача, потеря сети, запрет доступа и rate limit различимы. Поздний ответ предыдущего аккаунта не меняет новый экран; после отзыва доступа приватные данные скрыты. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC3` · sensitive: failure-scenario]
- AC4: В установленном Desktop из Board и List открывается одна изменяемая по ширине панель; описание Markdown находится перед комментариями, доступны репозиторий, автор, исполнители, метки и внешняя ссылка. Управление клавиатурой и возврат фокуса работают при узком и широком окне. [verify: judged]
- AC5: Открытый GitHub issue с завершённым Flow и закрытый issue с активным Flow показывают обе независимые характеристики. Блокировка или открытый вопрос ведут к своей причине или вопросу, обычное обновление сохраняет выбор карточки. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC5`]
- AC6: Список, детали и начальный контекст выполняются под выбранным аккаунтом. При 403/404 в приватном репозитории видна ошибка и повтор с правильным аккаунтом. Успешное чтение пустого описания даёт пустое описание. GitHub Markdown не может инициировать локальную команду или запись. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC6` · sensitive: failure-scenario]
- AC7: Для тикета B при открытом проекте A выбирается checkout B. При нескольких подходящих checkout виден выбор; при отсутствии — подключение проекта. Один номер тикета в A и B даёт разные привязки. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC7`]

Повторное открытие из другой точки возвращает в ту же сессию. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC8`]

Подготовка доходит до плана без ручной отправки первого сообщения; исполнение начинается отдельным действием. Новый запрос с изменившимся контекстом допускает новое уточнение. [verify: exec `python3 .metaproject/flows/511-2026-11-21-desktop-issues-board/verify.py AC10`]

При отключённом Task Manager или недоступном координаторе карточка сохраняет контекст и предлагает конкретное действие восстановления.
