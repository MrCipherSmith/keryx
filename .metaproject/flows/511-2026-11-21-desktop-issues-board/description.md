# GitHub Issues в Keryx Desktop

## Problem

Вкладка Pull requests обслуживает репозиторий проекта. Пользователю нужна рабочая очередь тикетов GitHub-аккаунта из нескольких репозиториев. Сейчас обсуждение в Shell, подготовка Flow и поиск созданного пакета требуют отдельных действий. Теряется связь между описанием тикета, ответом пользователя и работой в локальном checkout.

## Expected Outcome

Пользователь выбирает тикет в Issues, читает описание и обсуждение, открывает связанную сессию в Sessions и из той же карточки подготавливает Flow. Координатор собирает контекст в проекте тикета и задаёт вопросы в этой сессии. После перезапуска доступны та же история и тот же Flow с фактическим этапом. Если тикет входит в GitHub Project, можно открыть доску этого проекта и, при наличии прав, изменить его Status.

## Outcome criteria

- Запрос пользователя: «кнопка создания фло на основании тикета - с прохожджением этапов инициализации фло сбора контекста и тп».
- Наблюдаемый результат — из одного приватного тикета получены одна основная сессия и один пакет с описанием задачи, контекстом, планом, задачами и проверяемыми критериями. Повторный клик и восстановление после сбоя возвращают к той же работе.
- Точка передачи этого проектного Flow 511 — статус `initializing`. Решение о заморозке принимает пользователь. Следующий исполнитель приступает после заморозки и отдельного запуска.

## Границы продукта

Включены аккаунт, доска и список, фильтры, детальная панель с обсуждением, интеграция с GitHub Projects Status и двусторонняя навигация Issues ↔ Sessions ↔ Flows. Публикация комментариев от агента, создание и массовое редактирование тикетов, поддержка сторонних трекеров, автоматическое слияние PR и выпуск релизов требуют отдельной постановки. Переход в GitHub доступен во внешнем браузере. Обычный Shell и общие навыки Metaproject должны работать и без установленного Desktop.
