# Acceptance Criteria

- AC1: Opening a copy of a database created with main's schema migrates it in place: the number of attempts is unchanged, every attempt has exactly one Review keyed by repository id, PR number and viewer (case-insensitive), rounds are numbered by first appearance of a base..head pair in creation order, a continuation joins its predecessor's round, `previous_run_id` links each attempt to the one it follows, and a second open changes nothing. · sensitive: failure-scenario [verify: exec `bun test src/review/desk-run-store.test.ts`]
- AC2: One PR with three historical runs on three ranges is one Review with rounds 1–3; a new attempt (start, retry on the same range, continuation, new head) is assigned its Review and round when it is recorded. [verify: exec `bun test src/review/desk-run-store.test.ts`]
- AC3: A read-only store on an unmigrated database still returns badges and active numbers, and SQL `attachBadges` stays equal to `localBadge` for every query condition, including the round of an outdated result. [verify: exec `bun test src/review/desk-run-store.test.ts src/review/board-badges.test.ts`]
- AC4: `keryx review reviews --json` returns one summary per Review with state, freshness, rounds and latest findings; state and freshness follow the specification table, and a missing store returns an empty list without creating one. [verify: exec `bun test src/review/review-entity.test.ts src/commands/review-reviews.test.ts`]
- AC5: The Desktop bridge builds `review reviews --json [--repo]` only for a reviews-only request and refuses any combination with other board modes. (Rust unit tests run in CI only; no local toolchain) [verify: judged]
- AC6: The project tabs read Sessions, Flows, Reviews, Pull requests, Issues, Metaproject with shortcuts in that order, and the Reviews tab shows Reviews in the columns Running · Waiting on you · Behind · Published (· Closed when shown) with list view, search and filters. [verify: exec `sh -c 'cd apps/desktop && bun test src/reviews src/shell'`]
- AC7: The Review panel shows the rounds timeline and the review interface (history, report, answer, publication, lifecycle); the Pull requests panel no longer contains it and offers "Open in Reviews" for a PR that has a Review. [verify: exec `sh -c 'cd apps/desktop && bun test src/reviews src/review'`]
- AC8: The Reviews tab indicator lights for `needs_answer`, `ready` without a publication decision and `stopped`, and stays off otherwise; the Pull requests indicator no longer lights from a local review that waits on the user. · sensitive: mutation [verify: exec `sh -c 'cd apps/desktop && bun test src/reviews src/review'`]
- AC9: The attention-set logic in `ReviewBoard.tsx` is unchanged, and every line changed in `needsViewerAttention` is pinned by a test (each one-line mutation fails at least one test). · sensitive: mutation [verify: judged]
- AC10: The outdated-review action reads "New review round" and names the round it follows; F-024's text comparison is gone and the outdated note appears once. [verify: exec `sh -c 'cd apps/desktop && bun test src/review'`]
- AC11: The migration run on a copy of the local working database keeps every attempt and assigns each to one Review. (operator database; counts recorded in the journal, no data committed) [verify: judged]
- AC12: Desktop and root test suites, typecheck and lint pass; CI is green or every failure is explained. [verify: invariant `sh -c 'bun run typecheck && cd apps/desktop && bun test src && bunx tsc --noEmit'`]
