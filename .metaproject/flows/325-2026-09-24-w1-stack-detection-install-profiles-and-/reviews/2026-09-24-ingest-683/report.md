## New-defect sweep and high-risk surfaces

- **Path containment** covers every fs op in `src/gdskills/manifest/`. apply: the prior-state guard loop, then a per-destination guard before `pathExists`, `sha256OfFile`, `mkdir` and `copyFile`. doctor: a guard over all records before any `pathExists` or `sha256OfFile`; the orphan scan uses `readdir` withFileTypes, which does not follow symlinked dirs. uninstall: a guard over all records before any `rm`. The install-state file path is `TARGET_ID_PATTERN`-gated. I found no escape. A remaining robustness gap: a recorded path, or a planned destination, that is a directory crashes `sha256OfFile` with EISDIR. The `rel === root` case (e.g. `.claude/skills`) is explicitly accepted, so this is reachable. Nothing is deleted (R3-3).
- **Fail-open in src/stack**: the new "raw newline inside a basic string" rule returns a broken reason, which makes the python signal uncertain rather than dropped. No new fail-closed path was found. One edge is noted, not raised: a valid `"""…""""` string (a quote right before the closing delimiter) closes early, but this also only fails open.
- **Eval verdict soundness**:
  - Can something reach `pass` without real evidence? Yes, through the behavior half. An unknown grader string, or an empty `expected_behavior`, is graded as passing (R3-1).
  - The gate still does not recompute the verdict (R3-2).
  - Can a legitimate authored eval be wrongly failed? Only through documented design choices (cross-category outranking, the Cyrillic tokenizer gap noted in the journal), so I do not re-raise them.
  - A malformed evals.json surfaces as a raw TypeError or SyntaxError, and the CLI still exits 1 (R3-6).
- **stocktake --scope all**: three near-duplicate skills give exit 0. A project `SKILL.md` that cannot be read (EACCES) crashes the whole run with a raw error and no report (R3-4; it lives in catalog-index.ts and also affects eval/scout `--scope all`).
- **Determinism**: on a mixed fixture (react+nest+mobx package.json, pyproject, Dockerfile, go.mod, .c/.go files), 3× `stack detect --json` and 3× `skills install --dry-run --json --profile react --target claude` gave identical sha1s. `stack detect` persists `.metaproject/data/stack/stack.json`, which AC4 requires; the dry-run writes nothing.
