# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `src/harness/decision/classifier.ts` (new) defines a `TaskClassifier` interface (`classify(task, categories) -> Promise<{ok:true, category, confidence, source} | {ok:false, reason}>`) and a `NullClassifier` that always resolves `{ok:false, reason:"no classifier configured"}` — the default when nothing is configured or enabled, verified by a test.
- AC2: `src/harness/decision/deterministic-shortcuts.ts` (new) exports a pure `classifyDeterministic(line)` that bypasses any classifier call: a line starting with `/` is left unclassified entirely (slash commands already bypass routing upstream); a short chit-chat line (length/word-count under a documented bound, matching greeting/thanks/short-affirmation shapes) resolves `"quick"`; a line naming a review (`review`, `PR`, `pull request`, `code review`) resolves `"review"` — proven by a fixture table of inputs and expected outcomes, including negative cases that must NOT match.
- AC3: `MainModelTaskClassifier` (`src/harness/decision/main-model-classifier.ts`) sends one short, non-streaming, tool-free request to an injected provider/model with a strict one-token label prompt over the candidate category names, and parses the reply into `{category, confidence}` — an unparseable or out-of-vocabulary reply is `{ok:false, reason:"unparseable classifier response"}`, never a guessed category, proven by tests with an injected provider stub (exact match, whitespace/casing noise, out-of-vocabulary, empty reply).
- AC4: `JevTaskClassifier` (`src/harness/decision/jev-classifier.ts`) is built on the existing `callJevSystemOne` client (`src/harness/decision/jev-client.ts`, flow 306) rather than a new abstraction: one `choice` question whose `criteria` are the wired category names plus a `confidence` `noul` question; selected only when a Jev credential resolves (`resolveJevApiKeyResolution`) AND the operator has opted in (`classifier: "jev"` in the routing/classifier setting, AC7); a confidence below a documented default threshold (0.6) is `{ok:false, reason:"low confidence"}`, not a returned category — proven by tests with an injected `fetch` stub (success, low confidence, missing credential, malformed response) and zero real network calls.
- AC5: `classifyTurn` (`src/harness/decision/classify-turn.ts`) implements the documented fallback chain in order — deterministic shortcut (AC2) first, else Jev (AC4) when opted-in and credentialed, else the main-model classifier (AC3), else no classification (`NullClassifier`, AC1) — each classifier stage bounded by a shared timeout (default 3000ms, documented and configurable) that never throws or blocks the caller: a timeout, network error, or parse error at any stage degrades to the next stage or to "no classification" and is recorded as the fallback reason, proven by a test per stage transition including a hanging-classifier timeout case.
- AC6: The category `classifyTurn` returns resolves a provider/model through the existing routing table (`resolveCategoryDetailed`, `src/harness/routing/table.ts`) exactly as the `review`/`subagents` call sites already do; an explicit `/model`/pinned-model turn, or a turn whose category was already named by the caller, skips classification entirely and is never overridden — proven by a test asserting zero classifier invocations on that path and by a test asserting the resolved category's table entry decides the turn's provider/model when no explicit pin is set.
- AC7: `keryx shell`'s interactive turn dispatch (`src/tui/tui-shell.ts`) gains an opt-in `/route on|off` command (default off, mirroring `/guard`'s exact shape: a per-user `ShellConfig.routingClassifier.enabled` setting, a live togglable local binding, and a `--route`-equivalent session-only override) — classification (AC5) only runs for a turn when routing is enabled, proven by a source-shape test mirroring `turn-guard-shell-wiring.test.ts` plus a `keryx shell` integration test that a disabled session never calls the classifier.
- AC8: Per-turn visibility: when a turn actually used a routed (non-`default`) category, a small tag appears under that turn's output (e.g. `[quick -> claude-haiku-4.5]`, naming category, resolved provider/model, and classifier source) and the sidebar (`sb-route` row, mounted after the existing `Model`/`Guard` rows) shows whether routing is on and the count/last decision this session — proven by a render test asserting the tag text and the sidebar row's content for an on/off state.
- AC9: Cost and usage are recorded for every classifier call that reaches a real client — Jev's own `usage` (input/output tokens, cost) and the main-model classifier's provider usage — surfaced in the per-turn tag's detail (or a `/route` detail view reachable from the tag/sidebar) the same way `/guard`'s advisory view shows Jev usage, proven by a test asserting usage fields are threaded from the classifier result into the rendered detail.
- AC10: Every test added by this flow is hermetic (injected `fetch`/provider stubs only, zero real network calls anywhere in the test suite), passes on macOS (no Linux-only path/shell assumptions), and is revert-checked (fails red against the pre-flow tree).
- AC11: A live check script (`scripts/routing-classifier-live-check.ts`), run with `env -u OPENROUTER_API_KEY` so the saved credential resolves instead, classifies 20 realistic, hand-labeled sample keryx-shell requests spanning every wired category, makes at most ~40 total Jev/systemone HTTP calls, never prints the API key, and reports accuracy (correct/n), per-call latency, and total cost to a journaled output file.
- AC12: Documentation (`docs/docs/cli-reference.md` and/or the shell docs, `README.md` where the shell's slash commands are listed) covers `/route on|off`, the fallback chain (Jev -> main-model -> none), the default-off opt-in, and the bounded-latency/fail-closed contract; CI is green and `keryx health run` passes.
