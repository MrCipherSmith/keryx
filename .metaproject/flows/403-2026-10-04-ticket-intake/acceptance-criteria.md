# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: Опрос по ответам фейкового `gh` выделяет события пяти видов (назначенный тикет, запрос ревью, упавший CI на PR оператора, комментарий в его PR, движение на доске), каждое с ключом из п. 2. [verify: exec `bun test src/intake/intake-events.test.ts`]
- AC2: Первый опрос — базовая линия: найденное помечается увиденным, карточек нет. Следующий опрос с одним новым событием даёт ровно одну карточку. [verify: exec `bun test src/intake/intake-baseline.test.ts`]
- AC3: Повторный опрос без изменений, перезапуск serve между опросами и изменение `updatedAt` показанного тикета новых карточек не создают. [verify: exec `bun test src/intake/intake-dedupe.test.ts`]
- AC4: Карточка содержит вид, репозиторий, заголовок, ссылку, оценку до 400 символов и предложение из набора, допустимого для вида; HTML экранирован, секреты отредактированы, тело тикета обрезано. Модель вызывается без инструментов. Недоступная или некорректная оценка даёт карточку без предложения, а не потерю карточки. [verify: exec `bun test src/intake/intake-card.test.ts`]
- AC5: Набор кнопок соответствует виду карточки (п. 4); `callback_data` не длиннее 64 байт, не содержит URL и заголовков; выполняемое действие определяется реестром, а не данными нажатия. [verify: exec `bun test src/intake/intake-buttons.test.ts`]
- AC6: «Взять в работу» запускает `flow init --issue` со ссылкой из реестра в корне сопоставленного проекта; flow в статусе `initializing`, AC не заморожены, нет вызовов, меняющих GitHub; журнал flow и реестр содержат `decided-by`, время, id карточки и предложение, происхождение записано как `agent-proposal` с источником. [verify: exec `bun test src/intake/intake-take.test.ts`]
- AC7: «Взять в работу» без сопоставленного локального проекта или при ошибке `flow init` не оставляет частичного flow: карточка правится с причиной, реестр пишет `failed`, повторное нажатие допустимо. [verify: exec `bun test src/intake/intake-take-failure.test.ts`]
- AC8: «Отклонить», «Пропустить», «Игнорировать» и «Понятно» пишут решение и ничего не создают (ни flow, ни вызовов `gh`). «Позже» пишет решение и один раз возвращает карточку через заданный срок вне тихих часов (поддельные часы). [verify: exec `bun test src/intake/intake-decline-later.test.ts`]
- AC9: «Открыть ревью-flow» создаёт flow `Review <repo>#<n>` со ссылкой на PR в описании, без записи в GitHub. [verify: exec `bun test src/intake/intake-review-flow.test.ts`]
- AC10: «Разобрать» запускает советующий ci-triage под лимитом бюджета и присылает обрезанный результат с редакцией секретов в топик; flow и записи в GitHub не создаются. [verify: exec `bun test src/intake/intake-ci-triage.test.ts`]
- AC11: Повторное нажатие, нажатие после истечения срока и два одновременных нажатия: действие выполняется не больше одного раза, лишние нажатия получают короткий ответ («уже решено», «истекло»), карточка правится на месте. [verify: exec `bun test src/intake/intake-press-guards.test.ts`]
- AC12: Нажатие от id вне allowlist и нажатие с несовпадающим чатом или сообщением игнорируются и журналируются с id и временем, без текста. [verify: exec `bun test src/intake/intake-allowlist.test.ts`]
- AC13: Остановка serve между приёмом нажатия и завершением действия, затем перезапуск: ровно один flow, нажатие обработано один раз; карточки, поставленные в очередь при остановленном serve, уходят после перезапуска. [verify: exec `bun test src/intake/intake-restart.test.ts`]
- AC14: Без человека нет вызовов, которые меняют GitHub или состояние flow: каталог granted-tools опроса содержит только чтения (добавленные два чтения тоже), фейковые `gh` и состояние flow фиксируют ноль мутаций за целый прогон опроса и оценки; добавление мутирующей или вне списка записи роняет тест. [verify: invariant `bun test src/intake/intake-readonly.test.ts`]
- AC15: Тихие часы и лимит карточек в час соблюдаются; сверх лимита создаётся одна карточка «ещё N событий», ни одно событие не теряется. [verify: exec `bun test src/intake/intake-quiet-limits.test.ts`]
- AC16: Лимиты запуска: бюджет, таймаут, память; превышение останавливает запуск и пишется в отчёт со строкой статуса. Аккаунт GitHub выбирается по пути проекта, `gh auth switch/login` нигде не вызывается; для репозиториев под `~/work/**` опрос только читает, кнопка «Взять в работу» выключена, пока не включена конфигом. [verify: exec `bun test src/intake/intake-limits-accounts.test.ts`]
- AC17: Сбой `gh`, модели или доставки пишется в отчёт запуска и строкой статуса в топике; остальные источники продолжают работать; недоставленная карточка повторяется с нарастающей задержкой. [verify: exec `bun test src/intake/intake-failures.test.ts`]
- AC18: Нажатия из служебного топика «Intake» доходят до обработчика intake; нажатия кнопок согласования в топиках сессий работают как прежде. [verify: exec `bun test src/remote/intake-callback-route.test.ts`]
- AC19: TUI: строка боковой панели `Intake: <N ждут> | следующий опрос <время> | пауза | выкл`; модалка `/intake` со вкладками «Ждут», «Решённые», «Отложенные», «События» и клавишами `t` взять, `d` отклонить, `l` позже, `p` пауза/пуск, `esc` закрыть; пункт меню; команда `/intake [status|list|pause|resume|poll]`; текстовый эквивалент в readline-шелле; CLI `keryx intake` с теми же действиями. Решение из TUI проходит тот же код, что и кнопка, и пишется как `decidedBy: tui`; решённая в одной поверхности карточка в другой не действует повторно. Новая карточка появляется в панели без перезапуска. Все поверхности строятся из одного объекта статуса. [verify: exec `bun test src/tui/intake-surface.test.ts`]
- AC20: `keryx intake report --json` показывает по видам: число карточек, решения по действиям, медиану времени ответа, долю совпадений с предложением, связку «карточка → flow → PR»; экспорт не содержит заголовков, тел и текстов оценки. [verify: exec `bun test src/intake/intake-report.test.ts`]
- AC21: Ни один тест не обращается к GitHub, Telegram или модели: только фейковые `gh`, часы, Bot API и модель. [verify: invariant `bun test src/intake/no-live-network.test.ts`]
- AC22: Документация описывает intake, настройку (репозитории, расписание, топик, тихие часы, лимиты, срок кнопок), гарантию «только чтение без человека» и варианты второго этапа; README, cli-reference, wiki, commands-by-task, сайт и CHANGELOG обновлены; версия на main выше текущей. [verify: exec `bun test src/docs/intake-docs.test.ts`]
- AC23: Живая приёмка: неделя на реальном репозитории (сначала личный `MrCipherSmith/keryx`; рабочий только с отдельного OK оператора), минимум один тикет взят кнопкой и прошёл цикл до PR. [verify: judged]
- AC24: Каждая карточка из живой недели понятна без открытия GitHub, а предложение действия разумно, на взгляд оператора. [verify: judged]
- AC25: После релиза пакет, установленный только из npm, стартует `keryx serve` с фейковым Bot API и присылает тестовую карточку; живой Telegram только с OK оператора. Выполняется при ближайшем релизе, который оператор разрешит (правило 8). [verify: none — ручной смоук из опубликованного пакета, запись в журнале]
