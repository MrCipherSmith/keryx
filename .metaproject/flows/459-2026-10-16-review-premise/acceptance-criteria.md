# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- Every criterion ends with [verify: exec `<command>`],
  [verify: invariant `<command>`], [verify: judged] or
  [verify: none — <reason>].
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `keryx review ingest --premises <file|->` reads a premise claims file (context.md "Contract") and merges it delete-only after dedupe: `upheld` changes nothing; `downgraded` lowers severity (a raise is rejected); `challenged`/`owner-decision` mark the finding held; claims with an unknown finding id, a judge equal to the finding's reporter, `challenged` without an intent signal or practice source, or a held verdict without a question (owner-decision without ≥2 options) are rejected and listed in scope.md; the claims are stored in `research-evidence/premises.json` and on each finding record. Tests per rule. · sensitive: failure-scenario [verify: exec `bun test src/review/premise.test.ts`]
- AC2: A held finding is not counted as an open blocker/major by the verdict, is listed as "awaiting operator: <ids>", and readiness and the flow review gate fail while any held finding has no operator decision; a downgraded severity is the one verdict and dedupe use. Tests. [verify: exec `bun test src/review/verdict.test.ts src/review/readiness.test.ts src/flow/review-gate.test.ts src/review/dedupe.test.ts`]
- AC3: Operator decision kind `premise-question`: `keryx review decide-premise --package <dir> --finding <id> --answer uphold|dismiss --reason "<why>"` needs a terminal (refused in the no-prompt routine list) and has a keryx shell card `review_decide_premise`; `uphold` returns the finding to kept at its original severity, `dismiss` records `dismissed-incorrect` with the operator's reason; after it, readiness and the gate pass for that finding. Tests. [verify: exec `bun test src/review/premise-decision.test.ts src/commands/review-operator-cli.test.ts src/commands/operator-confirm-review-tools.test.ts`]
- AC4: `review-premise` is a bundled reviewer (catalog, install manifest, both skill copies byte-identical, length ceiling set, `model_tier: deep`, not in the fan-out roster, never path-gated, iron-laws and class-scope exemptions with reasons, `keryx review tier` gives it deep); its SKILL.md requires claim-first reading (the finding's claim before the reviewer's argument), the four questions (intent, accepted practice, consistency, fix soundness), cited signals or sources for `challenged`, and delete-only output. [verify: invariant `bun test src/gdskills/ src/review/coverage.test.ts src/commands/skills.bundled-verify.test.ts`]
- AC5: Every reviewer carries a fourth shared law, from the canonical block: an explicit override, suppression, exemption, a comment or commit giving a reason, or a sibling doing the same is a deliberate choice, not a defect until its reason is read and shown wrong; a project rule is checked against accepted platform practice and its known exceptions before a deviation from it is reported. review-layout's RTL section names what does not mirror (media/playback controls and progress, timelines, numbers and code, charts' time axes unless the product decides otherwise). [verify: invariant `bun test src/gdskills/review-skills-iron-laws.test.ts src/gdskills/`]
- AC6: review-orchestrator runs `review-premise` as Wave D after the verifier over the canonical findings (severity ≥ minor; in a delta round only those without a carried premise), passes its result with `--premises`, and stays within its length ceiling. flow-orchestrator, job-orchestrator, review-pr-feedback and feature-dev never pass a held finding in `fix_context.review_feedback`; they ask the operator (card in keryx shell, question tool elsewhere) and record the answer with `review decide-premise`; a flow whose source is a follow-up issue or an external review finding runs `review-premise` on it before freeze. Both copies identical. [verify: invariant `bun test src/gdskills/`]
- AC7: Evaluation (live, Opus): on a synthetic fixture reproducing the #7849 case (explicit `dir="ltr"` on a playback timeline, an exemption note, a sibling media control doing the same) `review-premise` returns `challenged` or `owner-decision` for the "timeline pinned LTR" finding, citing an intent signal and a platform practice source; on the round-2 ground-truth findings of #992 and #1005 (and the fixture's real control findings) it challenges none. Results and dispatch/token counts in `eval/`. [verify: judged]
- AC8: The repository stays green (CI) and a patch release containing this flow is published to npm. [verify: exec `npm view @mrciphersmith/keryx version`]
