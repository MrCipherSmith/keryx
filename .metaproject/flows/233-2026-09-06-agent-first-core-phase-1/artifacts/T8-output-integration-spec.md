# Output boundary integration

Approved AFC02/AFC15 use the pure deterministic core validator before JSON serialization or text emission. Root integrates the T19 helper through security/guard (the sanctioned MCP dependency) and the public security service; worker owns pure detectors/validator.

MCP dispatch adds sibling redaction metadata to tool/resource results. It never inserts metadata into operation JSON. Tool results, tool exceptions, unknown caller tool names, resource content and resource exceptions all cross the validator. Format-unsafe becomes a safe error with no raw value, fingerprint, or unsafe JSON scalar replacement. Error templates avoid echoing caller-controlled labels unvalidated. SDK transports preserve metadata in _meta and safe resource errors.

Legacy redactToolOutput configuration remains parseable, but does not authorize secret disclosure: mandatory deterministic secret floor applies even if advisory module/policy is disabled. Optional security diagnostics remain separately configured. Safe outputs remain byte-compatible where possible. Declared operation schema must validate safe representation, unsupported schemas fail closed; absent explicit schema guarantees only JSON shape/type preservation, never an unverified arbitrary domain constraint.

New RED MCP tests provide core acceptance. Add adapter tests for config-disabled/error paths and actual SDK metadata propagation before final integration verification. No model/provider/network dependency is added.
