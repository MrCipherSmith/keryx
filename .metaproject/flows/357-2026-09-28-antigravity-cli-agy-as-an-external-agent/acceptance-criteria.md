# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: (registry) `src/harness/external/registry.ts` gains `antigravity-cli` (label "Antigravity", binary `agy`, detect `--version`, version pattern matching `1.2.12`-style output, knownGoodRange min `1.2.12`, sandboxModes `read-only` and `worktree-write`, streamingInput true, resumable true, reportsCost false, budgetFlag false); `keryx agents external list` shows it `binary-missing` when `agy` is absent and `available` with the parsed version when present (tests with an injected detection outcome); `probe` never reads a credential.
- AC2: (codec) `src/harness/external/codec/antigravity-cli.ts`, added to `EXTERNAL_CODECS`, builds argv `agy -p <prompt> --output-format stream-json --print-timeout <n>s [--model <slug>] [--sandbox] [--conversation <id>]`, never `--dangerously-skip-permissions`; read-only adds `--sandbox`; resume adds `--conversation <id>`. Tests pin each.
- AC3: (events) the codec parses the recorded live transcript `fixtures/external/live/antigravity-cli/2026-09-28/read-only-ok.stream.jsonl` — events `{event:"init", conversation_id, init:{cwd,tools,permission_mode}}`, `{event:"step_update", step_update:{conversation_id, step_index, state, step_type, text_delta?, duration_seconds?, usage?}}`, `{event:"result", result:{conversation_id, status, response, duration_seconds, num_turns, usage:{input_tokens, output_tokens, thinking_tokens, cache_read_tokens, total_tokens}}}` — into the external runtime's event contract: assistant text from `agent_response` deltas, the final response, usage and the conversation id recorded; an unknown event or step_type increments the parse-skip counter and does not fail the run. Test replays the fixture and asserts outcome `completed`, response `OK`, usage totals and conversation id.
- AC4: (outcomes) result `status` SUCCESS → completed; SUCCESS with a soft-denial notice on stderr → completed with the denials listed (never plain success); WAITING → blocked-on-approval; ERROR with an authentication message or a non-TTY auth exit → not-logged-in with the fix "run `agy` once interactively"; ERROR otherwise → failed with `error`; CANCELED/INTERRUPTED → cancelled; INVALID → invalid-request; no result before the timeout → timed-out. One test per row (synthetic lines where no live one exists).
- AC5: (environment) `EXTERNAL_RUNTIME_CREDENTIAL_ALLOW["antigravity-cli"]` is an empty list; a test with a synthetic parent env holding Google, OpenAI, Anthropic and GitHub keys shows none reach the child while `HOME` and `PATH` do; no code path opens anything under `~/.gemini/antigravity-cli/` (test asserts the codec and runtime never reference that path, and a fake spawn port run records no such file access).
- AC6: (privacy and consent) `antigravity-cli` is added to the built-in `/external` block-list defaults in `src/lib/external-providers.ts` with the reason that Google collects prompts and agent actions by default; with `/external off` a dispatch is refused before spawning via the existing `ExternalBlockedError`. A one-time consent (TTY only) states the terms-of-service residual risk and the data collection and is recorded as `externalAgents.consent["antigravity-cli"]` in the keryx user config; without it, a non-TTY dispatch is refused with `consent-required`. Tests for all three.
- AC7: (sandbox scope) a `worktree-write` dispatch to `antigravity-cli` is refused with `not-implemented` (line-stream write mode does not exist yet), `read-only` runs in the disposable worktree and leaves the operator tree untouched; tests with the fake spawn port. TUI: the agent appears in the external-agent picker and live surfaces like the other agents (existing surfaces enumerate the registry — a test or a rendered-row assertion shows it).
- AC8: (live proof and docs) a live read-only run through keryx itself (`keryx agents external run antigravity-cli --task "<small read-only task>"`, with `externalAgents.enabled` on for the run and restored after) succeeds on this machine and its transcript is committed under `fixtures/external/live/antigravity-cli/2026-09-28/`; the operator guide (`docs/docs/guides/` external-agents page or the ACP/external guide) and `docs/docs/harness.md` describe install, one-time login, consent, data collection and the read-only limit; `docs/requirements/keryx-antigravity-agent/` status updated to implemented (read-only); typecheck, lint, touched tests and the external-runtime suites pass; CHANGELOG entry and package.json bump.
