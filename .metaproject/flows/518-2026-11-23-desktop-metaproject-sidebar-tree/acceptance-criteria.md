# Acceptance Criteria

- AC1: A v2 `tree` request with `scope: "graph"` returns, for the root and for any folder, the folders containing indexed files (sorted, with file counts, a module folder carrying its module node) followed by that folder's file nodes (sorted), never symbols; pages of at most 100 entries chain by `nextCursor` to the full child list with no duplicate or missing entry; `scope: "wiki"` returns page-type groups at the root and a group's pages under it. [verify: exec `bun test src/integrations/metaproject-explorer-tree.test.ts`]
- AC2: Malformed `tree` requests (unknown keys, bad scope, absolute or `..` parent, bad cursor) answer `invalid-input`; an unknown parent answers `not-found`; a cursor or `expectedSnapshotId` from another snapshot answers `stale-snapshot`; `capabilities` lists `tree`; v1 requests parse and answer exactly as before. [verify: exec `bun test src/integrations/metaproject-explorer-tree.test.ts src/integrations/metaproject-explorer.test.ts` · sensitive: failure-scenario]
- AC3: The Desktop Rust command accepts a well-formed `tree` request, refuses a malformed one, and still requires of a CLI only the six existing actions. [verify: exec `cd apps/desktop/src-tauri && cargo test --locked metaproject`]
- AC4: Desktop learns from the capability probe whether the CLI offers `tree`; against a CLI that does not, the explorer negotiates successfully and the sidebar shows today's flat list with no error. [verify: exec `cd apps/desktop && bun test src/platform/metaproject.test.ts src/metaproject/MetaprojectView.dom.test.tsx` · sensitive: failure-scenario]
- AC5: The tree component renders folders, groups and node rows with WAI-ARIA tree semantics and roving focus; Up/Down/Left/Right/Home/End/Enter/Space behave as the plan states; expanding reads a folder once and shows a loading row; a failed folder read shows an inline error whose Retry re-reads only that folder; "Show more" appends the next page in order; selecting a node row calls the selection callback with that node; a graph that is not built shows an empty-state line. [verify: exec `cd apps/desktop && bun test src/metaproject/MetaprojectTree.dom.test.tsx` · sensitive: failure-scenario]
- AC6: In the explorer, the tree shows without a query and flat results with one; expanded folders and the selection survive leaving and returning to the view and switching between Graph and Wiki; a selection made elsewhere expands its ancestors and scrolls its row into view without moving focus; a new snapshot keeps the expanded set, drops stale children and answers, and never sends an old-snapshot cursor. [verify: exec `cd apps/desktop && bun test src/metaproject/MetaprojectView.dom.test.tsx`]
- AC7: The Desktop package type-checks and its whole test suite passes. [verify: exec `cd apps/desktop && bunx tsc --noEmit && bun test src`]
- AC8: The core package lints and type-checks. [verify: exec `bun run lint && bun run typecheck`]
- AC9: The Desktop Metaproject guide describes the tree (Graph folders, Wiki groups, keyboard, behaviour with an older CLI) and the docs checks pass. [verify: exec `bun run docs:check`]
