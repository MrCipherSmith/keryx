# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: evals.json accepts a `grader: "judge"` expectation (rubric, pass_criteria, optional fail_criteria), with a required scenario-level `calibration` {known_right, known_wrong} and optional `anti_patterns`. A malformed judge spec is refused with an EvalSpecError that names the file. Existing contains/regex/not-contains/model specs load and grade unchanged, and tests prove both.
- AC2: The judge prompt wraps the task prompt and the answer as untrusted data, inside content-derived boundary tags, and tells the judge to ignore any instruction in them. It requires a JSON verdict {verdict, reason}. `parseJudgeVerdict` rejects any other shape. An empty answer fails without a judge call, and an unparseable verdict fails the trial. Unit tests cover injection, wrapper-closing, non-JSON and missing-field cases.
- AC3: `keryx skills eval --judge <provider>[:<model>]` builds a judge separate from `--runner` that fails closed like the runner and never prints the key. A report records `judge`, `judgeModel`, `judgePromptVersion` and `catalogDigest`. For each trial it records the raw output, its sha256, the deterministic results and the judge verdict. A judge scenario run without `--judge` is `skipped`, never passed.
- AC4: `regradeRecordedReport` re-derives every ran behavior scenario's pass count from its trial records: it checks each output hash, recomputes the deterministic expectations and reads the judge verdicts. The stable-pack gate fails a report whose recorded counts disagree with its records.
- AC5: The gate is hardened per R2-6. runner/model and judge/judgeModel must be in `STACK_PACK_GATE_POLICY` (deepseek/deepseek-chat), not merely non-empty. `catalogDigest` ties trigger results to the bundled catalog: on drift, the gate re-scores the triggers against the current bundled catalog and fails if any result changed. Tests show that a forged runner "x"/model "y", a forged judge, and forged pass counts without matching records each fail.
- AC6: The integrity guard keeps I1-I5, extended to judge scenarios, and adds four rules. I6: every declared anti_pattern is named in the skill's SKILL.md. I7: every declared anti_pattern appears in known_wrong. I8: judge scenarios carry no not-contains expectation. I9: every stack-pack scenario is a judge scenario. Synthetic fixtures prove that each new rule fires.
- AC7: For every judge scenario in every stack pack, the anti-gaming harness asserts these judge verdicts: FAIL on empty, echo, known-wrong, known-wrong plus a judge-injection paragraph, and known-wrong plus rubric stuffing; PASS on known-right. Unit tests replay recorded real DeepSeek verdicts, and a missing or stale recording fails the test. An opt-in live check (`keryx skills judge-check`, and the `KERYX_LIVE_JUDGE=1` test) re-runs the harness against the judge.
- AC8: All 18 batch-1 skills (ts-js-node, react, python, go) are migrated to rubric scenarios. Each has authored calibration answers, and each known-wrong answer commits an anti-pattern the skill forbids. No SKILL.md in those packs is changed by this flow, which `git diff` shows.
- AC9: The three suppression scenarios where DeepSeek scored 0 are analysed: nodejs-build-fix no-ts-ignore-suppression, react-build-fix no-disable-hooks-lint and python-build-fix mypy-error-no-blanket-suppress. The journal and W1 record whether the old grader was mis-specified. The evidence is real recorded DeepSeek outputs re-graded under the old expectations.
- AC10: Honest gate re-run: each of the 18 skills is evaluated once with `bun ./src/cli.ts skills eval <id> --scope bundled --runner deepseek:deepseek-chat --judge deepseek:deepseek-chat --strictness high --trials 5 --json`, with no skill or grader edits during the run. Each pack's governance/eval.json is built only from those raw outputs. Packs that clear checkStablePackGate become stable, with their pair generated by `bun ./src/cli.ts agents generate --stack <id>`. The others stay experimental, with the reason recorded in agent-refs.json and W1.
- AC11: The docs reflect the new grader and the re-run outcome: the W1/W2 specs, the CLI reference (`skills eval --judge`, `skills judge-check`) and a rubric-authoring guide covering rubric scenarios, calibration answers and the anti-gaming requirements. The stack-coverage count changes only if a pack cleared the gate.
- AC12: Targeted tests for the touched modules, typecheck and eslint on the changed files pass, and PR CI is green.
