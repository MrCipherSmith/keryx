## Что нельзя смешивать по одному файлу

1. `archiveDocument`: у нас boolean означает optional, в удалённой версии — pinned. Значение true имеет противоположный смысл; store/storage и все вызывающие места должны переноситься согласованно.
2. Git recovery: `/delivery-jobs/:id/reconcile` с expectedVersion/decision/reason и `/deliveries/:id/resolve` с retry/abandon — разные API. Нельзя считать retry эквивалентом read-only inspect.
3. Revision summary: наш UI ожидает, что `/revisions/:id?summary=1` не возвращает файлы; удалённый backend для этого URL отдаёт полную ревизию. UI и endpoint должны выбираться вместе.
4. `web-assets.generated.ts` нужно пересобрать после выбора UI, не объединять вручную.

- Зафиксировать текущий remote head и создать из него изолированную интеграционную ветку.

- Для backend предпочесть наши гарантии восстановления, ограниченных ресурсов и scoped reads. Для UI сохранить нашу основу и добавить удалённые demo events/SDK paging assertions. Перенести лёгкую справку и дополнительные позитивные проверки.
- Повторить gates на объединённом коде, включая настоящий TCP SDK и extracted pinned runtime; затем обычный push новых коммитов в PR, без merge в main и без force-push.
