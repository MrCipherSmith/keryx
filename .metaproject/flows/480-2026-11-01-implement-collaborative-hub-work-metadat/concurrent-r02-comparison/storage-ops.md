# Storage / contract / operations comparison

Snapshots: ours `bb65652ca` (verified product tree `2aadf1165`); remote `8dcb765f072c5e8cb287175af7d7c9ce300ce322`; common reviewed base `d50652ac`. Read-only source/test comparison, not a new full review or a remote test certification. No merges, checkouts, edits, installs or pushes performed.

| Area | Recommendation | Concrete difference and reason |
|---|---|---|
| Legacy hot transactions and serialization | **Ours; preserve remote tests** | Both `store.load` implementations reuse persisted `hub_state.body` as the optimistic baseline and avoid reserializing on reads. Ours `store.writeTransaction/materialize` does not parse/stringify legacy history if the callback only uses `remote`; actual mutation shares one prepared serialization with `legacyArtifacts.persist`. Remote `readLegacy/writeTransaction` always loads and compares `serializedLegacy(state)` and serializes again on persistence. Its own `legacy-artifacts.test.ts` explicitly expects no-op **1 parse/1 serialization**, mutation **2/2**. Remote `remote-v2/index.ts` still calls `store.writeTransaction((_state, repo) => ...)`, so this is a real remaining call pattern, not an unused API. Ours costs reflective Proxy traps and a `prepare` interface; remote is simpler, but does less work elimination. Preserve remote save-reuse/notification/count assertions alongside ours zero-materialization, stale-save, rollback and returned-snapshot tests. |
| Startup legacy/session projections | **Compose: remote bootstrap structure + ours transaction behavior** | Both hash the canonical raw body into the same `legacy-projection-digest` setting and atomically rebuild `hub_legacy_records`/`hub_sessions` after old-writer drift. Remote `store.ts:recordProjectionDigest` uses one startup transaction and handles absent body via `stateDigest(body ?? '')`; ours retains two older bootstrap markers plus a later digest reconciliation. Remote is a smaller initialization path. Its `store.projections.test.ts` additionally checks retained session, session created by the old writer, old project and new project; preserve those assertions. No new durable-schema incompatibility in these projection tables was identified. |
| Document archive quotas and exact bytes | **Compose carefully, retain ours fail-closed behavior** | Both keep old immutable archives, skip new opportunistic legacy history at capacity, and refuse mandatory new Work pins. **API polarity is opposite**: ours `archiveDocument(document, optional = false)` and `store.syncLegacy(..., true)`; remote `archiveDocument(document, pinned = true)` and `syncLegacy(..., false)`. Mixing only one file reverses policy. Keep these as one coherent change, preferably with a named mode in a future implementation. On same project/id/version but a different digest, ours checks the exact digest then non-ignoring INSERT hits the existing key; remote checks existence by version and uses `INSERT OR IGNORE`, potentially returning true without storing the supplied representation (source-derived distinction, not newly executed here). Preserve immutable-conflict rejection rather than silently ignoring mismatches. Shared blob addressing, noncanonical-base64 preservation and writer-v4 fence are otherwise unchanged in this diff. |
| Amendment resolution and incident aggregates | **Ours + remote regression assertions** | `commandState` loads resolving amendment Decisions explicitly in both; SQL condition order differs without changing meaning. Ours has composite `hub_work_decision_target` index, four approve/withdraw retry combinations; remote has three combinations and an explicit approvedRevisionId assertion. Incident projections differ materially: ours uses indexed `LIMIT 201`, explicit >200 refusal, deduplicated Attempt support and one acceptance-decision SQL join per Attempt. Remote `addIncidentContext` deduplicates Attempt IDs but fetches all matching incident rows, then queries Decisions once per related submission. Keep ours bounded/scoped behavior and `storage.incidents.test.ts` count regression; preserve remote explicit post-resolution pin assertions. |
| Public schemas, capabilities and live contract tests | **Equivalent wire behavior; compose tests** | Both AttentionPage unions include EvidenceRecord and both capabilities return exactly the original six public limits. Remote constructs those six via local destructuring; ours uses `publicWorkLimits`; no wire change. Remote removes explicit `minItems: 0` from `affectedIntentIds`; JSON Schema defaults to zero, so Flow-only `[]` remains valid in both command/domain schemas. Ours `http.projections.test.ts` uses real `createHubApplication`, SQLite export/reopen and authorization; remote `http.contract.test.ts:served` uses a minimal HubStore/auth stub around the production Work handler. **Preserve its unique browser `liveWorkAdapter(...).attention()` → served AttentionPage integration test**, plus our real application tests. |
| Attempt participant authorization | **Equivalent; compose tests / remote small helper shape acceptable** | Ours `participant(transaction,a)` and remote `participant(actor,a)` both require actor.id==participantId and reject agent use of a human-method Attempt on start/report/subject/evidence/submit/withdraw. Error codes/policies match; messages differ. Remote `handlers-attempts.test.ts` explicitly pairs denied colleague/agent with successful owner actions. Ours `participant.authorization.test.ts` additionally covers an agent sharing the human participant ID (method-mismatch). Keep both useful assertions; no actor-policy reconciliation is necessary in this owned scope. |
| Migration queue readiness | **Ours; preserve remote terminal-state intent** | Both treat applied/rejected/removed queue history as settled. Remote `migrate-legacy.py:info_for` directly queries `json_extract(body, '$.item.state')`. Ours additionally inspects `PRAGMA table_info`, conservatively counts rows in old body-less schemas and uses `json_valid` before extraction, retaining malformed JSON as unknown/unresolved. Ours `migrate-legacy-boundaries.test.py` contains explicit body-less and malformed-data cases from `4759009a1`; these were needed after the initial actual gate failed. Keep this hardened implementation and tests. |
| Safety-backup retention | **Equivalent implementation; compose regression coverage** | Both retain newest three, referenced pre-upgrade copy, and every copy younger than 14 days. Remote omits `find ... -print`, relying on find's equivalent default action. Remote test asserts eight young upgrade copies survive and old pre-rollback copies except the pointer are removed. Ours tests additionally exercise an old newest-set/count floor, an untouched old manual backup, and a separate all-young case; our isolated mutation verification killed both `NR>3→NR>1` and age-guard removal. Keep both age/pruning and count-minimum assertions. Neither requires changing the approved age policy. |
| Packaging, CI and runtime safeguards | **Ours offline controls; retain remote explicit opt-in intent** | Both default suites gate the extracted-runtime network integration and CI opts in. Remote uses `KERYX_LIVE_TEAM_HUB_INSTALL=1`, warms a fresh private cache inside that test, then relies on `--offline`. This is stronger offline evidence: our pinned Bun1.3.14 probe showed `--offline` alone can return success with an initially empty cache. Preserve ours ordinary missing-cache/URL-refusal tests and actual extracted SDK proof. The real native-request cleanup hardening is outside this owned file set; keep the already verified `2aadf1165` behavior during any later request-wrapper integration. |
| Work help and documentation metadata | **Remote lightweight help module + both help tests** | Both `printHubHelp` route root/deep Work help to WORK_HELP. Remote extracts `work/help.ts` and imports it directly instead of importing the command implementation and its client/OpenAPI dependencies. This is a useful small dependency reduction; retain remote file and corresponding CLI re-export/use, with ours root and deep main-CLI spawn regressions. Both fix H1/Version placement; no contradictory metadata or Flow-only-empty-array requirement was found here. |

- `src/hub/store.projections.test.ts`: old-writer logout plus created/retained sessions and both projects; optional archive-full writes with mandatory pin refusal.
- `src/hub/work/handlers-attempts.test.ts`: successful original participant for every denied follow-up command and withdrawal.
- `src/hub/work/http.contract.test.ts`: served attention through the actual browser adapter; explicit capabilities schema check.
- `src/hub/work/storage.scenarios.test.ts`: Intent-only amendment approvedRevisionId and exactly-one resolving Decision assertions.
