# Acceptance Criteria

Rules:

- Criteria lines use the exact format `- ACn: <criterion>`.
- After `flow freeze` this file is checksum-protected: any edit outside
  `keryx flow ac update` fails every gate and status transition.
- Completion requires every ACn to be confirmed via
  `keryx flow ac confirm <id> <ACn>`.

## Criteria

- AC1: `agentEntrypoints.root` is written as entries `{ runtime, path, scope: "local" | "shared" }` (Codex local entries also carry `mode: "override" | "skip"`); a manifest holding the legacy string array is still read by init, update and rules commands, and one `keryx update` rewrites it to the entry form.
- AC2: In a git repository with tracked `AGENTS.md` and `CLAUDE.md`, after `keryx init` and again after `keryx update`, the `keryx:index` block is present in `CLAUDE.local.md` and absent from `CLAUDE.md` and `AGENTS.md`, and `git status --porcelain` lists none of `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `.claude/settings.json`.
- AC3: With Codex mode `override`, `AGENTS.override.md` contains the full current `AGENTS.md` content plus the keryx block and is regenerated by `keryx update` after `AGENTS.md` changes; no code path writes `AGENTS.override.md` without the `AGENTS.md` content, and when `AGENTS.md` is absent Codex is skipped with a message and no tracked `AGENTS.md` or `CLAUDE.md` is created.
- AC4: With Codex mode `skip`, no Codex file is written or modified and the command output says Codex was skipped.
- AC5: Keryx-managed Claude hooks are written to `.claude/settings.local.json`; after init, update and migration every keryx-managed hook command appears exactly once per event across `.claude/settings.json` and `.claude/settings.local.json` combined.
- AC6: When `.metaproject/` is ignored as a whole, init and update write no ignore block anywhere; otherwise the managed block is written to `info/exclude` of the git common directory (also from a linked worktree) and the tracked `.gitignore` is not modified.
- AC7: After init and after update, `git check-ignore` reports `CLAUDE.local.md`, `AGENTS.override.md` and `.claude/settings.local.json` as ignored, with missing ones added to `info/exclude`.
- AC8: A repository with the legacy string-array `root`, managed blocks as uncommitted edits in tracked `AGENTS.md`, `CLAUDE.md` and `.gitignore`, and managed hooks as uncommitted edits in `.claude/settings.json` is migrated by one `keryx update`: `git diff --quiet` passes for each of those files, the blocks and hooks exist only in the local targets, and a second `keryx update` changes no file.
- AC9: When a tracked file carries a managed block plus unrelated uncommitted edits, update removes only the text between the markers, preserves the other edits byte-for-byte, and names the file in its output.
- AC10: When the managed block is present in `HEAD` of a tracked entrypoint, update migrates that entry with `scope: "shared"`, leaves the file unmodified, and prints how to switch it to local.
- AC11: `keryx doctor` reports a managed block or managed hooks found in a tracked file whose scope is local as a warning that includes the fix command, and reports a stale `AGENTS.override.md`; `keryx standard doctor` raises no entrypoint error on a migrated repository.
- AC12: The index block text, the agent-entrypoint-manager and agent-entrypoint-distiller skills, and the user docs describe the local targets; no shipped source text tells the reader the block lives in "this AGENTS.md/CLAUDE.md file".
- AC13: Tests cover fresh init, migration, idempotency, a tracked file with unrelated local edits, and `AGENTS.override.md` never written without `AGENTS.md` content; the full test suite, typecheck and lint pass.
