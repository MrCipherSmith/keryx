# Implementation Plan

Status: ready (context collected, decisions confirmed by the owner 2026-09-30)

## Approach

One model for "where does keryx write, and is that place shared or local", read by every
writer, instead of literals repeated per writer. Evidence for each point is in
`context.md` ("Agent Findings", sections A–H).

### Manifest

```json
"agentEntrypoints": {
  "index": ".metaproject/index.md",
  "readme": ".metaproject/README.md",
  "metaproject": ".metaproject/index.md",
  "root": [
    { "runtime": "claude", "path": "CLAUDE.local.md", "scope": "local" },
    { "runtime": "codex", "path": "AGENTS.override.md", "scope": "local", "mode": "override", "source": "AGENTS.md" }
  ],
  "claudeSettings": { "path": ".claude/settings.local.json", "scope": "local" }
}
```

- `scope: "shared"` entries are `CLAUDE.md` / `AGENTS.md` / `.claude/settings.json` — today's behaviour, an explicit opt-in.
- Codex local `mode` is `"override"` or `"skip"`; it is always written, never inferred at write time.
- One normalizer reads both the new form and the legacy string array. The three local
  `agentEntrypoints` types (init.ts, update.ts, rules.ts) collapse onto it.
- The rule-import source list (tracked `.metaproject/rules/<file>.md` copies) is no longer
  the `root` list: it stays the team files that exist on disk (`AGENTS.md`, `CLAUDE.md`).
  Local targets are never imported into tracked rules (context H5).

### Writers

- **Claude, local**: block in `CLAUDE.local.md`, created when missing. When the repo has
  `AGENTS.md` and no `CLAUDE.md`, the implementer first checks the Claude Code memory
  docs for whether a `CLAUDE.local.md` suppresses an AGENTS.md fallback; only if it does,
  the generated file carries an `@AGENTS.md` import (context H1). The finding and its
  source are journaled either way.
- **Codex, local/override**: `AGENTS.override.md` = a provenance line naming the source
  and its sha256, the block, then the full `AGENTS.md` content (block-stripped if the
  source still carries one). Regenerated by `keryx update` and `keryx rules sync`;
  staleness (source hash mismatch) and the 32 KiB Codex cap are doctor warnings.
  `AGENTS.md` absent → Codex is skipped with a message naming the two ways out (create
  `AGENTS.md`, or set scope shared). Owner decision.
- **Codex, local/skip**: nothing written, one line in the command output says so.
- **No tracked defaults**: `ensureDefaultAgentEntrypoints` stops creating tracked
  `AGENTS.md`/`CLAUDE.md` when scope is local (context H6).
- **Claude hooks**: every Claude `settings.json` surface (security, ctx, orient, learning
  observer, jev edit guard, `unmigratedHooks`) resolves its path through one resolver
  backed by `claudeSettings`; the literal stops being repeated (context D). All move
  together so `assertRegistryCoherent` stays per-path coherent.
- **Ignore rules**: `git check-ignore --no-index` decides. `.metaproject/` ignored as a
  whole → nothing written. Otherwise the managed `# keryx:begin … # keryx:end` block goes
  to `<git-common-dir>/info/exclude` (resolved with `git rev-parse --git-common-dir`, so
  linked worktrees share it), written with the managed-git-hook out-of-root pattern and
  a contained-write ratchet allowlist entry (context C, H12). Each local target not
  already ignored is added to the same block. Outside a git repository the local files
  are still written and the ignore step is skipped with a note (context H19).

### Migration on `keryx update`

Per tracked file that carries a managed block (or managed hooks) while its target scope
would be local:

1. **Block or hooks present in `HEAD`** → the team committed it. The entry migrates as
   `scope: "shared"`, the file is not touched, and update prints how to switch to local.
   Owner decision; keeps the tree clean and the second run a no-op.
2. **Not in `HEAD`, file otherwise equal to `HEAD`** → write the local target, then
   restore the tracked file to its `HEAD` bytes and verify with `git diff --quiet -- <file>`.
   Restoring from `HEAD` rather than re-serialising is what makes byte-identity reachable
   despite blank-line collapsing and JSON re-formatting (context H8, H9).
3. **Not in `HEAD`, file has unrelated uncommitted edits** → remove only the text between
   the markers (or only the keryx-managed hook groups), keep the edits, report the file.
4. **Untracked file created by keryx that holds nothing but the block** → left in place and
   reported; keryx does not delete a file it cannot prove it owns.

The legacy string array is rewritten to the entry form in the same run. The managed
`.gitignore` block follows the same three cases. After migration the block and the hooks
exist in exactly one place.

### Readers that must learn the local targets

`src/standard/validate.ts` + `profiles.ts` (otherwise every migrated repo gets
`entrypoint-missing-index-link`, context H4), `keryx doctor` (new check: managed block or
managed hooks in a tracked file while scope is local → warning with `keryx update` as the
fix; stale or oversized `AGENTS.override.md`; local target missing in this worktree,
context H2), `audit-harness` surfaces and `write-run` flagged basenames (H15), the
stale-worktree prune (H14), `--preview` output (H18), the zed probe and
`review-jev-rules` strippers if they assume the shared files.

## Steps

1. T5 — entrypoint-target model, manifest normalizer + legacy migration decision, local-ignore library. Pure modules with unit tests; no command wiring.
2. T6 — index-block writers and migration wired into `init`, `update`, `rules sync`, `rules distill`.
3. T7 — ignore rules: `check-ignore`, `.git/info/exclude`, tracked `.gitignore` migration, local targets ignored.
4. T8 — Claude hooks resolve through `claudeSettings`; hook migration; never in both files.
5. T9 — readers: standard validate/profiles, doctor checks, audit surfaces, worktree prune, preview.
6. T10 — docs, skills, templates, index-block wording, CHANGELOG, version bump.
7. T11 — end-to-end acceptance run of the worktree build against throwaway git repositories.
8. T3 — full suite, typecheck, lint green. T4 — review.

Tasks run serially: T6–T9 edit the same command files.

## Risks

- A gitignored local file exists only in the worktree that ran `keryx update`. Not solved
  here; doctor reports a missing local target so the gap is visible (H2).
- Cloud/remote Claude sessions do not read `settings.local.json` (H22). Teams that need
  hooks there use `scope: "shared"`; documented.
- `metaproject.json` is tracked, so scope and Codex mode are team settings, not
  per-developer ones (H7). Documented, not changed.
- `AGENTS.override.md` goes stale between an upstream `AGENTS.md` change and the next
  `keryx update`; until then Codex reads the older team text. Doctor warns.
- The opt-in `rules-export` block (`keryx:rules` in CLAUDE.md/AGENTS.md) has the same
  tracked-file problem and is left as a follow-up (H16).
- Guards expected to fire and need updating: capability-matrix JSON, registry tests,
  gitignore-guard, contained-write ratchet, skill length ceiling (H17).
